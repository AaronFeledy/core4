# SvelteKit

Create the Lando services for a SvelteKit frontend with Node and an optional
database. The recipe writes `.lando.yml`, not application files. Its adapter
picker records an environment hint; install and configure the adapter yourself.

Before you begin, install Lando and complete provider setup. For a new app,
run the initialization command from the directory that will contain it. If this
README is already in a generated app, skip the `lando init` and `cd` lines below. Run
the remaining app commands from that directory.

```sh
lando init --recipe sveltekit --name=my-sveltekit --yes
cd my-sveltekit
lando start
lando info
```

`--yes` uses Node lts, the `node` adapter, and no database. Pass `--answer` to change those.

To choose a different stack, use this initialization command instead of the
default one above. Run it from the parent directory, not inside the app:

```sh
lando init --recipe sveltekit --name=my-sveltekit --yes \
  --answer=adapter=auto \
  --answer=database=postgres
```

| Option | Values | Default |
| --- | --- | --- |
| `node` | `lts`, `22` | `lts` |
| `adapter` | `node`, `auto` | `node` |
| `database` | `none`, `postgres`, `mariadb` | `none` |

The scaffold writes only `.lando.yml`. It declares a `web` service on `node:<node>` with an HTTP endpoint on port 5173 and your adapter choice exposed as the `SVELTEKIT_ADAPTER` environment variable. Pick `postgres` or `mariadb` and the Landofile adds a `database` service of that type that `web` waits on. Keep `none` and there is no `database` service at all.

`lando start` keeps the Node service idle; it does not start Vite. The Landofile declares a `dev` task for that. After installing your app and starting it, run:

{/* lando-lint: not-e2e the dev server runs in the foreground until interrupted */}
```sh
lando dev
```

`lando dev` runs `vite dev --host 0.0.0.0 --port 5173 --strictPort`, so the proxy can reach Vite on the recipe's port without any `server` settings in `vite.config`. It also sets Vite's `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` variable to the hostname Lando publishes for `web`, so Vite accepts requests through the proxy and still rejects every other hostname. It needs a started app. Change the `--port` value in `tooling.dev` when you change `port:`. An authored `environment.PORT` must match `port:` or planning fails.

The Landofile also declares `lando svelte`, and the `web` service adds `lando npm` and `lando npx`. All of them run inside `web`:

```sh
lando svelte --help
lando npm install
```

`lando svelte` runs the `svelte-kit` binary your project installed, through the project's package manager, so `lando svelte sync` runs the SvelteKit CLI in the container, not on your host. `lando dev` runs the project's `vite` binary the same way. Neither downloads anything, so install your dependencies first. A project that declares Yarn or pnpm in `package.json` gets `lando yarn`, or `lando pnpm` and `lando pnpx`, in place of `lando npm` and `lando npx`.

`lando start` prints the app URL at `https://<app-name>.lndo.site`. `lando info` repeats it.

`lando destroy -y` removes the app containers and networks and keeps its named volumes. See [Keep data across stop, restart, and destroy](https://aaronfeledy.github.io/core4/guides/tutorial/app-lifecycle/#keep-data-across-stop-restart-and-destroy).
