## Codebase Patterns

- The disposition matrix (US-466) is the single classification source: coverage gate, docs matrix, rejection remediation text, and conformance skip-list are all derived artifacts. Never hand-maintain a second key list.
- The vendored Compose schema is a coverage oracle, not a codegen source: Effect Schema in @lando/sdk stays hand-authored per spec §1.2.
- Pin source is a compose-go tag (compose-spec/compose-spec is an untagged mirror; never pin to it).
- Keep the networked `codegen:compose-vendor` refresh outside generic offline `codegen`; tests and coverage gates read only committed bytes.
- The vendored upstream schema is checksum-pinned byte-for-byte and excluded from formatting; format the pin and tooling, never the schema payload.
- Top-level Compose dispositions need AppPlan-specific rationales; `configs` and `secrets` are preserved because AppPlan has no provider-neutral fields for them.
- A per-command oclif `--format` `options:` list does not validate anything: the universal resolver strips `--format` before oclif parses and reinjects `flags.format`. Real validation is `RESULT_FORMATS` in `core/src/cli/format-flags.ts`, so a command silently ignoring a format is a bug in its own option mapping, not in the flag declaration.
- A new or changed static oclif flag is inert until `bun run codegen:oclif-manifest` runs: `--help` and compiled-path flag validation both read the generated `compiled-manifest.ts`. `core/oclif.manifest.json` is gitignored; `compiled-manifest.ts` and `docs/reference/commands.mdx` are the committed artifacts.

- **Learnings for future iterations:**
  - `--format` is stripped from argv by `resolveResultFormat` BEFORE oclif parses, then reinjected as `flags.format`. So a per-command `options: [...]` list never validates `--format`; the real allow-list is `RESULT_FORMATS` in `core/src/cli/format-flags.ts`. That is why `--format yaml` was accepted yet silently rendered a table for so long — the only real gate was the positive filter in `appConfigOptionsFromInput`. Keep that filter a positive allow-list: the universal default is `"text"`, which must keep falling through to `?? "table"`.
  - A new static oclif flag is NOT live until `bun run codegen:oclif-manifest` runs. `--help`, and the compiled dual-dispatch flag validation, both read the generated `compiled-manifest.ts`, so an un-regenerated manifest looks exactly like a broken flag. `core/oclif.manifest.json` is gitignored; only `compiled-manifest.ts` and `docs/reference/commands.mdx` are committed artifacts.
  - Order matters in `renderAppConfigResult`: the `get` and write-verb guards must stay ahead of the format branch, or `app config set ... --format yaml` starts dumping a whole Landofile.
  - The shared `invalid_option` remediation ("Supply --flag with one of its declared values.") never names the allowed values. Rather than widen that every-command message for one story, assert discoverability through `--help`; revisit centrally if more flags need it.
