## Codebase Patterns

- The disposition matrix (US-466) is the single classification source: coverage gate, docs matrix, rejection remediation text, and conformance skip-list are all derived artifacts. Never hand-maintain a second key list.
- The vendored Compose schema is a coverage oracle, not a codegen source: Effect Schema in @lando/sdk stays hand-authored per spec §1.2.
- Pin source is a compose-go tag (compose-spec/compose-spec is an untagged mirror; never pin to it).
- Keep the networked `codegen:compose-vendor` refresh outside generic offline `codegen`; tests and coverage gates read only committed bytes.
- The vendored upstream schema is checksum-pinned byte-for-byte and excluded from formatting; format the pin and tooling, never the schema payload.
- Top-level Compose dispositions need AppPlan-specific rationales; `configs` and `secrets` are preserved because AppPlan has no provider-neutral fields for them.
- Landofile decode runs twice (per-file, then over the merged result with `onExcessProperty: "error"`), so every `ServiceConfig` field transform must accept its own canonical output as input. Pair each new alternate-form field with a `decode(decode(x)) === decode(x)` test; an encode round-trip test alone will not catch the second pass.
- A per-command oclif `--format` `options:` list does not validate anything: the universal resolver strips `--format` before oclif parses and reinjects `flags.format`. Real validation is `RESULT_FORMATS` in `core/src/cli/format-flags.ts`, so a command silently ignoring a format is a bug in its own option mapping, not in the flag declaration.
- A new or changed static oclif flag is inert until `bun run codegen:oclif-manifest` runs: `--help` and compiled-path flag validation both read the generated `compiled-manifest.ts`. `core/oclif.manifest.json` is gitignored; `compiled-manifest.ts` and `docs/reference/commands.mdx` are the committed artifacts.
- Build multi-form schema test fixtures by decoding an ENCODED document through the schema and asserting against the decoded result, rather than hand-writing canonical decoded values. It removes a whole class of wrong-by-guess assertions and makes the test prove canonicalization instead of assuming it.
- `Pick<T, "a"> & { readonly b?: B }` is not interchangeable with `Pick<T, "a" | "b">` under `exactOptionalPropertyTypes`: the hand-written optional excludes `undefined` and rejects the real source type. Spell narrowed views as a `Pick` of the source so optionality stays identical.
- The app-plan cache key deliberately omits provider capabilities, so any capability gate must also run on the cached-plan path; and any change to planner OUTPUT semantics needs an `APP_PLAN_CACHE_SCHEMA_VERSION` bump, because the key is derived from the authored Landofile and will not roll on its own.
- Biome scans untracked sibling checkouts. A stale `.worktrees/` directory is git-excluded and invisible to `git status`, yet makes `bun run lint` fail on files outside the change; scope Biome to tracked package dirs before believing a repo-wide lint failure.
- The machine-output envelope narrows every error to `{_tag, message, remediation}` by design. Structured error context belongs in the message and in the bug-report formatter's extra fields, not in a per-error widening of the shared envelope.
- Schema parse-error messages can reach the plain terminal renderer unchanged. Never interpolate raw Landofile values into those messages; use constant grammar/remediation text so control bytes cannot alter terminal output.

## 2026-07-26 02:40 CDT - US-469
- Made the Compose `ports`, `expose`, and `volumes` service vocabulary real: both the short-string grammar and the long object form now decode, canonicalize, and normalize into Lando's endpoint and mount models. Grammar moved out of the plugin and into two new SDK schema modules so a single parser serves every consumer; `ServiceConfig.ports` is now a canonical `ComposePortEntry[]`, `volumes` a canonical `ComposeVolumeEntry[]`, and `expose` is a new field. `ServiceConfig` stays a plain `Schema.Struct` (field-level transforms only) and the encoder emits the Compose long form, so `Schema.encode` round-trips.
- Port grammar matches compose-go: `[HOST:]CONTAINER[/PROTO]`, bracketed IPv6, default tcp, numeric-or-string `published`. Container-only and equal-length mapped ranges expand at decode into one endpoint per port; a published range against a scalar target, an unequal-length range, and a long-form ranged `published` all fail with remediation to enumerate mappings, because `EndpointPublication.hostPort` is a single number. `sctp` fails since `EndpointPlan.protocol` has no such member.

- Lando-key precedence now actually works: an active `appMount`, any explicit `mounts[].target`, and any explicit `storage[].target` suppress the whole overlapping `volumes:` entry, matched on exact container target (so `/app` does not suppress `/app/web`) and resolved before the append-only feature context is touched. This corrected an inverted precedence: previously a compose-inferred store won and the authored Lando `storage:` entry was skipped.
- Rejected matrix keys stay absent from the accepted schemas and fail closed through the Landofile decode path; the tagged matrix-sourced error surface remains US-475's. Short-volume `ro`/`rw` normalize, `nocopy`/`z`/`Z`/propagation tokens fail naming their matrix key, and unknown tokens are ignored for compose-go parity.
