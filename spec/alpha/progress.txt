## Codebase Patterns

- Durable Alpha/phase/version claims live in README, contributing docs, and tests. Files outside the specification tree must restate those facts; they must not cite specification-tree paths (the spec-reference boundary).
- The public Alpha publish line is unsigned `4.0.0-dev.N` on dist-tag `dev`. `4.0.0-alpha.N` is not the current scheme.
- Unix CI compiled artifacts are all named `lando`. A six-target GitHub assemble must download each `lando-<id>` artifact into a distinct directory and rename with `releaseBinaryFileName` (`lando-<id>` / `lando-<id>.exe`). Dumping them into one `dist/` overwrites.
- The generated `release` workflow publishes unsigned six-target GitHub prereleases only. Live npm `dev` publish stays on `scripts/release.ts`; do not add `npm publish` to `.github/workflows/release.yml`.
- Intel Mac fail-closed lives in `@lando/provider-lando` (`rejectIntelMacHost` on setup, bundle resolve, ensureRuntime, getStatus), not in provider precedence. Capability default stays `lando`. Do not set `isAvailable` false or file-sync silently skips.
- Live setup/doctor evidence is the generated `platform-readiness` workflow plus `scripts/platform-readiness-doctor.ts` (decode doctor JSON; `self` and `status: fail` and non-running setup-readiness are blocking; warnings are not). GitHub-hosted macOS arm64 and Windows arm64 cannot nested-virt; those cells are fail-closed self-hosted `lando-virt` labels, not advisory skips.
- A runtime-bundle host key can be assembled current-commit from `runtime-bundle-sources.json` and `RUNTIME_BUNDLE_TARGETS` before it appears in the committed published manifest. `REQUIRED_RUNTIME_HOST_KEYS` stays the published set.

- `lando init --name` without `--destination` writes `<cwd>/<name>/` (`resolveInitDestination`). Scripts that init then start must chdir into that directory.
- Public recipes that must answer `recipes validate <path>` ship `recipes/<id>/recipe.yml` byte-identical to the builtin embed YAML (toolbox and rails). README.mdx-only public trees cannot be validated as a directory.
- Recipe journeys clone as sibling committed-workflow generators that import `PLATFORM_READINESS_CELLS`. Do not fold them into setup/doctor jobs or fork a second cell table.
- Bundled `lando init` writes only `manifest.files` dests. Extra renderer Map keys are dropped. Dest + Map must ship together; keep `recipes/<id>/recipe.yml` byte-identical to the embed YAML.
- `ruby:3.3-slim` has no `make`. A recipe that `gem install`s native gems must add a prior `build.artifact` apt-get of `build-essential`. Recompile `dist/lando` after renderer changes; live init uses the compiled embed.
- Alpha 1 exit is a Status + runbook lock over existing six-cell workflows. Do not invent new journeys. Tests freeze README/ci.md phrases plus job keys in platform-readiness, drupal-journey, and rails-journey; they must not read the specification tree. If ci.md says `not Linux x64 only`, assert absence of the full historical sentence `Historical Alpha CI was Linux x64 only`, not the substring `Linux x64 only`.
- With `exactOptionalPropertyTypes`, copy Schema.optional fields by omitting undefined keys; do not assign `T | undefined` into `prop?: T`.
- Traefik host publish is the persisted chosen pair (socket-helper uses bindHttpPort/bindHttpsPort). 38080/38443 are last-resort try-list entries, not a hidden extra PortBinding.
- Doctor leftover-proxy probes and start-path EADDRINUSE remap use the persisted Traefik publish pair (bind hops if set, else advertised ports). Missing acquisition state falls back to 38080/38443; HTTPS leftover HTTP probes use role, not port===38443.
- Preferred 80/443 occupancy is plugin doctor check `preferred-host-ports`, not leftover `proxy-loopback-ports`. Leftover probes persisted Traefik ports and only leftover-rootlessport. Occupancy TCP-probes 80/443 on all platforms, skips this-instance claims and leftover-rootlessport, and warns on foreign holders. Do not reuse leftover `readPort` (HTTP success is healthy-proxy) or `isOurLoopbackForwarder` (would skip DDEV Traefik).
- When a story names a specification-tree section as the durable contract, that section is the lock. Do not restate those facts in README Status unless the story requires it. public-alpha-contract tests freeze Alpha 1 copy only and must not cite the specification tree.
