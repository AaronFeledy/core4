## Conventions

- Story IDs US-561..US-591; prd.json priority order is execution order (strict). Ordering guarantees no story depends on a later story.
- PRD-02 (keys), PRD-03 (services), PRD-04 (php) are mutually independent after US-561 and may run in parallel; PRD-05 requires PRD-04 + its own US-575 first; US-579 requires US-569 only for mssql coverage; US-580..581 closed the original wave; US-584..US-591 are the residual tranche (shipped-feature holes) and may run in parallel except US-585 before anything that assumes ServiceInfo.creds is populated.
- Feature wave, not infra: every user-visible surface ships its executable guide/README in the same story. Load `lando-write-docs` before authoring guides; guides are prose-first MDX with real `<Run>`/`<Verify>`.
- New service types must satisfy the full §6.12.1 per-service-type implementation checklist (resolution, contract suites, tooling, creds, schema publication) in the same change.
- SDK schema changes follow sdk/AGENTS.md: API_COMPATIBILITY.md where required + `bun run codegen:schema-snapshot`.
- Landofile un-gating removes keys from BETA_TOP_LEVEL_KEYS in landofile/src/service.ts one story at a time; never remove the whole gate in one story.
- Plugins may not depend on @lando/core; @lando/sql contributes through the generated composition root; all byte movement rides DataMover (§10.11); probe/paths/state-store boundary rules apply.
- Full-suite lock is always `bun test` (or explicit shard --run commands) with positive test counts. Never `bun run test` alone.
- After adding plugins/sql, run `bun install` and include the package in test shards.
- Run touched semantic gates per story: check:boundaries, check:guide-coverage, check:guide-drift, lint:guides, codegen:check when generated outputs move.
- Do not touch unrelated dirty working-tree files from other waves.
- Out of scope (do not implement): hoster connectors/RemoteSource impls, custom SSH-key mounts (sshAgent.sidecar:false stays rejected), staged §8.8.10 recipes (node-api, astro, sveltekit, nextjs, django, fastapi, rails, jekyll, hugo, eleventy, empty), image save/load.

## Codebase Patterns (carry forward)

- Official Tomcat empty ROOT returns HTTP 404; healthchecks must not use `curl -f`.
- Official `varnish:6` ignores `VARNISH_BACKEND_*` and needs generated VCL; `varnish:7` honors host+port env vars. Prefer one generated-VCL path for both majors.
- Official Varnish jails away from root even when the container user is root; catalog Varnish must exec `varnishd -F ... -j none` to bind :80 under rootless Podman.
- New catalog service types publish `@lando/sdk/schema/services/<type>` with `ServiceConfig.pick` plus a narrowed `type` literal; inherited picked fields need descriptions or schema-snapshot fails.
- `app:config` does not plan. Planner-derived deprecation warnings need `app:cache:refresh`; `lando doctor --deprecations` must scan the authored Landofile because doctor bootstraps at `none`.
- Service types live in plugins/service-lando/src/services/*.ts with _schema-helpers/_port-helpers/_volume-helpers; php build steps in php-prerequisites.ts (checksum-pinned downloads).
- Landofile service keys that are not Compose aliases must be added to `ServiceConfig` fields; the unknown-key allowlist is `Object.keys(ServiceConfig.fields)`, so a PHP-only schema does not make `composer:` authorable.
- The GHCR PHP base-image workflow matrix is hardcoded in `scripts/build-php-base-workflow.ts`, not derived from `SUPPORTED_PHP_VERSIONS`.
- Deferred commands: ids live on `LandoCommandSpec.deferred` plus `core/test/cli/fixtures/deferred-commands.json`; `deferred-commands.ts` is only `notImplementedErrorForSpec`. Remaining trio: `meta:events:follow`, `meta:plugin:login`, `meta:plugin:logout` (4.1).
- `recipes/` is the v4.0 shipped recipe set. `core/build.config.ts` `bundledRecipes` is a superset (staged ids plus `node-postgres`/`node-ts`); do not treat binary embed as the public table.
- Recipe manifests: recipes/<id>/recipe.yml + README.mdx (executable, feeds scaffold README generation); bundled registration via scripts/build-bundled-recipes.ts.
- Guide INDEX at docs/guides/INDEX.md; coverage enforced by check:guide-coverage.
- Planner-read file content outside Landofile expression provenance must contribute source/hash metadata to `deriveAppPlanCacheKey`; embedding parsed values in a service type's normalized config is not a reliable cache identity.
- Widening `AppPlanner.plan`'s error union requires adding the same tagged error to every App-handle and global-lifecycle error union that plans (`StartAppError`, `StopAppError`, `InfoAppError`, `ExecAppError`, `LogsAppError`, `LoadGlobalPlanError`, and the `meta:global:*` / `EnsureGlobalServices` unions).
- App-scoped command-routing policy belongs in the fresh app-command cache; native dispatch and help consume that cache without bootstrapping, while canonical command ids bypass alias policy.
- Dynamic and template-rendered Landofile command caches use file-based freshness only and serve the last full decode when non-file inputs change; do not fingerprint environment, host, or template-render inputs until a dedicated provenance contract authorizes them.
- Registry-backed services in generated bootstrap layers must receive registry entries through one-way injection; importing the built-in command registry back from a bootstrap service creates a command-spec/runtime-layer cycle.
- `ProviderCapabilities` fields added with `optionalWith` defaults become required on the decoded Type; every capability fixture must set the new field, and adding a property re-diffs sibling `allOf` optional structs in schema-compatibility.
- Cross-service catalog wiring that needs sibling discovery belongs in an `AppFeature` (`activatedBy` + `selectors`), not in `ServiceType.resolve`; resolve cannot see other services.
- nginx PHP FastCGI preset activates on `backend: <service>` and fastcgi_passes to that service on port 9000; omit `backend:` for stock static nginx.
- PHP `xdebug:` mode lives in `zz-lando-xdebug.ini`, not `XDEBUG_MODE` env, so `lando xdebug on|off` can reload Apache/FPM without a rebuild; env would win over the ini rewrite.
- An AppFeature with no selectors selects every service and will cycle with nginx PHP-FPM wiring; select PHP via `hasFeature` plus database `types:` when sibling discovery must not include nginx.
- File-backed Compose `configs:` hash into the app-plan cache like `env_file`. Bundled providers declare `composeProjectFields`/`composeServiceFields` `configs` and realize grants as read-only binds; `external: true` fails closed.
- Recipe `extends:` flattens before RecipeManifest validate. `flatten.ts` must not import `service.ts` (cycle). Bare `.` is not a local recipe path; use `./` or a `recipe.yml` path.
- Remote `extends` hops are YAML-only and jailed to the published parent root; `recipe.ts` is not executed from a remote parent tree.
- Bundled PHP recipes emit versioned database types (`mariadb:11.4`) that plan through `loadServiceTypeWithVersion`. `allowOverride` is rejected on `via: fpm`; nginx+FPM recipes must omit it and add an `edge` service with `backend:`.
- Laravel/symfony reuse php-stack like lamp; optional queue workers are a hand-written `via: cli` service, not a php-stack helper.
- A bundled child that `extends:` a parent still needs its own renderer registered under the child id. Flatten merges the manifest only; init looks up `lookupRecipeRenderer(manifest.id)` and never calls the parent renderer.
- Plugin-owned app commands that select among Landofile services should resolve the target from authored service types before `AppPlanner.plan`. Planner capability failures otherwise swallow tagged selection errors.
- Exec `AttachStdin` must be true when `stdinStream` is set, not only for `stdin: inherit`. After a finite stdin stream, half-close the write side (`socket.end()`) once headers are flushed; do not destroy the hijack or mysql hangs or never sees the dump.
- Native volume restore must stop the database container first. `RuntimeProvider.start/stop` are the per-service hooks; app CLI start/stop stay apply/destroy. Do not force `volumeSnapshot: copy` for InnoDB.
- `app:cache:refresh` has no top-level alias; teach `lando app:cache:refresh`. `--renderer=verbose` dumps every event payload and is not the OpenTUI task tree.
- DNS rebinding for custom loopback names is environmental. There is no Lando flag or doctor check; document remediations on the external-access guide.
