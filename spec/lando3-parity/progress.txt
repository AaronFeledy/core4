## Conventions

- Story IDs US-561..US-581; prd.json priority order is execution order (strict). Ordering guarantees no story depends on a later story.
- PRD-02 (keys), PRD-03 (services), PRD-04 (php) are mutually independent after US-561 and may run in parallel; PRD-05 requires PRD-04 + its own US-575 first; US-579 requires US-569 only for mssql coverage; US-580..581 last.
- Feature wave, not infra: every user-visible surface ships its executable guide/README in the same story. Load `lando-write-docs` before authoring guides; guides are prose-first MDX with real `<Run>`/`<Verify>`.
- New service types must satisfy the full §6.12.1 per-service-type implementation checklist (resolution, contract suites, tooling, creds, schema publication) in the same change.
- SDK schema changes follow sdk/AGENTS.md: API_COMPATIBILITY.md where required + `bun run codegen:schema-snapshot`.
- Landofile un-gating removes keys from BETA_TOP_LEVEL_KEYS in landofile/src/service.ts one story at a time; never remove the whole gate in one story.
- Plugins may not depend on @lando/core; @lando/sql contributes through the generated composition root; all byte movement rides DataMover (§10.11); probe/paths/state-store boundary rules apply.
- Full-suite lock is always `bun test` (or explicit shard --run commands) with positive test counts. Never `bun run test` alone.
- After adding plugins/sql, run `bun install` and include the package in test shards.
- Run touched semantic gates per story: check:boundaries, check:guide-coverage, check:guide-drift, lint:guides, codegen:check when generated outputs move.
- Do not touch unrelated dirty working-tree files from other waves.
- Out of scope (do not implement): hoster connectors/RemoteSource impls, custom SSH-key mounts (sshAgent.sidecar:false stays rejected), staged §8.8.10 recipes (node-api, astro, sveltekit, nextjs, django, fastapi, rails, jekyll, hugo, eleventy, empty), image save/load.

## Codebase Patterns (carry forward)

- Service types live in plugins/service-lando/src/services/*.ts with _schema-helpers/_port-helpers/_volume-helpers; php build steps in php-prerequisites.ts (checksum-pinned downloads).
- Deferred commands: core/src/cli/deferred-commands.ts + per-spec `deferred:` blocks.
- Recipe manifests: recipes/<id>/recipe.yml + README.mdx (executable, feeds scaffold README generation); bundled registration via scripts/build-bundled-recipes.ts.
- Guide INDEX at docs/guides/INDEX.md; coverage enforced by check:guide-coverage.
- Planner-read file content outside Landofile expression provenance must contribute source/hash metadata to `deriveAppPlanCacheKey`; embedding parsed values in a service type's normalized config is not a reliable cache identity.
- App-scoped command-routing policy belongs in the fresh app-command cache; native dispatch and help consume that cache without bootstrapping, while canonical command ids bypass alias policy.
- Dynamic and template-rendered Landofile command caches use file-based freshness only and serve the last full decode when non-file inputs change; do not fingerprint environment, host, or template-render inputs until a dedicated provenance contract authorizes them.
