## Codebase Patterns

- ConfigService Live is `core/src/services/config.ts` (`loadGlobalConfigSync`). Ignore the stale "Status: stub" comment on `core/src/config/service.ts`.
- Pure `@lando/sdk/network-trust` resolves CA **paths** only; PEM bytes are a core IO concern (HttpClient, setup, planner).
- `LANDO_NETWORK_CA_CERTS` is read in `resolveNetworkTrustPlan`; inject **flags** need friendly env aliases in `paths/src/overlay.ts` (US-489) — generic `LANDO_CONFIG__*` alone is insufficient vs §7.6.
- Service features must not take ConfigService; AppPlanner seeds `lando.security` feature config after one global resolve per plan.
- `setCerts` / `CertificatePlan` are leaf TLS for routes — do not overload for corporate CA PEMs.
- Artifact build steps use `buildKeyInputs` (see php-prerequisites) for digest material; exclude HTTP(S)_PROXY from environment build-key hashing.
- Derived image builds currently pack only a generated Dockerfile; CA packing is new work in container-runtime.
- `LANDO_BASE_DEFAULT_FEATURE_IDS` must gain `lando.security`; priority 1100 orders apply regardless of list position.
