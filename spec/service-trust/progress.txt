## Codebase Patterns

- Nested Landofile authoring aliases: model them as a `Schema.transform` whose `from` schema declares
  mutually exclusive `Schema.Union` variants, with `Schema.optional(Schema.Never)` anti-fields for
  every competing spelling. Keep the canonical variant first so canonical output survives a second
  decode. Annotate the `from` union so its description survives into `ServiceConfigInput` and the
  published artifact.
- A nested `Schema.Struct` publishes `additionalProperties: false`, so unknown nested keys fail closed
  under both default and strict decode and surface as path-precise lint violations.
- After any `ServiceConfig` field change, run `bun run codegen:schema-snapshot` early: it refreshes
  `dist/schemas`, `dist/command-schemas`, and `docs/reference/schemas`, and it runs the
  public-field-description gate.

## Ownership notes (spec-derived, easy to get wrong)

- lando.boot (priority 100) owns only the /etc/lando/* DIRECTORY scaffold, baked into the artifact.
- lando.env (priority 700) owns /etc/lando/environment content, env.d/, per-exec sourcing, and the
  LANDO_LINUX_* distro exports. It already ships at plugins/service-lando/src/features/env.ts.
- LANDO_CA_BUNDLE is always /etc/lando/certs/ca-bundle.pem, before and after the first rebuild.

  documenting the canonical form, aliases, inherit flags, and the `certs` distinction.
- Verification: typecheck, lint passed; schema/landofile test spot checks passed (444 SDK schema
  assertions plus 54 core Landofile tests); `lint:guides`, `check:guide-coverage`,
  `check:generated-output` green; real `.lando.yml` files linted through `lintLandofile` — the alias
  form reports `valid: true`, and a misspelled `inheritNetworkCA` plus `security.certs` reports
  per-key violations listing the six accepted keys.
- **Learnings for future iterations:**
  - Nested service authoring aliases belong in a `Schema.transform` whose `from` struct carries every
    accepted spelling; annotate that `from` struct (not just the field site) or the description is
    dropped from `ServiceConfigInput` and its published artifact.
  - A nested `Schema.Struct` yields `additionalProperties: false`, so unknown nested keys fail even
    under default decode options and surface as path-precise `app:config:lint` violations naming the
    accepted key set — no extra guard is needed for fail-closed behavior.
  - `bun test` prints no summary when every test in a file fails; use
    `--reporter=junit --reporter-outfile=<path>` to capture per-case RED evidence.
  - Guides whose scenarios are all `render={false}` add no generated scenario tests, so a new guide
    of that shape leaves `build-guide-scenarios` output unchanged.
