## Codebase Patterns

- Preserve superseded ROADMAP decisions as struck historical text followed by an explicit **Superseded** authority and the still-deferred remainder.
- Discover workspace manifests by expanding root `package.json#workspaces`; package-boundary rules must not maintain a second fixed package-root list.
- When a boundary rule has manifest and source halves, both must consume one exported policy table; a private source allowlist can silently reopen edges the manifest policy forbids.
- Source-edge burn-down allowlists must pin normalized target, edge kind, and type-only status; raw specifier matching alone permits nested-path and value-import bypasses.
- Package-local tests in a new workspace package need an explicit `scripts/test-shards.ts` include; workspace membership alone does not put them in CI unit shards.
- Assert public entry-point coverage against the `package.json#exports` keys rather than a hand-maintained list; an inventory that omits a subpath silently stops proving that subpath resolves.
- A post-publish install smoke must wait for every exact-version package it installs, not only the primary one; packages published later can still be unresolvable when the first install runs.
- Suites listed in `NIGHTLY_TIER_TESTS` (`scripts/test-shards.ts`) never run in PR shards, so their drift assertions can go red on `main` unnoticed; run them by path after touching the generator they guard.
- Derive boundary-inventory completeness from `BOUNDARY_RULE_IDS`; a maintained table without a registry-backed test can silently omit a new rule and its seam justification.
- Keep a retired boundary gate name as a package-script alias to its structural owner when callers may still use it, but remove the duplicate CI execution and record the alias in the boundary inventory.
