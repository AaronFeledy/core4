# Config translation progress

## Codebase Patterns
- Spec-class stories edit `spec/01..19-*.md` + `spec/README.md`; cross-refs use `§N.N` numbers (README topic lookup maps `§N` to file). Core spec text must state durable detail itself and never cite story ids or the PRD subdirectories.
- Gates for spec-only work: `bun run spec/config-translation/check-coordinated-plan.mjs` (omit `--initial` once any story passes), `bun run check:boundaries`, `bun run lint`, plus a grep scan for forbidden tokens (`ConfigFormat`, `LANDO_MOUNT`, `!lando3`, `LANDO_INFO`, `US-6xx`) and no new em-dashes in added lines.
- The plan checker only scans the three PRD directories for stale story refs and forbidden strings; the core spec files are covered by the grep scan, not the script.
- Parallel spec editing works well when partitioned by file (no two editors on one file); README topic rows go last because they cite final headings.
- Frozen naming contract for later stories: translators `lando4` / `recipe` / `lando3` (decode-only); inputs `landofile-document-set` / `recipe-request`; diagnostics `generated | dropped | rewritten | unsupported | non-portable | needs-review`; transaction states `prepared | committing | committed | blocked`; artifacts `<file>.bak.<full-before-sha256>` and `<target>.lando-stage.<transaction-id>`; secret dispositions `secret-store` or one `postInit.stdin` / `postInit.secretEnv.<name>` sink; commands `app:config:translate --to`, `app:config:explain`, `app:config:migrate`; events `pre-restart` / `post-restart`; doctor checks `lando3-leftovers` / `lando3-shadow`; binary `lando4` / `lando4.exe` during Alpha/Beta.
