# Lando 3 → Lando 4 gap analysis

Audit date: 2026-09-23. The Lando 3 compatibility wave is closed. These tables compare the Lando 3 surface recorded in [`reference/kitchen-sink.lando.yml`](./reference/kitchen-sink.lando.yml) and [`reference/kitchen-sink.config.yml`](./reference/kitchen-sink.config.yml) (561 real Landofiles, core source) against implemented native Lando 4 behavior and `lando4 app:config:translate --from lando3` results, not pre-implementation gaps. Historical section headings are retained; sections [5](#5-closed-disposition-and-owners) and [6](#6-residual-option-disposition) remain the normative decisions and owners.

Status vocabulary: **absent** (no schema, no code), **decoded-only** (schema accepts, nothing reads it), **partial** (exists with a narrower shape), **renamed** (same capability, different key; not a gap, listed only where users will trip), **rejected** (recorded design decision with remediation), **closed** (the owned capability or explicit conversion disposition is implemented; not blanket Lando 3 parity).

Conversion reads supplied app documents, not `~/.lando`, legacy global state, or CLI history. Explicit legacy settings and embedded command strings receive the diagnostics noted below; command guidance does not rewrite shell scripts. `--write` commits validated outputs through a managed-file transaction and refuses blocking diagnostics (`core/src/cli/commands/app-config-translate-write.ts`). Malformed selected YAML, unsafe tags/aliases, unsupported recipes/versions, and execution-shaping rejected fields still fail closed (`plugins/lando3/src/translator.ts`, `plugins/lando3/src/legacy-tags.ts`, `sdk/src/landofile/legacy/index.ts`).

Priority is by how many real Landofiles in the corpus depend on it and whether a user can work around it in Lando 4 today.

## 1. Structural gaps (no Lando 4 analog; change how apps are authored)

| # | Lando 3 | Corpus | Lando 4 today | Gap |
|---|---|---|---|---|
| S1 | **Live recipes.** `recipe: drupal11` + `config:` is expanded on every start; `services.appserver:` deltas merge *over* the injected service. 215/561 files are recipe apps and nearly all of them layer deltas (build steps, env, `overrides`). | 38% | Ordinary authoring files carry producer/options provenance; option expressions resolve without running recipe code (`landofile/src/recipe-expressions.ts`). No runtime expansion. | **Closed:** supported recipes decompose and merge authored deltas (`plugins/lando3/src/recipe-lowering.ts`). Hoster and drupal7–9 recipes remain unsupported; refresh is explicit, not a live recipe/include. |
| S2 | **Tooling option surface.** `options:` (yargs flags: `default`, `alias`, `describe`, `passthrough`, `boolean`, `choices`, `interactive` prompts), positionals declared in the key (`"drupal-update [module]"`), `positionals`/`usage`/`examples`, `user:`, `level: engine`, `disabled`/`false` to remove an injected command, multi-service `cmd: [{svc: cmd}, …]`, `service: :service` dynamic dispatch from an option, trailing `&`. | `options` 54x, multi-service `cmd` 34x, `user` 41x, `level` 13x | Native flags/args, disabled tasks, ordered service/host/user/dir steps, and dynamic service selection execute (`engine/src/operations/tooling-compile.ts`); `:host` works for plain tooling. | **Closed:** options → flags, positionals → args, command lists → ordered `cmds`, false → disabled (`plugins/lando3/src/lower-tooling.ts`, `plugins/lando3/src/lower-tooling-input.ts`). Level/usage/examples/prompts/background and extra aliases get drop guidance; forwarding/positional differences get review diagnostics. |
| S3 | **Tooling-scoped events.** `pre-<tool>`/`post-<tool>` for every tooling name; `post-db-import` is the canonical Drupal pattern (updatedb, cim, cr after import). A `post-db-import` hook requires a matching effective task; orphan hooks are dropped with guidance, not silently attached to `db:import`. |
| S4 | **Proxy string routes + middlewares.** `proxy.web: [host, host:port, host/path, "*-x.lndo.site", "a.*.b.lndo.site:8080/p"]`; object `{hostname, port, pathname, middlewares: [{name,key,value}]}`, `-secured` suffix; middleware merge by name across layers; `pathname` = PathPrefix **plus stripprefix**. | proxy 120x; string form ~90% of entries | Shorthand and objects normalize to routes with explicit filters; Traefik renders strip-prefix and header middleware (`plugins/proxy-traefik/src/routing.ts`). | S5 | **Build-step user split.** `build_as_root` / `build` / `run_as_root` / `run` (+`_internal`): four phases × two users, executed by `exec` after the container exists, gated by a config-hash lock. | `build` 152x, `build_as_root` 73x, `run_as_root` 12x, `run` 16x | Artifact/app steps carry users; app exec passes them, image builds restore final USER, and build keys hash them (`engine/src/services/build-app-step-runner.ts`, `engine/src/services/build-key.ts`, `container-runtime/src/image-build.ts`). | **Closed:** build/run hooks → artifact/app steps, root before user and internal before authored (`plugins/lando3/src/build-hooks.ts`). Review image-phase semantics; mixed Compose build plus Lando hooks and non-string hooks are unsupported. |
| S6 | **Container env contract.** `LANDO_INFO` (JSON of every service's info incl. DB creds, read by every `settings.lando.php`/`wp-config` in the wild), `LANDO_MOUNT`, `LANDO_APP_PROJECT`, `LANDO_DOMAIN`, `LANDO_HOST_IP`, `LANDO_PROXY_*`, `host.lando.internal` alias. | scripts in most PHP apps reference `$LANDO_INFO` or `$LANDO_MOUNT` | Typed `LANDO_DB_*`/`LANDO_SERVICE_*` and `LANDO_PROJECT_MOUNT` replace the old aggregate. Capable providers get `host.lando.internal` plus `LANDO_HOST_IP` set to that name (`engine/src/subsystems/networking.ts`). | **Closed with migration:** conversion removes hand-wired host alias/IP; `LANDO_INFO`, `LANDO_MOUNT`, and settings-file references receive review guidance, not compatibility aliases or script rewrites (`plugins/lando3/src/host-reachability.ts`, `plugins/lando3/src/legacy-references.ts`). |
| S7 | **Default mounts and home persistence.** `/app` (with `LANDO_MOUNT`), `/user` = `$HOME`, `/lando` = `~/.lando`, `/helpers`, and a per-service `home_<svc>` volume at `/var/www` so Composer/npm/yarn caches, `~/.gitconfig`, `~/.ssh/config` survive rebuilds. | universal | `/app` plus planned-user home persistence, `home: false` opt-out and explicit `home.path` (`engine/src/planner/home.ts`). No automatic `/user`, `/lando`, `/helpers`, or legacy-state binds. | **Closed:** home settings lower; Compose services get `home: false`, and unknown custom-image/user homes get opt-out plus path remediation (`plugins/lando3/src/lower-runtime-intent.ts`). Legacy helper/home-bind workflows still need manual mounts or replacement scripts. |
| S8 | **`overrides:` escape hatch**: raw Compose merged last on any service type. | 51x on recipe services alone | Supported first-class Compose fields remain capability-gated; native rejection is explicit (`landofile/src/compose/dispositions.ts`). | **Closed:** supported override fields lift to the service; `tty`, `stdin_open`, `links`, `network_mode`, `container_name`, and volume `consistency` block the affected service (`plugins/lando3/src/compose-dispositions.ts`, `plugins/lando3/src/compose-fields.ts`). No raw escape hatch bypasses rejection. |

## 6. Residual option disposition

Every catalog and command variant not owned by a native IR story has a closed conversion result. `target` means explicit v4 authoring output, `drop` means a `dropped` or `needs-review` diagnostic with remediation, and `unsupported` blocks conversion of the affected service or app.

| Legacy variant | Disposition | Exact result | Owner |
|---|---|---|---|
| PHP 5.6 through 8.0 and any absent service version | unsupported | Reject against generated ServiceType version metadata; do not manufacture images. | US-618E, US-621C1 |
| PHP `via: nginx` | target | Emit separate nginx service with backend reference; preserve supported apache/fpm/cli directly. | US-621C1 |
| PHP xdebug object | target/drop | Map supported mode/start/port fields; diagnose each unknown config key, never retain a residual object. | US-621C8 |
| PHP config.php/vhosts/pool/server | target | Emit read-only generic config mounts at the owning catalog's documented container paths. | US-621C1 |
| Lando 3 implicit Composer environment and launchers | drop | Emit migration guidance; do not add hidden environment or launchers. | US-621C8 |
| MySQL/MariaDB `authentication` | target | Emit the equivalent explicit server option in the generated `99-lando.cnf`. | US-621C1 |
| Memcached `mem` | target | Emit the catalog memory command argument. | US-621C8 |
| Elasticsearch/OpenSearch `mem` and plugins | target/unsupported | Map heap memory; reject plugin installation until a native catalog field exists. | US-621C8 |
| Solr core/config and versions | target/unsupported | Map cores and US-618A config directory; reject versions absent from generated metadata. | US-621C1 |

Unsupported versions, hosters, malformed YAML, unsafe tags/aliases, and rejected Compose fields remain intentional rejection fixtures. Corpus presence is evidence for diagnostics and prioritization, not a promise that every fixture converts successfully.
