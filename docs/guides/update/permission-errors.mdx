# Update permission errors

## Manual remediation on POSIX

`UpdatePermissionError` surfaces when there is `EACCES` or `EPERM` while staging, backing up,
replacing, rolling back, or re-executing the binary. POSIX remediation names the install path and
shows the manual `sudo` install command, but it doesn't run `sudo` for the user. The update path does
not invoke `PrivilegeService`, `sudo`, UAC prompts, or any other silent elevation mechanism.

## Windows fallback

When Windows replacement fails because the executable is locked, remediation tells the user to close
Lando processes and run the same file moves manually from an elevated shell if UAC is required. The
manual steps preserve the backup path `lando.exe.bak` so the user can restore the previous executable
if replacement fails.

## Telemetry categories

Update records only the categorized success or failure outcome through the `update-outcome` event.
The canonical telemetry fields are `version`, `targetVersion`, `channel`, `platform`, `outcome`.
`UpdatePermissionError` maps to the `permission_failure` telemetry category, and telemetry omits
install paths, hostnames, user ids, URLs with tokens, and raw command output.
