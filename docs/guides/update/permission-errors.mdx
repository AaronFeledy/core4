# Update permission errors

> **Alpha status:** In-place `lando update` is **not a shipping user path**. `update.lando.dev` is down, and there is no signed Windows or macOS binary to replace. See [Alpha install and bug reports](../../alpha-install-and-bug-reports.md).

If you cannot execute the Linux x64 binary you downloaded, you do not have an updater problem. You have a file you do not own. Put `lando` in a directory you can write, `chmod +x`, and rerun `lando --version`.

Alpha does not elevate for you. It will not run `sudo`, UAC, or any other silent privilege hop to overwrite an install path.

When in-place update does ship, a permission failure will name the path and stop. The code path does not invoke elevation. Until that ship date, replace the binary yourself from a `v4.0.0-dev.N` prerelease or from source.
