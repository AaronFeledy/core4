# Update channels and manifests

> **Alpha status:** `https://update.lando.dev` is **not serving v4**. `lando update` cannot fetch a signed channel manifest. See [Alpha install and bug reports](../../alpha-install-and-bug-reports.md).

For now, [install a newer GitHub prerelease](../install/github-releases.mdx) for your platform or build from source. Verify the download and use `lando --version` to confirm the replacement before running setup.

The updater code will resolve three channel names, and only these three: `stable`, `next`, `dev`. Planned URLs:

| Channel | Planned manifest |
| --- | --- |
| `stable` | `https://update.lando.dev/v4/stable.json` |
| `next` | `https://update.lando.dev/v4/next.json` |
| `dev` | `https://update.lando.dev/v4/dev.json` |

`LANDO_CHANNEL` on the POSIX installer script uses the same three names. Those URLs 404 today. A version like `v4.0.0-dev.N` maps to the `dev` channel in code. That mapping does not make a host exist.

When the host is up, a signed manifest older than the last signed version seen for that channel is refused as possible replay. Until then, there is no manifest to trust and no auto-update to run.
