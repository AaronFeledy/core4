# Profile PHP requests with XHProf and XHGui

A slow page tells you something is slow, not which function. Install the XHProf extension in your PHP service, send each web request's profile to an XHGui service, and read the call graph in your browser.

You need Lando 4 with a ready provider. The default provider is `lando` (managed Podman). Run the host commands from a new app directory for this demo. In an existing app, merge the services, mount, and tooling into your Landofile rather than replacing it.

## Configure PHP, XHGui, and Postgres

Save this as `.lando.yml` in your app directory:

```yaml
name: xhprof-demo
services:
  app:
    type: "php:8.3"
    primary: true
    build:
      artifact:
        - "pecl install xhprof"
        - "docker-php-ext-enable xhprof"
    mounts:
      - source: "./xhprof.ini"
        target: "/usr/local/etc/php/conf.d/zz-xhprof.ini"
        readOnly: true
  xhgui:
    type: compose
    image: xhgui/xhgui:0.23
    appMount: false
    home: false
    environment:
      XHGUI_SAVE_HANDLER: pdo
      XHGUI_PDO_DSN: "pgsql:host=profiles;dbname=xhgui"
      XHGUI_PDO_USER: xhgui
      XHGUI_PDO_PASS: xhgui
    endpoints:
      - _tag: internal
        name: ui
        protocol: http
        port: 80
    dependsOn:
      profiles:
        condition: service_healthy
  profiles:
    type: postgres
    creds:
      user: xhgui
      password: xhgui
      database: xhgui
tooling:
  composer:
    service: app
    cmd: [composer]
    dir: /app
```

- `app` runs PHP 8.3 under Apache. The two `build.artifact` steps compile and enable XHProf when Lando builds the image, and the mount drops a PHP ini file into the image's `conf.d` directory.
- `xhgui` runs the upstream XHGui image, which serves its UI on port 80. `appMount: false` keeps your source out of it, and `home: false` skips home persistence, which a Compose image needs unless you set `home.path`. The `ui` endpoint gives Lando an HTTP port to proxy, so the UI gets its own `*.lndo.site` URL.
- `profiles` is the Postgres store. XHGui creates its `results` and `watches` tables on first use. `dependsOn` holds XHGui until the Postgres healthcheck passes.
- `composer` runs Composer inside `app`. The PHP service ships Composer, so there is nothing else to install.

Save this as `xhprof.ini` next to the Landofile:

```ini
auto_prepend_file = /app/xhgui-header.php
```

Save this as `xhgui-header.php` next to the Landofile:

```php
<?php
$autoload = '/app/vendor/perftools/php-profiler/autoload.php';
if (PHP_SAPI === 'cli' || !is_file($autoload)) {
    return;
}
require_once $autoload;

try {
    $profiler = new \Xhgui\Profiler\Profiler([
        'save.handler' => \Xhgui\Profiler\Profiler::SAVER_UPLOAD,
        'save.handler.upload' => ['url' => 'http://xhgui/run/import'],
    ]);
    $profiler->start();
} catch (\Throwable $e) {
    error_log('xhgui: ' . $e->getMessage());
}
```

PHP runs this file before every script. It skips the CLI, so `lando composer` and other commands aren't profiled, and it does nothing until the profiler package is installed. Web requests upload their profile to `http://xhgui/run/import` when they finish; `xhgui` is the service key on the app network.

Save this as `index.php` so there is something worth measuring:

```php
<?php
function fib(int $n): int
{
    return $n < 2 ? $n : fib($n - 1) + fib($n - 2);
}

echo 'fib(25) = ' . fib(25) . "\n";
```

## Start and install the profiler

```sh
lando start
lando exec app -- php -m
lando composer require perftools/php-profiler
```

Check that `xhprof` appears in the module list. Composer writes `composer.json` and `composer.lock` to your app directory; commit both so the next `lando composer install` gets the same profiler release.

## Profile a request

Run `lando info` and open the `app` URL in your browser. The page prints `fib(25) = 75025`.

Open the `xhgui` URL from `lando info`. Check that the run list shows a run for `/`, then open it and check that its function table lists `fib`. Every page load adds a run.

If no run appears, check that `xhprof` is in `lando exec app -- php -m` and that `vendor/perftools/php-profiler` exists in your app directory.

## Keep profiles local

Each profile stores the request's query string, server variables (including request headers and cookies), and the PHP environment. This XHGui has no login and accepts uploads without a token. Keep it on your machine, and don't profile requests that carry real credentials or customer data.

## Keep or remove the profiles

`lando destroy -y` removes the app's containers and networks but keeps its volumes, so saved runs and the installed `vendor` directory are still there after the next start:

```sh
lando destroy -y
```

Add `--volumes` only when you want to delete the app's persistent volumes, including every saved profile. Your source files stay on the host.
