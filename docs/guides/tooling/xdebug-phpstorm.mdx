# Debug PHP with Xdebug in PhpStorm

Turn Xdebug on with `xdebug: true` (or a mode string). Lando installs the extension as a checksum-pinned build step, points `client_host` at `host.docker.internal`, and listens on port `9003`. Then toggle it without a rebuild:

```yaml
services:
  app:
    type: "php:8.3"
    primary: true
    xdebug: true
```

```sh
lando xdebug on
lando xdebug off
lando xdebug status
```

`xdebug: true` enables mode `debug`. A string such as `xdebug: "debug,develop"` sets `xdebug.mode` to that list. `xdebug: false` (the default) installs nothing. Setting `XDEBUG_MODE` in `environment:` does not add the extension.

## Pick an XDEBUG_MODE

These are Xdebug 3 mode values. They take effect once `xdebug:` installs the extension:

- `off` disables Xdebug entirely (`lando xdebug off`).
- `debug` is step debugging (breakpoints, step-in/over/out). PhpStorm needs this.
- `develop` gives richer `var_dump()` and stack traces on errors.
- `debug,develop` combines modes as a comma-separated list.
- `coverage` collects code coverage.

## Listen in PhpStorm

Start listening from `Run > Start Listening for PHP Debug Connections` (or the phone-handset icon) before you trigger a request. PhpStorm listens on port `9003` by default, matching Xdebug 3.

A browser extension or `XDEBUG_SESSION=PHPSTORM` cookie/query param triggers the debug connection per request. For CLI scripts, set `XDEBUG_TRIGGER=1` as a one-off env var.

Add a server in `Settings > PHP > Servers` whose name matches the value your app sends (or use the "absolute path on server" mapping without a name), and map `/app` to your project's local root so breakpoints land on the file you edit. On the first accepted debug connection, PhpStorm offers to auto-create the server entry and path mapping.

On Docker Desktop (macOS, Windows), `host.docker.internal` resolves automatically. On Linux without Docker Desktop, add `host.docker.internal` via `extra_hosts` or set `client_host` to the bridge gateway IP. If PhpStorm never receives a connection, confirm `lando xdebug status` shows the extension, then check the listener, port 9003, mode `debug`, and `client_host`. If a breakpoint hits but the wrong file opens, the server's path mapping does not match the container path. Fix it under `Settings > PHP > Servers`.
