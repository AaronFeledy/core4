# Xdebug in PhpStorm

Lando's stock `php` service does not install Xdebug. The `-apache-bookworm` image ships with only
`gd`, `intl`, `mbstring`, `opcache`, the PDO drivers, and `zip` — there's no PECL install, no
`docker-php-ext-enable`, and no runtime toggle that adds the extension for you. The `xdebug-demo`
fixture below sets `XDEBUG_MODE`/`XDEBUG_CONFIG` under `environment:` purely to prove those values
survive Landofile resolution into the running container; without the extension present, PHP ignores
them entirely and no debug connection can occur. Getting an actual listener connection requires
adding the extension yourself first — see the `php-customization` guide for installing it via
`build.artifact` or a custom image — after which the env vars below start doing real work.

```yaml
services:
  app:
    type: "php:8.3"
    primary: true
    environment:
      XDEBUG_MODE: debug
      XDEBUG_CONFIG: "client_host=host.docker.internal"
```

## XDEBUG_MODE values

These are Xdebug 3's own mode values — they only take effect once you've added the extension
yourself (see the intro above); the stock `php` service never reads them:

- `off` — disable Xdebug entirely.
- `debug` — enable step debugging (breakpoints, step-in/over/out), which PhpStorm needs.
- `develop` — enable enhanced `var_dump()` output, stack traces on errors, and the built-in function trace.
- `debug,develop` — combine modes as a comma-separated list.
- `coverage` — enable code coverage collection.

## PhpStorm listener setup

Everything below assumes you've already installed Xdebug into your PHP image (see the
`php-customization` guide) — Lando's stock `php` service has no listener to connect to without it.
Once the extension is present, start listening for PHP debug connections from
`Run > Start Listening for PHP Debug Connections` (or the phone-handset icon) before triggering a
request. PhpStorm listens on port `9003` by default, matching Xdebug 3's default.

A browser extension or manual `XDEBUG_SESSION=PHPSTORM` cookie/query param triggers the debug
connection per request. For CLI scripts, set `XDEBUG_TRIGGER=1` as a one-off env var on the command
instead.

Add a server in `Settings > PHP > Servers` whose name matches the value your app sends (or use the
"absolute path on server" mapping without a name), and map `/app` to your project's local root so
PhpStorm resolves breakpoints to the right file. On the first accepted debug connection, PhpStorm
offers to auto-create the server entry and path mapping from the incoming request.

On Docker Desktop (macOS, Windows), `host.docker.internal` resolves automatically. On Linux without
Docker Desktop, either add `host.docker.internal` via `extra_hosts` or set `XDEBUG_CONFIG` to the
docker0 bridge gateway IP directly. If PhpStorm never receives a connection, first confirm the
extension is actually installed and enabled in the container, then check the listener, port 9003,
`XDEBUG_MODE includes debug`, and `client_host`. If a breakpoint hits but the wrong (or no) file
opens, the server's path mapping doesn't match the container path — correct it under
`Settings > PHP > Servers`.
