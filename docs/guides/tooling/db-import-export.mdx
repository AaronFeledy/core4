# Import and export app databases

Use `lando db:import` and `lando db:export` for dump files. Use `lando db:snapshot` and `lando db:restore` for volume snapshots. Use `lando db:reset` when you want an empty database.

A single database service needs no `--service` flag. Two or more database services require `--service <name>`.

```sh
lando db:export dump.sql.gz
lando db:import dump.sql.gz --yes
```

`.gz` files gzip and gunzip on the way through. Credentials stay in the service environment, not on argv.

## Dump files

`db:export` writes `<service>.sql.gz` in the app root unless you pass a path. Relative paths resolve from the app root.

```sh
lando db:export backups/app.sql.gz --service database
lando db:import backups/app.sql.gz --service database --yes
```

MySQL, MariaDB, Postgres, and MongoDB stream through the client. SQL Server uses `sqlcmd` backup and restore files.

## Snapshots

Snapshots land in Lando's snapshot store, not next to your dump files.

```sh
lando db:snapshot --label before-change
lando db:restore before-change
```

## Confirm destructive work

`db:import` into a non-empty database and every `db:reset` ask first. `--yes` skips the prompt. Non-interactive runs without `--yes` fail with `SqlConfirmRequiredError` and list the steps.

```sh
lando db:reset --yes
```
