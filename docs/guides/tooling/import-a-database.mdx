# Import a SQL dump

Prefer `lando db:import` from the bundled SQL plugin. It decompresses `.gz` and `.zst` dumps on the host. See [Import and export app databases](/guides/tooling/db-import-export/). For a plain SQL file, piping it into the database client works too.

Grab the database name and user from `lando info` first. It redacts the password, and the commands below don't need it.

```sh
lando info
```

Run the bundled helper from your app directory with the database service running. Back up any data you need before importing; the dump can change or delete existing data. For a file, use `lando db:import dump.sql.gz --yes`.

To read the dump from stdin in a POSIX shell, run:

```sh
lando db:import - --yes < dump.sql
```

`--yes` is required because Lando cannot prompt while stdin carries the dump. Stdin imports need temporary disk space for the uncompressed dump; see [streaming imports](./db-import-export.mdx#stream-a-dump-through-stdout-or-stdin).

## Import into MySQL or MariaDB

The `mysql` and `mariadb` service types ship a client task that already connects to the app database. Feed it the dump:

```sh
lando mysql < dump.sql
lando mariadb < dump.sql
```

To pick the client flags yourself, run it through `lando exec`. The service name is the hostname. Defaults are user `lando`, password `lando`, and database equal to the app name unless you set `database:`.

```sh
lando exec db -- mysql -u lando -plando myapp < dump.sql
```

Feed the dump on stdin from the host. Recipes do not add a second alias on top of `lando db:import`.

## Import into Postgres

The `postgres` type ships `psql` the same way:

```sh
lando psql < dump.sql
```

Postgres generates its password per app, but `psql` inside the service connects as `lando` without one, so the `lando exec` form needs no password either:

```sh
lando exec db -- psql -U lando -d myapp < dump.sql
```

Pipe the dump on stdin. `-f` only works when the file already exists inside the service.

Piped input reaches the client as plain bytes, not through a terminal. Nothing echoes back, and the client exits when the file ends.

## Write a tooling alias

Add your own client command when you want a shorter invocation:

```yaml
name: import-a-database-demo
services:
  db:
    type: mysql
    primary: true
tooling:
  mysql:
    service: db
    cmd: mysql -u lando -plando import-a-database-demo
```

Then `lando mysql` runs that client, and `lando mysql < dump.sql` imports through it.
