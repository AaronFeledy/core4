# Import a SQL dump

Prefer `lando db:import` from the bundled SQL plugin. See [Import and export app databases](/guides/tooling/db-import-export/). You can still pipe a dump through `lando exec` if you want the raw client.

Read the database name, user, and password from `lando info` first.

```sh
lando info
```

Use `lando db:import dump.sql.gz --yes` when you want the bundled helper. `lando exec` is still there if you want the raw client.

## Import into MySQL or MariaDB

The service name is the hostname. Defaults are user `lando`, password `lando`, and database equal to the app name unless you set `database:`.

```sh
lando exec db -- mysql -u lando -plando myapp < dump.sql
```

Feed the dump on stdin from the host. Recipes do not add a second alias on top of `lando db:import`.

## Import into Postgres

Postgres derives the password per app. Copy it from `lando info`. Do not hardcode it.

```sh
lando exec db -- psql -U lando -d myapp < dump.sql
```

Pipe the dump on stdin. `-f` only works when the file already exists inside the service.

## Write a tooling alias

Add your own client command when you want a shorter invocation:

```yaml
name: import-a-database-demo
services:
  db:
    type: mysql
    primary: true
tooling:
  mysql:
    service: db
    cmd: mysql -u lando -plando import-a-database-demo
```

Then `lando mysql` runs that client. For dump files, prefer `lando db:import`.
