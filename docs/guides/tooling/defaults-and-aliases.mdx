# Set defaults for tooling tasks

Use `toolingDefaults` when most commands run in the same service, directory, or environment. Each
task inherits those values, then its own `service`, `dir`, `env`, and `vars` win where they overlap.

```yaml
toolingDefaults:
  service: web
  dir: /app
  env:
    APP_ENV: development
  vars:
    MODE: default

tooling:
  build:
    cmd: bun run build
  lint:
    service: worker
    dir: /app/tools
    env:
      APP_ENV: ci
    cmd: bun run lint
```

Here, `build` uses every default. `lint` targets `worker`, runs from `/app/tools`, and replaces
`APP_ENV`, while still inheriting `MODE`. A task's `dir` is the working directory inside its target
service; Lando does not resolve it against the host app directory.

## Precedence

Task-local values win first. Values supplied by included tooling fragments come next. App-wide
`toolingDefaults` fill whatever remains. This keeps shared commands useful without making individual
tasks surrender their sharper settings.
