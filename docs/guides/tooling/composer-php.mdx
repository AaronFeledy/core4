# Composer on PHP

Declare a `composer` tooling task targeting a PHP service and Lando routes it through the fast,
cache-backed tooling path — no provider bootstrap needed just to discover the command:

```yaml
name: composer-php-demo
services:
  appserver:
    type: php:8.3
tooling:
  composer:
    service: appserver
    cmd:
      - sh
      - -c
      - composer "$@"
      - composer
```

## Bare command and canonical id both work

```sh
lando composer --version
```

```sh
lando app:composer --version
```

Both forms use the same route: the router reads only a fresh app command cache before
provider-backed execution starts. If the cache is stale or missing, the command fails with a message
naming the fix — `lando app:cache:refresh`, `lando start`, or `lando rebuild`. After routing, the
normal tooling path still enforces version, provider, environment, and runtime policies through
`runTooling`.

## What's available before provider bootstrap

At the tooling bootstrap level, only `LandofileService` and `CommandRegistry` are available.
`RuntimeProvider`, `RuntimeProviderRegistry`, `AppPlanner`, and `ToolingEngine` are intentionally
unavailable until a later app/provider path actually needs them — command discovery and routing
don't.
