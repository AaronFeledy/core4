# Output streaming and the task tree

Running a tooling command from the app root, e.g. `lando composer install`, publishes a
task-tree event sequence: a parent `task.tree.start` opens for the tooling command
(`parentId tooling:composer`), one child `task.start` starts per target service
(`taskId tooling:composer:appserver`), each output line streams into the child task as a
`task.detail` event on `stdout`/`stderr`, a zero exit closes the child with `task.complete`
(`summary 'completed with exit code 0'`), and the parent tree closes with a `task.tree.complete`
carrying its succeeded/failed counts.

A command that exits non-zero follows the same shape but ends differently: stderr lines still stream
as `task.detail` events, the failing exit closes the child with `task.fail`
(`summary 'failed with exit code 7', exitCode 7`), and the parent's `task.tree.complete` records the
failure in its counts.

## Renderer modes

| Mode | Behavior |
| --- | --- |
| `lando` (default), `verbose` | Renders the concurrent task tree — a parent line plus an indented child line per service, each with a spinner and the most recent `task.detail` lines. |
| `plain` | Flat stream, preserving the Alpha behavior: one `[stepId]`-prefixed line per `task.detail` event, no tree, no spinners. |
| `json` | Emits NDJSON of every `task.*` event on stderr, giving embedding hosts and CI consumers the structured event stream. |
