# Stream tooling output

From the app root, run a tooling task whose target service is already running. This example assumes a PHP app with a [Composer task](./composer-php.mdx):

```sh
lando composer install
```

At a terminal, Lando hands the terminal to the command. Its own output and progress bars show as-is, your keystrokes reach it, resizing the window resizes its terminal, and Ctrl-C stops it. Prompts work: a bare `lando psql` is a live session, and `npx` can ask before it installs a package.

Redirect stdin and Lando runs without a PTY and publishes a task tree instead:

```sh
lando composer install < /dev/null
```

Redirected input still reaches the command as plain bytes, with no terminal in between, so `lando psql < dump.sql` runs the dump and exits.

The tree has a parent task for the command and one child for the run, then a complete or fail close with the exit code. Command output does not ride that tree as per-line `task.detail` events. Host and container tools share one sink: bytes print as they arrive, value-only redacted and byte-exact, including a last line with no trailing newline.

Redirect stdout and the file or pipe gets the command's output and nothing else. The examples below use an app-defined task named `gen`; replace it with your own task. The task tree, warnings, and other Lando messages go to stderr, so a dump task writes a clean dump. Redirecting stdout also drops the PTY, whatever stdin is:

```sh
lando gen > out.txt
lando gen | wc -l
```

The same split applies to `:host` tasks, `.bun.sh` scripts, `lando exec`, and `lando run`. Every other command follows it too: `lando start > start.log` keeps the ready summary and leaves the progress on your terminal.

A non-zero exit follows the same shape. Stderr still streams. The failing child closes with the exit code, and the parent records the failure in its counts. JSON and YAML results set `ok: false` while retaining the command's typed result and tagged failure; choosing a machine format does not turn a failed child into success.

## Secrets on the wire

Human formats mask only registered secret values on the live byte stream, including values split across writes. Lando holds only a trailing prefix that could complete a registered value. It leaves assignments, URLs, arbitrary binary bytes, and line endings alone otherwise. stdout and stderr follow the same rule on a terminal or in a file.

Live JSON commands such as `lando exec --format=json` first mask registered values across byte boundaries. They emit a frame for each complete line, flushing a partial line at end of stream or at 64 KiB. Invalid UTF-8 becomes the replacement character. The full secrets profile then masks the frame text, so pattern matching restarts at each capped fragment. Registered-value matching spans those fragments.

## Pick a renderer mode

| Mode | Progress and messages | Command output |
| --- | --- | --- |
| `lando` (default) | Live task tree on the stderr terminal, even when you redirect stdout to a file. Piped stdout or a non-terminal stderr gets one line per event on stderr. | stdout |
| `verbose` | Human line plus the full event payload for every event, on stderr. | stdout |
| `plain` | One line per event on stderr, no tree, no spinners. | stdout |
| `json` | Structured events and messages on stderr with a human result format such as `--format=text`. Machine formats keep stderr quiet. | stdout; the result format selects raw payload or machine output |

Tooling `--format=json` and `--format=yaml` collect stdout and stderr into one result envelope instead of printing the payload separately. Library and event invocations also collect output unless the host supplies a live sink. Collection uses memory proportional to the output; human live delivery does not keep a second copy.

Captured results include `stdout` and `stderr`, even when both are empty strings. When a live sink receives the bytes, the result omits those fields instead; MCP returns the delivered bytes in the envelope's `output.chunks`.

[MCP calls](../agent-native/mcp.mdx#read-streamed-command-output) retain a bounded, redacted tail in the final envelope's `output` field. A progress token also enables live notifications; it is not required to receive final output. `output.truncated` tells you whether any captured output was dropped. MCP text output follows the same UTF-8 and redaction rules as live JSON output, not the byte-exact human stream.

With a human result format, the `json` renderer writes progress and messages to stderr as structured events. Live JSON commands such as `lando exec --format=json` put events in the stdout stream instead, so one newline-delimited stream carries `stdout` and `stderr` data frames, `event` frames, and the final `result` frame. Events keep their own order, but their position relative to data frames can shift, because a data frame waits for its complete line. Filter on `_tag` rather than position.

When both streams reach your terminal, Lando erases the live tree, writes each output chunk to its own stdout or stderr channel, then repaints the tree on stderr. A partial output line waits for its newline before the tree repaints. Redirect stdout to a file and the live tree stays on your terminal. Pipe stdout into another command and Lando prints one progress line per event instead, since that command writes to the same terminal and a repaint would wipe its output. Redirect stderr and you get only the command's stdout on your terminal. Interactive prompts also draw on stderr, so redirecting stdout does not disable them.
