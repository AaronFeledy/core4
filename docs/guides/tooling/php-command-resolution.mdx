# Resolve PHP commands

Start a tooling task's `cmd` with `:php-local` to run a project-local PHP command from any directory in your app. This `.lando.yml` adds `lando phpunit` and `lando console`:

```yaml
name: php-command-resolution-demo
services:
  appserver:
    type: "php:8.3"
    primary: true
tooling:
  composer:
    service: appserver
    cmd: composer
  phpunit:
    service: appserver
    cmd: [":php-local", "phpunit"]
    wrapper: true
  console:
    service: appserver
    cmd: [":php-local", "bin/console"]
    wrapper: true
```

`lando phpunit` runs your project's `vendor/bin/phpunit`, and `lando console` runs `php bin/console`, whether you start them in the app root or deep inside `src/`. Arguments you pass, such as `lando phpunit tests/Unit`, stay relative to the directory you run them from. After editing the Landofile, run `lando app:config:lint --format=json` from the app directory to check the tasks.

## How `:php-local` finds the command

Every PHP service declares the `:php-local` launcher. Put it first in an argv-list `cmd`, then the command. Each time the task runs, it looks from your current directory up to the app root:

| Command after `:php-local` | What runs |
| --- | --- |
| A name, such as `phpunit` or `drush` | The nearest `vendor/bin/<name>`. A project file with that name, such as Laravel's `artisan`, runs with `php`. Otherwise the name on the service `PATH`. |
| A path, such as `bin/console` or `cli/joomla.php` | `php` with the nearest copy of that file. |

If nothing matches, the task fails with exit status 127 and names the command. `:php-local` doesn't change the working directory or `PATH`, and the command's own exit status comes back to you.

A plain relative `cmd: vendor/bin/phpunit` resolves against the directory you run the task from, because Lando maps your host directory into the container. It works from the app root and fails anywhere else, so use `:php-local` instead.

The Laravel, Symfony, and Joomla recipes use it for `lando artisan`, `lando console`, and `lando joomla`. The Drupal recipes use the related `:drupal-local` launcher, which adds Drupal defaults for Drush, PHP_CodeSniffer, and PHPStan; see [Lint PHP on the Drupal recipe](../recipes/drupal-workflow.mdx#lint-php).

## Where bare names resolve

Composer is preinstalled on `PATH`, at `/usr/local/bin/composer`, so a bare `cmd: composer` always runs it. Global tools you add with `composer.packages` install there too. A bare `cmd` without `:php-local` is wrapped in `sh -c` and resolves only through the service's `PATH`; Lando doesn't add or reorder `PATH` entries.

For a full Drupal setup with Kernel, Functional, and browser tests, see [Run Drupal tests with PHPUnit and headless Chrome](../recipes/drupal-testing.mdx).
