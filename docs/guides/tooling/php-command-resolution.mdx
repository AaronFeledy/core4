# Resolve PHP commands

A tooling command's bare name resolves through the target service's container `PATH`. Lando does not prepend `vendor/bin`. Pin project-local binaries yourself:

```yaml
name: php-command-resolution-demo
services:
  appserver:
    type: "php:8.3"
    primary: true
tooling:
  composer:
    service: appserver
    cmd: composer
  phpunit:
    service: appserver
    cmd: vendor/bin/phpunit
```

Composer is the one PHP tool preinstalled on `PATH`, at `/usr/local/bin/composer`. A bare `composer` always hits that binary. Drush, PHPUnit, PHP-CS-Fixer, and anything else under `vendor/bin` need an explicit path.

The Drupal recipe shows the pattern: its generated `drush` task pins `vendor/bin/drush` instead of trusting a bare `drush`.

## How the command is composed

A bare `cmd` is wrapped in `sh -c` and executed as-is. Only the container's own `PATH` decides what a bare name resolves to. The tooling engine sets a cwd (the app mount target, `/app` by default) and an environment map. It does not add or reorder `PATH` entries. Relative cmds like `vendor/bin/phpunit` resolve against that cwd.

## When a bare name is safe

Composer is installed once, at build time, to `/usr/local/bin/composer`. A bare `composer` is never ambiguous. Everything else under `vendor/bin` needs a pinned path.

## Live PATH order

Every tooling command runs through the selected provider's `exec`, which inherits the container image's own `PATH` unchanged.
