# VS Code

A workspace `tasks.json` lets you run Lando commands from the Command Palette or a keybinding
instead of retyping them in the terminal. This guide uses the `vscode-demo` fixture with a PHP
service named `appserver` and a Node service named `node`:

```yaml
name: vscode-demo
services:
  appserver:
    type: "php:8.3"
    primary: true
  node:
    type: "node:22"
```

## Tasks and debugging

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "lando: start",
      "type": "shell",
      "command": "lando start",
      "problemMatcher": []
    },
    {
      "label": "lando: rebuild",
      "type": "shell",
      "command": "lando rebuild -y",
      "problemMatcher": []
    },
    {
      "label": "lando: logs",
      "type": "shell",
      "command": "lando logs -f",
      "isBackground": true,
      "problemMatcher": []
    }
  ]
}
```

Open the Command Palette, choose `Tasks: Run Task`, then pick the Lando task by its label.
`lando rebuild -y` recreates containers from the current Landofile, so it discards changes that are
not persisted in the Landofile or a mounted volume.

PHP debugging needs Xdebug installed first — Lando's stock `php` service (the `appserver` service
here) ships no Xdebug extension, so there's nothing for a `launch.json` PHP debug config to connect
to out of the box. See the `php-customization` guide for adding the extension via `build.artifact`
or a custom image. Once it's installed and enabled, a PHP debug config's `pathMappings` maps the
in-container app path to your workspace folder so VS Code can set breakpoints against the files you
actually edit; the Xdebug side listens on port `9003` by default. `app` is Lando's default
in-container app mount; adjust the key if a service overrides its mount path.

For Node debugging, start your process with `node --inspect=0.0.0.0:9229 server.js`, publish the
debug port on the node service, and attach with `address: localhost`, `port: 9229`,
`localRoot: ${workspaceFolder}`, `remoteRoot: /app`, and `restart: true`.

Use `lando shell --service appserver` when you want a persistent interactive session from VS Code's
integrated terminal; use `lando exec appserver -- <command>` for a single one-off command without
leaving the task open.
