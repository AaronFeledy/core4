# Run Lando from VS Code

Add a workspace `tasks.json` so you can run Lando from the Command Palette instead of retyping it in the terminal. This guide uses a PHP service named `appserver` and a Node service named `node`:

```yaml
name: vscode-demo
services:
  appserver:
    type: "php:8.3"
    primary: true
  node:
    type: "node:22"
```

## Add tasks

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "lando: start",
      "type": "shell",
      "command": "lando start",
      "problemMatcher": []
    },
    {
      "label": "lando: rebuild",
      "type": "shell",
      "command": "lando rebuild -y",
      "problemMatcher": []
    },
    {
      "label": "lando: logs",
      "type": "shell",
      "command": "lando logs -f",
      "isBackground": true,
      "problemMatcher": []
    }
  ]
}
```

Open the Command Palette, choose `Tasks: Run Task`, then pick the Lando task by its label. `lando rebuild -y` recreates containers from the current Landofile, so it discards changes that are not persisted in the Landofile or a mounted volume.

## Debug PHP and Node

PHP debugging uses Xdebug. Set `xdebug: true` on the PHP service so Lando installs the extension and listens on port `9003`. See [Xdebug in PhpStorm](xdebug-phpstorm.mdx). A `launch.json` PHP debug config's `pathMappings` maps the in-container app path to your workspace folder. `app` is Lando's default in-container app mount; adjust the key if a service overrides its mount path.

For Node, start with `node --inspect=0.0.0.0:9229 server.js`, publish the debug port on the node service, and attach with `address: localhost`, `port: 9229`, `localRoot: ${workspaceFolder}`, `remoteRoot: /app`, and `restart: true`.

Use `lando shell --service appserver` for a persistent session from VS Code's integrated terminal. Use `lando exec appserver -- <command>` for a one-off.
