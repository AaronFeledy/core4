# Include tooling fragments

Add tooling fragment references to `.lando.yml` through `includes:` with `kind: tooling`. The example below expects `docs/.lando.tasks.yml` and `api/.lando.tasks.yml` to exist under your app root; each supplies the tooling tasks you want to include. The `toolingIncludes:` shorthand uses the same machinery. Inside a tooling fragment, only `toolingIncludes:` nests further fragments. A bare `includes:` key in a fragment fails closed with tagged `LandofileIncludeError`.

```yaml
name: tooling-includes-demo
runtime: 4
includes:
  - source: ./docs/.lando.tasks.yml
    kind: tooling
    namespace: docs
    aliases: [documentation]
    excludes: [publish]
    vars:
      DOCS_PORT: 4321
toolingIncludes:
  api:
    file: ./api/.lando.tasks.yml
    internal: true
services:
  web:
    type: node
    primary: true
tooling:
  build:
    service: web
    cmd: bun run build
```

Save the Landofile and referenced files, then run `lando app:config --format=json` from the app directory. Check that the expected namespaced tasks appear. A missing file fails unless its include is marked `optional: true`.

## Know the resolution contract

Included tasks register as `app:<namespace>:<task>`. `flatten: true` drops the namespace prefix. `internal: true` hides tasks from command listings while leaving them callable. `aliases: [documentation]` aliases the include namespace. `excludes: [publish]` removes tasks before flattening or namespace registration.

Include-level `vars:` apply to every included task unless the task defines the same var. `optional: true` suppresses missing-fragment errors. Fragments that include each other fail closed with `LandofileIncludeError` (`kind: "cycle"`), the same error a Landofile include cycle raises. Every tooling include failure names the entry that declared it: `path` is `["includes", <index>]` or `["toolingIncludes", <namespace>]`, next to the file and layer that hold it, so `lando app:config:lint` reports the problem at that entry.

`{{ recipe.<option> }}` and `{{ env.* }}` expressions inside a tooling fragment resolve against the including app's merged recipe options and the host environment, the same way they do in the app's own Landofile. A fragment has no `recipe:` of its own.

`load()` and `import()` inside a tooling fragment resolve relative to the fragment's own directory. A bad value in a tooling fragment is a `LandofileValidationError` whose `file` is the fragment and whose `issues` name the path, not a generic include error.
