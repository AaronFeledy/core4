# Include tooling fragments

Tooling fragments load through `includes:` with `kind: tooling`. The `toolingIncludes:` shorthand uses the same machinery. Inside a tooling fragment, only `toolingIncludes:` nests further fragments. A bare `includes:` key in a fragment fails closed with tagged `LandofileIncludeError`.

```yaml
name: tooling-includes-demo
runtime: 4
includes:
  - source: ./docs/.lando.tasks.yml
    kind: tooling
    namespace: docs
    aliases: [documentation]
    excludes: [publish]
    vars:
      DOCS_PORT: 4321
toolingIncludes:
  api:
    file: ./api/.lando.tasks.yml
    internal: true
services:
  web:
    type: node
    primary: true
tooling:
  build:
    service: web
    cmd: bun run build
```

## Know the resolution contract

Included tasks register as `app:<namespace>:<task>`. `flatten: true` drops the namespace prefix. `internal: true` hides tasks from command listings while leaving them callable. `aliases: [documentation]` aliases the include namespace. `excludes: [publish]` removes tasks before flattening or namespace registration.

Include-level `vars:` apply to every included task unless the task defines the same var. `optional: true` suppresses missing-fragment errors. Fragments that include each other fail closed with tagged `ToolingIncludeCycleError`.
