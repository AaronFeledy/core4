# Answer or skip prompts

```sh
lando init --recipe lamp --yes
lando setup --no-interactive
```

`--yes` resolves every prompt from recipe defaults and never opens a prompt surface. `--no-interactive` disables prompting and fails with a tagged missing-answer error when a required value has no answer or default.

Values supplied via `--answer` or an `--answers` file are validated and used directly, so the matching prompt is never shown. A non-TTY stdin keeps the line-based path. `LANDO_NO_OPENTUI_PROMPTS=1` forces that same line-based reader even on an interactive TTY. Any renderer import or probe failure degrades to that fallback.

These controls appear wherever Lando asks for input: recipe prompts during `apps:init`, the provider choice during `lando setup` when you have not pinned it, and the trust confirmation before a plugin runs as trusted host code.

## How prompts look

Free-text prompts (recipe name, description, path) render as a focused single-line input. Longer answers use a textarea. Choice prompts with more than a few options render as a vertical select list with arrow-key navigation and an explicit indicator on the highlighted row. Multi-choice uses the same list: Space toggles the focused row while the highlighted-row cursor stays independent, and Enter submits every checked choice. Confirmations and two-to-four-option choices render as a horizontal tab-select.

The prompt message lives on the panel's border title. Secret prompts decline the graphical surface and keep the line-based reader, so secret values are never echoed, logged, or captured in a transcript.

## Validation and cancellation

A value that fails the recipe constraint re-prompts in place with the validation message shown inline. In non-interactive paths the same failure is a tagged error carrying the `--answer` remediation. Ctrl-C or Esc cancels the prompt, restores the terminal, and aborts the command.
