# Init from a remote recipe

`lando init` can load a recipe hosted somewhere other than the bundled set: a
git repository, a tarball, an npm package, or the recipe registry. It fetches
the tree, compiles its `recipe.yml`, and writes the app the same way a bundled
recipe does. A remote tree is read as YAML only: a `recipe.ts` in the fetched
tree is never evaluated. See [remote recipe sources](../recipes/remote-sources.mdx)
for a complete `recipe.yml` and what `validate` reports before anything is written.

Each source requires the flag that tells Lando where to find `recipe.yml`, and
each fails fast, before any clone or download, when that flag is missing.
`--source` only accepts `git`, `tarball`, `npm`, and `registry`; any other
value is rejected outright.

## git

```sh
lando init --source=git --url=<git-url>
```

Fetches the repository's default branch, then reads `recipe.yml` from its
root. Append `@ref` to the URL for a tag, branch, or full commit SHA, such as
`--url=https://github.com/acme/lando-recipes.git@v2.1.0`. Add `--path` when
`recipe.yml` lives in a subdirectory of a monorepo:

```sh
lando init --source=git --url=<git-url> --path=packages/my-recipe
```

## tarball

```sh
lando init --source=tarball --url=<tarball-url> --checksum=<sha256>
```

Downloads a tar/tar.gz archive, verifies it against the 64-hex `--checksum`,
then reads `recipe.yml` from the extracted root. `--checksum` is optional;
without it Lando warns with the computed digest and, when interactive,
prompts once before continuing. Add `--path` when `recipe.yml` lives in a
subdirectory of the archive:

```sh
lando init --source=tarball --url=<tarball-url> --path=packages/my-recipe
```

## npm

```sh
lando init --source=npm --package=@lando/recipe-foo
```

Resolves the package's metadata, downloads the published tarball, and reads
`recipe.yml` from the extracted `package/` root. An `@version` suffix pins an
exact published version or dist-tag; without it Lando uses the registry
latest dist-tag:

```sh
lando init --source=npm --package=@lando/recipe-foo@1.2.3
```

Add `--path` when `recipe.yml` lives in a subdirectory of the published
package:

```sh
lando init --source=npm --package=@lando/recipe-foo --path=recipes/my-recipe
```

## registry

```sh
lando init --source=registry --id=<recipe-id>
```

Resolves a recipe id through the configured registry, then reads
`recipe.yml` from the resolved git clone or tarball extract. With no
override, Lando queries the default recipe registry URL,
`https://registry.lando.dev/recipes/`. Override the registry base URL for
private or test registries:

```sh
lando init --source=registry --id=<recipe-id> --registry-url=<url>
```

See [remote recipe sources](../recipes/remote-sources.mdx) for the git cache
location, ref handling, and the `RecipeSourceError` kinds raised before a
clone.
