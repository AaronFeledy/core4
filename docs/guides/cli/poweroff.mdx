# Power off every app

`lando poweroff` stops every Lando-managed app on the host, not just this
one.

Warning: this command reaches beyond the current app. Run it only when you
mean to stop everything. It removes scratch apps and their disposable data
unless you pass `--keep-scratch`.

Run this from any directory on your host:

```sh
lando poweroff -y
```

The command reports when apps have powered off or when there are none to stop. If an app fails to stop, follow the reported remediation and retry; Lando keeps the runtime available for recovery.

## Scope flags

Skip the shared global app with `--keep-global`, so host-wide services such
as the proxy keep running. Skip scratch apps with `--keep-scratch`, so
disposable throwaway apps stay up while every other app stops.

Poweroff does not prompt for confirmation. `-y`/`--yes` is accepted, but is
not required for scripts.

User apps stop first, followed by scratch cleanup, then the global app.
The next `lando start` brings back the global services that app uses,
including Traefik and the SSH agent sidecar.
After poweroff, `lando list` reports apps as `stopped` when the API confirms no running containers or the managed runtime is idle. For that idle state, `lando stop` finishes host-side cleanup without launching the runtime, and `lando destroy` launches it to remove the app's resources.

If runtime state is `unknown` after a crash, `wsl --terminate`, or the first poweroff after an upgrade, `lando destroy` launches or repairs the managed runtime holding the app's resources before checking and removing them. You don't need to start the app first. `lando destroy --root` and `lando apps:gc --prune` do the same for deleted app folders. If runtime preparation fails, cleanup reports that failure and leaves the resources for retry.

On Linux and WSL, Lando records a shutdown receipt after confirming that containers are quiescent, the runtime service has exited, and its private pause process has been torn down. With an absent API, that receipt establishes idle after shutdown or a reboot; each runtime launch invalidates it first. Without valid receipt evidence, status remains `unknown`, because process observations alone cannot prove workloads stopped. On macOS and Windows, read-only inspection of a stopped managed machine establishes idle. Neither status observation nor stop launches the runtime.
Lando stops the managed runtime service only after all targeted apps stop.
Before it does, Lando removes containers that image builds left behind, so
their storage helpers don't keep running.
If an app cannot stop, the command fails with that app's id and remediation
instead of reporting it as powered off. The runtime stays available so you
can resolve the failure and retry.

`lando poweroff` is a top-level alias for `lando apps:poweroff`. Both
invoke the same command. It works from any directory; you don't need to be
inside an app root to run it.
