# Run commands inside a service

`lando exec` runs a one-off command inside a running service. At a terminal it doesn't attach your keyboard, so commands finish without waiting for input. Add `-i` when you want to type into the command. Piped or redirected input always reaches the command.

A service name before `--` selects that service; otherwise the primary service is used. Everything after `--` is the exact argv handed to the service. The command spec is non-strict, so it parses no flags of its own past that point.

```sh
lando exec -- echo hello world
lando exec -i -- cat
lando exec appserver -- echo hello world
lando exec --user www-data -- whoami
lando exec --cwd /srv/app -- pwd
```

Open a shell with `lando ssh` or `lando shell --service <name>`.

## Pipe input in

Pipe or redirect stdin, and the command reads it as plain bytes, then exits when the input ends:

```sh
printf 'hello\n' | lando exec -- cat
lando exec db -- mysql -u lando -plando myapp < dump.sql
```

The command gets a terminal only when your stdin and stdout are both terminals. Piped input never goes through one, so nothing echoes back. Pipe the output away (`| grep`) and the command gets no terminal either, so tools that color only on a terminal print plain text.

## Exit codes

`app:exec` sets its own command exit code to the executed command's `exitCode`. A non-zero result is mirrored onto the CLI process, so `lando exec` propagates the target command's failure to the shell.

## Masked output

Lando masks credentials in what `lando exec`, `lando logs`, and tooling print. A value from a service environment key named like a password, token, key, or secret prints as `[redacted]`, and so does the password in a connection URL. The service itself still gets the real value.

Lando's published default credentials, `lando` and `landolando`, print as-is. They're documented defaults, not secrets, and masking them would also blank `host.lando.internal` and every `lando doctor` hint. To keep a password masked, set your own or pull it from a [secret store](../config/secret-stores.mdx).

## Machine-readable output

`--format json` emits one JSON object per stdout/stderr chunk, then exactly one result frame:

```sh
lando exec --format json -- <command>
```

Each non-empty stdout chunk becomes one stdout frame tagged with the target service. A non-empty stderr chunk becomes one stderr frame the same way. An empty stream emits no frame for that stream. The stream always terminates with exactly one result frame carrying the app, service, command, exit code, stdout, and stderr.
