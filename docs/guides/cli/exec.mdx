# Run commands inside a service

`lando exec` runs a one-off command inside a running service. At a terminal it doesn't attach your keyboard, so commands finish without waiting for input. Add `-i` when you want to type into the command. Piped or redirected input always reaches the command.

Run these commands from your app directory on the host. A service name before `--` selects that service; otherwise Lando uses the primary service. Everything after `--` belongs to the command inside the service, including its flags. Replace `appserver`, the user, and the working directory with values from your app.

```sh
lando exec -- echo hello world
lando exec -i -- cat
lando exec appserver -- echo hello world
lando exec --user www-data -- whoami
lando exec --cwd /srv/app -- pwd
```

Open a shell with `lando ssh` or `lando shell --service <name>`.

## Pipe input in

Pipe or redirect stdin, and the command reads it as plain bytes, then exits when the input ends:

```sh
printf 'hello\n' | lando exec -- cat
lando exec db -- mysql -u lando -plando myapp < dump.sql
```

The command gets a terminal only when your stdin and stdout are both terminals. Piped input never goes through one, so nothing echoes back. Pipe the output away (`| grep`) and the command gets no terminal either, so tools that color only on a terminal print plain text.

## Back up and restore service files

Redirected stdout is not a terminal, so `lando exec` allocates no PTY and streams raw bytes without keeping a second copy in its result. Use that to archive a directory inside a service and land the archive on the host. `-C <path> .` stores the contents of that path, not a top-level folder named after it. Human formats mask only registered secret values, even across chunk boundaries. Uncompressed tar files and text assignments such as `PASSWORD=public` keep their bytes unless a registered value appears in them. Terminal and redirected output follow the same rule.

These one-liners are for a POSIX shell (bash or zsh). PowerShell and cmd.exe are unverified.

Warning: restoring into a non-empty target merges files and overwrites matching names. Files absent from the archive remain in the target. Move or empty the target first if you need an exact copy, and preserve any files you still need.

```sh
lando exec appserver -- tar -czf - -C /app/web/sites/default/files . > files.tgz
lando exec appserver -- tar -xzf - -C /app/web/sites/default/files < files.tgz
```

WordPress uploads use the same shape:

```sh
lando exec appserver -- tar -czf - -C /app/wp-content/uploads . > uploads.tgz
lando exec appserver -- tar -xzf - -C /app/wp-content/uploads < uploads.tgz
```

If you [excluded that path from file sync](../setup/file-sync-excludes.mdx), the files live on the service overlay, not on the host. A named volume is the same idea: pass that volume's mount path to `-C`.

Unverified: if the service image has `zstd`:

```sh
lando exec appserver -- tar -c -I zstd -f - -C /app/web/sites/default/files . > files.tar.zst
lando exec appserver -- tar -x -I zstd -f - -C /app/web/sites/default/files < files.tar.zst
```

## Exit codes

`app:exec` sets its own command exit code to the executed command's `exitCode`. A non-zero result is mirrored onto the CLI process, so `lando exec` propagates the target command's failure to the shell.

## Masked output

Human modes for `lando exec`, tooling, and `lando run` mask only known secret values on the live byte stream. Pattern classes stay off that path so binary dumps keep their shape. `lando logs` and other structured surfaces still use the full secrets profile. The service itself still gets the real value.

Lando's published default credentials, `lando` and `landolando`, are not collected as secrets just because an environment key looks sensitive. Explicit registration or resolution from a [secret store](../config/secret-stores.mdx) still masks them.

## Machine-readable output

`--format json` emits newline-delimited JSON stream frames, then exactly one result frame:

```sh
lando exec --format json -- <command>
```

Each data frame carries a complete line of stdout or stderr, or up to 64 KiB when a line is longer. Registered values are masked on bytes first, including across frames. Invalid UTF-8 becomes the replacement character, then the full secrets profile masks the decoded text. A partial final line is emitted at end of stream. Pattern matching restarts at each 64 KiB fragment; the registered-value matcher does not.

An empty stream emits no data frames. Exactly one result frame follows the data, carrying the app, service, command, and exit code. Its stdout and stderr are empty because the data frames already delivered them. YAML and library calls without a live sink collect stdout and stderr in the result instead; that uses memory proportional to the output.
