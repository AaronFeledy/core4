# See more CLI output

There is no `lando --debug`. Pick a renderer mode.

```sh
lando info --renderer=verbose
```

`--renderer=verbose` is the firehose. `--debug` is not coming back.

## Pick a renderer

| Mode | What you get |
| --- | --- |
| `lando` (default) | Bundled TTY task tree and summaries. |
| `plain` | One human line per renderable event on stdout. No tree, no spinners. |
| `json` | Structured `{_tag:"event", ...}` lines on stderr. The command result still prints on stdout as a JSON envelope. |
| `verbose` | The human line plus the full event payload for every event. This is the debug dump, not the task tree. |

Set the mode three ways. First match wins:

1. `--renderer=verbose`
2. `LANDO_RENDERER=verbose`
3. `renderer: verbose` in global config

The default is `lando`.

`--format=json` changes the command result shape. It does not switch the event stream. `--renderer=json` forces the result format to JSON and also emits JSON events on stderr.

```sh
lando info --format=json
lando info --renderer=json
```

An unknown mode fails with `RendererSelectionError`.

## Debug without `--debug`

Use `--renderer=verbose` or `LANDO_RENDERER=verbose`.

`LANDO_DEBUG=1` is not a host CLI switch. Lando only forwards it into `lando shell` as an env var.

For scripts and agents, prefer `--format=json` and read `ok`, `error._tag`, and `remediation`.
