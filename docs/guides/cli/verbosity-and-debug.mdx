# See more CLI output

`lando version --verbose` dumps every render event. `lando version --debug` does that and raises Effect diagnostic logs.

```sh
lando version --verbose
lando version --debug
```

`--debug` is `--log-level=debug` plus `--verbose`. `--log-level` only changes the diagnostic floor. Pass `--renderer=lando` when you want the TUI. Pass `--renderer=json` when you want the JSON envelope on stdout.

## Pick a renderer

| Mode | What you get |
| --- | --- |
| `lando` (default) | Live tree on terminal stderr, including when you redirect stdout; line-mode narration on stderr otherwise. |
| `plain` | One human line per renderable event on stderr. No live tree, no spinners. |
| `json` | The result as a JSON envelope on stdout. Add `--format=text` to get structured `{_tag:"event", ...}` lines on stderr next to the human result. |
| `verbose` | The human line plus the full event payload for every event on stderr. This is the dump, not the task tree. |

Set the mode three ways. First match wins:

- `--renderer=verbose`
- `LANDO_RENDERER=verbose`
- `renderer: verbose` in global config

The default is `lando`.

`--format=json` and `--format=yaml` change the command result shape. With the `lando`, `plain`, or `json` renderer they also keep progress off stderr, so a script reads one clean result from stdout. Desktop notifications, explicit diagnostics, and deprecation warnings still use stderr, and `verbose` still dumps every event there. `--renderer=json` defaults the result format to JSON, and an explicit `--format` wins. Streaming commands such as `lando exec`, `lando logs --follow`, `lando start`, and `lando rebuild` change one thing under `--format=json`: their events arrive on stdout as `event` frames in the same stream as the output, for every renderer, including `verbose`. See [Stream tooling output](../tooling/output-streaming.mdx#pick-a-renderer-mode).

```sh
lando info --format=json
lando info --renderer=json
```

An unknown mode fails with `RendererSelectionError`.

## Turn on more output

`--verbose` flips the default renderer to `verbose`. An explicit `--renderer`, `LANDO_RENDERER`, or `renderer:` config value stays put.

`--debug` also sets the log level to `debug`. Effect logs go to stderr. They are not command output. `meta:mcp` (except `--list`) and the host-proxy worker stay silent.

Set the log level three ways. First match wins:

- `--log-level=debug` or `--debug`
- `LANDO_LOG_LEVEL=debug`
- `logLevel: debug` in global config

The default log level is `none`. The CLI stays quiet until you ask. `LANDO_DEBUG` is not a host CLI switch. Lando only forwards `LANDO_DEBUG=1` into `lando shell`.

For scripts and agents, prefer `--format=json` or `--renderer=json` and read `ok`, `error._tag`, and `remediation`.

## Turn off color

Set `NO_COLOR` to any non-empty value and Lando prints its task tree, notices, summaries, and help without color:

```sh
NO_COLOR=1 lando start
```

Status still reads from the glyphs (`✓`, `✗`, `!`, `◌`), and bold and dim stay. `TERM=dumb` turns color off too and also prints one progress line per event instead of a redrawing tree. `FORCE_COLOR` does not turn Lando's color back on. Interactive prompts switch to your terminal's default colors and keep the `▶` marker on the current choice. When `lando exec`, `lando ssh`, or a service tooling task runs on your terminal, Lando also passes `NO_COLOR=1` into the container, so tools that honor the convention go plain too; a `NO_COLOR` your service already sets wins. Lando never rewrites the output of the tools you run, so a command such as `lando exec web -- ls --color=always` keeps its own colors.
