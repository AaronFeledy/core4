# Terminal UI polish

Use these design tokens and presentation rules when contributing to the bundled `lando` renderer. This contributor reference stays off the user navigation.

Everyday CLI work lives in [everyday commands](./everyday-commands.mdx). Do not treat the TTY rail, OpenTUI, or desktop-notification policy as something you configure from a Landofile.

You get a compact live task tree on the stderr terminal, even when you redirect stdout to a file. Piping stdout into another command switches to one line per event. plain, json, non-TTY, and CI output stay undecorated. All narration, prompts, and notification controls use stderr, leaving stdout for command results and output. Result summaries use stdout's terminal width and styling. A missing native binding never fails the command. The process falls back to line input.

Redirect stderr to hide the tree without hiding your result summary. Prompts need terminal stdin and stderr, but still work with stdout redirected. Expand a task with Enter and collapse it with Escape; the alternate-screen tail and resize handling use the stderr terminal too.

If you are changing renderer goldens, start from the contributing visual-QA page, then use this reference to check the presentation rules.

## Quiet rail tokens

The TTY `lando` frame uses the terminal default background and foreground. The pink left rail is Lando chrome only. Identity text is bold in the default color. Footer verdicts are dim default. Status colors are the standard terminal palette (red, green, yellow, cyan, dim). Status is never color-only. Every state uses semantic glyphs. Status is glyph plus compact optional metadata.

Glyphs: `◌` pending, spinner or `·` running, `✓` success, `–` skipped, `✗` failed.

Titles are identity-only. Footers use `done`, nonzero `ok` / `failed` counts, or a running ratio. Cached and skipped stay on the row as `cached` and `skipped`.

Layout tokens:

- 40 columns is the minimum proven width (also 80, 100, and 120)
- identity-only titles in bold default color
- two-space row rhythm for dense scannable rows
- dimmed detail tails behind status rows
- progress rails stay semantic (live running only)

Anti-patterns: no undifferentiated rainbow logs, no SaaS-purple gradients, no dense ASCII art, no decorative motion.

## Color opt-out

The host opts out of color when `NO_COLOR` holds any non-empty value or `TERM` is `dumb`. `FORCE_COLOR` does not override it. The stdio IO resolves this once as `RendererNarrationIO.noColor`; renderer code reads that fact, or the `color` capability derived from it, and never reads the environment itself.

Under the opt-out, the task tree, notices, result summaries, OSC 8 hyperlinks, and help drop every foreground and background color. Bold, dim, and default-color resets may stay, and the glyphs, text, and layout must match the colored frame once escape sequences are stripped. That is why status is never color-only. `TERM=dumb` also omits the terminal stream, so the tree falls back to one line per event. Tool payload bytes pass through untouched. The OpenTUI prompt theme does not follow the opt-out yet.

## Desktop notification policy

The `@lando/notify-lando` plugin, not core or the renderer, decides when a command completion publishes `notify.desktop`. It ships bundled and enabled by default.

`notify.commands` adds canonical command ids. Entries are ordered, deduplicated, and validated against the cwd-independent global built-in/global-plugin command registry. Landofile-derived tooling and app-local plugin ids fail with `ConfigError` regardless of cwd. Eligible configured `none`, `minimal`, and `plugins` commands acquire subscribers without changing their declared bootstrap metadata. Doctor, installation-config repair, version, shellenv, and uninstall retain their safe-mode bootstraps instead.

Subscriber registration uses metadata without discovering an app or loading its Landofile. The terminal-event family matches at dispatch, so it can observe new app command ids in a retained runtime without reinstalling handlers. Exact app-command selectors may remain deferred until an app catalog is available; an explicit command-cache refresh validates them against that catalog. Static unknown selectors still fail registration.

`notify.enabled: false` silences desktop notification policy. Environment overrides `LANDO_NOTIFY_ENABLED`, `LANDO_NOTIFY_THRESHOLD_MS`, and `LANDO_NOTIFY_COMMANDS` map to `notify.enabled`, `notify.thresholdMs`, and the JSON-array `notify.commands` value.

Only the outer invocation (`parentInvocationId` absent) may publish one success or failure notification. Nested events carry `parentInvocationId` and stay observable, but they never independently trigger foreground presentation. The renderer decides presentation through `renderer.capabilities.notifications`. The default `lando` renderer publishes all four capabilities as true when stderr is a terminal at construction, except `color`, which is false under the [color opt-out](#color-opt-out). It does this without importing OpenTUI or probing the terminal. Notifications use OSC 99 on stderr immediately; terminals without OSC 99 support ignore them. Non-terminal stderr publishes all four capabilities as false and drops desktop notifications.
