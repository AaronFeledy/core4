# Refresh a stale app cache

`lando app:cache:refresh` rebuilds the app plan, tooling graph, and command index without starting services.

```sh
lando app:cache:refresh
```

There is no top-level `lando cache:refresh` alias. Use the `app:` form.

If a tooling command vanished after you edited the Landofile, refresh before you start rewriting YAML.

## When the cache goes stale

Lando caches the planned app so later commands can skip a full plan. That cache is stale after you:

- Edit `.lando.yml` or another merged Landofile layer
- Change an `includes:` fragment or its lockfile
- Change a file the Landofile `load()`s or `import()`s
- Add, remove, or update a plugin
- Upgrade Lando itself

A missing tooling command after one of those edits is the usual tell. The router says to run `lando app:cache:refresh`, `lando start`, or `lando rebuild`.

`lando app:config` prints the authored Landofile. It does not rebuild the plan. Use `app:cache:refresh` when you need planner or command-index output, not just the YAML you wrote.

## Inspect, then refresh

Read the authored Landofile first, then rebuild the caches.

```yaml
name: cache-refresh-demo
services:
  app:
    type: "node:lts"
    primary: true
tooling:
  hello:
    service: app
    cmd: echo hello
```

## Machine output

```sh
lando app:cache:refresh --format=json
```

The envelope includes `result.app`, `result.commandsCompiled`, and cache paths. Failures carry a tagged `error._tag` plus remediation.
