# Read and write global config

Run `lando config --format=json` to read your effective host-level settings. It never changes a project's Landofile or the shared global app.

    <Step name="json-shape">

      <Verify command="lando config --format=json" expect={{ stdout: { regex: "\"config\":\\s*\\{" } }} />
      <Verify command="lando config --format=json" expect={{ stdout: { regex: "\"format\":\\s*\"json\"" } }} />
    </Step>
  </Scenario>

## Set app defaults and read them back

Use `appEnv` for environment defaults and `appLabels` for container-label defaults. They apply to user-app services; values authored on a service win. The full view includes both maps under `result.config`. A lookup also returns the selected map or scalar under `result.value`.

These commands replace each whole map. Keep any existing entries you want before running them.

```sh
lando config set appEnv '{"TEAM":"platform"}' --type=json
lando config set appLabels '{"team":"platform"}' --type=json
lando config get appEnv --format=json
lando config get appLabels --format=json
lando config --format=json
```

The equivalent `config.yml` entries are:

```yaml
appEnv:
  TEAM: platform
appLabels:
  team: platform
```

The view exposes public settings, not internal bookkeeping. Secret-bearing environment values and proxy credentials are redacted before output, including single-key lookups and JSON or YAML output. Redaction does not change the values stored in `config.yml`.

## Choose the effective value

`ConfigService` merges the global config in a deterministic order. A later source wins: defaults, then `config.yml`, then `LANDO_CONFIG__*` env vars, then inline flags. A `LANDO_CONFIG__*` env var maps its SCREAMING_SNAKE_CASE path to the matching camelCase config key and overrides the file for that key, for example `LANDO_CONFIG__DEFAULT_PROVIDER_ID=podman`.

The installation config lives at `config.yml` under the resolved user config root, for example `/home/user/.local/share/lando/config.yml` on Linux.

`LANDO_PROVIDER` does not persist as last-used. After a successful `lando setup --provider=docker`, later `lando doctor` and `lando start` stay on Docker.

## Get, set, unset, validate, or edit a key

```sh
# Read a single dot-path key
lando config get defaultProviderId

# Write a single dot-path key to config.yml; --type controls how the value is parsed
lando config set defaultProviderId podman --type string

# Remove a key from config.yml
lando config unset defaultProviderId

# Decode config.yml against the GlobalConfig schema without changing anything
lando config validate

# Open config.yml in $VISUAL or $EDITOR, or pass --editor
lando config edit
```

## Add host-wide lifecycle steps

`hostEvents` in `config.yml` runs the same lifecycle steps for every user app. Only the file can set it: `LANDO_CONFIG__*` overlays drop the key, and `lando config set` / `lando config unset` refuse every `hostEvents` path.

```yaml
hostEvents:
  pre-start:
    - cmd: echo host-wide
      service: ":host"
```

Use `lando config edit` or edit the file itself. `lando config --format=json` includes `hostEvents` in the public view. See [Run tasks at app lifecycle events](../landofile/events.mdx) for step shapes, order, dedupe, skip rules, and the `LANDO_HOST_EVENT` guard.

## Configure the shared global app

`lando global:config` reads or writes the shared global Lando app's Landofile stack. That always-on app hosts host-wide services such as the proxy. It is not the installation config from `lando config`. Lando starts Traefik for you as part of that global app.

  <Scenario id="shared-global-app-config" render>
    <Step name="json-shape">
      <Run command="lando global:config --format=json" />
      <Verify command="lando global:config --format=json" expect={{ stdout: { regex: "\"app\":\\s*\"global\"" } }} />
      <Verify command="lando global:config --format=json" expect={{ stdout: { regex: "\"source\":\\s*\"global\"" } }} />
      <Verify command="lando global:config --format=json" expect={{ stdout: { regex: "\"paths\":\\s*\\{" } }} />
      <Verify command="lando global:config --format=json" expect={{ stdout: { regex: "\"landofile\":\\s*\\{" } }} />
    </Step>
  </Scenario>
</Guide>

The result envelope reports `app` (the global app id), `source` (the fixed literal `global`), `materialized` (whether the dist Landofile has been materialized), both file paths (`distLandofile`, `userLandofile`), a `paths` object, and the decoded `landofile` shape.

The hand-editable overlay Landofile for the shared global app lives at `<userDataRoot>/global/.lando.yml`, for example `/home/user/.local/share/lando/global/.lando.yml` on Linux. The generated dist Landofile that merges plugin-contributed global services on top of the user overlay lives at `<userDataRoot>/global/.lando.dist.yml`.

```sh
# Write a dot-path key into the global user Landofile
lando global:config set services.mailpit.type mailpit

# Remove a dot-path key from the global user Landofile
lando global:config unset services.mailpit

# Decode the global user Landofile against the Landofile schema without changing anything
lando global:config validate

# Open the global user Landofile in $VISUAL or $EDITOR, or pass --editor
lando global:config edit
```
