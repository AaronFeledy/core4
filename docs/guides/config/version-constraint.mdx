# Constrain the Lando version

Set `lando:` at the top of `.lando.yml`:

```yaml
lando: ">=4.1 <5"
```

The value supports the full npm-semver range grammar: comparators, unions
(`||`), hyphen ranges, x-ranges, `^`, `~`, and exact versions. Prereleases
participate in ordering, and build metadata does not affect precedence. The
`lando:` key constrains the Lando core binary only; `runtime:` and
`services.*.api` remain separate surfaces.

## Failure

Unsatisfied constraints fail before app planning or provider action, with a
tagged `LandofileVersionConstraintError`. The message carries the declared
range, source layer, and running version, so agents don't have to scrape
prose. JSON envelopes serialize `_tag`, `message`, and `remediation`
directly:

```
{ ok: false, error: { _tag, message, remediation } }
```

## Skipping the check

`LANDO_SKIP_VERSION_CONSTRAINT=1` downgrades an unsatisfied valid range to a
warning for the current invocation only. The skip does not rewrite the
Landofile, mutate the app-plan cache, or mark the constraint satisfied. It
applies to the current process only. `lando doctor --app` reports when the
skip env is active and includes the same source-layer context.

## Repairing a mismatch

```sh
# Inspect unsatisfied ranges and source layers without prose scraping
lando doctor --app --format=json

# Install a compatible Lando binary when the project requires a newer core
lando update
```

Or relax or correct the `lando:` range after confirming the project
intentionally supports the running version.
