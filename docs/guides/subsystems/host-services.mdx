# Reach host services and sibling stacks

Use `host.lando.internal` to call an API or other service running on your computer from a Lando container. `localhost` inside the container points back to that container.

You need a working Lando 4 setup and Python 3 for this example. Keep your current provider; Docker is not required. If you haven't set up Lando yet, follow [Pick a container provider](../setup/provider-selection.mdx). On Windows, run the host commands in PowerShell.

## Configure the app

Create an empty app directory and save this as `.lando.yml`:

```yaml
name: host-reach-demo
services:
  web:
    type: compose
    image: alpine:3
    command: ["sleep", "infinity"]
    primary: true
    extra_hosts:
      - "api.test:host-gateway"
```

`web` is an Alpine container with `wget`, standing in for your app service. The optional `extra_hosts` entry adds `api.test` for an application that expects that name.

Start the app from this directory:

```sh
lando start
lando exec web -- sh -c 'echo "$LANDO_HOST_IP"'
```

The second command should print `host.lando.internal`. Lando adds that alias and variable when the provider supports host access; you don't configure them yourself. See [Reach your host from inside a service](../services/home-and-host.mdx#reach-your-host-from-inside-a-service) for that behavior.

## Bind the host service to 0.0.0.0

The demo server listens on all IPv4 interfaces. Other devices may reach it wherever your firewall allows access, so serve only a new, empty directory, not your project or home directory. For a real API or database, prefer a specific reachable host interface and restrict access before widening its bind address.

In a second host terminal, create the empty directory and start the server. On Windows, replace `python3` with `py` or `python`:

```sh
mkdir host-service-demo
cd host-service-demo
python3 -m http.server 8000 --bind 0.0.0.0
```

Leave this terminal running. Keeping the server in the foreground also lets you stop it with Ctrl+C on every platform.

This bind is separate from the Lando router. The router listens on `127.0.0.1` by default, set by `router.bindAddress` in the installation `config.yml` or `LANDO_ROUTER_BIND_ADDRESS`. Setting it to `0.0.0.0` or `::` exposes the router to your local network, and `lando doctor` warns. A specific interface IP is treated as intentional LAN sharing. See [Reach an app from another device](./external-access.mdx) for details.

## Reach the host from the container

Back in the app directory in your first terminal, request the server:

```sh
lando exec web -- wget -qO- http://host.lando.internal:8000/
```

The HTML directory listing confirms the container reached your host server. Use `http://host.lando.internal:8000` in your app's configuration, or read the hostname from `LANDO_HOST_IP` and supply the port separately.

## Use a host name from extra_hosts

The example maps `api.test` to the same host gateway. Check both names and make a request:

```sh
lando exec web -- getent hosts api.test host.lando.internal
lando exec web -- wget -qO- http://api.test:8000/
```

Both names should resolve to the same address and return the same listing. Use `http://api.test:8000` when the host service expects `api.test` in the HTTP `Host` header.

Don't rely on a name in your computer's hosts file being available or correct inside a container. Docker and Podman handle that file differently, and a copied `127.0.0.1` entry still points back to the container. Add `extra_hosts` to each service that needs the name.

## Check a refused or timed-out connection

Check where the server is listening on the host. Run the command for your operating system:

```sh
ss -ltn 'sport = :8000'                # Linux
lsof -nP -iTCP:8000 -sTCP:LISTEN       # macOS
netstat -an | findstr :8000            # Windows
```

The demo should listen on `0.0.0.0:8000` or `*:8000`. On a native Linux bridge network, a service bound only to `127.0.0.1` cannot accept traffic sent to the host's bridge address. Bind to an appropriate host interface, or use `0.0.0.0` with the access restrictions described above.

Rootless runtimes and VM-backed providers can forward host traffic differently. Don't assume the gateway address printed inside a container is an address you can bind on your computer. If the server is listening but the request times out, check the host firewall and allow only the required port and source network. Don't disable the firewall to make the example work.

## Reach a sibling Compose stack

For another Compose project's database, mail catcher, or API, follow [Reach another project's services](../config/networks.mdx). It covers [including the stack in your app](../config/networks.mdx#fold-the-stack-into-your-app), [joining an existing network on the same engine](../config/networks.mdx#join-the-stacks-network), and [using a published host port](../config/networks.mdx#reach-the-stack-through-your-host). The default `lando` provider manages its own Podman runtime, separate from a system Docker or Podman stack.

With the host-port route, point the app at `http://host.lando.internal:8025` for a service published on host port `8025`. A loopback-only publication may not be reachable from the container, especially over a native Linux bridge. Before changing it, check the exposure: `"0.0.0.0:8025:8025"` publishes on all IPv4 interfaces. Prefer a suitable host interface and firewall restrictions when the service must stay off the LAN. A gateway IP from inside a VM or rootless network is not necessarily a usable publish address.

## Clean up

Press Ctrl+C in the server terminal. Then remove the demo app's containers from the app directory:

```sh
lando destroy -y
```
