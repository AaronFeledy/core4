# Scanner service

`UrlScanner` is the Effect Service tag published in `@lando/sdk`; plugins implement
`UrlScannerShape`. The `runScannerContract` runner from `@lando/sdk/test` validates a plugin's `id`,
`scan()`, and `detectCollisions()`. `TestUrlScanner` (built with `makeTestUrlScanner`) is the
in-memory test double — it records calls and returns empty endpoints with no collisions.

## Endpoint discovery

`scan(appId: AppId): Effect<ScanResult, ScannerError>` scans all host-facing endpoints for an app and
returns reachable URLs and status codes. `lando info --json` includes the scanner output verbatim via
`ScanResult.endpoints`. Discovery combines provider inspect output with proxy routing rules, so live
scanning needs running containers and a provider socket.

## Port collisions

`detectCollisions(appIds): Effect<PortCollision[], ScannerError | PortCollisionError>` detects host
port conflicts across multiple apps. `PortCollisionError` is raised when two apps conflict on the same
host port; it includes the port number and every conflicting app and service id. Detection compares
host ports across multiple apps, so it needs running containers to observe real bindings. Unit tests
verify the `UrlScanner` contract against `TestUrlScanner` in `sdk/test/contract/url-scanner.test.ts`.

## Retry primitive

The default scanner maps retry/delay/timeout onto `runProbe` from `@lando/sdk/probe` instead of a
hand-rolled `Effect.retry` or `Schedule` loop. Probe-backed scans return green/yellow/red verdicts
plus redacted detail for non-green results (`ScanEndpoint.outcome`/`detail`). `UrlScannerLive` (in
`engine/src/subsystems/scanner/live.ts`) is the default runtime scanner; `UrlScannerUnavailableLive`
remains only for explicit degraded/test wiring.
