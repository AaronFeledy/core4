# Scanner service

`UrlScanner` probes the HTTP addresses of running services and checks host-port
collisions across apps. This contributor reference describes the runtime inputs;
application developers can read the resulting URLs with `lando info`.

The live scanner needs running containers and a provider socket. Its targets are the service `connections` that `lando info --format=json` reports: only `host`-scope connections that are `assigned`, `active`, `http` or `https`, and not on a wildcard hostname. A publication is `active` only when the provider actually reported that binding, and a route only when the router reported it loaded. `app`-scope listeners, `tcp` and `udp` addresses, and `pending` or `inactive` connections are never probed. The scanner appends its configured `path` after a route's `pathPrefix`. Collision detection compares the assigned host ports of active host connections across apps.

This is not a user how-to. Print URLs with `lando info`. See [everyday commands](../cli/everyday-commands.mdx).
