# Healthcheck runner

`HealthcheckRunner` is the Effect Service tag published in `@lando/sdk`; plugins implement
`HealthcheckRunnerShape`. The `runHealthcheckContract` runner from `@lando/sdk/test` validates a
plugin's `id` and that `run()` resolves with a `HealthcheckResult`. `TestHealthcheckRunner` (built
with `makeTestHealthcheckRunner`) is the in-memory test double — it records run calls and returns
`healthy=true` — while core tests inject a fake provider exec to cover provider-exec behavior without
a live container.

## Probe types

`HealthcheckPlan` supports three probe kinds:

- `cmd` (`kind: command`) — runs inside the container via `RuntimeProvider.exec`.
- `tcp` (`kind: tcp`) — checks TCP port reachability from inside the per-app network.
- `http` (`kind: http`) — checks that the service URL returns a 2xx response from inside the per-app
  network.

## Failures and timeouts

`HealthcheckTimeoutError` is raised when a healthcheck fails within its timeout; it includes
`service`, `probe`, and `lastStatus`. `HealthcheckError` is raised for other healthcheck failures,
such as provider-exec being unavailable. Unit tests verify the `HealthcheckRunner` contract against
`TestHealthcheckRunner` in `sdk/test/contract/healthcheck-runner.test.ts`.

## Retry primitive

The provider-exec `HealthcheckRunner` uses `runProbe` from `@lando/sdk/probe` for its
retry/delay/timeout loops, not a hand-rolled `Effect.retry` or `Schedule` (enforced by
`check:probe-boundary`). `ProbeResult.lastError` is redacted via `RedactionService` before it reaches
events or transcripts. `HealthcheckRunnerLive` (in `engine/src/subsystems/healthcheck/live.ts`) wires
provider-exec to `RuntimeProvider.exec` and redacts the final provider status.
