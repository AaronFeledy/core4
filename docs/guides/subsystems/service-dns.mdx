# Reach services by name

Use a service key such as `database` when one service connects to another in the
same app. Browser URLs and cross-app names serve different purposes; the table
below shows which name belongs in each context. From the app directory on the
host, start the app and inspect both kinds of address:

```sh
lando start
lando info
```

`lando info` groups each service's connections by where you dial them from.
Host connections are the addresses you reach from this machine: route URLs for
your browser and published host ports, including a TCP port for a database you
open from a desktop client. App Network connections are the addresses other
services in the app use, spelled `protocol://<service>:<port>`, such as
`tcp://database:3306`. A host URL is not the hostname PHP uses to reach MySQL;
the App Network address is.

The default provider is `lando` (managed Podman).

## Pick the right name

| Where you are | Name to use | Example |
| --- | --- | --- |
| Another service in this app | The service key | `database` |
| Another app, or Traefik's backend | `<service>.<app>.internal` | `database.service-dns-demo.internal` |
| Host browser | `*.lndo.site` | `https://app.service-dns-demo.lndo.site` |

Use the service key inside the app. Use `<service>.<app>.internal` across apps and for Traefik backends. Use `LANDO_MAIL_HOST` for Mailpit. Use `*.lndo.site` only in the host browser.

## Connect with the service key

Configure the MySQL client in your app service to connect to `database`. Do not
send that traffic through `*.lndo.site`. The Landofile below shows the host in the
`db-query` tooling command; use the database's configured credentials when running
your client.

Recipe and service connection tables use the same host: the service key, not `127.0.0.1` or `localhost` (see [Add MariaDB](../services/mariadb.mdx)).

```yaml
name: service-dns-demo
services:
  app:
    type: "php:8.3"
    primary: true
    db_client: auto
  database:
    type: mysql
    creds:
      user: app
      password: secret
      database: app
tooling:
  db-query:
    service: app
    cmd: mysql -h database -u app app -e "SELECT 1"
```

That `-h database` is intra-app DNS on the per-app bridge `lando-service-dns-demo`. `lando info --format=json` lists the same name and port as a `database` connection with `scope: "app"` and `url: "tcp://database:3306"`, so a script can read the address instead of hardcoding it.

## Reach another app with `.internal`

Cross-app names live on `lando_bridge_network`. The alias is `<service>.<app>.internal`. Traefik dials `http://app.service-dns-demo.internal:80` for this app, not a `*.lndo.site` hostname.

Global Mailpit is `mailpit.global.internal`. Non-global `type: lando` services get `LANDO_MAIL_HOST=mailpit.global.internal` and `LANDO_MAIL_PORT=1025`. Point SMTP at those env values.

`lando info` does not list `.internal` names. Its `app`-scope connections use plain service keys on the app network; cross-app aliases live on the shared bridge and are not connections.

Issued leaf certs list the service name and `<service>.<app>.internal` as SANs.

Routes need shared cross-app networking and the same provider as the host router. The default `lando` provider advertises shared networking on Linux, macOS, and Windows. A routed app pinned to a different provider fails planning with `RouteProviderMismatchError`. See [Routing needs one provider](../setup/provider-selection.mdx#routing-needs-one-provider).

## Open `*.lndo.site` on this machine

Public DNS answers `*.lndo.site` with `127.0.0.1`; Traefik routes the request on your app host. Lando does not configure host DNS. On another device, loopback points at that device, not the app host. Custom `proxy.defaultDomain` values need your own DNS rule. See [Reach an app from another device](./external-access.mdx) and [Resolve lndo.site on this machine](./host-proxy.mdx).

## Keep host gateways separate

These names are not service DNS:

| Name | What it is |
| --- | --- |
| `host.lando.internal` | Planner-managed host-gateway alias when the provider supports host reachability; default Xdebug `client_host` |
| `host.containers.internal` | Podman-native host-gateway hostname; availability depends on the runtime and platform |
| `host.docker.internal` | Docker-native host-gateway hostname, unrelated to Lando's default Xdebug transport |

Use `host.lando.internal` to reach the host from a Lando service. The planner adds it and sets `LANDO_HOST_IP` to that name only when the provider supports host reachability. Neither is supplied when the provider cannot reach the host.

Engine-native hostnames are not portable across every provider and platform. Keep an explicitly authored Xdebug host if your setup needs it. Use service DNS, not a host-gateway name, for databases running as Lando services.
