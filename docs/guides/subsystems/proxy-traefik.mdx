# Use the Traefik proxy

From an app directory, start an app with routes and read its published URLs.
For HTTPS, run `lando setup` first so the local certificate authority is ready.
Lando starts Traefik when the app needs routing; do not start it by hand.

```sh
lando start
lando info
```

Open the URL `lando info` prints. Hostnames look like `web.myapp.lndo.site`. Apps share the router's listener ports, and Traefik selects a route by hostname
and path. Use distinct route identities for different backends; sharing a listener
does not prevent hostname conflicts.

Before `start` or `restart` reports success, Lando confirms that Traefik loaded
the app's complete route configuration. Unchanged routes are checked immediately,
without rewriting their files or reissuing current certificates. This confirms
routing configuration, not the HTTP status your app returns.

If Traefik cannot confirm the routes within 30 seconds, the command fails with
`ProxyApplyError` instead of claiming readiness. The app stays available for
diagnosis. Inspect the router before retrying:

```sh
lando global:logs --service=traefik --tail=100
lando global:info
lando doctor
```

The Traefik dashboard is at `traefik.lndo.site/dashboard/` over HTTP and HTTPS, and global Mailpit is at `https://mailpit.lndo.site`. Both follow global `proxy.defaultDomain`. Add the selected port when it is not 80 or 443.

When 80 and 443 are free, those URLs omit the port. When something else owns them, start prints `Port 80 is in use` or `Port 443 is in use`, names the holder if it can, and says `using 8080.` or `using 8443.` Then `lando info` prints the bound URLs, like `http://app.myapp.lndo.site:8080` and `https://app.myapp.lndo.site:8443`.

On Linux and WSL, when `router.bindAddress` is `127.0.0.1` and binding ports 80 and 443 needs elevated permissions, Lando can ask to install a systemd socket proxy. Its public listeners and Traefik's backend ports stay on `127.0.0.1`. It forwards HTTP and HTTPS traffic without changing DNS. Declining keeps the unprivileged fallback-port path.

## Read lando info and lando doctor

```sh
lando info
lando doctor --format=json
```

`lando doctor --format=json` puts `preferred-host-ports` in `result.provider.checks`. That check is `warn` with `runtimeStatus: preferred-port-occupied` when something else owns 80 or 443. The `router` check in `result.subsystems.checks` sets `context.acquisitionMode` to `occupied-hop` and reports the selected `httpPort` and `httpsPort`. Use the URL from `lando info`. To move back to your preferred ports, free them, then run `lando setup`.

## Prepare HTTPS

HTTPS routes need a certificate authority. Run `lando setup` first so mkcert can issue certs and trust the local CA:

```sh
lando setup
lando start
lando info
```

HTTP-only apps skip CA setup. If a browser warns on HTTPS, see [Trust local HTTPS certificates](./certificates-mkcert.mdx).

The default domain is `lndo.site`. Public DNS answers every `*.lndo.site` name with `127.0.0.1`, so most hosts need no DNS setup. Offline hosts, and resolvers that drop loopback answers as DNS-rebinding protection, need a local rule; see [Resolve lndo.site on this machine](./host-proxy.mdx). Other devices on the LAN get that same loopback answer, which points them at themselves. See [Reach an app from another device](./external-access.mdx).

Most apps skip `routes:`. A service with no `routes:` and no `proxy.<name>` entry gets the default hostname. Author routes and Lando serves exactly those instead, so list every name you want. Set `routes: []` (or `proxy.<name>: []`) to give a service no hostname at all; its published host ports still work.

Interactive `lando init` shows configured URL candidates after you answer the
recipe questions. These come from explicit authored routes, which can omit the
service prefix. They use the configured domain and preferred router ports, but
cannot establish runtime fallback ports or reachability. No explicit candidate
does not mean the app will have no automatic routes. Use `lando info` after
starting the app for its published URLs.

## Change the default domain

Set `proxy.defaultDomain` in global config, then restart the app:

```sh
lando config set proxy.defaultDomain lndo.test
lando restart
lando info
```

Use a plain DNS domain like `lndo.test`, with no scheme, port, path, or wildcard. Each label can have at most 63 characters, and the whole domain at most 253. `lando config set` rejects other values with an issue naming `proxy.defaultDomain` and leaves the config file unchanged. Preview validation without writing with `--dry-run`:

```sh
lando config set proxy.defaultDomain lndo.site:8080 --dry-run --format=json
```

Default hostnames move to the new domain, like `web.myapp.lndo.test`, and so do recipe routes written as `{{ app.name }}.{{ proxy.defaultDomain }}`. Hostnames you spelled out in full under `routes:` stay as written. Restart each app to publish its new routes and issue certificates for the new names.

Restarting an app with routing enabled also moves the Traefik dashboard to `traefik.lndo.test/dashboard/`. Traefik picks up the change without recreating its container. Global services publish their routes when the global app starts, so run `lando global:restart` to move global Mailpit to `https://mailpit.lndo.test`.

Lando does not add DNS for your domain. Point `*.lndo.test` at `127.0.0.1` with dnsmasq or your resolver, or add each hostname to `/etc/hosts`. Until then, if URL checking is on, `lando restart` marks each affected row with `!` and an `unreachable` reason such as `ENOTFOUND`. Those are Lando-side problems. Rows that get an HTTP response say what your app or web server returned; a `•` row is your app's own answer, not a Lando warning.

## Set router ports

HTTP tries `80`, then `8080`, `8000`, `8888`, `8008`, `38080`. HTTPS tries `443`, then `8443`, `4443`, `4433`, `4444`, `444`, `38443`. First free port per protocol wins. An empty fallback array means preferred-only.

```yaml
name: proxy-host-ports
services:
  app:
    type: "node:22"
    primary: true
router:
  httpPort: 8080
  httpsPort: 8443
  httpFallbacks: [8000, 8888, 8008, 38080]
  httpsFallbacks: [4443, 4433, 4444, 444, 38443]
```

This Landofile prefers 8080 and 8443, then walks the rest of each list. The same port and fallback settings work in the installation `config.yml`. Env aliases are `LANDO_ROUTER_HTTP_PORT`, `LANDO_ROUTER_HTTPS_PORT`, `LANDO_ROUTER_HTTP_FALLBACKS`, and `LANDO_ROUTER_HTTPS_FALLBACKS`. Fallback env values must be JSON arrays such as `[8000,8888]`.

Router ports are shared by every app. After changing the `router` block in `config.yml`, run `lando setup`. Setup rescans the candidate ports and moves Traefik to the pair it picks, even while Traefik is running. Starting an app that uses the router also picks up changed router ports; with unchanged config, app and scratch starts keep the owned pair so URLs stay stable. `lando global:restart` keeps the ports Traefik already has.

```sh
lando setup
lando info
```

After Traefik starts or restarts, Lando gives it up to 10 seconds to answer on both router ports before it warns. If `lando global:restart` or `lando global:rebuild` still warns that the ports did not answer, read Traefik's startup log and check the published ports:

```sh
lando global:logs --service=traefik --tail=100
lando global:info
```

## Set the shared router bind

The default `router.bindAddress` is `127.0.0.1`. To share the proxy on your LAN, set it to the host's LAN interface IP in the installation `config.yml`, or use `LANDO_ROUTER_BIND_ADDRESS`. A Landofile value is ignored and `lando app:config:lint` warns because one app cannot change the shared listener.

`0.0.0.0` and `::` bind on every interface, subject to the host firewall. `lando doctor` warns about those wildcard binds. A specific non-loopback IP is reported as intentional LAN sharing.

On Linux and WSL, any bind other than `127.0.0.1` bypasses the loopback socket helper. Lando publishes Traefik directly on the selected address and tries the configured fallback ports if it cannot bind the preferred ports. An installed helper does not provide LAN-facing ports 80 and 443.

After changing the global bind, run these commands from an app directory that uses the router:

```sh
lando start
lando global:info
lando doctor --format=json
```

The `router-bind-address` check reports `bind-application-unconfirmed` when the selected bind has not been confirmed against the running HTTP and HTTPS port bindings. If a previous bind was confirmed, `lastAppliedBindAddress` records it. Do not assume a change from a wildcard address to loopback has taken effect while this warning remains. Inspect the global service and retry `lando start`.

Changing the bind does not change route hostnames or DNS. Other devices still need to resolve those names to the app host's LAN IP. See [Reach an app from another device](./external-access.mdx).

## Read an unmatched host

Hit a hostname the proxy does not know, such as `web.no-such-app.lndo.site`, and you always get HTTP **404**. Which body you see depends on the request:

- Browser GET or HEAD that prefers `text/html` (positive `q` on Accept) → HTML titled **Route not found | Lando**, status line **`404 · Lando proxy`**, and steps that point you at `lando start` → `lando info` → `lando doctor`
- Default curl, `Accept: application/json`, `text/html;q=0`, or POST (even with `text/html`) → plain `text/plain; charset=utf-8` body exactly `404 page not found` plus a newline
- HEAD with an HTML Accept → HTML `Content-Type`, empty body

Use the URL from `lando info`. Guessing the hostname is how you land on the proxy page instead of your app. Some services publish **HTTPS-only** routes; HTTP to that hostname can hit this proxy diagnostic even when HTTPS to the same host returns the app (200).

Illustrative checks:

```sh
curl -i http://web.no-such-app.lndo.site/
curl -i -H 'Accept: text/html' http://web.no-such-app.lndo.site/
curl -i -X POST -H 'Accept: text/html' http://web.no-such-app.lndo.site/
```

Wrong host, stopped app, or HTTPS-only route on HTTP: same proxy rules. Matched HTTPS still returns the app.

When the host *does* match and the request reaches a Lando web server (for example default `static:nginx`), missing files and bare directories look different: **`404 · Lando web server`** / "Page not found", or **`403 · Lando web server`** / "Access denied". Same path on an unmatched host stays **`404 · Lando proxy`**. See [Serve a static site](../services/static.mdx).

## Verify

```sh
lando doctor
lando info
```

After setup, the `router` check should pass when Traefik holds 80 and 443. If it fails, rerun `lando setup`, then start the app again.

A `preferred-host-ports` warn means something else owns 80 or 443. Read the selected URLs with `lando info`. If a URL is empty, inspect the `router` check.

Lando starts the proxy. Do not launch Traefik yourself.
