# Use the Traefik proxy

Start an app. Lando starts Traefik for you. You do not start Traefik by hand.

```sh
lando start
lando info
```

Open the URL `lando info` prints. Hostnames look like `web.myapp.lndo.site`. Two apps never collide on the same host port because Traefik routes by hostname.

When 80 and 443 are free, those URLs omit the port. When something else owns them, start prints `Port 80 is in use` or `Port 443 is in use`, names the holder if it can, and says `using 8080.` or `using 8443.` Then `lando info` prints the bound URLs, like `http://app.myapp.lndo.site:8080` and `https://app.myapp.lndo.site:8443`.

## Read lando info and lando doctor

```sh
lando info
lando doctor --format=json
```

`lando doctor --format=json` puts `preferred-host-ports` in `result.provider.checks`. That check is `warn` with `runtimeStatus: preferred-port-occupied` when something else owns 80 or 443. The `router` check in `result.subsystems.checks` sets `context.acquisitionMode` to `occupied-hop` while Traefik is on the fallback ports.

## Prepare HTTPS

HTTPS routes need a certificate authority. Run `lando setup` first so mkcert can issue certs and trust the local CA:

```sh
lando setup
lando start
lando info
```

HTTP-only apps skip CA setup. If a browser warns on HTTPS, see [Trust local HTTPS certificates](./certificates-mkcert.mdx).

The default domain is `lndo.site`. `lando setup` writes `*.lndo.site` into this machine's DNS. Other devices on the LAN do not get that entry. See [Reach an app from another device](./external-access.mdx). Custom domains you resolve to loopback can fail when the router blocks DNS rebinding. That same guide covers the remediations.

You can author extra `routes:` when a service needs more than the default hostname. Most apps do not need that block.

## Set router ports

HTTP tries `80`, then `8080`, `8000`, `8888`, `8008`, `38080`. HTTPS tries `443`, then `8443`, `4443`, `4433`, `4444`, `444`, `38443`. First free port per protocol wins. An empty fallback array means preferred-only.

```yaml
name: proxy-host-ports
services:
  app:
    type: "node:22"
    primary: true
router:
  httpPort: 8080
  httpsPort: 8443
  httpFallbacks: [8000, 8888, 8008, 38080]
  httpsFallbacks: [4443, 4433, 4444, 444, 38443]
```

This Landofile prefers 8080 and 8443, then walks the rest of each list. The same `router` block works in the installation `config.yml`. Env aliases are `LANDO_ROUTER_HTTP_PORT`, `LANDO_ROUTER_HTTPS_PORT`, `LANDO_ROUTER_BIND_ADDRESS`, `LANDO_ROUTER_HTTP_FALLBACKS`, and `LANDO_ROUTER_HTTPS_FALLBACKS`. Fallback env values must be JSON arrays such as `[8000,8888]`. The default bind address is `127.0.0.1`.

Router ports are shared by every app. After changing the preferred ports or fallback lists, restart the shared router before starting the app:

```sh
lando global:restart
lando start
lando info
```

## Verify

```sh
lando doctor
lando info
```

After setup, the `router` check should pass when Traefik holds 80 and 443. If it fails, rerun `lando setup`, then start the app again.

A `preferred-host-ports` warn means something else owns 80 or 443. Read the selected URLs with `lando info`. If a URL is empty, inspect the `router` check.

Lando starts the proxy. Do not launch Traefik yourself.
