# Reach an app from another device

Bind a published port to `0.0.0.0` when you want LAN or external reachability. By default, host-exposed ports bind to `127.0.0.1` and stay on this machine.

```yaml
name: external-access-demo
services:
  web:
    type: compose
    image: traefik/whoami:v1.10
    primary: true
    ports:
      - 0.0.0.0:8080:80
```

## Only bind wide on purpose

Binding a service to `0.0.0.0` exposes it to every device on your LAN. On a shared or untrusted network, that includes anyone else on that network. Only bind wide when you intend LAN or external reachability. Never do it for services holding real credentials or unreviewed dev tooling. Prefer a named interface IP over `0.0.0.0` when you can.

Reverting a wide bind needs a rebuild, not just a restart. Remove `host_ip` or set it back to `127.0.0.1`, then run `lando rebuild -y`.

## Compose ports short-syntax reference

| Form | Meaning |
| --- | --- |
| `80` | Container port only. The provider assigns the host port, bound to loopback. |
| `8080:80` | Explicit host port mapped to a container port, still bound to loopback. |
| `0.0.0.0:8080:80` | `host_ip:host_port:container_port`. The explicit `host_ip` is what opts the binding beyond loopback. |
| `8080:80/udp` | Append `/protocol` to select `udp`. `tcp` is the default when omitted. |
| `8080-8090:80-90` | Equal-length host and container ranges map port-for-port in order. |

The long-form object accepts the same fields as `target` / `published` / `host_ip` / `protocol`. `host_ip` still controls bind scope:

```yaml
ports:
  - target: 80
    published: 8080
    host_ip: 0.0.0.0
    protocol: tcp
```

## The proxy does not widen LAN reach

The proxy answers a hostname like `web.external-access-demo.lndo.site`, but that hostname only resolves on this machine. `lando setup` writes `*.lndo.site` resolution into this machine's DNS only. It never touches other devices.

Proxy routing and published ports are independent. Reaching a proxied hostname from the host does not need a `ports:` entry. `ports:` only controls direct host-port publication.

Another device on the LAN has no `*.lndo.site` DNS entry, so it cannot reach the proxy by hostname. It can reach an explicitly bound `IP:port`, or you can add an equivalent hosts entry on that device.

## Custom domains and DNS rebinding

`*.lndo.site` is written on this machine by `lando setup`. It never goes through your LAN router.

A custom hostname you point at `127.0.0.1` often does. Many home and office routers refuse DNS answers that map a public-looking name to loopback. That protection is called DNS rebinding, and it makes the custom name fail on this host even though the app is running.

Lando has no flag that turns that protection off. Pick one of these:

1. Keep the default `*.lndo.site` names and run `lando setup` so this machine resolves them locally. See [Resolve lndo.site on this machine](./host-proxy.mdx).
2. Own DNS yourself: `lando setup --host-proxy=none`, then add `/etc/hosts` or dnsmasq entries on this machine.
3. From another device, skip hostnames. Use the LAN `IP:port` from the bind above.
4. On the router, allowlist the custom zone or disable DNS rebinding protection for it. That is a router setting, not a Lando setting.

Proxy hostname routing is covered in [Use the Traefik proxy](./proxy-traefik.mdx).

## Reach the app from a second device

Find this machine's LAN IP:

```sh
ip addr show     # Linux
ifconfig         # macOS
ipconfig         # Windows
```

From the other device, browse to the host LAN IP and the published host port. Not the container port, and not a `*.lndo.site` hostname:

```text
http://<host-lan-ip>:8080
```

A `0.0.0.0` bind opens the container port mapping, but the host OS firewall can still refuse the inbound connection. Add an allow rule if you need one.
