# Reach an app from another device

Bind a published port to `0.0.0.0` when you intend other devices to reach it.
By default, host-exposed ports bind to `127.0.0.1` and stay on this machine.
A wide bind exposes the service to other devices wherever the host firewall
allows access. Do not use it for services with real credentials or unreviewed
development tools; prefer a specific interface IP when possible.

Save this example as `.lando.yml` in an app directory, then run `lando start`
there. From a second device, open `http://<host-lan-ip>:8080`, replacing
`<host-lan-ip>` with the app host's LAN address. The response confirms direct
port access; it does not test proxy hostname resolution.

```yaml
name: external-access-demo
services:
  web:
    type: compose
    image: traefik/whoami:v1.10
    home: false
    primary: true
    ports:
      - 0.0.0.0:8080:80
```

## Only bind wide on purpose

Binding a service to `0.0.0.0` exposes it to every device on your LAN. On a shared or untrusted network, that includes anyone else on that network. Only bind wide when you intend LAN or external reachability. Never do it for services holding real credentials or unreviewed dev tooling. Prefer a named interface IP over `0.0.0.0` when you can.

Reverting a wide bind is a create-config change. Remove `host_ip` or set it back to `127.0.0.1`, then run `lando start`. Bare `lando restart` also stop/starts and applies it. Selected `lando restart -s` refuses bind drift and tells you to run `lando rebuild -s <name>`.

## Compose ports short-syntax reference

| Form | Meaning |
| --- | --- |
| `80` | Container port only. Lando picks a free host port in 30000-32767, bound to loopback, and keeps it across restarts. When the daemon isn't on this host (remote URL, Docker Desktop VM, Windows), the provider picks instead. |
| `8080:80` | Explicit host port mapped to a container port, still bound to loopback. |
| `0.0.0.0:8080:80` | `host_ip:host_port:container_port`. The explicit `host_ip` is what opts the binding beyond loopback. |
| `8080:80/udp` | Append `/protocol` to select `udp`. `tcp` is the default when omitted. |
| `8080-8090:80-90` | Equal-length host and container ranges map port-for-port in order. |

The long-form object accepts the same fields as `target` / `published` / `host_ip` / `protocol`. `host_ip` still controls bind scope:

```yaml
ports:
  - target: 80
    published: 8080
    host_ip: 0.0.0.0
    protocol: tcp
```

## The proxy does not widen LAN reach

The proxy answers a hostname like `web.external-access-demo.lndo.site`. Public DNS resolves `*.lndo.site` to `127.0.0.1`, and Lando does not write host DNS rules. On another device, that address points at the device itself, not your app host.

The shared proxy listener is a separate bind from a service `ports:` `host_ip`. Default is `127.0.0.1`. Set `router.bindAddress` or `LANDO_ROUTER_BIND_ADDRESS` to a LAN address when you want the proxy itself reachable from another device, then run `lando setup`. `0.0.0.0` and `::` publish on every interface; `lando doctor` warns.

Proxy routing and published ports are independent. Reaching a proxied hostname from the host does not need a `ports:` entry. `ports:` only controls direct host-port publication.

On a typed service such as `node` or `mysql`, `ports:` adds host publications without removing the type's own listener. The service keeps its primary port whether `ports:` is absent or an empty list, and a published entry that targets that same port publishes that listener on the host; it keeps the listener's protocol and primary marking. A published port the type doesn't know is reported as plain `tcp` or `udp`, because a Compose port mapping describes transport, not application protocol. A Compose `app_protocol` value is kept as a hint and doesn't change that. `expose:` adds an App Network `tcp` listener for any port the service doesn't already declare. To remove a service's listeners from the plan, set `endpoints: []`; an explicit `endpoints:` list is authoritative and `ports:` cannot stand in for it.

`lando info` shows the result as connections grouped by scope. The `0.0.0.0:8080:80` publication above is the Host connection `tcp://localhost:8080`; Lando shows a wildcard bind as `localhost`, the address you use from this machine. `web` also keeps its App Network address, `tcp://web:80`, for other services in the app. `web` is a raw Compose service, so Lando knows that port only as TCP and does not hyperlink or scan it. Declare `protocol: http` in an explicit `endpoints:` entry when you want HTTP treatment.

Another device can reach an explicitly bound `IP:port`. To use a proxy hostname there, point it at the app host's LAN IP with your own DNS or hosts entry and ensure the proxy listener and firewall allow LAN access.

## Custom domains and DNS rebinding

Public `*.lndo.site` answers pass through your configured resolver, which may be your LAN router. Offline hosts or unreachable public DNS can make these names fail.

Many home and office resolvers/routers also drop DNS answers that map a public-looking name to loopback. DNS-rebinding protection can block both `*.lndo.site` and custom domains even while the app is running.

Lando has no flag that changes host DNS or turns that protection off. Choose the fix for your network:

- Configure a local dnsmasq or OS resolver rule that maps `*.<domain>` to `127.0.0.1`, or add hosts entries for individual names. Use your `proxy.defaultDomain` (default `lndo.site`). See [Resolve lndo.site on this machine](./host-proxy.mdx).
- If your resolver blocks loopback answers, allowlist the specific development zone, including `lndo.site` if you use it. Keep DNS-rebinding protection enabled for other zones.
- From another device, use the LAN `IP:port` from the bind above, or configure that device's hostname resolution to the app host's LAN IP, not loopback.

Run `lando doctor` on the app host after changing its DNS rule.

Proxy hostname routing is covered in [Use the Traefik proxy](./proxy-traefik.mdx).

## Reach the app from a second device

Find this machine's LAN IP:

```sh
ip addr show     # Linux
ifconfig         # macOS
ipconfig         # Windows
```

From the other device, browse to the host LAN IP and the published host port. Not the container port, and not a `*.lndo.site` hostname:

```text
http://<host-lan-ip>:8080
```

A `0.0.0.0` bind opens the container port mapping, but the host OS firewall can still refuse the inbound connection. Add an allow rule if you need one.
