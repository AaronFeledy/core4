# Resolve lndo.site on this machine

Run `lando doctor` to check whether your app domain resolves to `127.0.0.1` on this machine.

```sh
lando doctor
```

Public DNS answers `*.lndo.site`, the default app domain, with `127.0.0.1`. Lando does not write host DNS rules. Offline hosts, unreachable public DNS, or a LAN resolver/router with DNS-rebinding protection can prevent those answers from reaching you.

On another device, `127.0.0.1` points at that device, not your app host. To reach an app from another device, bind a port on purpose. See [Reach an app from another device](./external-access.mdx).

## Manage DNS yourself

If the lookup fails, configure dnsmasq or an OS resolver rule so `*.lndo.site` resolves to `127.0.0.1`. Hosts files do not support wildcards; add an entry for each hostname you use instead.

If you set `proxy.defaultDomain` to a custom domain such as `lndo.test`, configure the same local rule for that domain. Neither `lando setup` nor `--host-proxy=none` changes host DNS. DNS-rebinding protection can affect both default and custom domains. See [Reach an app from another device](./external-access.mdx).

## Verify

```sh
lando doctor
```

Doctor probes `lando-doctor-probe.<domain>` using your configured `proxy.defaultDomain` (default `lndo.site`). If it fails, add a local DNS rule for that domain and run `lando doctor` again. This DNS pass does not cover container-to-host callbacks. Starting an app still needs a host-proxy transport session; if that session cannot start, `lando start` can fail with `HostProxyTransportUnavailableError`. Doctor checks that transport separately.

If the detached worker cannot start, the error names its log at `<userCacheRoot>/logs/host-proxy-worker-<appId>.log`. An observed worker exit includes its exit code and a redacted stderr tail. Payload delivery failures, readiness timeouts, closed stdout, and invalid readiness frames also name the log; a worker still alive after the bounded wait has no reported exit code. Logs are owner-only (`0600` on POSIX, a private ACL on Windows), and Lando creates the logs directory with mode `0700`. Worker outer-failure output is redacted before it reaches the log, and tails are redacted before entering errors.

The host-proxy bearer token and session id are masked as `[redacted]` in `exec` and `logs` output, including commands run after `start` exits. Later commands read current container credentials and matching owner-only worker records without contacting the worker.

To open a URL or reveal an app file in your host's file manager from a service, use [`xdg-open` or `open` through the host proxy](./host-open.mdx). Those callbacks are separate from DNS resolution.
