# Resolve lndo.site on this machine

`*.lndo.site` app URLs need to resolve to `127.0.0.1` on this machine. Run setup to prepare Lando, then check the hostname resolution.

```sh
lando setup
```

The default domain is `lndo.site`. If your DNS does not already send `*.lndo.site` to `127.0.0.1`, configure a local DNS rule.

Other devices on the LAN do not get that DNS entry. To reach an app from another device, bind a port on purpose. See [Reach an app from another device](./external-access.mdx).

## Manage DNS yourself

If you already own DNS (corporate split-DNS, dnsmasq, or your own `/etc/hosts` entries):

```sh
lando setup --host-proxy=none
```

That opts out of Lando-managed DNS.

Custom public-looking names pointed at loopback often trip router DNS rebinding protection. See [Reach an app from another device](./external-access.mdx).

## Verify

```sh
lando doctor
```

Doctor checks whether a `*.lndo.site` name resolves to `127.0.0.1`. Skipping Lando-managed DNS is fine when that lookup works. If it fails, add a local DNS rule for `*.lndo.site` and run `lando doctor` again. This DNS pass does not cover container-to-host callbacks. Starting an app still needs a host-proxy transport session; if that session cannot start, `lando start` can fail with `HostProxyTransportUnavailableError`. Doctor checks that transport separately.
