# First-run readiness for the managed runtime

The managed runtime bundle extracts into Lando's private runtime bin
directory, `<userDataRoot>/runtime/bin`. Runtime sockets and PID files live
beside it under `<userDataRoot>/runtime/run` — not in system Podman or
Docker locations. Setup records the installed runtime bin directory and
bundle version in `provider-lando/setup-state.json` for later readiness
checks.

## Safe extraction

Bundle bytes are SHA-256 verified with `verifyRuntimeBundle` before any
extraction work starts. The same safe entry validation covers both
`.tar.gz` (Linux/macOS) and `.zip` (Windows) bundles. Unsafe archive
entries — path traversal, absolute paths, symlinks, hardlinks — fail with
remediation and leave `runtimeBinDir` untouched.

## Installs are idempotent

A `.runtime-installed-version` marker records the installed bundle version;
a matching version skips re-extraction on the next setup run. A changed
version installs into a sibling temp directory before replacing the old bin
tree — temp dir plus rename, never an in-place overwrite. Runtime binaries
and helpers (`podman`, `gvproxy`, `conmon`, `crun`/`runc`, `netavark`,
`aardvark-dns`) install with executable bits on POSIX hosts.

## Runtime service status

`lando doctor` reports the managed `runtime-service` check from a real
socket/PID probe, not a hardcoded running state. If the service stopped or
got killed, the next runtime-needing command self-heals by rerunning
`ensureRuntime` and relaunching the private socket. Setup records running
state, socket path, PID, and runtime version in `setup/readiness.json` under
`runtimeService`, which doctor shows as the last-recorded readiness
context.

`apps:poweroff` stops the managed runtime service after app shutdown, while
preserving keep-global and keep-scratch app filtering. Uninstall plans and
executes runtime-service teardown before removing the private runtime
directory, under both keep-data and purge modes. If a `runtime-service` PID
ends up orphaned, doctor surfaces it with manual remediation rather than
promising an unsupported `doctor --fix` path.
