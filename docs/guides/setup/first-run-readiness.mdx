# Check first-run readiness

Run `lando doctor` after `lando setup`. Doctor reports whether the managed runtime is up.

```sh
lando setup
lando doctor
```

The default provider is `lando` (managed Podman). Setup extracts a private runtime into Lando's own data directory, not into system Podman or Docker paths. On Linux that data root is `$XDG_DATA_HOME/lando` (`~/.local/share/lando`).

## When setup fails

Default setup may fail on Alpha. Host prerequisites (uidmap, subuid/subgid ranges, cgroups) can block the managed runtime, and the committed runtime-bundle manifest may still be placeholders.

If doctor or setup names a host prerequisite, fix it and rerun `lando setup`. Then run `lando doctor` again.

On Intel Macs (`darwin-x64`), managed `lando` fail-closes. Docker is the live path. Install Docker Desktop, then:

```sh
lando setup --provider=docker
```

On Linux, if the managed runtime still cannot install and you have working system Docker, use the same command as the supported fallback.

After a successful `lando setup --provider=docker`, later `lando doctor` and `lando start` stay on Docker. `LANDO_PROVIDER` does not persist.

`lando setup` and `lando setup --yes` ignore leftover `defaultProviderId` in user config.

## What doctor checks

Doctor probes the managed runtime. If the runtime stopped, the next command that needs it starts it again.

`lando poweroff` stops apps and then the managed runtime. Uninstall tears the runtime down before it removes Lando's private runtime directory.

If doctor reports an orphaned runtime process, follow the printed remediation.

## Verify

```sh
lando doctor
lando --version
```

Doctor should name the provider you are on.
