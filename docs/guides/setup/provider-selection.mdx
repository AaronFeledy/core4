# Pick a container provider

Run `lando setup`, then `lando doctor`. The default provider is `lando` (Lando-managed Podman). It does not need system Docker or Podman.

If that setup fails, switch to system Docker. That is the supported Linux fallback, not an advanced preference.

## Fall back to Docker

You need working system Docker.

1. Run setup with Docker:

```sh
lando setup --provider=docker
```

Or set the provider for this shell:

```sh
LANDO_PROVIDER=docker lando setup
```

2. Verify with Docker still selected:

```sh
lando doctor --provider=docker
```

Or:

```sh
LANDO_PROVIDER=docker lando doctor
```

Bare `lando doctor` reports the managed `lando` provider. Setup does not save Docker as your default. Keep passing `--provider=docker` or `LANDO_PROVIDER=docker` on later commands. `lando setup` and `lando setup --yes` do not honor leftover `defaultProviderId` in user config. `--yes` consents to confirmation and privileged host changes. It does not switch providers.

System `podman` is also opt-in with `--provider=podman`. It needs an existing Podman install. Setup fails with remediation if that runtime is missing. It does not install Docker or Podman for you.

## Override the provider

Setup (`lando setup`, including `--yes`) uses:

```
--provider > LANDO_PROVIDER > capability default (lando)
```

App commands (`lando start`, `lando doctor`) use:

```
--provider > Landofile provider: > LANDO_PROVIDER > user-config defaultProviderId > capability default (lando)
```

Force Docker for one command:

```sh
lando start --provider=docker
```

Or for one shell:

```sh
LANDO_PROVIDER=docker lando start
```

## Resolve a provider conflict

If `lando doctor` reports a conflict between the managed Lando runtime and system Podman, pick one provider explicitly:

```sh
lando setup --provider=lando
```

or, when you already have system Docker:

```sh
lando setup --provider=docker
```

or, when you already have system Podman:

```sh
lando setup --provider=podman
```

## Verify with lando doctor

```sh
lando doctor --provider=docker
lando --version
```

Or:

```sh
LANDO_PROVIDER=docker lando doctor
```

Doctor should name the provider you selected. After a Docker fallback, bare `lando doctor` still reports managed `lando`.
