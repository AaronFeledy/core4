# Setup is guided, not automatic

`lando setup` provisions the container runtime provider before app lifecycle commands need one. Run it
yourself; Lando does not provision a provider in the background when you first run `lando start`. When
you don't pass `--provider` and `LANDO_PROVIDER` is unset, setup uses the bundled managed provider
(`lando`), even if leftover `defaultProviderId` in user config says `docker` or `podman`. That default
does not require an existing Docker or Podman install. Choosing `--provider=docker` or
`--provider=podman` instead requires that system runtime to already be present; setup fails with
remediation, rather than installing one for you, when it is missing.

For scripts and CI, pass `--no-interactive` to skip prompts while keeping the same guided defaults, or
combine `--yes` with an explicit `--provider` for a fully deterministic invocation. `--yes` consents to
confirmation and privileged host changes; leftover config still does not pick Docker. See the
[corporate network trust guide](../config/corporate-network-trust.mdx) for CA and proxy trust setup, and
run `lando doctor` afterward to confirm setup readiness, as described in the
[doctor walkthrough](../subsystems/doctor-walkthrough.mdx).

## Non-interactive and CI

```sh
# Same guided defaults, no follow-up prompts
lando setup --no-interactive

# Confirms setup prompts but does not change provider precedence
lando setup --yes

# Recommended CI shape: choose the provider and confirmation mode explicitly
lando setup --yes --provider=lando
```

For `linux-x64` provider-integration CI, set `LANDO_RUNTIME_BUNDLE_MANIFEST`
to stage a current-commit runtime bundle tarball and point setup at the
local file manifest before `ensureRuntime` brings up the managed socket. CI
teardown uses the Lando-managed `podman` binary with isolated `--root`,
`--runroot`, and `--config` so cleanup targets the same store the job
created, after `lando poweroff`.

## System providers don't self-install

`lando setup --provider=podman` requires an existing Podman installation
and fails with remediation when Podman is unavailable.
`lando setup --provider=docker` requires an existing Docker installation
and fails with remediation the same way. Use
`lando setup --provider=lando` for the bundled managed runtime instead of
selecting a system provider you don't already have.
