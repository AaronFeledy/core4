# Run lando setup

Run `lando setup` yourself. Lando does not provision a provider in the background when you first run `lando start`.

The default provider is `lando` (managed Podman). It does not need system Docker or Podman.

## Use the defaults

```sh
lando setup
```

Then verify:

```sh
lando doctor
```

`lando setup` and `lando setup --yes` ignore leftover `defaultProviderId` in user config. `--yes` consents to confirmation and privileged host changes. It does not switch providers.

Default setup may fail on Alpha. Host prerequisites can block the managed runtime, and the committed runtime-bundle manifest may still be placeholders. If setup names a host prerequisite, fix it and rerun `lando setup`.

## Fall back to Docker

You need working system Docker.

```sh
lando setup --provider=docker
```

After a successful `lando setup --provider=docker`, later `lando doctor` and `lando start` stay on Docker. You do not need to repeat the flag.

`LANDO_PROVIDER=docker lando setup` does not persist. If you only set the env, keep it for later commands.

`--provider=docker` and `--provider=podman` require that system runtime to already be present. Setup fails with remediation when it is missing. It does not install Docker or Podman for you.

## Skip prompts

```sh
lando setup --no-interactive
lando setup --yes
lando setup --yes --provider=lando
```

`--no-interactive` skips prompts and keeps the same guided defaults. Combine `--yes` with an explicit `--provider` when you want a fully determined run.
