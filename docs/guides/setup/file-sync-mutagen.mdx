# Accelerate slow bind mounts with Mutagen

Mutagen-backed file sync is not a user command on Alpha. There is no `lando mutagen`. Linux x64 bind mounts are native, so `lando setup` records file-sync as satisfied and does not download Mutagen.

The bundled engine still fails closed until a live Mutagen host client ships. `lando setup` can provision pinned Mutagen binaries on slow bind-mount providers (macOS and Windows VMs). That client is not wired up as a working session path yet.

## What works today

Exclude paths in the Landofile. That is the user file-sync control on Alpha:

```yaml
services:
  app:
    type: "node:22"
    primary: true
    appMount:
      excludes:
        - dist
```

See [Exclude paths from file sync](./file-sync-excludes.mdx).

`lando setup --skip-file-sync` exists for those future slow hosts. It defers Mutagen download to the first accelerated `lando start`. Do not use it to switch providers. `--yes` is consent, not a provider switch.

When a slow-mount host is supported, `lando doctor` will run the `file-sync` check only if `bindMountPerformance` is `slow`. Native Linux Docker or Podman skips that check.
