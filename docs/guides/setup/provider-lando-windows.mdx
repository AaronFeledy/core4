# Use the managed Lando runtime on Windows

Alpha binaries are Linux x64 today. There is no Windows `lando.exe` in Alpha. This page records the Windows `lando` provider path so the facts are here when that host is supported.

On a future Windows binary, default `lando setup` installs a Lando-owned Podman machine. It does not need system Docker or Podman.

Lando talks to that machine over the named pipe `\\.\pipe\podman-lando`, not a Unix socket. Bind mounts are VM-mediated, so `bindMountPerformance` reports `slow`.

## What setup will do

Lando imports the host native CA store only into machines it created. A user-owned machine stays untouched.

Lando never auto-elevates or runs Hyper-V prep for you. If setup names Hyper-V as a prerequisite, fix it in an Administrator terminal and rerun `lando setup`. `--yes` is consent, not a provider switch.

Until a Windows binary ships, install the Linux x64 binary inside WSL. See [Install Lando on WSL](../install/wsl.mdx).
