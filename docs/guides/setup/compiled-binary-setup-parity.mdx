# Run setup from the compiled binary

Lando ships signed compiled `lando` binaries for Linux, macOS, and Windows on each GitHub release, and the installers at `get.lando.dev` install the same binaries. Setup behaves the same whether you ran the installer or installed a downloaded binary by hand.

[Put the downloaded binary on PATH](../install/path-and-setup.mdx) first, then run setup in your terminal and follow the prompts. Choose the recommended Lando-managed runtime on supported hosts; Docker is not required. On an Intel Mac (`darwin-x64`), install and start Docker Desktop first, then choose Docker when setup asks. Setup does not install Docker for you.

`lando setup` is the user command. It is the same native command as `lando meta:setup`. Use the short name.

```sh
lando setup
lando doctor
```

The default provider is `lando` (managed Podman). If that setup fails and you have working system Docker:

```sh
lando setup --provider=docker
```

`--yes` consents to confirmation. It does not switch providers. See [Pick a container provider](./provider-selection.mdx#what-persists).

Unknown setup flags fail before the run. That is the compiled binary behaving like source, not a second setup tool.

See [Install from a GitHub release](../install/github-releases.mdx) and [Run lando setup](./provider-auto-setup.mdx).
