# Use system Podman on Linux

Run `lando setup --provider=podman` when you already have rootless Podman. This is opt-in. The default provider is `lando` (managed Podman).

## Run setup

You need working system Podman.

```sh
lando setup --provider=podman
```

Then verify:

```sh
lando doctor --provider=podman
```

After `lando setup --provider=podman`, later commands go back to the default `lando` provider unless you keep `--provider=podman`, keep `LANDO_PROVIDER=podman`, or set Landofile `provider: podman`.

`LANDO_PROVIDER=podman lando setup` does not persist. If you only set the env, keep it for later commands.

`--yes` consents to confirmation and privileged host changes. It does not switch providers.

Setup fails with remediation if Podman is missing. It does not install Podman for you.

Rootless Podman talks to `$XDG_RUNTIME_DIR/podman/podman.sock`. Bind mounts are native on Linux, so you skip the slow-mount file-sync path.

## Resolve a socket conflict

If `lando doctor` reports that system Podman and the managed Lando runtime target the same socket, pick one:

```sh
lando setup --provider=lando
```

or keep system Podman:

```sh
lando setup --provider=podman
```

If you already have Docker and the managed runtime is not what you want, the supported Linux fallback is `lando setup --provider=docker`.

See [Pick a container provider](./provider-selection.mdx).
