# Provider podman linux

## Linux socket discovery

Unit tests exercise the user-installed Podman socket discovery precedence; the rendered live socket path requires a real rootless Podman install.

Rootless Linux default when XDG_RUNTIME_DIR is set (`$XDG_RUNTIME_DIR/podman/podman.sock`).

Discovery precedence.

User-installed rootless Podman talks straight to the host; bind mounts are native on Linux.

## Linux opt in

provider-podman is opt-in only; the rendered flow requires a Landofile checkout and a real Podman socket.

Opt in by setting provider in your .lando.yml.

Or pass --provider=podman to lando setup.

```sh
lando setup --provider=podman
```

Default stays @lando/provider-lando; provider-podman never auto-loads.

Provider integration suites gate on @lando/core/testing live socket resolution instead of requiring LANDO_TEST_PODMAN_SOCKET when the managed lando socket is already up (`resolveLiveProviderSocket`).

## Linux provider lando conflict

provider-lando records its managed socket in this JSON file when lando setup runs (`$LANDO_DATA_DIR/providers/provider-lando/setup-state.json`).

Tagged subclass of ProviderUnavailableError surfaced when both providers target the same socket (`ProviderLandoConflictError`).

Conflict remediation guidance.
