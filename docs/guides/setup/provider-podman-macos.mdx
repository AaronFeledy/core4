# Use Podman Desktop on macOS

Download the macOS binary for your architecture from a `v4.0.0-dev.N` [GitHub prerelease](../install/github-releases.mdx), then [put it on PATH](../install/path-and-setup.mdx). System Podman is an opt-in provider; setup does not install it for you.

Start your existing Podman Desktop machine before running:

```sh
lando setup --provider=podman
```

Run `lando doctor --provider=podman` after setup to verify the provider.

`--yes` consents to confirmation. It does not switch providers. See [What persists](./provider-selection.mdx#what-persists).

The default machine socket is `$HOME/.local/share/containers/podman/machine/podman-machine-default/podman.sock`. Override the machine name, for example to target a rootful machine, without editing config:

```sh
LANDO_PODMAN_MACHINE=podman-machine-default-root
```

Bind mounts are VM-mediated on macOS Podman Desktop, so `bindMountPerformance` reports `slow`.

If the machine socket is unreachable, Lando raises `PodmanMachineNotRunningError`. Start the machine from the CLI:

```sh
podman machine start podman-machine-default
```

Or open Podman Desktop and start `podman-machine-default`.
See [Pick a container provider](./provider-selection.mdx) for provider selection, persistence, and the Docker Desktop path required for managed-provider setup on Intel Macs.
