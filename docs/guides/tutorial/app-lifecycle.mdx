# Start, inspect, and tear down an app

Start a Node and Postgres environment, inspect it, run a command inside Node, then stop or remove it. First [install Lando](../install/path-and-setup.mdx) and complete `lando setup` for your platform. Create a separate app directory and save the following as `.lando.yml` in it:

```yaml
name: app-lifecycle-demo
services:
  app:
    type: "node:22"
    primary: true
  db:
    type: postgres
```

The primary service is the default target whenever a command omits
`--service`.

## Run the everyday loop

From the directory containing `.lando.yml`, run `lando start`, then `lando info`. Check that both `app` and `db` appear before continuing. The Node service supplies a development environment; this example does not launch a web application.

Keep the app running for the inspection and shell commands below. Use `lando stop` when you finish working, or follow [Tear down](#tear-down) when you want to remove its containers and networks.

## Inspect a running app

These commands are read-only. Run them as often as you like:

```sh
# Show every service, its connection details, and the app URLs
lando info

# The same data as machine-readable JSON
lando info --format=json

# Show a bounded snapshot of the combined logs from every service
lando logs

# Follow just the primary app service's logs in real time
lando logs --service app --follow

# Print the fully-resolved Landofile (includes merged, templates rendered)
lando app:config --format=json
```

## Work inside the app

Run one-off commands in a service, or open a shell:

```sh
# Run a command in a named service
lando exec app -- node --version

# Omit the service to target the primary service
lando exec -- node --version

# Open an interactive shell in the primary service
lando ssh

# Or in a specific service
lando ssh --service db
```

Tooling aliases declared under `tooling:` run inside their target service.
`lando npm install`, `lando psql`, and so on.

## Restart and rebuild

`lando rebuild` and `lando destroy` ask for confirmation first. Pass `-y` to skip the prompt in scripts.

Bare `restart` stops then starts, so it removes and recreates containers. It is not an in-place process restart. `lando start` applies Landofile changes such as command, environment, image, and mounts, and keeps unchanged containers and volumes. Reach for `rebuild` when you need a forced image pull or a forced rerun of build steps whose command text did not change. `start` does not take `-y`.

```sh
# Stop the app's containers but keep volumes and state
lando stop

# Bring the app up and apply create-config changes. Volumes stay
lando start

# Stop then start in one step
lando restart

# Force a pull and build refresh, then recreate containers
lando rebuild
```

## Tear down

`destroy` removes the app's containers and networks. Volumes stay unless you pass `--volumes` or `--purge`. The `-y` flag is required in non-interactive contexts:

```sh
lando destroy -y
```

Snapshots survive plain `destroy` and `--volumes`. **`lando destroy --purge -y` also deletes this folder's catalogued snapshots**, including native data through the provider that recorded each snapshot. It works when an earlier destroy left only ownership inventory. Snapshots belong to the source volume's canonical owner root, so other app folders keep theirs even if they share this app's name. See [Import and export app databases](../tooling/db-import-export.mdx) before moving a database between apps or providers.

Changing providers doesn't move an applied app. If `lando start` fails with `AppPlacementError`, retire the old copy explicitly:

```sh
lando destroy --provider=lando --yes
```

Only the selected provider's state and resources are touched. See [Recover an app left on another provider](../setup/provider-selection.mdx#recover-an-app-left-on-another-provider).

`stop` and `destroy` use the provider's last applied plan when the Landofile is
missing or invalid. That means you can still tear down an app after deleting its
directory or breaking its config. Lando verifies the stored app root, owner, and
provider before it touches anything.

Teardown looks at what is actually running before it reads your config. An app
that was never started reports `unchanged` and exits 0, even when its Landofile
does not validate. If a plain `destroy` kept your data volumes, a later
`lando destroy -y --volumes` still removes them and tells you what it removed.

The next commands affect the whole host, not just this tutorial app. Poweroff also removes scratch apps and their disposable data unless you pass `--keep-scratch`. Run it only when you mean to stop all targeted apps:

```sh
# List every Lando app known on this host and its status
lando apps:list

# Stop every running Lando app and the shared services at once
lando apps:poweroff
```
