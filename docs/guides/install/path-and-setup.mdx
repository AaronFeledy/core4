# Put lando on PATH and run setup

> **Alpha status:** `get.lando.dev` and `update.lando.dev` are not serving v4 yet. Download the binary from a GitHub dev prerelease. See [Alpha install and bug reports](../../alpha-install-and-bug-reports.md).

After you download and verify the platform-qualified binary from a `v4.0.0-dev.N` prerelease, put it on PATH as `lando`. These commands preserve an existing executable in a unique backup before installing. For Linux x64, run these commands from the download directory:

```sh
(
  set -eu
  chmod +x lando-linux-x64
  mkdir -p "$HOME/.local/bin"
  if [ -e "$HOME/.local/bin/lando" ] || [ -L "$HOME/.local/bin/lando" ]; then
    landoBackup=$(mktemp "$HOME/.local/bin/lando.bak.XXXXXX")
    mv "$HOME/.local/bin/lando" "$landoBackup"
  fi
  mv -n lando-linux-x64 "$HOME/.local/bin/lando"
  test ! -e lando-linux-x64
) &&
export PATH="$HOME/.local/bin:$PATH" &&
command -v lando &&
lando --version
```

Replace `lando-linux-x64` with the asset you downloaded on Linux or macOS. Add `$HOME/.local/bin` to your shell profile's PATH to keep `lando` available in new terminals.

On Windows, name the downloaded asset `lando.exe`, then move it into a directory on PATH. The commands below back up an existing `lando.exe` in that directory before installing the Alpha. In PowerShell from the download directory:

```powershell
Rename-Item .\lando-windows-x64.exe lando.exe
$landoInstallDir = "$env:LOCALAPPDATA\Programs\Lando"
New-Item -ItemType Directory -Force $landoInstallDir | Out-Null
$landoExe = Join-Path $landoInstallDir 'lando.exe'
if (Test-Path -LiteralPath $landoExe) {
  Move-Item -LiteralPath $landoExe -Destination "$landoExe.bak.$(Get-Date -Format yyyyMMddHHmmss)"
}
Move-Item .\lando.exe $landoExe
$env:PATH = "$env:LOCALAPPDATA\Programs\Lando;$env:PATH"
Get-Command lando | Select-Object -ExpandProperty Source
lando --version
```

Use `lando-windows-arm64.exe` on ARM64 Windows. `Get-Command` should point to the `lando.exe` you just moved. If it points to an older installation, correct your PATH or remove an older `lando` alias from your PowerShell profile before continuing. To keep this directory first on PATH in new PowerShell sessions, append the PATH entry to your profile. These commands create the profile if it is missing and preserve any existing content:

```powershell
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $PROFILE) | Out-Null
if (-not (Test-Path -LiteralPath $PROFILE)) { New-Item -ItemType File -Path $PROFILE | Out-Null }
$landoProfilePath = @'
$landoBin = Join-Path $env:LOCALAPPDATA 'Programs\Lando'
if (($env:PATH -split [IO.Path]::PathSeparator)[0] -ne $landoBin) {
  $env:PATH = $landoBin + [IO.Path]::PathSeparator + $env:PATH
}
'@
Add-Content -LiteralPath $PROFILE -Value $landoProfilePath
```

Run these once for each profile where you want Lando. The current session already has the PATH entry from the earlier command. Then:

```sh
lando setup
lando doctor
```

The default provider is `lando` (managed Podman). Default setup may fail on Alpha if host prerequisites block the managed runtime. If the managed runtime still cannot install and you have working system Docker:

```sh
lando setup --provider=docker
```

`--yes` consents to confirmation and privileged host changes. It does not switch providers.

`lando shellenv` prints a profile snippet for the current shell. Use `--shell=powershell` in PowerShell or `--shell=posix` in a POSIX shell. A manually installed compiled binary adds its own directory when there is no install record. An installer-managed copy uses the verified directory from its install record. The profile commands above keep your chosen directory first on PATH.
