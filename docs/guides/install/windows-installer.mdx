# Install Lando on Windows

Install the Windows binary and run it as `lando` in PowerShell. WSL is optional.

## Run the installer

The PowerShell installer at `https://get.lando.dev/install.ps1` downloads `lando-windows-x64.exe`, verifies its signed checksum, installs it, and offers to run `lando setup`. It needs `cosign` on PATH for signature verification. Download the script and run it:

```powershell
Invoke-WebRequest https://get.lando.dev/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

If your execution policy blocks the script, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, or keep the `-ExecutionPolicy Bypass` form above.

The installer maps an AMD64 host to `windows-x64` and fails on any other architecture before downloading anything. On ARM64 Windows, download `lando-windows-arm64.exe` from the [GitHub release](./github-releases.mdx) and install it by hand.

The installer reads the channel manifest (`stable` by default; set `LANDO_CHANNEL=next` or `LANDO_CHANNEL=dev` for another channel), then downloads the binary, `SHA256SUMS`, `SHA256SUMS.sig`, and `SHA256SUMS.crt`. It verifies the keyless cosign signature against the release workflow identity, checks the binary against the verified manifest, and installs it at `$env:LANDO_INSTALL_DIR\lando.exe`, defaulting to `%LOCALAPPDATA%\Lando\Data\bin\lando.exe`. It refuses to replace a `lando.exe` it did not install unless the install record still matches the file on disk.

When it finishes, the installer prints the PowerShell commands that put the install directory on PATH for this session and in `$PROFILE`, then asks `Run lando.exe setup now? [y/N]`. Set `LANDO_INSTALL_RUN_SETUP=1` to run setup without the prompt or `LANDO_INSTALL_SKIP_SETUP=1` to skip it.

## Install by hand

1. Download `lando-windows-x64.exe` (or `lando-windows-arm64.exe` on ARM64) and `SHA256SUMS` from the same [GitHub release](https://github.com/AaronFeledy/core4/releases). Check the asset against `SHA256SUMS` as [Install from a GitHub release](./github-releases.mdx) describes before renaming the binary.
2. Follow [Put lando on PATH and run setup](./path-and-setup.mdx) to rename it to `lando.exe`, add its directory to PATH, and save the PATH entry in your PowerShell profile.

## Verify and set up

```powershell
Get-Command lando | Select-Object -ExpandProperty Source
lando --version
lando setup
lando doctor
```

`Get-Command` should point to the `lando.exe` you installed. If it points to an older installation, correct your PATH or remove an older `lando` alias from your PowerShell profile before continuing.

If setup reports a missing host prerequisite, follow its remediation and rerun `lando setup`. Include `lando doctor` output when you [report a bug](../../alpha-install-and-bug-reports.md#bug-report-checklist).

Do not pass `--provider=docker` to "get Windows working." The default provider is `lando` (managed Podman). `--yes` is consent, not a provider switch.
