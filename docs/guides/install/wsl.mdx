# Install Lando on WSL

Download `lando-linux-x64` (or `lando-linux-arm64` on ARM WSL) from a GitHub `v4.0.0-dev.N` prerelease and run it inside your WSL distro.

> **Alpha status:** WSL uses the Linux binary. Unsigned Windows `.exe` assets also exist on the same prerelease if you want a native Windows CLI. The POSIX installer at `https://get.lando.dev/install.sh` is not up yet. See [Alpha install and bug reports](../../alpha-install-and-bug-reports.md) for current install options.

## Download the Linux binary

Work inside the WSL distro shell, not a Windows prompt.

1. Open the [Releases page](https://github.com/AaronFeledy/core4/releases) and find the latest `v4.0.0-dev.N` prerelease.
2. Download `lando-linux-x64` (or `lando-linux-arm64`) and `SHA256SUMS`.
3. Verify the checksum:

```sh
sha256sum -c SHA256SUMS
```

The checksum command must report `OK` for the platform-qualified file you downloaded. If it does not, delete both files and download them again from the same prerelease.

4. Make it executable and put it on PATH:

```sh
chmod +x lando-linux-x64
```

Move that file into a directory already on PATH, or add its directory to PATH in your distro profile (`~/.bashrc` or `~/.zshrc`). Then verify:

```sh
lando --version
```

Once `lando` is on PATH, `lando shellenv` prints a profile snippet you can append so new shells keep it.

PATH is per distro. Installing in one WSL distro does not put `lando` on PATH in another distro or in Windows.

Prefer the GitHub release. If no dev prerelease exists yet, download the `lando-<platform>` artifact from a successful main CI run. That needs a GitHub login. Extract the zip and verify the binary yourself.

## Keep the app off /mnt/c

Never keep the app under `/mnt/c` or another Windows drive mount. WSL2 serves that path over 9P, so I/O is slow and permissions do not match what containers expect.

Keep the app on the Linux filesystem:

```
/home/<user>/code/my-app
```

Avoid this path:

```
/mnt/c/Users/<user>/code/my-app
```

Lando data on WSL uses Linux XDG paths. Data defaults to `$XDG_DATA_HOME/lando` (`~/.local/share/lando`). Config defaults to `$XDG_CONFIG_HOME/lando` (`~/.config/lando`).

## Run setup

```sh
lando setup
```

The default provider is `lando` (managed Podman). It does not need system Docker or Podman.

Default setup may fail on Alpha. Host prerequisites can block the managed runtime. If setup names a host prerequisite, fix it and rerun `lando setup`.

If the managed runtime still cannot install and you have working system Docker:

```sh
lando setup --provider=docker
```

After a successful `lando setup --provider=docker`, later `lando doctor` and `lando start` stay on Docker. You do not need to repeat the flag.

`LANDO_PROVIDER=docker lando setup` does not persist. If you only set the env, keep it for later commands.

`lando setup` and `lando setup --yes` ignore leftover `defaultProviderId` in user config. `--yes` consents to confirmation and privileged host changes. It does not switch providers.

Do not pass `--provider=podman` unless you already have system Podman and want that opt-in. Setup does not install Docker or Podman for you.

Lando starts Traefik when you start an app. You do not start Traefik by hand.

## Trust the CA in a Windows browser

`lando setup` runs `mkcert -install` inside the WSL distro. That trusts the root CA in the distro Linux trust store, not in Windows. A proxied HTTPS site opened from a Windows browser still shows a warning until you trust the same CA on Windows.

Print the CAROOT directory from inside the distro:

```sh
mkcert -CAROOT
```

`rootCA.pem` in that directory is the certificate to trust on Windows. Windows can read files in the distro through `\\wsl.localhost\<distro>`, so PowerShell can reach `rootCA.pem` without copying it first.

From an elevated PowerShell prompt:

```powershell
certutil -addstore -f "ROOT" rootCA.pem
```

Chrome and Edge trust the Windows store immediately. Firefox uses its own store, so import the same `rootCA.pem` in `about:preferences#privacy`.

You do not need a Windows Lando install for this CA step. Native Windows binaries are a separate install path.

## Verify

```sh
lando doctor
lando --version
```

Doctor should name the `lando` provider, or Docker if that is the last-used provider you set with `lando setup --provider=docker`.
