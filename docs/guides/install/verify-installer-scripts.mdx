# Verify the installer scripts

Each installer script is keyless-signed with cosign through the GitHub Actions release workflow. Verify a script before you run it when your policy does not allow piping a download into a shell.

## Published URLs

| Script | URL | Signature | Certificate |
| --- | --- | --- | --- |
| POSIX installer | `https://get.lando.dev/install.sh` | `https://get.lando.dev/install.sh.sig` | `https://get.lando.dev/install.sh.crt` |
| Windows installer | `https://get.lando.dev/install.ps1` | `https://get.lando.dev/install.ps1.sig` | `https://get.lando.dev/install.ps1.crt` |

## Verify a script

Download the script, its signature, and its certificate, then verify the blob against the release workflow identity:

```sh
curl -fsSLO https://get.lando.dev/install.sh
curl -fsSLO https://get.lando.dev/install.sh.sig
curl -fsSLO https://get.lando.dev/install.sh.crt
cosign verify-blob \
  --certificate-identity-regexp '^https://github.com/AaronFeledy/core4/.github/workflows/release.yml@refs/tags/.+$' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --signature install.sh.sig \
  --certificate install.sh.crt \
  install.sh
```

Replace `install.sh` with `install.ps1` to verify the Windows script. `cosign verify-blob` prints `Verified OK` when the signature matches. Run the verified file afterwards with `sh install.sh` or `powershell -ExecutionPolicy Bypass -File install.ps1`.

Each release's notes repeat these commands with the exact identity used for that tag. The same keyless signatures cover the release binaries; see [Install from a GitHub release](./github-releases.mdx).
