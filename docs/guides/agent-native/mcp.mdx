# Drive Lando through MCP

An MCP client starts `lando mcp` as a child process and owns its stdin and stdout
pipes. The server speaks MCP over newline-delimited JSON-RPC and runs until the
client closes stdin. Keep stdin open until every outstanding request id has
answered; closing early interrupts in-flight tool calls. Serve mode writes
protocol frames only; it does not wrap startup or shutdown in a Lando
command-result envelope.

Configure the MCP client to launch `lando mcp` with piped stdin and stdout.
Audit the effective catalog without starting the long-running server with
`lando mcp --list --format=json`.

```sh
lando mcp --list --format=json
```

Check that the catalog includes the tools you intend to expose before connecting
the client.

## Initialize the client

Lando negotiates MCP protocol versions `2025-06-18`, `2025-03-26`, and
`2024-11-05`. An `initialize` that offers `2025-06-18` gets `2025-06-18` back.
Write one complete JSON-RPC object followed by a newline for every request or
notification. An inbound frame over 1 MiB ends the session.

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"my-agent","version":"1.0.0"}}}
```

## Call a tool and read its result

Every tool in `tools/list` carries an `outputSchema`. A `tools/call` result has
`structuredContent` holding the redacted, bounded `CommandResultEnvelope` for the
command, plus the same JSON as a `text` content block for clients that ignore
structured output. `isError` is `true` whenever the envelope is not `ok`, so a
command's own tagged failure (for example `LandofileNotFoundError`) arrives as a
normal tool result you can read.

Rejections that never reach the command (bad input, `Server busy`, an
interrupted call) also come back as a tool result with `isError: true`; the
`text` block is the tagged error as JSON and there is no `structuredContent`.
A tool outside the effective allowlist is never registered, so calling it gets
the protocol's unknown-tool error, code `-32602`.

Send integer flags as JSON numbers without a fractional part. For example, the
`app:logs` tool declares `flags.tail` as `integer`:

```json
{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"app:logs","arguments":{"flags":{"tail":20}}}}
```

`20.5` and `"20"` are rejected with `McpToolInputError` naming `flags.tail`.
For tooling tasks, send positional arguments by name in `args`; Lando applies
their declared `order`, just as the CLI does. Hyphen-leading values stay positional.

Positions are resolved by `order` and never compacted. A trailing positional
with no value may be left out. Omit one that has no `default` while a later
positional has a value (sent by you or filled from its `default`) and the call
fails with `ToolingInputError`; `field` names the omitted argument and the
message reads `Positional argument <name> cannot be omitted because a later
positional argument has a value.` With a task declaring `label` at `order: 0`
and `channel` at `order: 1` with `default: stable`, this call fails on `label`:

```json
{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"app:tag","arguments":{"args":{"channel":"beta"}}}}
```

The tag, message, and `field` are byte-identical to what the CLI emits for the
same declaration and input.

## Confirm changes to an app

`app:rebuild` asks before it recreates containers. It is not in the default
allowlist; expose it with `--allow app:rebuild` or `mcp.allow`. `app:destroy`
stays forbidden unless you allowlist it explicitly the same way. Once exposed,
either command proceeds without a question when the call sends `flags.yes: true`.

Without `yes`, what happens depends on the client. A client that advertised the
`elicitation` capability in `initialize` gets an `elicitation/create` request
with a `{ confirm: boolean }` form; the message names the tool, the app's
directory, and what the command is about to do. Accept with `confirm: true` and the command runs.
Decline, cancel, answer `confirm: false`, or say nothing for 120 seconds and the
call returns `isError: true` with a `CommandConfirmationError` whose `reason` is
`declined`. A client without elicitation gets the same error with `reason`
`non-interactive`. Elicitation never lifts a deny: a tool outside the effective
allowlist is still unknown to the session.

```json
{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"app:rebuild","arguments":{"flags":{"yes":true}}}}
```

## Read resources and complete schema names

The server also publishes read-only resources. Each JSON payload reuses the
matching command result schema and is redacted and bounded the same way tool
results are.

| URI | What you get |
| --- | --- |
| `lando://app/config` | Resolved configuration for the app in the server's working directory |
| `lando://app/info` | Services and endpoints for that app |
| `lando://apps` | Known apps and their services |
| `lando://doctor` | Host-safe diagnostics, no fixes applied |
| `lando://schemas/{name}` | A public Lando JSON schema by name |

App-scoped resources resolve the app from the directory `lando mcp` was started
in and fail with the usual tagged errors when there is no app there. The
`lando://schemas/{name}` template supports `completion/complete`, so a client
can tab through the public schema registry instead of guessing names.

```json
{"jsonrpc":"2.0","id":7,"method":"completion/complete","params":{"ref":{"type":"ref/resource","uri":"lando://schemas/{name}"},"argument":{"name":"name","value":"CommandResult"}}}
```

The two read-only tools are `app:config:get`, which reads one resolved
configuration key (`args.key` is required), and `app:config:view`, which
reads the complete resolved Landofile. Umbrella and write-capable ids:
`app:config`, `app:config:set`, `app:config:unset`, `app:config:edit`,
`app:config:validate` are not MCP tools, even through explicit allow
configuration.

Protocol input and output stay bounded. An inbound frame, including one
still being read, is capped at 1 MiB. At most 256 unresolved tool calls are
retained; request 257 gets a tool result with `isError: true` whose text is
a `McpTransportError` reading `Server busy`, and it carries no
`structuredContent`. Each serialized JSON payload is capped at 8 MiB, and a
stdout write that does not finish fails after 5 seconds.
