# Change a Drupal stack after init

`lando init --recipe drupal` writes PHP 8.3, Apache, MariaDB 11.4, Composer 2, and webroot `/app/web`. Edit `.lando.yml` after that, then `lando rebuild -y`.

Init prompts for Drupal 10 or 11, PHP 8.1 through 8.5, Apache or nginx plus FPM, MariaDB, MySQL, or PostgreSQL, Composer, and webroot. `--yes` keeps Drupal 11, PHP 8.3, Apache, `mariadb:11.4`, Composer 2, and `/app/web`.

## See the generated defaults

The generated Landofile is an Apache-backed `appserver` on `php:8.3`, webroot `/app/web`, `allowOverride: true`, `composer: "2"`, a `database` service with `type: mariadb:11.4`, plus `drush` and `composer` tooling that call project-local `vendor/bin/drush` and `composer`.

## Pin PHP 8.1 through 8.4

Init already offers PHP 8.1 through 8.5. You can still edit `services.appserver.type` after the fact and rebuild.

```yaml
services:
  appserver:
    type: php:8.1
```

## Swap the database engine

The default `database` service is `type: mariadb:11.4`. Swap `type:` to another engine or pin an image. A rebuild does not migrate old data.

```yaml
services:
  database:
    type: mysql
    image: mysql:8.4
```

## Run two database services

Add a second database service and put it on the appserver `dependsOn` list.

```yaml
services:
  appserver:
    dependsOn:
      - database
      - database-legacy
  database:
    type: mariadb
  database-legacy:
    type: mysql
    image: mysql:8.0
```

## Set a Drush URI and move the webroot

The generated `drush` task has no `DRUSH_OPTIONS_URI`. Add it under `services.appserver.environment`. If you also move the webroot to `/app/docroot`, leave `tooling.drush.cmds` as `vendor/bin/drush`. Drush lives at the Composer project root, not under the webroot.

```yaml
services:
  appserver:
    webroot: /app/docroot
    environment:
      DRUSH_OPTIONS_URI: https://drupal-stack-overrides.lndo.site
```

## Bind-mount PHP and database config

There is no recipe shorthand for a custom `php.ini`. Compose `configs:` grants are realized as read-only binds. Bind-mount host files with `volumes:` remains a valid option.

```yaml
services:
  appserver:
    volumes:
      - ./config/custom-php.ini:/usr/local/etc/php/conf.d/zzz-custom.ini:ro
  database:
    volumes:
      - ./config/custom-mariadb.cnf:/etc/mysql/conf.d/zzz-custom.cnf:ro
```
