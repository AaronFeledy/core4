# Run the Symfony recipe

```sh
lando init --recipe symfony --name=symfony-demo --yes
cd symfony-demo
lando start
```

The named init creates `symfony-demo/` and writes only `.lando.yml` there. Change into it before app commands. `--yes` keeps PHP 8.4, PostgreSQL 16, Composer 2, and webroot `/app/public`. Apache is up after start. Drop a Symfony app in so `bin/console` exists.

Default PHP is 8.4, so `symfony new` / `symfony/skeleton` can install the current 8.x line. Pass `--answer=php=8.3` if you want the 7.4 LTS line.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.4`, `framework: symfony`, webroot `/app/public`, Composer `2`, Apache on port `80`, depends on `database` and `cache`, gets `DATABASE_URL` and `REDIS_URL` |
| `database` | `type: postgres:16` |
| `cache` | `type: redis` |
| Tooling | `lando console` (`php bin/console`) and `lando composer` on `appserver` |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Pass `--answer=database=mariadb:11.4` when you want MariaDB instead.

## Run console, Composer, and the clients

Composer will not install into a directory that already has `.lando.yml`:

```sh
lando composer create-project symfony/skeleton tmp-app --no-interaction
```

Move `tmp-app` up into the app root and keep `.lando.yml`. Then:

```sh
lando console --version
lando console about
lando composer --version
lando redis-cli ping
lando psql
```

`lando console` is `php bin/console` on `appserver`. Swap `symfony-demo` for your app name anywhere you pass the database name yourself.

## Connect Doctrine and Redis

`appserver` already has the connection strings:

| Variable | Postgres default | With `--answer=database=mariadb:11.4` |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://lando:<password>@database:5432/symfony-demo?serverVersion=16&charset=utf8` | `mysql://lando:lando@database:3306/symfony-demo?serverVersion=11.4.0-MariaDB&charset=utf8mb4` |
| `REDIS_URL` | `redis://cache:6379` | `redis://cache:6379` |

Doctrine reads `DATABASE_URL`, so the skeleton's `config/packages/doctrine.yaml` needs no edits and `lando console doctrine:database:create` connects first try. Symfony's Dotenv never overrides a real environment variable, so the injected value wins over whatever `.env` ships with. Leave the `DATABASE_URL` line in `.env` alone or delete it; either way `appserver` uses Lando's.

Do not paste the Postgres password into `.env.local`. The Landofile fills it from the database service's resolved credentials, so it follows an authored `creds:` block and survives a rebuild. `lando info` shows the user and database name and redacts the password; `lando exec appserver -- printenv DATABASE_URL` prints the whole thing.

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
