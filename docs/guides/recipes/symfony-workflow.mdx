# Run the Symfony recipe

```sh
lando init --recipe symfony --name=symfony-demo --yes
lando start
```

`--yes` is consent on init. It skips prompts. It is not a start flag.

The default provider is `lando` (managed Podman). First start builds `appserver`, `database`, and `cache`. Open the URL `lando info` prints when it finishes. If host ports 80 or 443 are already taken, that URL may use fallback ports such as `:8080` and `:8443`.

## See what the recipe writes

Init writes `.lando.yml`. It does not create a Symfony app tree. Drop your app into that directory (or create one with Composer) so `bin/console` exists at the app root.

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.3`, `framework: symfony`, webroot `/app/public`, Composer `2`, Apache on port `80`, depends on `database` and `cache` |
| `database` | `type: postgres:16` |
| `cache` | `type: redis` |
| Tooling | `lando console` (`php bin/console`) and `lando composer` against `appserver` |

Routes land on `{{ app.name }}.{{ proxy.defaultDomain }}` with both HTTP and HTTPS.

Pass `--answer` on init when you want a different PHP, database, Composer, or webroot (for example `--answer=database=mariadb:11.4`). Defaults above are what `--yes` alone writes.

## Run day-to-day tooling

After start, put a Symfony app in the app root. One path that works from an empty recipe directory on the default PHP 8.3 appserver:

```sh
lando composer create-project symfony/skeleton tmp-app --no-interaction
```

That resolves to Symfony **7.4** on PHP 8.3 (current `symfony/skeleton` 8.x wants PHP 8.4 or newer). Move `tmp-app` up into the app root and keep `.lando.yml`. Console without `bin/console` is just PHP yelling at you.

Then:

```sh
lando console --version
lando console about
lando composer --version
lando redis-cli ping
lando exec database -- psql -U lando -d symfony-demo -c 'SELECT version();'
```

`PONG` means Redis is awake. You can stop poking it.

Swap `symfony-demo` for your app name in that `psql` line.

## Connect Doctrine and Redis

Point the app at the services on the app network. Put host `database` and host `cache` in your Symfony `.env` (Doctrine `DATABASE_URL`, Redis DSN, or whatever your config reads):

| Setting | Postgres | Redis |
| --- | --- | --- |
| Host | `database` | `cache` |
| Database / DB | app name (here `symfony-demo`) | n/a |
| User | `lando` | n/a (no auth by default) |
| Password | from `lando info` (generated) | n/a |
| Port | `5432` | `6379` |

Read the Postgres password from `lando info`. Do not hardcode it.

## Destroy without surprises

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
