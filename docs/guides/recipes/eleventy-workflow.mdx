# Run the Eleventy recipe

Build an Eleventy site inside a Node service and preview it through Lando. Run these commands from your host terminal.

```sh
lando init --recipe eleventy --name=eleventy-demo --yes
cd eleventy-demo
lando start
```

`--yes` skips prompts. Eleventy declares no recipe options, so the only prompt is the app name. First start builds `builder` and `web`. If host ports 80 or 443 are already taken, `lando info` URLs may use fallback ports such as `:8080` and `:8443`.

Init writes a `package.json` that lists `@11ty/eleventy` as a dev dependency. When `builder` starts, it installs the project's dependencies and then runs the `start` script, `eleventy --serve --port 8080`. You don't install Eleventy yourself, and nothing is fetched through `npx`. The `builder` URL answers once that install finishes. Follow it with `lando logs --service builder`.

## Add a page, then build

Init does not create Eleventy templates. Add a single entry page (one input that maps to `_site/index.html`, not both `index.md` and `index.html`). First confirm the tooling:

```sh
lando npm --version
lando eleventy --version
lando eleventy --help
```

Write a tiny page, then build:

```sh
printf '%s\n' '# Hello from Eleventy on Lando' > index.md
lando eleventy
```

That writes `_site/index.html`. The `start` script already serves on `builder`, so open the `builder` URL `lando info` prints (for example `https://builder.eleventy-demo.lndo.site` or the same host with a fallback port). That development server provides live reload.

Once a build has written `_site/`, the app hostname URL (the **web** entry from `lando info`, for example `https://eleventy-demo.lndo.site`) serves it through nginx. `web` ships with `webroot: _site`, so there's nothing to configure. Keep editing against the **builder** URL for live reload; nginx picks up the next `lando eleventy` build.

Need a one-off rebuild while the development server keeps running? Use `lando eleventy`. It runs the Eleventy in your project's `node_modules` and never downloads one, so keep `@11ty/eleventy` in `package.json`.

## Change dependencies or the package manager

`builder` installs again each time its process starts, so a dependency you add to `package.json` arrives with the next `lando restart`. To install without restarting, run `lando npm install`.

The install and the `start` script both use the package manager `package.json` declares, and npm when it declares none. Add a `packageManager` entry for pnpm or Yarn and `builder` switches to it. See [Use your project's package manager](../services/node.mdx#use-your-projects-package-manager).

If the install fails, Eleventy never starts. `lando logs --service builder` shows the package manager's error. Fix it, then run `lando restart`.

## See what the recipe writes

Init writes `.lando.yml` and `package.json`. Add your templates beside them.

| Piece | What you get |
| --- | --- |
| `builder` | `node:lts`, port `8080`, command `[":node-install-run", "start"]`, which installs dependencies and then runs the `start` script |
| `web` | `static:nginx` serving `_site/` from the app mounted at `/app`, one route on both schemes |
| Tooling | `lando eleventy` on `builder`, which runs your project's installed `eleventy` binary. The `builder` service adds `lando npm` and `lando npx` |
| `package.json` | Private package with `@11ty/eleventy` as a dev dependency, `start` set to `eleventy --serve --port 8080`, and `build` set to `eleventy` |

`builder` is the day-to-day browse target while Eleventy serves. `web` is the nginx sidecar on the app hostname. Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS.

## Destroy without surprises

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
