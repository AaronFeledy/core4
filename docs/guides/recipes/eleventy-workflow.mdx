# Run the Eleventy recipe

```sh
lando init --recipe eleventy --name=eleventy-demo --yes
cd eleventy-demo
lando start
```

`--yes` skips prompts. Eleventy declares no recipe options, so the only prompt is the app name. First start builds `builder` and `web`. If host ports 80 or 443 are already taken, `lando info` URLs may use fallback ports such as `:8080` and `:8443`.

## See what the recipe writes

Init writes `.lando.yml` only. Put an Eleventy app in after start.

| Piece | What you get |
| --- | --- |
| `builder` | `node:lts`, port `8080`, command `npx @11ty/eleventy --serve --port 8080` |
| `web` | `static:nginx` with the app mounted at `/app` and one route on both schemes |
| Tooling | `lando eleventy` (`npx @11ty/eleventy`) and `lando npm` on `builder` |

`builder` is the day-to-day browse target while Eleventy serves. `web` is the nginx sidecar on the app hostname. Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS.

## Install Eleventy, then build

Init does not drop templates. Install into `builder`, then add a single entry page (one input that maps to `_site/index.html`, not both `index.md` and `index.html`):

```sh
lando npm init -y
lando npm install @11ty/eleventy
```

Confirm tooling:

```sh
lando npm --version
lando eleventy --version
lando eleventy --help
```

Write a tiny page, then build:

```sh
printf '%s\n' '# Hello from Eleventy on Lando' > index.md
lando eleventy
```

That writes `_site/index.html`. The recipe already runs `npx @11ty/eleventy --serve --port 8080` on `builder`, so open the `builder` URL `lando info` prints (for example `https://builder.eleventy-demo.lndo.site` or the same host with a fallback port). Live reload rides with that serve.

Prefer a one-shot rebuild without touching the long-running serve? `lando eleventy` is the same CLI via tooling.

## Destroy without surprises

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
