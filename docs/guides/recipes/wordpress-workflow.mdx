# Run the WordPress recipe

```sh
lando init --recipe wordpress --name=wp-demo --yes
cd wp-demo
lando start
```

The named init creates `wp-demo/` and writes only `.lando.yml` there. Change into it before app commands. `--yes` keeps PHP 8.4 and skips Redis. Start builds `appserver` with mysqli and checksum-verified WP-CLI, then brings up Apache and MariaDB. Confirm the tools below, then install WordPress.

If something else owns 80 or 443, Lando picks the next free port (usually `:8080` / `:8443`) and `lando info` shows it.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.4`, `framework: wordpress`, WP-CLI and mysqli, `memory_limit = 512M`, Apache on port `80`, depends on `database` (and `cache` with Redis) |
| `database` | `type: mariadb` (MariaDB 11.4) |
| `cache` (optional) | `type: redis` with `--answer=redis=true` |
| Tooling | `lando wp` and `lando composer` on `appserver`, `lando mariadb` from `database`, `lando redis-cli` when `cache` exists |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Pass `--answer=php=8.2` when you want PHP 8.2 instead.

## Confirm the tools

`framework: wordpress` installs pinned WP-CLI on stock PHP services and sets `WP_CLI_ALLOW_ROOT=1`, so `lando wp` works with Lando's root tooling user. It also writes `/usr/local/etc/php/conf.d/50-lando-wordpress.ini` with `memory_limit = 512M` for WP-CLI and web requests. Custom images supply their own tools and settings. Want a different limit? [Mount a later drop-in](../services/php-customization.mdx#mount-a-custom-phpini) such as `zz-custom.ini`.

```sh
lando wp --info
lando composer --version
lando mariadb -e 'SELECT 1 AS ok;'
```

## Download and install WordPress

```sh
lando wp core download
lando wp config create --dbname=wp-demo --dbuser=lando --dbpass=lando --dbhost=database --skip-check
```

Lando's proxy ends HTTPS and forwards plain HTTP to Apache, so WordPress can't tell the request was secure. Open `wp-config.php` and add this above the `That's all, stop editing!` line:

```php
if ( ( $_SERVER['HTTP_X_FORWARDED_PROTO'] ?? '' ) === 'https' ) {
    $_SERVER['HTTPS'] = 'on';
}
```

Skip it and the HTTPS page requests its CSS and JS over `http://`, which the browser blocks.

Leave `--admin_password` off. WP-CLI generates one and prints it once on an `Admin password:` line, so save it in your password manager.

```sh
lando wp core install \
  --url='https://wp-demo.lndo.site' \
  --title='WP Demo' \
  --admin_user=admin \
  --admin_email=admin@example.com \
  --skip-email
```

Match `--url` to the HTTPS endpoint `lando info` prints (add the port when info shows one). Then:

```sh
lando wp core is-installed
lando wp option get home
lando mariadb -e 'SHOW TABLES;'
```

Open the HTTPS URL. A fresh install serves the site title you passed to `core install`.

## Connect WordPress to MariaDB

| Setting | Value |
| --- | --- |
| Host | `database` |
| Database | app name (here `wp-demo`) |
| User | `lando` |
| Password | `lando` |
| Port | `3306` |

Put host `database` in `wp-config.php` (or in `config create --dbhost`). Do not use `127.0.0.1` or `localhost`. Root password is generated. `lando info` redacts it, and the `database` container holds it as `MARIADB_ROOT_PASSWORD` when you need it.

Add Redis at init with `--answer=redis=true`. That adds a `cache` service on `redis`. Wire an object cache plugin to host `cache` on port `6379` when you want it. Add `pecl install redis` and `docker-php-ext-enable redis` as root artifact steps if your object cache plugin needs the extension.

## Import a database

Import replaces what's in the app database, so snapshot it first:

```sh
lando db:snapshot --label before-import
lando db:import prod.sql.gz --yes
lando wp search-replace 'https://www.example.com' 'https://wp-demo.lndo.site' --all-tables --skip-columns=guid
lando wp cache flush
```

`.gz` dumps gunzip on the way in, and `--yes` skips the confirmation prompt. To roll back, find the `before-import` snapshot's id in `lando db:snapshots` and pass it to `lando db:restore`. `lando db:export` writes `database.sql.gz` when you want a dump of your own.

## Start from an existing site

Run init in the directory that holds `wp-config.php`. The `.` writes `.lando.yml` there instead of a new directory:

```sh
lando init . --recipe wordpress --name=my-site --yes
```

Add the HTTPS snippet from [Download and install WordPress](#download-and-install-wordpress) to `wp-config.php`. Then start, [confirm the tools](#confirm-the-tools), and point WordPress at MariaDB:

```sh
lando start
lando wp config set DB_HOST database
lando wp config set DB_NAME my-site
lando wp config set DB_USER lando
lando wp config set DB_PASSWORD lando
```

Bring your data over with [Import a database](#import-a-database), using `https://my-site.lndo.site` as the search-replace target.

## Catch outgoing mail

Add a Mailpit service to `.lando.yml`:

```yaml
services:
  mail:
    type: mailpit
```

Lando installs `msmtp` in `appserver` and points PHP's `sendmail_path` at it, so `wp_mail()` lands in Mailpit. Rebuild, send a test message, and get the inbox URL:

```sh
lando rebuild
lando wp eval 'var_dump( wp_mail( "you@example.test", "Mailpit check", "Hello" ) );'
lando info
```

Open the `mail` URL `lando info` prints.

## Debug with Xdebug

Add `xdebug: true` to `appserver`:

```yaml
services:
  appserver:
    xdebug: true
```

Rebuild so the extension lands in the image, then check it:

```sh
lando rebuild
lando xdebug status
```

Have your IDE listen on port `9003` and map `/app` to the project root. `lando xdebug off` and `lando xdebug on` toggle it without another rebuild.
