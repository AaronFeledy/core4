# Run the WordPress recipe

```sh
lando init --recipe wordpress --name=wp-demo --yes
cd wp-demo
lando start
```

The named init creates `wp-demo/` and writes only `.lando.yml` there. Change into it before app commands. `--yes` keeps PHP 8.3 and skips Redis. Apache and MariaDB are up after start. Drop WordPress into the app root so `index.php` exists, then open the URL `lando info` prints.

If something else owns 80 or 443, `lando info` shows `:8080` / `:8443`.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.3`, `framework: wordpress`, Apache on port `80`, depends on `database` |
| `database` | `type: mariadb` |
| `cache` (optional) | `type: redis` with `--answer=redis=true` |
| Tooling | `lando wp` and `lando composer` on `appserver`, plus `lando mariadb` from the database service |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Pass `--answer=php=8.2` when you want PHP 8.2 instead.

## Put WP-CLI and mysqli on appserver

Stock PHP images ship Composer and `pdo_mysql`. WordPress day-to-day also needs the `mysqli` extension and a `wp` binary on `appserver`. Add both as root `build.artifact` steps on `appserver`, then rebuild so they land in the image:

```yaml
services:
  appserver:
    build:
      artifact:
        - run: docker-php-ext-install mysqli
          user: root
        - run: >-
            set -eu;
            wp_cli="$(mktemp)";
            trap 'rm -f "$wp_cli"' EXIT;
            curl -fsSL -o "$wp_cli" https://github.com/wp-cli/wp-cli/releases/download/v2.12.0/wp-cli-2.12.0.phar;
            echo "ce34ddd838f7351d6759068d09793f26755463b4a4610a5a5c0a97b68220d85c  $wp_cli" | sha256sum -c -;
            install -m 0755 "$wp_cli" /usr/local/bin/wp
          user: root
```

This pins WP-CLI 2.12.0 and checks its published SHA-256 digest before `install` can write the binary. A mismatch fails the rebuild without installing the downloaded file.

Refresh the plan and rebuild:

```sh
lando app:cache:refresh
lando rebuild
```

`app:rebuild` has no `-y` flag. `lando restart` alone reuses the previous image. After rebuild, confirm the tools:

```sh
lando wp --allow-root --info
lando composer --version
lando mariadb -e 'SELECT 1 AS ok;'
```

WP-CLI runs as root inside tooling, so pass `--allow-root` on every `lando wp` invocation.

## Download and install WordPress

Core download wants more than the default 128M PHP memory limit. Raise it for that command, then generate an admin password locally. The generated value is not written to shell history, but it is printed once so you can save it in your password manager.

```sh
lando exec appserver -- php -d memory_limit=512M /usr/local/bin/wp --allow-root core download
lando wp --allow-root config create --dbname=wp-demo --dbuser=lando --dbpass=lando --dbhost=database --skip-check
WP_ADMIN_PASSWORD="$(openssl rand -base64 24)"
printf 'Save this WordPress admin password: %s\n' "$WP_ADMIN_PASSWORD"
lando wp --allow-root core install \
  --url='https://wp-demo.lndo.site' \
  --title='WP Demo' \
  --admin_user=admin \
  --admin_password="$WP_ADMIN_PASSWORD" \
  --admin_email=admin@example.com \
  --skip-email
unset WP_ADMIN_PASSWORD
```

Match `--url` to the HTTPS endpoint `lando info` prints (add the port when info shows one). Then:

```sh
lando wp --allow-root core is-installed
lando wp --allow-root option get home
lando composer --version
lando mariadb -e 'SHOW TABLES FROM `wp-demo`;'
```

Open the HTTPS URL. A fresh install serves the site title you passed to `core install`.

## Connect WordPress to MariaDB

| Setting | Value |
| --- | --- |
| Host | `database` |
| Database | app name (here `wp-demo`) |
| User | `lando` |
| Password | `lando` |
| Port | `3306` |

Put host `database` in `wp-config.php` (or in `config create --dbhost`). Do not use `127.0.0.1` or `localhost`. Root password is generated; you do not need it for the app user.

Add Redis at init with `--answer=redis=true`. That adds a `cache` service on `redis`. Wire an object cache plugin to host `cache` on port `6379` when you want it.

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
