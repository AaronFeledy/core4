# Change a LAMP stack after init

`lando init --recipe lamp` writes Apache, PHP 8.3, and MariaDB. Edit `.lando.yml` after that, then `lando rebuild -y`.

The recipe prompt is an app name and PHP `8.2` or `8.3` (default `8.3`). There is no prompt for the database engine, database version, Composer, or webroot.

## See the generated defaults

The generated Landofile is an Apache-backed `appserver` on `php:8.3` (or `8.2` if you chose it), `framework: none`, port `80`, a `database` service with `type: mariadb` and no version, plus `composer` and `php` tooling.

## Replace MariaDB with MySQL

Swap `type: mariadb` for `type: mysql` and pin the image. A rebuild does not migrate old data, so export first if you still need what's in there. See [Switch databases](../services/switching-databases.mdx).

```yaml
services:
  database:
    type: mysql
    image: mysql:8.4
```

## Run two database services

Add a second database service and put it on the appserver `dependsOn` list.

```yaml
services:
  appserver:
    dependsOn:
      - database
      - database-legacy
  database:
    type: mariadb
  database-legacy:
    type: mysql
    image: mysql:8.0
```

## Bind-mount PHP and database config

There is no recipe shorthand for a custom `php.ini`. The default `lando` provider cannot realize Compose `configs:`. Bind-mount host files with `volumes:` instead.

```yaml
services:
  appserver:
    volumes:
      - ./config/custom-php.ini:/usr/local/etc/php/conf.d/zzz-custom.ini:ro
  database:
    volumes:
      - ./config/custom-mariadb.cnf:/etc/mysql/conf.d/zzz-custom.cnf:ro
```

## Add a database client alias

The recipe already generates `composer` and `php` against `appserver`. Add a matching client against `database` so `lando <alias>` opens it.

| Database type | Client alias |
| --- | --- |
| `mariadb` | `lando mariadb` |
| `mysql` | `lando mysql` |
| `postgres` | `lando psql` |

```yaml
tooling:
  mariadb:
    service: database
    cmds:
      - mariadb
```
