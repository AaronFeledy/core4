# Run the Drupal contrib recipe

Develop a Drupal module, theme, or profile in its own git repository, with a
working Drupal site, tests, and linters around it. Lando keeps the Drupal site
in a volume at `/app` and mounts your checkout into it at
`web/<type>s/custom/<project>`, so Drupal core and `vendor/` never land in your
repository.

After setting up Lando, run these commands from the extension root on your host.
The root must contain exactly one `*.info.yml`. This guide uses a module named
`example` with `example.info.yml`. Substitute your extension's machine name.

```sh
lando init . --recipe drupal-contrib --name=example --yes --answer=project=example
lando start
lando drush status
```

The first `lando start` builds the Drupal site around your extension, which
takes a few minutes while Composer downloads Drupal. Later starts reuse it.
`lando drush status` reports the Drupal version once the site is ready.

`--yes` keeps Drupal `^11`, PHP 8.4, Apache, MariaDB 11.4, Composer 2, type
`module`, and machine name `example`. The machine name must match the root
info file. Pass `--answer=type=theme` or `--answer=type=profile` when that file
says so. The site's webroot is always `/app/web`.

## What the site contains

The site's `composer.json` lives in the volume, not in your repository. It
requires `drupal/core-recommended` and `drupal/core-dev` at the recipe's
`drupal` constraint, plus Drush and Drupal Coder. It also requires everything
in your extension's `require` and `require-dev`, with your constraints. Lando
doesn't install your extension as a Composer package: Drupal finds it at the
mounted path. Your extension's `composer.json` is never changed.

Point your IDE at the extension checkout.

## Run PHPUnit

Run tests from the extension root. Paths are relative to where you run the
command, the same as in your editor:

```sh
lando phpunit tests/src/Unit
lando phpunit --filter ExampleUnitTest tests/src/Unit
```

The task uses Drupal core's PHPUnit configuration and runs as `www-data`.
Kernel and browser tests use the recipe database. FunctionalJavascript tests
drive the `chrome` service. The recipe bakes in the Chrome service and
SIMPLETEST settings from
[Run Drupal tests with PHPUnit and headless Chrome](./drupal-testing.mdx), and
browser output goes under `/app/web/sites/simpletest`.

## Lint PHP

`lando phpcs`, `lando phpcbf`, and `lando phpstan` also run from your current
directory, so they read your extension's own `phpcs.xml.dist` and
`phpstan.neon.dist`, the same files drupal.org CI uses. With those files in the
extension root, run:

```sh
lando phpcs
lando phpstan analyse
```

Without a PHP_CodeSniffer config, name the standard and path:
`lando phpcs --standard=Drupal,DrupalPractice .`.

## Add a dependency to your extension

Add the package to your extension's `composer.json`, then sync the site. If
Composer isn't installed on your host, run it in `appserver` from the extension
root:

```sh
lando exec appserver -- composer require --no-update psr/clock:^1.0
lando drupal-contrib-sync
lando composer show psr/clock
```

`lando drupal-contrib-sync` brings the site in line with your `.lando.yml` and
your extension's `composer.json`. It adds, changes, and removes only the
requirements it manages. Packages already in the site's `composer.json` that it
didn't add, including ones you added with `lando composer`, keep their
constraint. When nothing changed, it reports that the site is up to date without
contacting Composer.

## Change the Drupal core constraint

Set `recipe.options.drupal` in `.lando.yml` to a Composer constraint, then sync:

```yaml
recipe:
  id: drupal-contrib
  options:
    drupal: "^10"
```

```sh
lando drupal-contrib-sync
lando composer show drupal/core-recommended
```

The sync moves `drupal/core-recommended` and `drupal/core-dev` to the new
constraint and updates the rest of the site with them, because Drush and the
test tools share Drupal's Symfony packages. `lando start` also syncs when the
constraint changed. This changes packages, not the database schema of an
installed site.

## Inspect the generated services

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.4`, `framework: drupal`, webroot `/app/web`, the `site` volume at `/app`, your checkout at `/app/web/<type>s/custom/<project>`, Composer `2`, Apache on port `80`, SIMPLETEST env, and a site sync on start; depends on `database` and `chrome` |
| `database` | `type: mariadb:11.4` |
| `chrome` | Selenium standalone Chromium for FunctionalJavascript tests |
| Site tooling | `lando drush`, `lando composer`, and `lando drupal-contrib-sync`, working directory `/app` |
| Extension tooling | `lando phpunit`, `lando phpcs`, `lando phpcbf`, and `lando phpstan`, working directory: wherever you run them |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Pass
`--answer=php=8.5`, `--answer=webserver=nginx`, `--answer=database=mysql:8.0`,
`--answer=database=postgres:16`, or `--answer='drupal=^10'` when you want those
instead. `--answer=php=8.6` uses the PHP 8.6 release-candidate image; Xdebug
isn't available there yet.

Nginx answers add an `edge` service in front of `appserver` (`via: fpm`) and
set `SIMPLETEST_BASE_URL` to `http://edge`. `edge` mounts the same `site`
volume read-only, so it serves the files the sync installs. Both webserver
choices set `uploadDirs: [sites/*/files]` on the service serving PHP.

Add a Node service if a theme build needs npm. See
[Compile PHP theme assets with Node](../services/node-theme-assets.mdx).

## Install Drupal

Install with Drush using the MariaDB credentials from `lando info`:

```sh
lando drush site:install standard \
  --db-url='mysql://lando:lando@database/example' \
  --site-name='Example' \
  --account-name=admin \
  --account-mail=admin@example.com \
  -y
```

Match the database name in `--db-url` to the app name. Use host `database`,
not `127.0.0.1`. For Postgres answers, use `pgsql://` and the password
`lando info` shows.

## Fix a failed sync

If `lando start` or `lando drupal-contrib-sync` reports a missing or mismatched
extension, check that the checkout has exactly one root `*.info.yml`. In
`.lando.yml`, set `recipe.options.project` to the filename without `.info.yml`
and `recipe.options.type` to the file's `type` (`module`, `theme`, or
`profile`). Keep the `recipe:` block, then move the mount and sync:

```sh
lando restart
lando drupal-contrib-sync
```

If Composer fails, for example because your extension requires a package that
conflicts with the Drupal core constraint, fix the requirement and run
`lando drupal-contrib-sync` again. A failed sync retries the same change, and an
interrupted first build resumes where it stopped.

## Destroy the app

This removes containers and networks. Add `--volumes` only if you also want to
delete the Drupal site and database. The extension checkout stays on the host.

```sh
lando destroy -y
```
