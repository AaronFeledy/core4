# Declare which commands a recipe may run

Put `runs` in `recipe.yml`. `ctx.run`, `postInit` `command` actions, and `choicesFrom` may use only those command ids.

```yaml
id: runs-allowlist
title: Runs allowlist
description: Recipe that may run git and composer.
version: 0.1.0
runs:
  - git
  - composer
```

When `runs` is present, any other id fails with `RecipeRunNotAllowedError` before a child process starts. The allowlist is exact ids, not globs.

## Leave `runs` off

If you omit `runs`, Lando uses a built-in default list of common VCS and language tools. Those ids run without a warning. Any other id warns and still runs. Add an explicit `runs` list when you want that warning gone, or when you want anything outside your list to fail closed.

One line of policy, then the recipe has to live with it. That is the point.

## Check the manifest

From the recipe directory (basename must match `id`):

```sh
lando meta recipes validate ./ --format=json
```

`valid` is `true` and `id` matches the directory name. The JSON envelope does not echo `runs`.
