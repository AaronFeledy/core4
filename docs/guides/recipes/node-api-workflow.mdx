# Run the Node API recipe

```sh
lando init --recipe node-api --name=node-api-demo --yes
cd node-api-demo
lando start
```

The named init creates `node-api-demo/` and writes only `.lando.yml` there. Change into it before app commands. `--yes` keeps Node `lts`, Express, and Postgres. First start brings `api` and `database` up. Until something listens on port `3000`, proxy URLs return HTTP 502. That is expected.

If something else owns 80 or 443, `lando info` shows `:8080` / `:8443`.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `api` | `node:lts` (or `node:22` with `--answer=node=22`), port `3000`, `API_FRAMEWORK` set to your framework pick, `DATABASE_URL` when Postgres is present |
| `database` | `type: postgres` by default; omitted with `--answer=database=none` |
| Tooling | `lando npm` and `lando node` on `api`; `lando psql` on `database` when Postgres is present |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Framework choices are `express`, `fastify`, and `hono`.

## Install the framework and serve it

Init does not drop an app scaffold. Initialize npm in the running `api` service, then install the framework you picked:

```sh
lando npm init -y
lando npm install express
```

Use `lando npm install fastify` for Fastify. Hono on Node also needs its server adapter:

```sh
lando npm install hono @hono/node-server
```

Add the matching `server.mjs` in the app root. Each version listens on `0.0.0.0:3000`, so the proxy can reach it.

### Serve with Express

```js
import express from "express";

const app = express();
const port = Number(process.env.PORT ?? 3000);

app.get("/", (_request, response) => response.send("Hello from Express!\n"));
app.listen(port, "0.0.0.0");
```

### Serve with Fastify

```js
import Fastify from "fastify";

const app = Fastify();
const port = Number(process.env.PORT ?? 3000);

app.get("/", async () => "Hello from Fastify!\n");
await app.listen({ port, host: "0.0.0.0" });
```

### Serve with Hono

```js
import { serve } from "@hono/node-server";
import { Hono } from "hono";

const app = new Hono();
const port = Number(process.env.PORT ?? 3000);

app.get("/", (context) => context.text("Hello from Hono!\n"));
serve({ fetch: app.fetch, port, hostname: "0.0.0.0" });
```

Delete the `# lando-generated:...` line at the top of `.lando.yml` so Lando stops managing that file, then point `api` at the entrypoint permanently:

```yaml
services:
  api:
    type: node:lts
    port: 3000
    command: node server.mjs
```

Then:

```sh
lando restart
lando info
```

Open the URL `lando info` prints. Prefer a one-shot serve without editing the Landofile?

```sh
lando node server.mjs
```

That binds port `3000` inside `api` until you stop it.

## Talk to Postgres

When you keep the default database, `api` already has `DATABASE_URL` set to `postgresql://lando:<password>@database:5432/node-api-demo`:

| Setting | Value |
| --- | --- |
| Host | `database` |
| Port | `5432` |
| Database | app name (here `node-api-demo`) |
| User | `lando` |
| Password | generated per app; filled into `DATABASE_URL` for you |

Install a client and hand it the URL:

```sh
lando npm install pg
```

```js
import pg from "pg";

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const { rows } = await pool.query("SELECT 1 AS ok");
```

Nothing in your code names the host or password. The Landofile fills `DATABASE_URL` from the database service's resolved credentials, so an authored `creds:` block and a rebuild both just work. With `--answer=database=none` there is no `database` service and no `DATABASE_URL`.

`lando info` lists the user and database name and redacts the password. `lando exec api -- printenv DATABASE_URL` masks the credentials in what it prints, `postgresql://[redacted]@database:5432/node-api-demo`. Your code inside `api` still gets the real value. Ping from tooling, no password needed:

```sh
lando psql -c 'SELECT 1'
```

## Pick Fastify, or skip Postgres with Hono

Fastify keeps the default Postgres service and sets `API_FRAMEWORK=fastify` on `api` (still port `3000`):

```sh
lando init --recipe node-api --name=node-api-fastify --yes \
  --answer=framework=fastify
```

Hono without Postgres drops the `database` service entirely and sets `API_FRAMEWORK=hono`:

```sh
lando init --recipe node-api --name=node-api-hono --yes \
  --answer=node=22 \
  --answer=framework=hono \
  --answer=database=none
```

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
