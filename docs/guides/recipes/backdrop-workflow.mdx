# Run the Backdrop recipe

```sh
lando init --recipe backdrop --name=backdrop-demo --yes
cd backdrop-demo
lando start
```

The named init creates `backdrop-demo/` and writes only `.lando.yml` there. Change into it before app commands. `--yes` keeps PHP 8.3, MariaDB 11.4, Composer 2, and webroot `/app`. Apache and MariaDB are up after start. Drop Backdrop into the app root so `index.php` exists, then open the URL `lando info` prints.

If something else owns 80 or 443, `lando info` shows `:8080` / `:8443`.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.3`, `framework: backdrop`, Apache on port `80`, depends on `database` |
| `database` | `type: mariadb:11.4` |
| Tooling | `lando bee`, `lando composer`, and `lando php` on `appserver`, plus `lando mariadb` from the database service |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. Pass `--answer=php=8.2` or `--answer=database=mysql:8.0` when you want those instead. PHP 8.6 is accepted (`--answer=php=8.6`) but runs a release-candidate image and has no Xdebug.

For the MySQL answer path, use `lando mysql` instead of `lando mariadb` for database commands.

`lando bee` runs the `bee` binary on `appserver`. That binary is not in the stock PHP image, so add it (below) before day-to-day Bee commands.

Init also sets `appserver.environment.BACKDROP_SETTINGS`, a JSON copy of the database credentials. Backdrop reads it from `$_SERVER`. PHP fills that from the container environment on the command line but not under Apache, so Bee sees the blob and the site doesn't. Put the credentials in `settings.local.php` (below) so both read the same file. On the command line the blob wins, so if you change the credentials, change or delete it too.

## Add Bee and mod_rewrite to appserver

Backdrop wants three things the stock PHP image doesn't give you: Apache's `mod_rewrite` for clean URLs (installed but off), Bee, and the `mysql` and `mysqldump` names Bee's `db-*` commands call. The MariaDB 11.4 client Lando installs on `appserver` (`db_client: auto`) names those `mariadb` and `mariadb-dump`. Add a root `build.artifact` step for each:

```yaml
services:
  appserver:
    build:
      artifact:
        - run: a2enmod rewrite
          user: root
        - run: ln -sf /usr/bin/mariadb /usr/local/bin/mysql && ln -sf /usr/bin/mariadb-dump /usr/local/bin/mysqldump
          user: root
        - run: curl -fsSL -o /usr/local/bin/bee https://github.com/backdrop-contrib/bee/releases/download/1.x-1.2.0/bee.phar && echo "9c7aaced21b0fe1e78bb34d8476e328b04da81beae4c422a065b483c1430937e  /usr/local/bin/bee" | sha256sum -c - && chmod 0755 /usr/local/bin/bee
          user: root
```

The last step pins Bee 1.x-1.2.0 and checks its published SHA-256 digest before `chmod`, so a bad download fails the rebuild instead of landing on `PATH`. On the MySQL answer, drop the `ln` step: `mysql-community-client` already ships `mysql` and `mysqldump`.

Rebuild, then check all three:

```sh
lando rebuild
lando exec appserver -- a2query -m rewrite
lando exec appserver -- mysqldump --version
lando bee version
```

`lando restart` keeps the old containers, so it won't pick these up. Step users and rebuild rules live in [Run build steps as root or as your app user](../services/build-steps.mdx).

## Download and install Backdrop

Pin a published full package and check the SHA-256 digest published with that release. This is Backdrop 1.35.1. A mismatch stops before anything lands in `/app`:

```sh
lando exec appserver -- sh -c 'set -eu; cd /tmp; rm -rf backdrop
  curl -fsSL -o backdrop.zip https://github.com/backdrop/backdrop/releases/download/1.35.1/backdrop.zip
  echo "7add8d49fdbfee6819cfb4866cd3501f5e06df8000e39652ecf896a2fa7a729c  backdrop.zip" | sha256sum -c -
  unzip -q backdrop.zip && cp -a backdrop/. /app/ && rm -rf backdrop backdrop.zip'
```

Put the Lando database credentials in `settings.local.php`, next to `settings.php` in the app root. Stock `settings.php` includes it, and Backdrop's `.gitignore` already skips it:

```php
<?php
$database = array(
  'database' => 'backdrop-demo',
  'username' => 'lando',
  'password' => 'lando',
  'host' => 'database',
);
```

Match `'database'` to the app name (here `backdrop-demo`). Then generate an admin password locally and install:

```sh
BACKDROP_ADMIN_PASSWORD="$(openssl rand -base64 24)"
printf 'Save this Backdrop admin password: %s\n' "$BACKDROP_ADMIN_PASSWORD"
lando bee install --auto \
  --db-name=backdrop-demo \
  --db-user=lando \
  --db-pass=lando \
  --db-host=database \
  --username=admin \
  --password="$BACKDROP_ADMIN_PASSWORD" \
  --email=admin@example.com \
  --site-name='Backdrop Demo'
unset BACKDROP_ADMIN_PASSWORD
```

`--auto` skips Bee's prompts and takes the defaults for anything you leave out. Bee still wants the `--db-*` flags, even though Backdrop connects through `settings.local.php`. The snippet assumes a POSIX shell with `openssl`. On Windows, generate the password however you like and pass it the same way.

Check the install:

```sh
lando bee status
lando mariadb -e 'SHOW TABLES;'
```

Apache runs as `www-data` and writes uploads and config under `files/`. Give it that directory:

```sh
lando exec appserver -- chown -R www-data:www-data /app/files
```

Bee runs as root, so if the site later can't write to `files/`, run that `chown` again. Open the HTTPS URL `lando info` prints. A fresh install serves the site name you passed to `install`.

## Connect Backdrop to MariaDB

| Setting | Value |
| --- | --- |
| Host | `database` |
| Database | app name (here `backdrop-demo`) |
| User | `lando` |
| Password | `lando` |
| Port | `3306` |

Use the service key `database`, not `127.0.0.1` or `localhost`. Root password is generated; you don't need it for the site.

## Work on an existing site

Init inside your checkout. The trailing `.` writes `.lando.yml` into the current directory and leaves your code alone:

```sh
cd my-backdrop-site
lando init --recipe backdrop --name=my-backdrop-site --yes .
lando start
```

Add the build steps above and the same `settings.local.php`, with `'database'` set to this app's name. Stock `settings.php` ends by including that file; add the include if yours doesn't. Keep it out of Git.

Copy the site's `files/` into the app root on your host, plus its active config directory if that lives outside `files/`. The app root is mounted at `/app`, so it shows up in `appserver` right away. Then load the database and hand `files/` to Apache:

```sh
lando db:import site.sql.gz --yes
lando bee cc all
lando exec appserver -- chown -R www-data:www-data /app/files
lando bee status
```

## Import and export the database

Export first: `db:import --yes` replaces whatever the database holds.

```sh
lando db:export backdrop.sql.gz
lando db:import backdrop.sql.gz --yes
lando bee cc all
```

`db:export` writes into your current directory. For a quick undo point, snapshot the database. `db:restore` replaces the data too, and it takes the id `db:snapshots` lists, not the label:

```sh
lando db:snapshot --label before-update
lando db:snapshots
lando db:restore <snapshot-id> --yes
```

Backdrop keeps active config as files, not in the database. Stock `settings.php` puts it under `files/config_<hash>/active`, where the hash comes from the `$database` array in `settings.php` itself. Credentials in `settings.local.php` don't move it. Dumps and snapshots don't carry it, so when you import another site's database, bring that site's active config directory to the path `$config_directories['active']` names. More flags: [Import and export app databases](../tooling/db-import-export.mdx).

## Log in with a one-time link

```sh
lando bee uli --base-url=https://backdrop-demo.lndo.site
```

Bee prints a one-time login link for the admin account. Match `--base-url` to the URL `lando info` prints, port included if the proxy fell back to `:8443`.

## Debug with Xdebug

Turn it on for `appserver`, then rebuild:

```yaml
services:
  appserver:
    xdebug: true
```

```sh
lando rebuild
lando xdebug status
```

Toggle it without another rebuild:

```sh
lando xdebug off
lando xdebug on
```

Point your IDE at port `9003` and map `/app` to the project root. Xdebug doesn't plan on `php:8.6`. IDE setup lives in [Debug PHP with Xdebug in PhpStorm](../tooling/xdebug-phpstorm.mdx).

## Catch outgoing mail

Add a Mailpit service, then rebuild. Every PHP service sends through it unless you set `mailFrom`, and Backdrop's default mail system calls PHP `mail()`, so password resets and contact forms land in its inbox:

```yaml
services:
  mail:
    type: mailpit
```

```sh
lando rebuild
lando exec appserver -- php -r 'mail("you@example.test", "Mailpit check", "Hello from Backdrop");'
lando info
```

Open the inbox URL `lando info` prints. Sender selection and ports live in [Add Mailpit](../services/mailpit.mdx).

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
