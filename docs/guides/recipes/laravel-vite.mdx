# Run Vite HMR with the Laravel recipe

`lando npm run dev` starts Vite inside the recipe's `node` service, but the browser can't reach it there. Give `node` a proxy route, point Laravel's Vite plugin at that hostname, and Blade edits reload the page.

Prerequisite: a running Laravel app from [Run the Laravel recipe](./laravel-workflow.mdx), with `lando npm install` done. Run the commands from the app directory on your host. The examples use app name `vite-demo`, the default `lndo.site` domain, and the stock skeleton that `composer create-project laravel/laravel` installs. Laravel 13 ships `laravel-vite-plugin` 3.x with Vite 8, and Laravel 12 ships plugin 2.x with Vite 7; the steps below work with either pair. Keep your installed plugin and Vite on compatible majors.

## Route the node service

The recipe writes `endpoints: []` on `node`, so it advertises nothing. In `.lando.yml`, replace the `node` service with this. Delete the `endpoints: []` line; a route needs an HTTP endpoint and `port: 5173` declares one. Then add `APP_URL` under `appserver`:

```yaml
services:
  appserver:
    environment:
      APP_URL: "{{ services.appserver.url }}"
  node:
    type: node:22
    primary: false
    port: 5173
    environment:
      APP_URL: "{{ services.appserver.url }}"
      VITE_DEV_SERVER_URL: "{{ services.node.url }}"
    routes:
      - hostname: "vite.{{ app.name }}.{{ proxy.defaultDomain }}"
        scheme: both
```

`{{ services.<name>.url }}` is the URL the router publishes for that service, the same one `lando info` prints, port included when the router isn't on 443. Lando fills it in when it creates the container. Laravel reads `APP_URL` on `appserver`. Vite runs in `node`, so `node` gets the app URL too, plus its own URL as `VITE_DEV_SERVER_URL`.

Keep the rest of the recipe's `appserver` block, including any `environment` keys it already has, and leave `database`, `cache`, and `tooling` as they are. If you leave `endpoints: []` in place, `lando app:config:lint` reports `Route vite.vite-demo.lndo.site for service node does not resolve to an HTTP endpoint.`

Apply it:

```sh
lando app:config:lint
lando start
lando info
```

`lando info` lists `https://vite.vite-demo.lndo.site` for `node`. Nothing answers there until Vite runs. `port: 5173` is the port inside the container, not a host port.

Check what the two services received:

```sh
lando exec appserver -- printenv APP_URL
lando exec node -- printenv VITE_DEV_SERVER_URL
```

On port 443, those print `https://vite-demo.lndo.site` and `https://vite.vite-demo.lndo.site`. If the router uses another port, both URLs include it, for example `:8443`. Use the printed URLs in the curl checks below. If the router later moves to another port, the next `lando start` recreates both services with the new URLs.

## Point Laravel at MariaDB and the proxy

Set these in `.env`. The recipe creates the database named after the app, with user and password `lando`, but does not inject Laravel's `DB_*` settings into `appserver`:

```dotenv
DB_CONNECTION=mariadb
DB_HOST=database
DB_PORT=3306
DB_DATABASE=vite-demo
DB_USERNAME=lando
DB_PASSWORD=lando
```

Clear any cached Laravel configuration, then create the session and cache tables the skeleton expects:

```sh
lando artisan config:clear
lando artisan migrate --no-interaction
```

Leave the `APP_URL` line that the skeleton's `.env` ships with. Laravel never lets `.env` replace a variable the container already has, so the value from `.lando.yml` wins. Vite treats `.env` the same way.

By default, `laravel-vite-plugin` allows cross-origin requests from `APP_URL`, loopback origins, and `*.test`. Because `node` receives `APP_URL` as the page's exact origin, the page can load modules from the Vite hostname. An explicit `server.cors` setting replaces those plugin defaults.

## Point Vite at the proxy

In `vite.config.js`, keep the skeleton's imports and `plugins` array as they are. Add the two `const` lines above `defineConfig` and replace only the `server` block:

```js
const devServer = new URL(process.env.VITE_DEV_SERVER_URL ?? 'http://localhost:5173');
const secure = devServer.protocol === 'https:';

export default defineConfig({
    // keep your existing plugins
    server: {
        host: '0.0.0.0',
        port: 5173,
        strictPort: true,
        allowedHosts: [devServer.hostname],
        hmr: {
            host: devServer.hostname,
            protocol: secure ? 'wss' : 'ws',
            clientPort: Number(devServer.port) || (secure ? 443 : 80),
        },
        watch: {
            ignored: ['**/storage/framework/views/**'],
        },
    },
});
```

Nothing here names your app or a port. The `localhost` fallback only keeps `npm run build` working where the variable isn't set, such as a deploy pipeline. `URL.port` is empty when the router is on the scheme's default port, so `clientPort` falls back to `443` or `80`. Keep `server.port` at `5173`; that's the port inside the container. Lando's proxy terminates HTTPS and forwards HTTP and WebSocket traffic to Node on `5173`, so Vite listens on `0.0.0.0` without `server.https`. `allowedHosts` lets Vite answer the proxy hostname, and `strictPort` stops Vite from drifting off the declared endpoint.

Leave `server.origin` unset. The plugin builds the URL it writes to `public/hot` from the `hmr` settings. Setting `server.origin` overrides that URL and, unless you also configure `server.cors`, replaces the entire default CORS origin list with that one origin.

Keep these settings under `hmr` for Laravel's plugin, which reads `hmr.host`, `hmr.protocol`, and `hmr.clientPort`. Vite 8 deprecates these WebSocket options in favor of `server.ws`, but still synchronizes them for compatibility.

## Run the dev server

```sh
lando npm run dev
```

Leave that running and wait for Vite's `ready` line and the `APP_URL` line from the Laravel plugin. In a second terminal:

```sh
cat public/hot
```

`public/hot` contains the Vite URL with an explicit port, `https://vite.vite-demo.lndo.site:443` when the router is on 443. Laravel's `@vite` directive reads that file over the shared `/app` mount. Reading it on the host checks the advertised URL, not whether the browser can reach Vite.

```sh
curl -fsS https://vite-demo.lndo.site/ | grep -o 'https://vite\.vite-demo\.lndo\.site:[0-9][0-9]*/[^"]*'
curl -fsS -o /dev/null https://vite.vite-demo.lndo.site/@vite/client
```

Check that the first command lists URLs ending in `/@vite/client`, `/resources/css/app.css`, and `/resources/js/app.js`, each with `:443` or the router's HTTPS port. That proves Laravel read `public/hot` and the page asks Vite for its assets. The second command exits 0 when the proxy reaches the running Vite server.

These host requests need both hostnames to resolve locally and your curl installation to trust Lando's CA. For DNS failures, see [Resolve lndo.site on this machine](../subsystems/host-dns.mdx). For certificate failures, see [Trust local HTTPS certificates](../subsystems/certificates-mkcert.mdx); curl may use a different CA bundle from your browser. Don't disable certificate verification to hide a trust failure.

On Linux with the default managed provider, PHP's project user maps app-file writes to your host user. If Laravel cannot write `storage` or `bootstrap/cache` on another platform or provider, see [Who owns your app files](../services/file-ownership.mdx), then retry the page request.

Open `https://vite-demo.lndo.site` in a browser. In developer tools, check for a WebSocket to `wss://vite.vite-demo.lndo.site` with status `101`. Then edit `resources/views/welcome.blade.php` and save; `refresh: true` reloads the page. If saves don't trigger a reload on your filesystem, add `usePolling: true` under `server.watch`; polling costs CPU.

Stop Vite with Ctrl+C in its terminal. The plugin deletes `public/hot` on a normal exit, including handled termination signals. Laravel then uses `public/build/manifest.json` if a build exists; otherwise, build the assets below. If an unhandled termination leaves `public/hot` behind, delete that stale file.

## Build and verify assets

With Vite stopped:

```sh
lando npm run build
curl -fsS https://vite-demo.lndo.site/ | grep -o 'https://vite-demo\.lndo\.site\(:[0-9][0-9]*\)\{0,1\}/build/assets/[^"]*'
```

Check that the page now loads hashed files from `/build/assets/` over `https`. The build writes `public/build/manifest.json` into the shared `/app`, so Apache serves it without a restart.
