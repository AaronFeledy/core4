# Run a TYPO3 site on the LAMP recipe

TYPO3 wants Composer, a `public/` webroot, working `.htaccess` rewrites, and a `fileadmin/` that never runs PHP. The LAMP recipe plus two typed keys covers all four. Run these commands from your host terminal.

```sh
lando init --recipe lamp --name=typo3-demo --answer=webroot=public --yes
cd typo3-demo
```

The named init creates `typo3-demo/` and writes only `.lando.yml` there. `--answer=webroot=public` points Apache at the directory TYPO3 serves. `--yes` keeps PHP 8.4, MariaDB 11.4, and Composer 2. TYPO3 14 needs PHP 8.2 or newer, so skip `--answer=php=8.1`.

## Add the TYPO3 pieces

Merge these keys into the generated `.lando.yml`. Keep its `recipe:` block: `webroot`, `type`, and `composer` read their values from it.

```yaml
services:
  appserver:
    allowOverride: true
    uploadDirs:
      - fileadmin
tooling:
  typo3:
    service: appserver
    user: www-data
    cmds:
      - php vendor/bin/typo3
    description: Run the TYPO3 CLI inside the appserver service.
```

- `allowOverride: true` lets Apache read the `public/.htaccess` TYPO3 writes, so page URLs rewrite to `index.php`.
- `uploadDirs` is relative to the webroot, so `fileadmin` covers `public/fileadmin`. A PHP request there gets Lando's 403 page instead of running.
- `lando typo3` runs the CLI as `www-data`, the user Apache runs as. Caches it writes stay writable by the site.

Then start the app:

```sh
lando app:config:lint
lando start
```

## Install TYPO3

Run the commands in this section from a POSIX shell on your host (WSL on Windows). The password step also needs `openssl`.

`create-project` wants an empty directory, and the app root already holds `.lando.yml`. Install into `tmp-app`, then copy it into the root:

```sh
lando composer create-project typo3/cms-base-distribution tmp-app "^14"
lando exec appserver -- sh -c "cp -a tmp-app/. . && rm -r tmp-app && chown -R $(id -u):$(id -g) /app"
```

Composer runs as root in the container. Your host shell expands `$(id -u):$(id -g)` before the command runs, so the final `chown` hands the code back to your host user. Your editor and host `lando` commands keep write access.

TYPO3's default password policy wants an uppercase letter, a lowercase letter, a digit, and a special character. Random base64 doesn't always include a special character, so the `Aa1-` prefix guarantees all four. Generate the admin password, then run setup:

```sh
TYPO3_ADMIN_PASSWORD="Aa1-$(openssl rand -base64 24)"
printf 'Save this TYPO3 admin password: %s\n' "$TYPO3_ADMIN_PASSWORD"
lando exec --user "$(id -u):$(id -g)" appserver -- php vendor/bin/typo3 setup \
  --driver=mysqli \
  --host=database \
  --port=3306 \
  --dbname=typo3-demo \
  --username=lando \
  --password=lando \
  --admin-username=admin \
  --admin-user-password="$TYPO3_ADMIN_PASSWORD" \
  --admin-email=admin@example.com \
  --project-name='TYPO3 Demo' \
  --create-site=https://typo3-demo.lndo.site/ \
  --server-type=apache \
  --force \
  -n
unset TYPO3_ADMIN_PASSWORD
```

Setup runs as your host user because it writes `config/` and `public/.htaccess` into your code. The password stays out of shell history, but it's on the command line, so process lists can see it while setup runs.

- `--dbname` matches the app name (here `typo3-demo`).
- `--create-site` takes a full URL. Use the HTTPS URL `lando info` prints, port included if the proxy picked a fallback.
- `--server-type=apache` writes `public/.htaccess`.

Give the web user only the directories TYPO3 writes to:

```sh
lando exec appserver -- chown -R www-data:www-data \
  /app/var /app/config/system /app/public/fileadmin /app/public/typo3temp
```

`config/system` is on the list because Admin Tools and `lando typo3 extension:setup` rewrite `settings.php`. Add `/app/config/sites` if you edit site configuration in the backend. Don't chown all of `/app` to `www-data`. Your code stays with your host user, so your editor and host `lando` commands keep write access.

On a Linux host the bind mount shares owners, so these directories also belong to uid `33` on the host. Edit files in `config/system` through `lando exec`, as the next section does for `additional.php`, or chown them back while you edit.

## Trust the Lando proxy

Lando's proxy serves HTTPS and forwards plain HTTP to Apache on port `80`. TYPO3 matches the request scheme against the site's `https://` base, and it ignores the proxy's `X-Forwarded-Proto` header until you trust the proxy. Until then, the front page answers "No site configuration found." Trust it from `config/system/additional.php`:

```sh
lando exec appserver -- sh -c 'cat > config/system/additional.php' <<'PHP'
<?php
$GLOBALS['TYPO3_CONF_VARS']['SYS']['reverseProxyIP'] = '*';
PHP
lando typo3 cache:flush
```

`*` trusts every client address, which is fine for a local Lando app. In production, list your real proxy IPs. The HTTP URL still returns TYPO3's 404 because the site base is `https://`. Use the HTTPS one.

Then confirm the day-to-day tools:

```sh
lando typo3 --version
lando typo3 site:list
lando composer --version
lando mariadb -e 'SELECT username FROM be_users;'
```

Open the HTTPS URL `lando info` prints. A fresh install serves the `Home` page setup created, with "Welcome to your default website".

## Open the backend

```sh
lando open --print
```

Add `/typo3/` to the URL it prints and sign in as `admin` with the password you saved.

## See what you built

| Piece | What you get |
| --- | --- |
| `appserver` | `php:8.4`, Apache on port `80`, webroot `public`, `.htaccess` on, PHP blocked in `fileadmin`, depends on `database` |
| `database` | `type: mariadb:11.4` |
| Tooling | `lando typo3` as `www-data`, `lando composer` and `lando php` on `appserver`, plus `lando mariadb` from the database service |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. On the `--answer=database=mysql:8.0` path, use `lando mysql` instead of `lando mariadb`.

Composer and `lando php` still run as root. After Composer adds or removes an extension, set it up and rebuild the caches as `www-data`:

```sh
lando composer require typo3/cms-redirects:"^14.3"
lando typo3 extension:setup
lando typo3 cache:flush
```

`extension:setup` creates the extension's tables. The flush clears cache files Composer's run left behind as root.

## Connect TYPO3 to MariaDB

| Setting | Value |
| --- | --- |
| Host | `database` |
| Database | app name (here `typo3-demo`) |
| User | `lando` |
| Password | `lando` |
| Port | `3306` |

Use the service key `database`, not `127.0.0.1` or `localhost`. Setup saved these in `config/system/settings.php`.

## Export and load the database

```sh
lando db:export typo3.sql.gz
```

`db:export` writes a gzipped dump into your current directory. To load a dump back, pipe it into the MariaDB client. It connects to the app's database, here `typo3-demo`:

```sh
gunzip -c typo3.sql.gz | lando mariadb
lando typo3 cache:flush
```

For a plain `.sql` file, use `lando mariadb < typo3.sql`. Run `lando typo3 cache:flush` after a load so TYPO3 stops serving pages built from the old data.

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
