# Declare which URLs a recipe may fetch

Put `fetchAllowlist` in `recipe.yml` next to the required `config` block to declare URL globs and validate the recipe. The current recipe factory context supplies `cwd` and `env`, not `ctx.fetch`. This declaration does not enable HTTP requests or sandbox trusted `recipe.ts` code.

```yaml
id: fetch-allowlist
title: Fetch allowlist
description: Recipe that may fetch from one API host.
version: 0.1.0
config:
  runtime: 4
  services:
    api:
      type: lando
      image: busybox:1.37
      command: sleep infinity
fetchAllowlist:
  - https://api.example.com/**
  - https://registry.lando.dev/recipes/*
```

`*` matches one path segment. `**` matches across segments. `https://api.example.com/**` matches any path on that host. `https://registry.lando.dev/recipes/*` matches one segment after `recipes/`, not a deeper path.

The example declares a policy; the validation command below does not contact either host. A successful validation is not evidence that a recipe fetch helper is available or that a request is allowed.

## Leave `fetchAllowlist` off

`fetchAllowlist` is optional. Omitting it does not change the current factory context or grant network access through Lando. Only run local TypeScript recipes you trust; see [Write a programmatic recipe](./programmatic-recipe.mdx) for the evaluation boundary.

## Check the manifest

From the recipe directory (basename must match `id`):

```sh
lando meta recipes validate ./ --format=json
```

`valid` is `true` and `id` matches the directory name. The JSON envelope does not echo `fetchAllowlist`.
