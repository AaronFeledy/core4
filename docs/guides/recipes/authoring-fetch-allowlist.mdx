# Declare which URLs a recipe may fetch

Put `fetchAllowlist` in `recipe.yml`. `ctx.fetch` may contact only those URL globs.

```yaml
id: fetch-allowlist
title: Fetch allowlist
description: Recipe that may fetch from one API host.
version: 0.1.0
fetchAllowlist:
  - https://api.example.com/**
  - https://registry.lando.dev/recipes/*
```

`*` matches one path segment. `**` matches across segments. `https://api.example.com/**` matches any path on that host. `https://registry.lando.dev/recipes/*` matches one segment after `recipes/`, not a deeper path.

A URL that misses every glob throws `RecipeFetchNotAllowedError` before the platform fetch runs. Redirects are checked the same way, including a relative `Location` resolved against the current URL.

## Leave `fetchAllowlist` off

`ctx.fetch` still runs. Lando warns once per URL that you have not declared the hosts the recipe contacts. Add the list when you want that warning gone, or when you want anything else to fail closed.

If a redirect walks off your list, that is still a deny. The allowlist is not a suggestion.

## Check the manifest

From the recipe directory (basename must match `id`):

```sh
lando meta recipes validate ./ --format=json
```

`valid` is `true` and `fetchAllowlist` lists the globs you wrote.
