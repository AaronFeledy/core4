# Recipes from remote sources

`lando init` can scaffold a recipe from git, a tarball, npm, or the Lando
recipe registry instead of a bundled recipe. Every remote source resolves
to recipe manifest parsing and prompt collection; rendering a non-bundled
recipe's files isn't implemented yet.

## Git

Clone a git repository as the recipe source, then read `recipe.yml` from
the clone root:

```sh
lando init --source=git --url=<git-url>
```

`--path=packages/my-recipe` selects an optional monorepo subdirectory;
`recipe.yml` must live at the top level of that subpath.

Git recipes are cached under the Lando user data root, keyed by the
resolved HEAD commit SHA: `<userDataRoot>/recipe-cache/git/<commitSha>/`.
The default cloner performs a shallow clone (`git clone --depth 1`), then
runs `git rev-parse HEAD` to pin the cache directory. If the commit
directory already exists, Lando discards the staging clone and reuses the
published cache entry.

Failure modes: `--source=git` requires `--url=<git-url>` (`missing-url`);
other `--source` values are rejected until their stories land
(`unsupported-source`); absolute paths and `..` escapes in `--path` are
rejected before cloning (`subpath-invalid`); a valid `--path` without
`recipe.yml` fails with git-specific remediation (`subpath-missing`);
interactive git credential prompts are disabled with
`GIT_TERMINAL_PROMPT=0` so auth failures fail fast (`auth`). All of these
surface as `RecipeSourceError` with the matching `kind`.
