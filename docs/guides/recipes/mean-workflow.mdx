# Run the MEAN recipe

Start the generated Express application with MongoDB. Run these commands from your host terminal; unlike recipes that only write a Landofile, this recipe includes application code.

```sh
lando init --recipe mean --name=mean-demo --yes
cd mean-demo
lando start
```

The named init creates `mean-demo/`. Change into it before app commands. `--yes` accepts initialization without prompts; it applies to `lando init`, not `lando start`.

When `api` starts, it installs the dependencies in `package.json` with npm and then runs the `start` script, `node server.js`, which serves the scaffold on port `3000`. `database` starts alongside it. That install runs each time the `api` process starts, so a dependency you add to `package.json` arrives with the next `lando restart`. If it fails, the server never starts and `lando logs --service api` shows the npm error. Open the URL `lando info` prints to see `Hello from Lando`. If host ports 80 or 443 are already taken, those URLs may use fallback ports such as `:8080` and `:8443`.

## See what the recipe writes

Init writes `.lando.yml`, `package.json`, and `server.js`. The Express scaffold listens on `PORT` and answers `GET /` with plain text.

| Piece | What you get |
| --- | --- |
| `api` | `node:lts` (or `node:22` when you pass `--answer=node=22`), port `3000`, command `[":node-install-run", "start"]`, `MONGO_URL` pointed at `database` |
| `database` | `type: mongodb` |
| `cache` (optional) | `type: redis` plus `REDIS_URL` when you pass `--answer=redis=true` |
| Tooling | `lando node` against `api`. The `api` service adds `lando npm` and `lando npx` |
| Scaffold | `package.json` with Express and a `start` script, `server.js` starter |

Routes land on `{{ app.name }}.{{ proxy.defaultDomain }}` with both HTTP and HTTPS.

## Run npm and Node tooling

Run npm and Node commands inside `api`:

```sh
lando npm --version
lando node --version
lando npm install mongodb
```

`lando npm install` adds the package right away, without waiting for a restart. The `start` script and the install both follow the package manager `package.json` declares, so a `packageManager` entry for pnpm or Yarn switches `api` to it. See [Use your project's package manager](../services/node.mdx#use-your-projects-package-manager).

## Talk to MongoDB

`MONGO_URL` on `api` already targets the app network:

| Setting | Value |
| --- | --- |
| Host | `database` |
| Port | `27017` |
| Database | app name (here `mean-demo`) |
| User | `lando` |
| Password | `lando` |
| Auth source | `admin` |

Ping from the database service:

```sh
lando exec database -- mongosh --quiet -u lando -p lando --authenticationDatabase admin --eval 'db.runCommand({ ping: 1 })'
```

Use `process.env.MONGO_URL` from Node. Do not hardcode credentials in app code you commit.

## Optional Redis

```sh
lando init --recipe mean --name=mean-redis --yes --answer=node=22 --answer=redis=true
```

That adds `cache` (`type: redis`) and sets `REDIS_URL=redis://cache:6379` on `api`.

## Destroy without surprises

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
