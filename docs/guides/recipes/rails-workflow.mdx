# Run the Rails recipe

```sh
lando init --recipe rails --name=rails-demo --yes
lando start
```

`--yes` is consent on init. It skips prompts. It is not a start flag.

The default provider is `lando` (managed Podman). First start builds `web` (installs `build-essential`, then `gem install rails`). That can take a minute. Open the URL `lando info` prints when it finishes.

## See what the recipe writes

Init writes `.lando.yml` plus a source-only `Gemfile` (`source "https://rubygems.org"`). The Rails gem itself comes from `build.artifact` on start, not from that Gemfile.

| Piece | What you get |
| --- | --- |
| `web` | `ruby:3.3`, `framework: rails`, port `3000`, depends on `database` and `cache` |
| `database` | `type: postgres` |
| `cache` | `type: redis` |
| Tooling | `lando rails` and `lando bundle` against `web`; `lando exec web -- rake` for rake |

Routes land on `{{ app.name }}.{{ proxy.defaultDomain }}` with both HTTP and HTTPS.

## Run day-to-day tooling

After start, Rails, Bundler, rake, Redis, and Postgres all run from the app:

```sh
lando rails --version
lando bundle --version
lando exec web -- rake --version
lando redis-cli ping
lando exec database -- psql -U lando -d rails-demo -c 'select 1'
```

`PONG` means Redis is awake. You can stop poking it.

First word after `exec` is the service. After you have a Rakefile, keep `lando exec web -- rake` for tasks. `lando rails` is the other door for Rails tasks.

Swap `rails-demo` for your app name in that `psql` line.

## Connect ActiveRecord and Redis

Point the app at the services on the app network:

| Setting | Postgres | Redis |
| --- | --- | --- |
| Host | `database` | `cache` |
| Database / DB | app name (here `rails-demo`) | n/a |
| User | `lando` | n/a (no auth by default) |
| Password | from `lando info` (generated) | n/a |
| Port | `5432` | `6379` |

Read the Postgres password from `lando info`. Do not hardcode it. Put host `database` in ActiveRecord and host `cache` in Redis.

## Destroy without surprises

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
