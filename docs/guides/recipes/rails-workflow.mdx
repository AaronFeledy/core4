# Run the Rails recipe

```sh
lando init --recipe rails --name=rails-demo --yes
cd rails-demo
lando start
```

The named init creates `rails-demo/`. Change into it before app commands. `--yes` skips the name prompt. First start builds `web`: `build-essential`, then `gem install rails`. That can take a minute. The `Gemfile` is just `source "https://rubygems.org"`. The Rails gem comes from that build step, not Bundler.

The `web` container stays up. The Rails server does not start on its own.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `web` | `ruby:3.3`, `framework: rails`, port `3000`, depends on `database` and `cache`, gets `DATABASE_URL` and `REDIS_URL` |
| `database` | `type: postgres` (image `postgres:16`) |
| `cache` | `type: redis` |
| Tooling | `lando rails`, `lando bundle`, and `lando rake` on `web` |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS.

## Run Rails, Bundler, Rake, and the clients

Put a Rails app in the directory (keep `.lando.yml`). Then:

```sh
lando rails --version
lando bundle --version
lando rake --version
lando redis-cli ping
lando psql
lando rails server -b 0.0.0.0
```

Bind `0.0.0.0` or the proxy cannot reach it. Then open the URL `lando info` prints.

`lando rake db:migrate` runs Rake on `web`. Swap `rails-demo` for your app name anywhere you pass the database name yourself.

## Connect ActiveRecord and Redis

`web` already has the connection strings:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | `postgresql://lando:<password>@database:5432/rails-demo` |
| `REDIS_URL` | `redis://cache:6379` |

ActiveRecord reads `DATABASE_URL` on its own, so `config/database.yml` can stay at the generator default and `lando rake db:create db:migrate` just works. Point your Redis client at `ENV["REDIS_URL"]`. Do not paste the password into `database.yml` or a committed `.env`; the Landofile fills it from the database service's resolved credentials, so it follows an authored `creds:` block and survives a rebuild.

`lando info` shows the user and database name and redacts the password. Inside `web`, `lando exec web -- printenv DATABASE_URL` prints the whole thing.

## Tear down

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
