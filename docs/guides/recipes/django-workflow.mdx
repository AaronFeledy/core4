# Run the Django recipe

```sh
lando init --recipe django --name=django-demo --yes
cd django-demo
lando start
```

`--yes` keeps Celery off. The named init creates `django-demo/` and writes only `.lando.yml` there. Change into that directory before app commands. Start brings up Python, Postgres, and Redis. Drop a Django project in so `manage.py` exists, then serve it.

If something else owns 80 or 443, `lando info` shows `:8080` / `:8443`.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `web` | `python:3.12`, `framework: django`, port `8000`, depends on `database` and `cache`, gets `DATABASE_URL` and `REDIS_URL` |
| `database` | `type: postgres` |
| `cache` | `type: redis` |
| `worker` (optional) | `python:3.12`, `framework: django`, `command: celery -A app worker --loglevel=info` with `--answer=celery=true`; same `DATABASE_URL` and `REDIS_URL` |
| Tooling | `lando django` (`python manage.py`) and `lando pip` on `web` |

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. `framework: django` sets `DJANGO_SETTINGS_MODULE=config.settings` on `web`.

## Scaffold Django with pip and django-admin

Install Django into the running `web` service, then create the project in the app root (`.lando.yml` can already be there):

```sh
lando pip install 'Django>=5,<6' 'psycopg[binary]>=3'
lando exec web -- django-admin startproject config .
```

Pin what you installed for the next rebuild:

```sh
lando exec web -- pip freeze > requirements.txt
```

Then the day-to-day tools work:

```sh
lando django --version
lando django check
lando pip --version
lando redis-cli ping
lando psql -c 'SELECT 1'
```

Add a Celery worker at init with `--answer=celery=true`:

```sh
lando init --recipe django --name=django-celery --yes --answer=celery=true
```

That service runs `celery -A app worker --loglevel=info`. Point Celery at your real app module before you start it.

## Connect Django to Postgres and Redis

`web` (and `worker`, when you asked for Celery) already has the connection strings:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | `postgresql://lando:<password>@database:5432/django-demo` |
| `REDIS_URL` | `redis://cache:6379` |

Django does not read `DATABASE_URL` by itself. Install `dj-database-url` and let it parse the value:

```sh
lando pip install dj-database-url
```

```python
import os
import dj_database_url

DATABASES = {"default": dj_database_url.config()}
CELERY_BROKER_URL = os.environ["REDIS_URL"]
```

Prefer no extra dependency? Split `os.environ["DATABASE_URL"]` with `urllib.parse.urlparse` and fill `DATABASES["default"]` from the parts. Either way, nothing in `settings.py` names host, user, or password, and the Landofile fills them from the database service's resolved credentials, so an authored `creds:` block and a rebuild both just work.

`lando info` lists the user and database name and redacts the password. `lando exec web -- printenv DATABASE_URL` masks the credentials in what it prints, `postgresql://[redacted]@database:5432/django-demo`. Django inside `web` still reads the real value.

Also set `ALLOWED_HOSTS` so the proxy hostname is accepted (for a local demo, `ALLOWED_HOSTS = ['*']` is fine).

```sh
lando django migrate --noinput
lando django runserver 0.0.0.0:8000
```

Bind `0.0.0.0` so Traefik can reach the process. Then open the URL from `lando info`.

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
