# Run the Django recipe

Create a Python, Postgres, and Redis environment, then add and serve a Django project. Run the commands from your host terminal.

```sh
lando init --recipe django --name=django-demo --yes
cd django-demo
lando start
```

`--yes` keeps Celery off. The named init creates `django-demo/` and writes only `.lando.yml` there. Change into that directory before app commands. Start brings up Python, Postgres, and Redis. The web container stays up without starting Django. Drop a Django project in so `manage.py` exists, then serve it.

If something else owns 80 or 443, `lando info` shows `:8080` / `:8443`.

## Scaffold Django with pip and django-admin

Install Django into the running `web` service, then create the project in the app root (`.lando.yml` can already be there):

```sh
lando pip install 'Django>=5,<6' 'psycopg[binary]>=3'
lando exec web -- django-admin startproject config .
```

`lando pip` installs into `/app/.venv`, the [dependency environment](../services/python.mdx) shared by `web` and the optional `worker`. Save the project-installed versions so Lando can install them on another checkout:

```sh
lando pip freeze --local > requirements.txt
```

On a fresh clone, run `lando start`. If you edit `requirements.txt` while the app is running, run `lando restart`.

Check that Django and the database clients are available:

```sh
lando django --version
lando django check
lando pip --version
lando redis-cli ping
lando psql -c 'SELECT 1'
```

## Run Celery against Redis

Add a Celery worker at init with `--answer=celery=true`:

```sh
lando init --recipe django --name=django-celery --yes --answer=celery=true
```

From the generated app directory, run `lando start`. It succeeds and warns that the worker is restarting if you haven't installed Celery or configured `config.celery` yet. The `web` service is available for the install.

Add `celery[redis]` to `requirements.txt` alongside Django (and `psycopg[binary]` for Postgres), then run `lando restart` to install them. If this is a new project, create `config` with `lando exec web -- django-admin startproject config .`.

Create `config/celery.py`:

```python
from celery import Celery

app = Celery("config")
app.config_from_object("django.conf:settings", namespace="CELERY")
app.autodiscover_tasks()
```

Add this to `config/__init__.py`:

```python
from .celery import app as celery_app
```

In `config/settings.py`, use the recipe's Redis URL as the broker:

```python
import os

CELERY_BROKER_URL = os.environ["REDIS_URL"]
```

The worker runs `celery -A config worker --loglevel=info` and retries on its own until the app and packages are ready. Check `lando logs --service=worker` for `ready`. After changing code or dependencies, run `lando restart -s worker` to reload the worker without restarting the database or web service.

## Connect Django to Postgres and Redis

`web` (and `worker`, when you asked for Celery) already has the connection strings:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | `postgresql://lando:<password>@database:5432/django-demo` |
| `REDIS_URL` | `redis://cache:6379` |

Django does not read `DATABASE_URL` by itself. Install `dj-database-url` and let it parse the value:

```sh
lando pip install dj-database-url
```

```python
import os
import dj_database_url

DATABASES = {"default": dj_database_url.config()}
CELERY_BROKER_URL = os.environ["REDIS_URL"]
```

Prefer no extra dependency? Split `os.environ["DATABASE_URL"]` with `urllib.parse.urlparse` and fill `DATABASES["default"]` from the parts. Either way, nothing in `settings.py` names host, user, or password, and the Landofile fills them from the database service's resolved credentials, so the application uses the credentials resolved from your `creds:` block after a rebuild.

`lando info` lists the user and database name and redacts the password. `lando exec web -- printenv DATABASE_URL` masks the credentials in what it prints, `postgresql://[redacted]@database:5432/django-demo`. Django inside `web` still reads the real value.

Django also rejects requests for hostnames it doesn't know. Pass it the hostname Lando publishes for `web`. Add this line to the `environment` block under `services.web` in `.lando.yml`:

```yaml
DJANGO_ALLOWED_HOSTS: "{{ service.hostname }}"
```

Then read it in `config/settings.py`:

```python
ALLOWED_HOSTS = [os.environ["DJANGO_ALLOWED_HOSTS"]]
```

Lando fills in the value when it creates the container, so run `lando start` to apply it. The hostname follows the app's route, and Django still rejects every other host. See [Read a service's public URL](../landofile/expressions.mdx#read-a-services-public-url).

```sh
lando django migrate --noinput
lando django runserver 0.0.0.0:8000
```

Bind `0.0.0.0` so Traefik can reach the process. Then open the URL from `lando info`.

## Use SQLite

Create a new SQLite app from the parent directory:

```sh
lando init --recipe django --name=django-sqlite --answer=database=sqlite --yes
cd django-sqlite
lando app:config:lint
```

Start the app, install Django and `dj-database-url`, and create the project with
`django-admin startproject config .` as above. SQLite needs no `psycopg` or
PostgreSQL client, so skip those client checks. Keep the `dj_database_url.config()` settings above:
`web` and the optional Celery worker receive `sqlite:////app/db.sqlite3`, an
absolute URL for `/app/db.sqlite3`. The app mount is `/app`;
`config/settings.py` resolves `BASE_DIR` to that root. Lando declares
`sqlite.path: db.sqlite3` on `web` and omits the database service.

After `lando django migrate --noinput` creates the file, export, import, and
snapshot it from the app directory. **Import replaces the database's contents
with the backup.**

```sh
lando db:export backup.sql.gz
lando db:import backup.sql.gz --yes
lando db:snapshot
```

See [Manage a SQLite file database](../tooling/sqlite-database.mdx) for file
backups and restore behavior.

## See what the recipe writes

| Piece | What you get |
| --- | --- |
| `web` | `python:3.12`, `framework: django`, port `8000`, depends on `database` and `cache`, gets `DATABASE_URL` and `REDIS_URL` |
| `database` | `type: postgres` |
| `cache` | `type: redis` |
| `worker` (optional) | `python:3.12`, `framework: django`, `command: exec celery -A config worker --loglevel=info` and `endpoints: []` (no route) with `--answer=celery=true`; shares `python-env`, `DATABASE_URL`, and `REDIS_URL` with `web` |
| Tooling | `lando django` (`python manage.py`) and `lando pip` (`python -m pip`) on `web` |

The Landofile writes `DJANGO_SETTINGS_MODULE: config.settings` into `environment` on `web` and the optional `worker`. Edit those fields if your project uses a different settings module. Port `8000` is also editable on `web`; keep your server bind in sync.

Routes use `{{ app.name }}.{{ proxy.defaultDomain }}` on HTTP and HTTPS. They reach Django only after you start its server.

## Destroy the app

```sh
lando destroy -y
```

That removes containers and networks. Volumes stay unless you pass `--volumes` or `--purge`.
