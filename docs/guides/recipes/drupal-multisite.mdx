# Run Drupal multisite on one appserver

The `drupal` recipe scaffolds one PHP appserver and one database. To run several sites, add routes, per-site `settings.php`, and Drush URI aliases to that generated Landofile.

Start with a running Drupal app and project-local Drush, as described in [Run the Drupal recipe](./drupal-workflow.mdx). Before installing the sites below, have a database administrator create the `site1` and `site2` databases and grant your chosen Drupal account access to both. The default MariaDB app account has access only to the initial app database; it cannot provision this multisite setup on its own.

Every site still shares the same appserver, PHP version, webroot, and database service. Multisite splits the Drupal document root and config, not the containers.

## Route one hostname per site

In `.lando.yml`, add one `routes:` entry per hostname under `services.appserver`. Every hostname reaches the same appserver.

```yaml
services:
  appserver:
    type: php:8.3
    webroot: web
    allowOverride: true
    routes:
      - hostname: site1.lndo.site
      - hostname: site2.lndo.site
```

Confirm the list with `lando app:config --format=json` before you start the app.

## Write per-site settings.php

Create or edit `web/sites/sites.php` in your app root to map your Lando hostnames:

```php
<?php
$sites['site1.lndo.site'] = 'site1';
$sites['site2.lndo.site'] = 'site2';
```

Create `web/sites/site1/settings.php` with the connection settings for `site1`, then create the corresponding file for `site2`. Both use the shared `database` service. The examples use a separately provisioned account named `drupal` with password `drupal`; these are example values, not the recipe defaults. Replace them in each settings file and in the install commands with the account your administrator configured:

```php
<?php
$databases['default']['default'] = [
  'driver' => 'mysql',
  'host' => 'database',
  'database' => 'site1',
  'username' => 'drupal',
  'password' => 'drupal',
  'prefix' => '',
];
```

The stock `mariadb` service provisions one database named after the app. It provides `lando mariadb`, not a `lando mysql` alias. The additional databases and account grants are prerequisites for the installers below; confirm they are in place before continuing.

## Add Drush URI aliases

Drush needs `--uri` because every site bootstraps on the same appserver. Bake the URI into one tooling task per site:

```yaml
tooling:
  drush-site1:
    service: appserver
    cmd:
      - vendor/bin/drush
      - --uri=https://site1.lndo.site
  drush-site2:
    service: appserver
    cmd:
      - vendor/bin/drush
      - --uri=https://site2.lndo.site
```

Each task supplies its site URI, so you do not need to repeat `--uri`.

## Install each site

Run `lando start` to apply the routes. Lando starts the proxy and issues certificates for each route. After confirming both databases and their account grants, install each site:

```sh
lando drush-site1 site-install standard --db-url=mysql://drupal:drupal@database/site1 -y
lando drush-site2 site-install standard --db-url=mysql://drupal:drupal@database/site2 -y
```

Check both installed sites:

```sh
lando drush-site1 status
lando drush-site2 status
```

Open each hostname:

- `https://site1.lndo.site`
- `https://site2.lndo.site`

## Know the shared-stack limits

One appserver means one PHP version, one `webroot`, one `allowOverride`, and one set of PHP extensions. You cannot run one site on a different PHP version than its neighbors.

The database is shared too. Per-site schemas live on the same `mariadb` instance, so a schema-level backup of one site still hits the server every other site depends on.
