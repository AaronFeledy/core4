# Extend a bundled recipe

Put `extends: lamp` in a child `recipe.yml`, then inspect the flattened result with `lando meta recipes describe ./`.

You ship the deltas. Lando walks the parent chain, merges prompts, files, and `postInit`, and hands every later command a single recipe. Pass `./` or `recipe.yml`. A bare `.` is not a local recipe path.

## Write the child recipe.yml

The directory basename must match `id`. This child sits on bundled `lamp`, drops the app-name prompt, overrides PHP, and adds one extra file:

```yaml
id: lamp-child
title: Lamp Child
description: Extends lamp with one prompt override and a dropped prompt.
version: 0.1.0
extends: lamp
prompts:
  - name: name
    drop: true
  - name: php
    type: select
    message: PHP version
    default: "8.2"
    choices:
      - value: "8.2"
      - value: "8.3"
files:
  - src: extra.txt
    dest: extra.txt
postInit:
  - type: gitInit
```

Keep `extra.txt` next to `recipe.yml` so the `files:` entry is real.

Merge is name-keyed, not "last array wins":

- Prompts merge by `name`. A child prompt with the same name replaces the parent. `drop: true` removes that parent prompt.
- Files merge by `dest`. The child dest wins.
- `postInit` is parent actions, then child actions.
- Scalar fields (`title`, `description`, `version`, and the rest) come from the child when set.

A missing parent or a cycle fails with `RecipeExtendsError` before validate can say the file is fine.

These commands read `recipe.yml`. There is no `recipe.ts` describe or validate path.

## Describe the flattened recipe

From the child directory:

```sh
lando meta recipes describe ./ --format=json
```

You should see `lamp-child` and the overridden `php` prompt. The dropped `name` prompt is gone.

## Validate the child

```sh
lando meta recipes validate ./ --format=json
```

`valid` is `true` and `id` is `lamp-child` when the parent resolves.
