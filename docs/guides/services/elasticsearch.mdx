# Add Elasticsearch

Add `type: elasticsearch` under `services` in `.lando.yml`. Lando pulls `docker.elastic.co/elasticsearch/elasticsearch:8.17.0` and listens on `9200`:

```yaml
name: elasticsearch-demo
services:
  search:
    type: elasticsearch
tooling:
  es-cli:
    service: search
    cmd:
      - sh
      - -c
      - 'test -n "$1" || set -- /; curl -sf -- "http://localhost:9200$1"'
      - es-cli
```

The default config sets `discovery.type: single-node` for local dev and disables `xpack.security.enabled`. That's convenient locally, not production-suitable. The default image is licensed under the Elastic License v2. Reach for OpenSearch when you need Apache 2.0 licensing.

## Check cluster health

The Landofile above declares `es-cli` as an app tooling alias. Query cluster health once the service is up:

```sh
lando es-cli /_cluster/health
```

A healthy single-node Elasticsearch reports `green` or `yellow`.

## List indices

```sh
lando es-cli /_cat/indices
```

## Pin a version

Set `image:` when the default Elasticsearch 8 image isn't the version you want:

```yaml
services:
  search:
    type: elasticsearch
    image: docker.elastic.co/elasticsearch/elasticsearch:7.17.0
```

## Change the HTTP port

Set `port:` to move the HTTP API, healthcheck, and endpoint together. Lando sets `http.port` from that value:

```yaml
services:
  search:
    type: elasticsearch
    port: 9201
```

The transport listener stays on `9300` by default. Move it with a scalar `transport.port` under `environment:` when HTTP needs that number:

```yaml
services:
  search:
    type: elasticsearch
    port: 9300
    environment:
      transport.port: "9301"
```

HTTP cannot equal the effective transport port. Planning fails when they collide.
Use one integer from `1` to `65535` for `transport.port`; ranges and malformed
values fail planning at `services.<name>.environment["transport.port"]`.
An authored `http.port` must match `port:`, or planning fails at that environment
key. Lando never appends flags to an authored `command:` or `entrypoint:`.

Validate with `lando app:cache:refresh --format=json` before start.

## Keep security off only for local dev

`xpack.security.enabled=false` is meant for local development. Production deployments must enable security and configure TLS.
