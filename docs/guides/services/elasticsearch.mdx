# Elasticsearch

Add Elasticsearch to your app by declaring `type: elasticsearch` in your
services block. Lando pulls `docker.elastic.co/elasticsearch/elasticsearch:8.17.0`
by default and listens on port `9200`:

```yaml
name: elasticsearch-demo
services:
  search:
    type: elasticsearch
tooling:
  es-cli:
    service: search
    cmd:
      - sh
      - -c
      - 'path=${1:-/}; curl -sf -- "http://localhost:9200${path}"'
      - es-cli
```

The default config sets `discovery.type: single-node` for local dev and
disables `xpack.security.enabled` — that's convenient locally but not
production-suitable. The default image is licensed under the Elastic License
v2; reach for OpenSearch instead when you need Apache 2.0 licensing.

## Check cluster health

The fixture above declares `es-cli` as an app tooling alias. Query cluster
health once the service is up:

```sh
lando es-cli /_cluster/health
```

A healthy single-node Elasticsearch reports `green` or `yellow`.

## List indices

```sh
lando es-cli /_cat/indices
```

## Pin a version

Use `image:` to pin a specific Elasticsearch version when the default
Elasticsearch 8 image isn't what you want:

```yaml
services:
  search:
    type: elasticsearch
    image: docker.elastic.co/elasticsearch/elasticsearch:7.17.0
```

## Security defaults are for local dev only

`xpack.security.enabled=false` is meant for local development. Production
deployments must enable security and configure TLS.
