# Compile PHP theme assets with Node

Compile your theme's Sass inside a Node sidecar without adding Node to PHP.
Start with an existing Lando 4 PHP app and a theme already on disk. The example
uses Drupal Bootstrap 5 under `web/themes/contrib/bootstrap5`.

## Add the Node sidecar

Merge this into your Landofile. Keep the recipe's `appserver`, database, and
existing tooling:

```yaml
services:
  node:
    type: "node:22"
    primary: false
    endpoints: []
tooling:
  npm:
    service: node
    dir: /app/web/themes/contrib/bootstrap5
    description: Run npm inside the theme.
    cmds:
      - npm
  npx:
    service: node
    dir: /app/web/themes/contrib/bootstrap5
    description: Run npx inside the theme.
    cmds:
      - npx
```

`lando npm install` runs in Node but writes dependencies into the theme's
`node_modules` directory. `lando npm run <script>` or `lando npx <tool>` runs
them there. Tailwind, Vite, PostCSS, and Prettier can use the same sidecar;
follow each tool's package and configuration requirements.

Rebuild, install, and compile:

```sh
lando rebuild -y
lando npm install
lando npm run build:sass
lando exec node -- test -s /app/web/themes/contrib/bootstrap5/css/style.css
```

The final command checks that the CSS file exists and is nonempty. Open the
site and check your changed styles too; an old CSS file alone does not prove
the new build was loaded.

WordPress themes use the same sidecar. With WordPress at the app root, change
both `dir:` values to `/app/wp-content/themes/mytheme`. A custom Drupal theme
under the default `web` webroot uses `/app/web/themes/custom/mytheme`. Adjust
these paths, and the verification path, if your webroot or app mount differs.

## Keep Node available for tooling

`type: "node:22"` selects the moving Node 22 image channel, not an exact patch
release. `primary: false` keeps Node from becoming the primary service;
leave `primary: true` on the PHP `appserver`. `endpoints: []` removes Node's
default internal HTTP endpoint. Do not add Node routes or published ports
for a service that is only there to run npm.

Omit `command:`. The Node service keeps an idle process so the container
stays up for tooling. The [Laravel recipe](../recipes/laravel-workflow.mdx)
ships this sidecar already; its `package.json` lives at the app root, so it
skips `dir:`.

## Point tooling at the theme

Node does not register `lando npm` or `lando npx` by itself. Author the tasks
and set `dir:` to the theme path inside the container. `/app` is the
bind-mounted app root.

A task `dir` supplies the working directory for the command. Use the absolute
container path shown here; Lando can also remap absolute host paths beneath a
bind mount. Set it on `npm` and `npx` only. An
app-wide `toolingDefaults.dir` would also move `lando drush` and
`lando composer`.

`lando npm install --save-dev sass` still forwards the extra argv to `npm`.
See [Declare flags and args on a tooling task](../tooling/flags-and-args.mdx).

## Install and build

```sh
lando npm install
lando npm run build:sass
```

Use `lando npm run` to list the theme's scripts, then use its build script.
[Drupal Bootstrap 5's package.json](https://git.drupalcode.org/project/bootstrap5/-/blob/4.0.x/package.json)
calls its Sass build `build:sass`. Other themes may use `build`, `build:css`, or
`sass`.

`lando npx sass scss/style.scss css/style.css` compiles that entry point without
a script. It is not a replacement for every build script: Bootstrap 5's
`build:sass` also compiles its editor and alternate-version stylesheets.

Compiled CSS writes into the theme on the shared `/app` mount, so the PHP
web service can serve it without a copy step. Your theme still has to load
that CSS: attach it through a Drupal library or enqueue it in WordPress.
This recipe builds files, not a Vite dev server or hot-reload proxy.

Do not put `sass` on service `globals` unless you want a global CLI for the
whole image. Theme `devDependencies` belong in the theme's `package.json`.
`globals` is for tools such as `gulp-cli`; see [Add Node.js](./node.mdx#install-global-npm-packages).

Skip `node-sass`, which is [end-of-life](https://sass-lang.com/blog/node-sass-is-end-of-life/).
The Dart Sass npm package name is [`sass`](https://sass-lang.com/install/).

## Watch Sass while you edit

If the theme has a watch script, leave it running in a second terminal:

```sh
lando npm run watch:sass
```

The idle Node command holds the container open. Stop the watch with Ctrl+C.

## Init a child theme package

If your child theme has no `package.json`, point `dir:` at its existing folder,
then create the package there. This does not create or register the theme:

```yaml
tooling:
  npm:
    service: node
    dir: /app/web/themes/custom/mytheme
    cmds:
      - npm
  npx:
    service: node
    dir: /app/web/themes/custom/mytheme
    cmds:
      - npx
```

```sh
lando npm init -y
lando npm install --save-dev sass
lando npx sass --version
```

Use your theme's existing `scss/style.scss` entry point. If it has no SCSS yet,
create `web/themes/custom/mytheme/scss/style.scss` in your editor:

```scss
body {
  color: #333;
}
```

Compile it, then check the generated file:

```sh
lando npx sass scss/style.scss css/style.css
lando exec node -- test -s /app/web/themes/custom/mytheme/css/style.css
```

`dir:` keeps every command in the child theme. You do not cd. Add a
`build:sass` script when you want `lando npm run build:sass` instead of raw
`npx`. A WordPress child theme uses its own folder under `wp-content/themes/`
when WordPress is installed at the app root. Keep its required `style.css`
theme header and enqueue the compiled CSS; creating an npm package does
neither.

## Pin the toolchain

Without a local install, `lando npx sass` can download Sass into npm's cache
and prompt for permission. It does not record a theme dependency. For a theme
you keep, save `sass` as a `devDependency` and commit `package.json` and
`package-lock.json`. Once they agree, use `lando npm ci` for a frozen install,
then `lando npm run build:sass`. Unlike `npm ci`, `npm install` can update the
lockfile when the package requirements change.

Dart Sass [deprecated Sass `@import` in 1.80.0](https://sass-lang.com/documentation/breaking-changes/import/).
Prefer `@use` and `@forward` in new files; follow your theme's migration
instructions for existing imports.

## Infer Node from the theme package

`packageRoot` changes only where Lando reads `.nvmrc` and `package.json` for
version inference. It does not change mounts or the container working
directory. You still need tooling `dir:` so `lando npm` runs in the theme.

Use it only with bare `type: node`, and only when that directory already
exists:

```yaml
services:
  node:
    type: node
    packageRoot: web/themes/contrib/bootstrap5
    primary: false
    endpoints: []
```

Pin `type: "node:22"` when the theme is not on disk yet, or when the Landofile
should own the version. Combining `packageRoot` with `type: "node:22"` fails
at plan time.

Service `workingDirectory` sets the container process cwd. It does not set
the theme directory for `lando npm` when Lando maps your shell's current
directory through the app mount. Set tooling `dir:` explicitly instead.

Lando reads `.nvmrc` first and checks it against `package.json` `engines.node`
when present. An exact `.nvmrc` value of `22.11.0` with `engines.node: ">=22"`
selects `node:22.11.0`. Without `.nvmrc`, that engine range selects the Node 22
channel, not the newest matching Node major.
