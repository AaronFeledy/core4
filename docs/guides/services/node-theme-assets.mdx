# Compile PHP theme assets with Node

Add a `node` service next to `appserver`, point tooling at the theme, then
install and run whatever the theme's `package.json` already lists. `lando npm
install` puts those tools in the Node service. `lando npm run <script>` or
`lando npx <tool>` runs them. Sass is the worked example. Tailwind, Vite,
PostCSS, and Prettier use the same sidecar and the same two commands.

```yaml
services:
  node:
    type: "node:22"
    primary: false
    endpoints: []
tooling:
  npm:
    service: node
    dir: /app/web/themes/contrib/bootstrap5
    description: Run npm inside the theme.
    cmds:
      - npm
  npx:
    service: node
    dir: /app/web/themes/contrib/bootstrap5
    description: Run npx inside the theme.
    cmds:
      - npx
```

Keep the recipe's `appserver`, database, and existing tooling. Rebuild, then:

```sh
lando rebuild -y
lando npm install
lando npm run build:sass
```

WordPress themes use the same sidecar. Change both `dir:` values to
`/app/wp-content/themes/mytheme`. A custom Drupal theme uses
`/app/web/themes/custom/mytheme`.

## Add the Node sidecar

`type: "node:22"` pins the image. `primary: false` leaves `appserver` as the
app you open. `endpoints: []` drops the default Node HTTP endpoint so Lando
does not publish a URL for a process that is only there to run npm.

Omit `command:`. The Node service keeps an idle process so the container
stays up for tooling. The [Laravel recipe](../recipes/laravel-workflow.mdx)
ships this sidecar already; its `package.json` lives at the app root, so it
skips `dir:`.

## Point tooling at the theme

Node does not register `lando npm` or `lando npx` by itself. Author the tasks
and set `dir:` to the theme path inside the container. `/app` is the
bind-mounted app root.

A task `dir` is the working directory inside that service. Lando does not
resolve it against the host checkout. Set it on `npm` and `npx` only. An
app-wide `toolingDefaults.dir` would also move `lando drush` and
`lando composer`.

`lando npm install --save-dev sass` still forwards the extra argv to `npm`.
See [Declare flags and args on a tooling task](../tooling/flags-and-args.mdx).

## Install and build

```sh
lando npm install
lando npm run build:sass
```

Use the script name the theme already lists. Drupal Bootstrap 5 calls its Sass
build `build:sass`. Other themes use `build`, `build:css`, or `sass`.

`lando npx sass scss/style.scss css/style.css` is the same compiler without a
script. Tailwind, Vite, PostCSS, and Prettier swap the binary and the script
name. The sidecar does not change.

Compiled CSS writes into the theme on the shared `/app` mount, so Apache or
nginx serves it without a copy step.

Do not put `sass` on service `globals` unless you want a global CLI for the
whole image. Theme `devDependencies` belong in the theme's `package.json`.
`globals` is for tools such as `gulp-cli`; see [Add Node.js](./node.mdx#install-global-npm-packages).

Skip `node-sass`. That binding is obsolete. The Dart Sass package name is
`sass`.

## Watch Sass while you edit

If the theme has a watch script, leave it running in a second terminal:

```sh
lando npm run watch:sass
```

The idle Node command holds the container open. Stop the watch with Ctrl+C.

## Init a child theme package

A generated sub-theme often has no `package.json`. Point `dir:` at that folder,
then create the package there:

```yaml
tooling:
  npm:
    service: node
    dir: /app/web/themes/custom/mytheme
    cmds:
      - npm
  npx:
    service: node
    dir: /app/web/themes/custom/mytheme
    cmds:
      - npx
```

```sh
lando npm init -y
lando npm install --save-dev sass
lando npx sass scss/style.scss css/style.css
```

`dir:` keeps every command in the child theme. You do not cd. Add a
`build:sass` script when you want `lando npm run build:sass` instead of raw
`npx`. A WordPress child theme is the same path under `wp-content/themes/`.

## Pin the toolchain

Bare `lando npx sass` with no local install fetches whatever version is
current. Fine for a one-off. For a theme you keep, pin `sass` as a
`devDependency` and commit `package-lock.json` so `lando npm install` and
`lando npm run build:sass` replay the same toolchain.

Dart Sass is dropping `@import`. Prefer `@use` and `@forward` in new files.

## Infer Node from the theme package

`packageRoot` changes only where Lando reads `.nvmrc` and `package.json` for
version inference. It does not change mounts or the container working
directory. You still need tooling `dir:` so `lando npm` runs in the theme.

Use it only with bare `type: node`, and only when that directory already
exists:

```yaml
services:
  node:
    type: node
    packageRoot: web/themes/contrib/bootstrap5
    primary: false
    endpoints: []
```

Pin `type: "node:22"` when the theme is not on disk yet, or when the Landofile
should own the version. Combining `packageRoot` with `type: "node:22"` fails
at plan time.

Service `workingDirectory` sets the container process cwd. It does not set
the cwd for `lando npm`. Tooling `dir:` does.
