# Run Playwright end-to-end tests against your app

Run your browser tests in an `e2e` service, with Playwright's browsers and system dependencies already installed. The browser reaches your app by service name, and you run the suite with `lando playwright test`.

You need Lando 4 with a ready provider. The default provider is `lando` (managed Podman). Use a new app directory for this demo; in an existing project, merge the examples instead of replacing your files.

This setup is for testing your own trusted app. The Playwright image runs as root, which disables Chromium's sandbox. Don't use this configuration to browse untrusted sites. See [Playwright's container guidance](https://playwright.dev/docs/docker) for that case.

## Configure the app and test service

Save this as `.lando.yml` in your app directory:

```yaml
name: playwright-demo
services:
  web:
    type: "node:22"
    primary: true
    port: 3000
    command: [node, server.mjs]
  e2e:
    type: "node:22"
    image: mcr.microsoft.com/playwright:v1.64.1-noble
    home: false
    endpoints: []
tooling:
  playwright:
    service: e2e
    dir: /app
    cmd: [npx, playwright]
```

The image includes the browsers, not your project's `@playwright/test` package. Keep the package version below and the image tag on the same release.

## Add the app and one test

Save this as `server.mjs` next to the Landofile:

```js
import { createServer } from "node:http";

const port = Number(process.env.PORT ?? 3000);
const server = createServer((_req, res) => {
  res.writeHead(200, { "content-type": "text/html; charset=utf-8" });
  res.end("<!doctype html><title>Playwright demo</title><h1>hello lando</h1>\n");
});
server.listen(port, "0.0.0.0");
process.on("SIGTERM", () => server.close(() => process.exit(0)));
```

Save this as `package.json`:

```json
{
  "name": "playwright-demo",
  "private": true,
  "type": "module",
  "scripts": {
    "test:e2e": "playwright test"
  },
  "devDependencies": {
    "@playwright/test": "1.64.1"
  }
}
```

Save this as `playwright.config.ts`:

```ts
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  reporter: [["list"], ["html", { open: "never" }]],
  use: {
    baseURL: process.env.BASE_URL ?? "http://web:3000",
    trace: "retain-on-failure",
  },
  projects: [{ name: "chromium", use: { ...devices["Desktop Chrome"] } }],
});
```

Create an `e2e` directory and save this as `e2e/home.spec.ts`:

```ts
import { expect, test } from "@playwright/test";

test("home page greets lando", async ({ page }) => {
  await page.goto("/");
  await expect(page).toHaveTitle("Playwright demo");
  await expect(page.getByRole("heading", { level: 1 })).toHaveText("hello lando");
});
```

## Start the app and run the suite

Run these commands from the app directory on your host. Lando runs npm, curl, and Playwright inside `e2e`. On Linux with Docker, files it creates on the host can be root-owned; the cleanup steps below account for this:

```sh
lando start
lando exec e2e -- npm install
lando playwright --version
lando exec e2e -- curl -fsS http://web:3000
lando playwright test
```

Check that the version is `1.64.1`, curl returns the demo HTML containing `hello lando`, and the test runner reports one passing Chromium test. That confirms the browser reached `web` over the app network. To check access from your host as well, run `lando info` and open the app URL it prints.

If curl cannot connect, the app may still be starting. Run `lando logs -s web`, fix any server error, and repeat the curl check before running the tests. `lando start` waits for containers to run; without a healthcheck, it doesn't wait for this Node server to answer HTTP requests.

Install dependencies in `e2e`, not `web`: each service has its own `node_modules` volume. Keep the generated `package-lock.json` with your project and use `lando exec e2e -- npm ci` for later installs from that lockfile. The matching image already contains the required browser builds, so this path doesn't need `playwright install` or `install-deps`.

## Run a file or project

The tooling entry appends your arguments to the project's Playwright command in `/app`:

```sh
lando playwright test e2e/home.spec.ts
lando playwright test --project=chromium
lando exec e2e -- npm run test:e2e
```

A failing assertion exits non-zero through `lando playwright`. A filter that finds no tests also fails unless you explicitly use Playwright's `--pass-with-no-tests` flag. Use the command as a script gate, but check that it actually ran the tests you intended. See the [Playwright CLI reference](https://playwright.dev/docs/test-cli) for other test filters.

## Read the report

Tests run headless. The HTML reporter writes `playwright-report/` in your app directory, and failed tests keep traces under `test-results/`. Add both directories to `.gitignore`; reports and traces can contain page content and other test data.

To serve the report on your host, you need Node.js 20 or newer and npm on the host. From the app directory, run:

```sh
npx --yes playwright@1.64.1 show-report playwright-report --host 127.0.0.1
```

Open the local URL the command prints, then stop the server with Ctrl+C when you're done. This is a host command, not `lando playwright show-report`: `e2e` has no published ports. Serving the folder with [Playwright's report viewer](https://playwright.dev/docs/test-reporters#html-reporter) also supports the report's attachments and trace links.

To record a trace even for a passing run:

```sh
lando exec e2e -- npx playwright test --trace on
```

The `--` separator passes `--trace` to Playwright instead of enabling Lando's own tracing.

Open [Playwright Trace Viewer](https://trace.playwright.dev/) in your host browser and select a `trace.zip` from `test-results/`. The viewer reads the file in your browser without uploading it. See [recording and viewing traces](https://playwright.dev/docs/trace-viewer) for more options.

Headed tests and the interactive test generator need a display. They aren't part of this headless setup.

## Keep the image and package together

When updating Playwright, change both the image tag in `.lando.yml` and the exact `@playwright/test` version in `package.json`. Rebuild `e2e`, install the updated package there, and check `lando playwright --version` before testing. A version mismatch can produce a missing-browser-executable error even though the image contains browsers.

If you deliberately use a different, supported Linux image that doesn't include Playwright's browsers, install them and their operating-system libraries in that service:

```sh
lando playwright install --with-deps chromium
```

`install chromium` alone downloads the browser; `install-deps chromium` installs only its system dependencies. Don't add these commands to the matching official-image path above. For a custom image, put the installation in its build so rebuilding the service doesn't lose it. Check [Playwright's browser requirements](https://playwright.dev/docs/browsers) before choosing a base image.

`e2e` uses the Node release inside the Playwright image, not the `22` in its Lando service type. Check it with `lando exec e2e -- node -v`. Keep `web` on the Node version your app targets.

## Understand the service settings

`baseURL` is `http://web:3000` because the browser runs inside `e2e`. There, `localhost` means `e2e`, not `web`. The URL from `lando info` is for your host browser.

The Node service type mounts the app at `/app` and keeps `e2e` running with an idle command. `home: false` skips home persistence because Lando cannot infer a home directory for a custom image. Without it or an explicit `home.path`, planning stops with `HomePathCapabilityError`.

`endpoints: []` opts `e2e` out of endpoint and route planning: the Node type's default `3000` listener is not planned, no route or host port is generated for it, and `lando info` lists nothing to connect to. The idle command still runs; this only changes what Lando plans and publishes. An explicit `endpoints:` list is the authoritative inventory for a service. `ports:` wouldn't do this: it only publishes host ports, and a typed service keeps its primary listener in the plan whether `ports:` is absent or empty. Browser tests make outgoing requests; they don't need a listening port on `e2e`.

## Tear down

The container user writes reports and `package-lock.json`. With this root-run image, these files may be root-owned on Linux hosts using Docker. If your host user can't remove the reports, the following command deletes both generated result directories from inside `e2e`. Save anything you want to keep first:

```sh
lando exec e2e -- sh -c 'rm -rf /app/playwright-report /app/test-results'
```

`lando destroy -y` removes the app containers and app-owned networks, but keeps source files and reports on the host. It also keeps the service's `node_modules` volume:

```sh
lando destroy -y
```

Only add `--volumes` when you want to delete the app's persistent volumes too. You'll need to reinstall dependencies after starting again.
