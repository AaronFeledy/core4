# Index and search with Meilisearch

Add Meilisearch to your app, put three documents in an index, and search them over HTTP. You can then run the same query from a Node service with the official JavaScript client.

You need Lando 4 with a ready provider. The default provider is `lando` (managed Podman). Run host commands from a new app directory for this demo. If you're adding search to an existing app, merge the service and tooling entries rather than replacing the Landofile.

Lando's default master key is the public value `lando`. The examples use it only for a disposable local demo. Don't expose this instance to untrusted users, and never put a real master or admin key in browser code. Use a private master key and scoped API keys before using real data.

## Configure Meilisearch and tooling

Save this as `.lando.yml` in your app directory:

```yaml
name: meilisearch-demo
services:
  search:
    type: meilisearch
  app:
    type: "node:22"
    primary: true
    endpoints: []
tooling:
  meili:
    service: search
    description: Call the Meilisearch HTTP API with curl.
    cmd: [curl, -fsS]
  node:
    service: app
    cmd: [node]
    description: Run Node inside the app service.
    dir: /app
  npm:
    service: app
    cmd: [npm]
    description: Run npm inside the app service.
    dir: /app
```

The `meili` alias runs curl inside `search`, with your arguments appended. Lando doesn't add a Meilisearch client command automatically. `app` is an idle Node service for the SDK example; `endpoints: []` gives it no endpoint because it isn't serving HTTP.

## Start and check the API

```sh
lando start
lando meili http://localhost:7700/health
lando meili -H 'Authorization: Bearer lando' http://localhost:7700/indexes
```

The health response should report `status: available`. The authenticated index list should have `total: 0` on a fresh instance. `localhost:7700` works here because the alias runs inside the Meilisearch container. `/health` doesn't require a key, but index, document, and task requests do.

If curl cannot connect, run `lando logs -s search` and resolve the startup error before continuing. An HTTP error makes the alias exit non-zero; missing or invalid authentication is different from a server that cannot be reached.

## Create an index and search

Create a `movies` index with `id` as its primary key:

```sh
lando meili -X POST -H 'Authorization: Bearer lando' -H 'Content-Type: application/json' \
  --data '{"uid":"movies","primaryKey":"id"}' \
  http://localhost:7700/indexes
```

The response contains a `taskUid`. It means the request was queued, not that the index is ready. Replace `<taskUid>` in the quoted URL with that number, then repeat the request until `status` is `succeeded`:

```sh
lando meili -H 'Authorization: Bearer lando' 'http://localhost:7700/tasks/<taskUid>'
```

If the task is `failed` or `canceled`, stop rather than polling forever. For a failed task, read its `error` field. If it reports `index_already_exists` on a repeated run, confirm that this is your demo index and that its primary key is `id` before continuing:

```sh
lando meili -H 'Authorization: Bearer lando' http://localhost:7700/indexes/movies
```

Add the documents only after index creation succeeds. This request replaces any existing documents with the same IDs, so use a separate demo index rather than one containing data you need:

```sh
lando meili -X POST -H 'Authorization: Bearer lando' -H 'Content-Type: application/json' \
  --data '[{"id":1,"title":"Casablanca","genres":["Drama","Romance"]},{"id":2,"title":"Cloud City","genres":["Sci-Fi"]},{"id":3,"title":"The Empire Strikes Back","genres":["Sci-Fi","Adventure"]}]' \
  http://localhost:7700/indexes/movies/documents
```

This write returns a new `taskUid`. Check that task with the same `/tasks/` command, using the new number, and wait for `succeeded` before searching. If it fails, inspect the task's `error` instead of assuming a successful HTTP response means the documents were indexed. See [Meilisearch's task lifecycle](https://www.meilisearch.com/docs/capabilities/indexing/tasks_and_batches/async_operations).

Search for the prefix `casa`:

```sh
lando meili -X POST -H 'Authorization: Bearer lando' -H 'Content-Type: application/json' \
  --data '{"q":"casa"}' \
  http://localhost:7700/indexes/movies/search
```

Check that `hits` includes the document titled `Casablanca`. This demonstrates [prefix search](https://www.meilisearch.com/docs/resources/internals/prefix), not a misspelling. An empty result after adding documents is a reason to check the document task again.

## Reach Meilisearch from another service

From another service, use `http://search:7700`: `search` is the service key. `localhost` inside `app` means the Node container, not Meilisearch.

Check both network access and authentication from `app`:

```sh
lando exec app -- curl -fsS http://search:7700/health
lando exec app -- curl -fsS -H 'Authorization: Bearer lando' http://search:7700/indexes
```

For a host client, run `lando info` and use the URL it lists for `search`. Don't assume that the internal name `search` resolves on your host, or that port `7700` is published there.

## Query from Node

Complete the HTTP indexing steps first. This script queries the existing `movies` index; it doesn't create it or load documents.

Use the official [JavaScript client](https://github.com/meilisearch/meilisearch-js/tree/v0.62.0). The pinned release below supports Node 22.12 or newer on the Node 22 line. Check `lando node --version` before installing it; use an up-to-date Node 22 service image if yours is older.

Save this as `package.json` next to the Landofile, or add the dependency to your existing package:

```json
{
  "name": "meilisearch-demo",
  "private": true,
  "type": "module",
  "dependencies": {
    "meilisearch": "0.62.0"
  }
}
```

Save this as `search.mjs` in the same directory:

```js
import { Meilisearch } from "meilisearch";

const client = new Meilisearch({
  host: "http://search:7700",
  apiKey: "lando",
});

const health = await client.health();
const results = await client.index("movies").search("casa");
console.log(JSON.stringify({ health, hits: results.hits.map((hit) => hit.title) }));
```

Install and run inside `app`:

```sh
lando npm install
lando node search.mjs
```

Check that the output includes `status: available` and `Casablanca` in `hits`. Keep `package-lock.json` with your project; later installs can use `lando npm ci`. The SDK version and server version don't use matching numbers: this SDK supports the Meilisearch v1 API used here.

## Use a private key

For anything beyond the disposable demo, generate a random master key of at least 16 bytes. Add `.lando.local.yml` to `.gitignore` before saving a real key there. Use this local override, replacing the placeholder with your generated value:

```yaml
services:
  search:
    environment:
      MEILI_MASTER_KEY: replace-with-your-generated-secret
```

Run `lando rebuild` after changing the key. Updating the master key also changes the derived API keys, so update your clients before retrying their requests. Don't print or paste real credentials into logs or shared examples.

Use the master key to manage API keys, then give backend code an admin or narrowly scoped key and browser search code a search-only key. Replace the demo `lando` credential in the HTTP headers and Node `apiKey` with the appropriate key. Follow [Meilisearch's key guidance](https://www.meilisearch.com/docs/resources/self_hosting/security/master_api_keys) when connecting a real application.

## Inspect the server and diagnose requests

The service type uses `getmeili/meilisearch:v1.11`, listens on `7700`, and stores index data under `/meili_data`. It sets `MEILI_ENV=development`, `MEILI_NO_ANALYTICS=true`, and the default `MEILI_MASTER_KEY=lando` unless you override them.

Set the service's `port:` to change its listener; Lando derives `MEILI_HTTP_ADDR` and the healthcheck from that port. If you also set `MEILI_HTTP_ADDR`, including through an env file or `appEnv`, it must use `:port`, `0.0.0.0:port`, or `[::]:port` with the same port. Lando preserves accepted text, but rejects malformed, loopback, or mismatched binds before starting containers. Remove the conflicting variable and set `port:` instead.

Check the running server's actual release rather than assuming the patch version behind the image tag:

```sh
lando meili -H 'Authorization: Bearer lando' http://localhost:7700/version
```

Read `pkgVersion` in the response. Substitute your key if you changed it.

The alias's `-f` flag makes HTTP errors fail, `-s` hides curl's progress meter, and `-S` keeps curl's error message visible. To see an API error's response body during diagnosis, run curl without `-f`. For example, this deliberately omits authentication:

```sh
lando exec search -- curl -sS -i http://localhost:7700/indexes
```

Expect an authentication error, not the index list. Add the correct Bearer header for normal requests.

## Pin a version

An image change is not a data migration. Before changing Meilisearch releases on an existing volume, back up your data and follow the [upgrade instructions for your source and target versions](https://www.meilisearch.com/docs/resources/migration/updating). Don't attach an older image to a database created by a newer release.

For a fresh instance, this example pins a patch release on the default v1.11 line:

```yaml
services:
  search:
    type: meilisearch
    image: getmeili/meilisearch:v1.11.3
```

With your own `image:`, Lando plans no home store for `search`. The separate `/meili_data` volume still persists index data.

After an authorized version change and any required migration, run `lando rebuild`, then repeat the health and `/version` checks. Also rerun a search; a running container alone doesn't prove the data is usable.

## Keep or remove the index data

`lando destroy -y` removes app containers and networks but keeps the `<app>-meilisearch-data` volume, so the index remains available after the next start:

```sh
lando destroy -y
```

Only add `--volumes` when you intend to delete the app's persistent volumes, including its indexes and the Node dependency volume. Back up anything you need first. Your source files stay on the host.
