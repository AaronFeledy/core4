# Add Meilisearch

Add `type: meilisearch` under `services` in `.lando.yml`. That resolves to the `meilisearch:1` image line. Lando pulls `getmeili/meilisearch:v1.11` and listens on `7700`:

```yaml
name: meilisearch-demo
services:
  search:
    type: meilisearch
```

## Check health and set a key

After start, query the same health endpoint that Lando checks inside `search`:

```sh
lando exec search -- curl -sf http://localhost:7700/health
```

A healthy Meilisearch reports a JSON body with `status: available`.

Lando starts Meilisearch in development mode with analytics disabled and the published default master key `lando`. That shared development key is not a private credential. Set `MEILI_MASTER_KEY` under `services.search.environment` to use your own key; keep real keys out of committed files:

```yaml
services:
  search:
    type: meilisearch
    environment:
      MEILI_MASTER_KEY: your-key-here
```

## Pin a version

For a custom `image:`, also set `home: false` on that service, or supply `home.path` for a home directory you know exists in the image. Without either, planning fails because Lando cannot infer the custom image's home. See [service home configuration](./home-and-host.mdx).

Set `image:` when the default v1.11 isn't the version you want:

```yaml
services:
  search:
    type: meilisearch
    image: getmeili/meilisearch:v1.10
```
