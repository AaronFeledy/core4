# Switch the database engine

Change `type:` from one database engine to another, then `lando rebuild -y`. That does not move your data.

## Start from MySQL

Start from a Landofile where `db` is declared as `type: mysql`:

```yaml
name: switching-databases-demo
services:
  db:
    type: mysql
```

## Rebuild as Postgres

Edit the Landofile: change `services.db.type` from `mysql` to `postgres`,
then run `lando rebuild -y` to recreate the container against the new
engine:

```yaml
name: switching-databases-demo
services:
  db:
    type: postgres
```

## Export before you rebuild

`rebuild` recreates the container; it does not convert your data. Swapping
`type: mysql` for `type: postgres` and rebuilding gets you a fresh, empty
Postgres volume. Your old MySQL data stays in the old MySQL volume and is
not converted or copied. Lando 4 ships no `db-import` or `db-export` command to bridge engines for you.

Always export your data from the old engine before you change `type:` and
rebuild, or you'll be staring at an empty database.

Dump from MySQL using the native client inside the `db` service:

```sh
lando exec db -- mysqldump -u lando -plando switching-databases-demo > dump.sql
```

MySQL and PostgreSQL speak different SQL dialects. A raw `mysqldump` file
isn't valid input for `psql` or `pg_restore`. Schema types, quoting, and dialect-specific syntax need conversion (tools like `pgloader` exist for this) before you load it into Postgres.

Once converted, restore into Postgres using the native client:

```sh
lando exec db -- psql -U lando -d switching-databases-demo -f converted-dump.sql
```
