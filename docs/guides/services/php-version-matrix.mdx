# PHP version matrix

`type: php:<version>` accepts exactly `8.1`, `8.2`, `8.3`, `8.4`, or `8.5`.
Every other version — including `8.0` and `8.6` — fails Landofile validation
before any build or container work happens. Each supported version
resolves to the matching stock upstream image, `php:<version>-apache-bookworm`:

```yaml
name: php-version-matrix-demo
services:
  app:
    type: "php:8.1"
    primary: true
```

`lando app:cache:refresh` rebuilds the app plan without starting anything —
a fast way to prove a `type:` resolves:

## Unsupported versions fail honestly

`php:8.0` and `php:8.6` are outside the supported catalog. Landofile
validation rejects them immediately, before any build or container work
starts, and names the supported alternatives:

## Pin a version

Pin any of the five supported minors under `type:`. There is no bare
`type: php` alias — always include the version:

```yaml
services:
  app:
    type: php:8.2
```

Set `image:` to override the stock `-apache-bookworm` image with a
`php-fpm` or CLI base instead:

```yaml
services:
  app:
    type: "php:8.3"
    image: php:8.3-fpm
```
