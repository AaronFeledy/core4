# Add LocalStack

Add `type: localstack` under `services` in `.lando.yml`:

```yaml
name: localstack-demo
services:
  aws:
    type: localstack
```

LocalStack serves its AWS-compatible APIs through the gateway on port `4566` by
default. Set `port:` to choose the planned listener. Lando never derives that
planned port from `GATEWAY_LISTEN`; the environment only names binds that must
include it. Point your SDK or application at `http://aws:4566`, or at the
service name with your authored `port:`, from another service in the app.

## Change the gateway port

Set `port:` to move the primary gateway listener, healthcheck, and endpoint
together:

```yaml
services:
  aws:
    type: localstack
    port: 14566
```

Without an authored `GATEWAY_LISTEN`, Lando sets `GATEWAY_LISTEN=0.0.0.0:14566`.
When you author `GATEWAY_LISTEN`, Lando preserves your string verbatim. Use one or more
comma-separated wildcard binds (`:port`, `0.0.0.0:port`, or `[::]:port`). Exactly
one bind must use the planned port. Extra wildcard binds become additional
internal endpoints named `gateway-<port>`. Loopback hosts, bare port numbers,
duplicates, malformed values, and non-wildcard addresses fail planning at
`services.<name>.environment.GATEWAY_LISTEN`.

```yaml
services:
  aws:
    type: localstack
    port: 14566
    environment:
      GATEWAY_LISTEN: " [::]:14566, :4566 "
```

Validate with `lando app:cache:refresh --format=json` before start.

## Keep gateway ports separate from DNS

LocalStack also runs a DNS server on TCP and UDP port `53`. Neither `port:`
nor an extra `GATEWAY_LISTEN` bind can use that port while DNS is enabled.
Planning rejects a primary collision at `services.<name>.port` and an extra
gateway collision at `services.<name>.environment.GATEWAY_LISTEN`.

To use `53` for the gateway, move DNS with `DNS_PORT`:

```yaml
services:
  aws:
    type: localstack
    port: 53
    environment:
      DNS_PORT: "1053"
```

The gateway now uses `53` and DNS uses `1053`; no gateway bind may use `1053`.
`DNS_PORT` must be one integer from `1` to `65535`, even when DNS is disabled.

Alternatively, set `environment.DNS_ADDRESS: "0"` to disable the DNS server
and release its port. Disabling DNS also removes LocalStack's DNS-based name
resolution, so use it only when your application does not need that behavior.
Other `DNS_ADDRESS` values do not release the reserved port.

Validate either change with `lando app:cache:refresh --format=json` before start.

## Keep local AWS data

Lando mounts persistent storage at `/var/lib/localstack`. Queues, buckets, and
other supported state survive normal stop and start cycles, so you can reuse local test data.

## Check readiness

The service checks `/_localstack/health` on the planned gateway port inside the
container, using `4566` when `port:` is omitted. Lando waits for that healthcheck
before treating LocalStack as ready.
If the service stays unhealthy, inspect its logs before debugging your app.

```sh
lando logs -s aws
```

## Run AWS commands

The service adds `awslocal` tooling automatically. It behaves like the AWS CLI
but targets the local gateway, so you don't need to repeat endpoint flags:

```sh
lando awslocal s3api create-bucket --bucket uploads
lando awslocal s3 ls
```
