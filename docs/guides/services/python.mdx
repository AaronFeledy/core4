# Add Python

Add `type: python:3.12` to your primary service in `.lando.yml`. Python has no bare `type: python` alias, so pin a version. Lando supports `python:3.12`. The default image is `python:3.12-slim`. Your repo mounts read-write at `/app`.

```yaml
name: python-demo
services:
  app:
    type: "python:3.12"
    primary: true
```

Add `framework:` when you want FastAPI, Django, or Flask defaults for port and env. Keep-alive still runs until you set `command:` or serve with `lando exec`.

Python publishes its port endpoint but has no default healthcheck or readiness probe, including for authored worker commands. Add `readiness:` when you want start to wait for application readiness; use `healthcheck:` separately for native ongoing monitoring. Without an effective readiness command, Lando checks that the process stays running. The slim image has no `curl`, so probe with Python itself in argv form. This example serves the app directory with Python's built-in HTTP server:

```yaml
services:
  app:
    type: "python:3.12"
    primary: true
    port: 8000
    command: [python, -m, http.server, "8000"]
    readiness: [python, -c, "import urllib.request; urllib.request.urlopen('http://localhost:8000/')"]
```

For an existing FastAPI project, save this complete service and tooling configuration in `.lando.yml`:

```yaml
name: python-fastapi
services:
  app:
    type: "python:3.12"
    framework: fastapi
    primary: true
    port: 8000
tooling:
  pip:
    service: app
    cmd: pip
  uv:
    service: app
    cmd: uv
  python:
    service: app
    cmd: python
```

| Framework | Default port | Useful bits |
| --- | --- | --- |
| `fastapi` | `8000` | Sets `UVICORN_HOST=0.0.0.0`; author the Uvicorn command below |
| `django` | `8000` | Sets `DJANGO_SETTINGS_MODULE=config.settings` |
| `flask` | `5000` | Sets `FLASK_APP=app` |
| `none` (default) | `8000` | Plain Python service |

## Pass `port:` to your Python server

Lando derives these variables from the same port as the internal HTTP endpoint. An explicit `port:` replaces the framework default:

| Framework | Port variables | Default host variable | Servers that read them |
| --- | --- | --- | --- |
| `none` | `PORT` (`8000`) | None | Gunicorn reads `PORT` and binds `0.0.0.0` |
| `django` | `PORT` (`8000`) | None | Gunicorn reads `PORT`; Django `runserver` does not |
| `fastapi` | `PORT`, `UVICORN_PORT` (`8000`) | `UVICORN_HOST=0.0.0.0` | Uvicorn CLI reads `UVICORN_*`; FastAPI CLI reads `PORT` |
| `flask` | `PORT`, `FLASK_RUN_PORT` (`5000`) | `FLASK_RUN_HOST=0.0.0.0` | `flask run` reads `FLASK_RUN_*`; Gunicorn reads `PORT` |

Port variables are not independent overrides. If an authored value is malformed or differs from the planned port, planning fails at `services.app.environment.<VAR>`. This includes inherited `appEnv` and env-file values. Set `port:` instead. Host variables are ordinary defaults: your authored host value wins, but a loopback address makes the server unreachable through the proxy.

FastAPI CLI does not read `UVICORN_*`. `fastapi run main.py` binds all interfaces and reads `PORT`; `fastapi dev main.py --host 0.0.0.0` still needs its host argument. Django needs `runserver 0.0.0.0:8000` (or your chosen port) because it reads neither port nor host from these variables. Python's built-in `http.server` also needs its port argument.

Python does not interpret `webroot:`. An explicit root fails planning unless
a composed plugin feature declares and handles it. Set `workingDirectory:`
to move the process, and configure static-file paths in your application or a
separate webserver.

Start it:

```sh
lando start
lando info
```

If host ports 80 or 443 are taken, `lando info` shows fallback ports such as `:8080` and `:8443`.

## Install deps with pip or uv

Lando installs `uv` in the stock Python service image, so it stays available after a restart or rebuild. Declare tooling in the Landofile (see the FastAPI example above), then install your project dependencies into `/app/.venv`. That path is a service-owned overlay: it is not synced to the host, and a host `.venv` is hidden inside the container. Restart and a plain `lando destroy` keep it. `lando destroy --volumes` or `--purge` removes it.

```sh
lando uv --version
lando uv venv /app/.venv
lando uv pip install --python /app/.venv/bin/python -r requirements.txt
lando exec app -- /app/.venv/bin/python --version
```

`lando pip install` into the image works for a quick try, but a rebuild drops those packages. Use `appMount.includes: [.venv]` if you want the host tree, for example for IDE autocomplete. A nested venv such as `backend/.venv` needs its own exclude to get a service-owned overlay. See [Exclude paths from the app mount](../setup/file-sync-excludes.mdx).

Need a one-shot system install with uv instead of a venv?

```sh
lando exec app -- uv pip install --system -r requirements.txt
```

## Serve FastAPI

The idle container lets you install dependencies before starting the server. The following commands assume your `requirements.txt` includes FastAPI and Uvicorn and your app root contains `main.py` with an ASGI object named `app`. Run Uvicorn once in the foreground:

```sh
lando exec app -- /app/.venv/bin/uvicorn main:app
```

Or set it as the service command and restart so Lando starts Uvicorn with the service:

```yaml
services:
  app:
    type: "python:3.12"
    framework: fastapi
    primary: true
    port: 8000
    command:
      - /app/.venv/bin/uvicorn
      - main:app
```

```sh
lando restart
lando info
```

Open the URL `lando info` prints. A tiny `main.py` that returns JSON is enough to prove the route.

## Django and Flask

Same service type. Swap the framework and bind the server you actually run:

```yaml
services:
  app:
    type: "python:3.12"
    framework: django
    primary: true
```

```yaml
services:
  app:
    type: "python:3.12"
    framework: flask
    primary: true
```

```sh
lando exec app -- /app/.venv/bin/python manage.py runserver 0.0.0.0:8000
lando exec app -- /app/.venv/bin/gunicorn app:app
```

## Pin an image

Slim is the default. Use the full image when wheels need build tools. A custom `image:` or a Dockerfile selected by `build.context` owns its toolchain, including `uv`; Lando only installs `uv` for the stock `python:3.12-slim` image:

```yaml
services:
  app:
    type: "python:3.12"
    image: python:3.12
```
