# Add a Compose service

Add `type: compose` under `services` in `.lando.yml` to run a third-party image outside the catalog. Compose ports use the short form, which maps to the container port. The app root is mounted at `/app` by default:

```yaml
name: compose-passthrough-demo
services:
  whoami:
    type: compose
    image: traefik/whoami:v1.10
    home: false
    ports:
      - 80:80
```

`home: false` disables home persistence for this custom image. The example publishes host port `80`, which must be free; choose another host-side port in `ports:` if needed and use it in the probe below.

Start it. Lando puts the passthrough service on the app network:

## Set `command` or `entrypoint`

A string `command:` or `entrypoint:` splits into argv like Compose: whitespace separates words, quotes group them, and no shell runs. `command: --port 8080` reaches the image's entrypoint as `["--port", "8080"]`. A list passes through as written. Splitting does not expand variables, and an unquoted `;`, `&`, `|`, `<`, or `>` ends the argv there.

`command` appends to the image's `ENTRYPOINT`, same as Compose. For shell features you need an image with a shell and no binary entrypoint in the way, then an explicit `sh -c` with the script in one quoted argument:

```yaml
services:
  sleeper:
    type: compose
    image: alpine:3.20
    appMount: false
    home: false
    command: sh -c "printf ready && exec sleep infinity"
```

That becomes `["sh", "-c", "printf ready && exec sleep infinity"]`. Malformed quotes fail planning with `LandofileValidationError`. Only `type: compose` splits strings this way; other service types run a string `command` as a shell script.

## Probe the service

From your host terminal, curl the published HTTP port after the service starts:

```sh
curl -sf http://localhost:80/
```

Use your chosen host port if you changed the mapping. The response includes a `Hostname:` line. The [whoami image](https://github.com/traefik/whoami/blob/v1.10.0/Dockerfile) contains a standalone binary, not a shell or curl, so probe it from the host rather than running those tools inside the service.

## See which Compose keys work

The compose passthrough only accepts a subset of Compose service keys. The
generated key matrix at `docs/reference/compose-key-matrix.mdx` publishes
every accepted, preserved, and rejected key. If a key is rejected, the
remediation is to move unsupported provider-specific config under
`providers.<id>`, or open an issue to grow the subset.

## Know what Lando adds

Lando injects none of its app identity or app-path `LANDO_*` variables into a
compose service. The only one it adds is `LANDO_HOST_IP`, the host alias
`host.lando.internal`, when the provider can reach your host. Set anything
else the image needs with `environment:` or `env_file:`.

Lando still bind-mounts the app source at `/app`, or at `appMount.target`
when you set one, and joins the service to the per-app network `lando-<slug>`
so it can reach the rest of the app by service name.

## Skip the app mount

Set `appMount: false` when the third-party image must not see the app
source. Every service type that mounts the app honors it:

```yaml
services:
  whoami:
    type: compose
    image: traefik/whoami:v1.10
    appMount: false
```
