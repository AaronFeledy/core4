# Compose passthrough

Run a third-party image outside the canonical service catalog by declaring
`type: compose` in your services block. Compose ports use the short form,
which maps to the container port, and the app root is mounted at `/app` by
default:

```yaml
name: compose-passthrough-demo
services:
  whoami:
    type: compose
    image: traefik/whoami:v1.10
    ports:
      - 80:80
tooling:
  probe:
    service: whoami
    cmd:
      - sh
      - -c
      - 'curl -sf http://localhost:80/'
      - probe
```

Start it and Lando wires the passthrough service into the app network:

## Probe the service

The fixture above declares `probe` as an app tooling alias. Run it once the
service is up to curl the HTTP surface:

```sh
lando probe
```

`traefik/whoami` responds with a body that starts with `Hostname: ...`.

## Allowed Compose keys

The compose passthrough only accepts a subset of Compose service keys. The
generated key matrix at `docs/reference/compose-key-matrix.mdx` publishes
every accepted, preserved, and rejected key. If a key is rejected, the
remediation is to move unsupported provider-specific config under
`providers.<id>`, or open an issue to grow the subset.

## The LANDO_* environment contract

Unless `appMount: false` is set, a compose service emits the same `LANDO_*`
identity variables as any other service, and joins the per-app network:

```
LANDO=ON
LANDO_APP_NAME
LANDO_APP_KIND
LANDO_PROJECT
LANDO_SERVICE_API
LANDO_SERVICE_NAME
LANDO_SERVICE_TYPE=compose
LANDO_APP_ROOT=/app
LANDO_PROJECT_MOUNT=/app
```

The service also joins the per-app network `lando-<slug>` like any other
service.

## Opt out of the app mount

Set `appMount: false` when the third-party image must not see the app
source. With it set, Lando skips the synthetic `/app` bind mount, and omits
`LANDO_APP_ROOT` and `LANDO_PROJECT_MOUNT`:

```yaml
services:
  whoami:
    type: compose
    image: traefik/whoami:v1.10
    appMount: false
```
