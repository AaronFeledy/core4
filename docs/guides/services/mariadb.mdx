# Add MariaDB

Put `type: mariadb` in your services block. Lando pulls `mariadb:11.4` and listens on `3306`:

```yaml
name: mariadb-demo
services:
  db:
    type: mariadb
```

Set `creds:` when you want explicit values. Defaults stay `lando` / `lando` / the app name, plus a generated root password. `creds.user` is the database username. Container `user:` is not.

```yaml
services:
  db:
    type: mariadb
    creds:
      user: lando
      password: lando
      database: mariadb-demo
      rootPassword: secret
```

Start it. Lando puts the database on the app network:

## Connect from another service

Other services use the service name as the hostname. Here that's `db`. Defaults:

| Setting | Value |
| --- | --- |
| Host | `db` |
| Database | the app name (`mariadb-demo`); override with `database:` under `services.db` |
| User | `lando` |
| Password | `lando` |

MariaDB also exports the `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` env names, so MySQL clients and frameworks connect unchanged. From inside the app network the connection URL is:

```
mysql://lando:lando@db:3306/mariadb-demo
```

MariaDB speaks the MySQL wire protocol, so that's the right scheme. That URL uses the default port; use your authored `port:` in application connection URLs.

## Open the client

The `mariadb` type ships the client task. After start:

```sh
lando mariadb
```

Import a dump with `lando db:import`. See [Import and export app databases](../tooling/db-import-export.mdx). Or pipe a plain SQL file straight into the client:

```sh
lando mariadb < dump.sql
```

## Add server config

Set `config.server` to an app-relative file when you need to tune the server:

```yaml
services:
  db:
    type: mariadb
    config:
      server: ./config/my.cnf
```

Lando mounts that file read-only at `/etc/mysql/conf.d/99-lando.cnf`. The server reads it as a drop-in on startup, after its own defaults. An authored listen port still takes precedence. It has to be a regular file, not a directory.

The path has to stay inside the app root. Absolute paths, paths that climb out of the app root, and symlinks that point outside it are rejected when Lando plans the app, before anything starts.

## Change the port

Set `port:` to move the daemon's listener, healthcheck, endpoint, and Lando's own clients together:

```yaml
services:
  db:
    type: mariadb
    port: 3307
```

Other services now connect to `db:3307`. Lando sets `MYSQL_TCP_PORT` for the server and in-container clients, and publishes the same value as `LANDO_DB_PORT`. `lando mariadb` and `lando db:*` commands use that planned port.

Setting `MYSQL_TCP_PORT` under `environment:` works too. If you set both forms, they must match or planning fails. With `config.server`, an authored port beats the option file's `port=` line. If you author `command:` or `entrypoint:`, you own the daemon's flags; pass `--port=3307` yourself if the option file sets another port.

Apply the change with `lando rebuild`, then check the running server:

```sh
lando mariadb -N -e 'SELECT @@port'
```

## Pin a version

Set `image:` when `mariadb:11.4` isn't the version you want. For example, the 10.11 LTS line:

```yaml
services:
  db:
    type: mariadb
    image: mariadb:10.11
```
