# Add MariaDB

Put `type: mariadb` in your services block. Lando pulls `mariadb:11.4` and listens on `3306`:

```yaml
name: mariadb-demo
services:
  db:
    type: mariadb
```

Set `creds:` when you want explicit values. Defaults stay `lando` / `lando` / the app name, plus a generated root password. `creds.user` is the database username. Container `user:` is not.

```yaml
services:
  db:
    type: mariadb
    creds:
      user: lando
      password: lando
      database: mariadb-demo
      rootPassword: secret
```

Start it. Lando puts the database on the app network:

## Connect from another service

Other services use the service name as the hostname. Here that's `db`. Defaults:

| Setting | Value |
| --- | --- |
| Host | `db` |
| Database | the app name (`mariadb-demo`); override with `database:` under `services.db` |
| User | `lando` |
| Password | `lando` |

MariaDB also exports the `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` env names, so MySQL clients and frameworks connect unchanged. From inside the app network the connection URL is:

```
mysql://lando:lando@db:3306/mariadb-demo
```

MariaDB speaks the MySQL wire protocol, so that's the right scheme.

## Open the client

The `mariadb` type ships the client task. After start:

```sh
lando mariadb
```

Import a dump with `lando db:import`. See [Import and export app databases](../tooling/db-import-export.mdx). You can still pipe into the client with `lando exec`.

## Pin a version

Set `image:` when `mariadb:11.4` isn't the version you want. For example, the 10.11 LTS line:

```yaml
services:
  db:
    type: mariadb
    image: mariadb:10.11
```
