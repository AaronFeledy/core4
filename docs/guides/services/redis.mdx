# Add Redis

Put `type: redis` in your services block. Lando pulls `redis:7` and listens on `6379`. The default command enables append-only persistence (`redis-server --appendonly yes`) so cached data survives a restart:

```yaml
name: redis-demo
services:
  cache:
    type: redis
```

## Connect from another service

Connect from another service using the service name `cache` as the hostname. Redis runs without auth unless you set `password:`. From inside the app network the connection URL is:

```
redis://cache:6379
```

## Open the client

The `redis` type ships the `redis-cli` client task. After start:

```sh
lando redis-cli ping
```

Store and read keys from the host with the same command:

```sh
lando redis-cli set hello world
```

## Require a password

Set `password:` on Redis. Keep real credentials in an untracked local Landofile or a secret reference, not your repository.

```yaml
services:
  cache:
    type: redis
    password: "${secret:redis-password}"
    persist: true
```

Run `lando rebuild`, then `lando redis-cli ping`. The generated client and healthcheck authenticate through the container environment, without putting the password in command arguments. Other services must supply the same password to their Redis client.

## Discard cached data on restart

`persist:` defaults to `true`. Setting it to `false` disables durable data storage, append-only files, and RDB snapshots. Don't use this for data you need to keep.

```yaml
services:
  cache:
    type: redis
    persist: false
```

Run `lando rebuild`, set a disposable key, then run `lando restart` and read it again:

```sh
lando redis-cli set temporary value
lando restart
lando redis-cli exists temporary
```

The key should no longer exist. A durable Redis service retains its keys instead.

## Pin a version

Set `image:` when `redis:7` isn't the version you want:

```yaml
services:
  cache:
    type: redis
    image: redis:6
```
