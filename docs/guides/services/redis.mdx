# Add Redis

Add `type: redis` under `services` in `.lando.yml`. Lando pulls `redis:7` and listens on `6379`. The default command enables append-only persistence (`redis-server --appendonly yes`) so cached data survives a restart:

```yaml
name: redis-demo
services:
  cache:
    type: redis
```

## Connect from another service

Connect from another service using the service name `cache` as the hostname. Redis runs without auth unless you set `password:`. From inside the app network the connection URL is:

```
redis://cache:6379
```

That URL uses the default port. Use your authored `port:` in application connection URLs.

## Open the client

The `redis` type ships the `redis-cli` client task. After start:

```sh
lando redis-cli ping
```

Store a key by invoking the client from your host terminal:

```sh
lando redis-cli set hello world
```

## Require a password

Set `password:` on Redis. Keep real credentials in an untracked local Landofile, not your repository.

```yaml
services:
  cache:
    type: redis
    password: lando
    persist: true
```

Run `lando start`, then `lando redis-cli ping`. The generated client and healthcheck authenticate through the container environment, without putting the password in command arguments. Other services must supply the same password to their Redis client.

## Discard cached data on restart

`persist:` defaults to `true`. Setting it to `false` disables durable data storage, append-only files, and RDB snapshots. Don't use this for data you need to keep.

```yaml
services:
  cache:
    type: redis
    persist: false
```

Run `lando start`, set a disposable key, then run `lando restart` and read it again:

```sh
lando redis-cli set temporary value
lando restart
lando redis-cli exists temporary
```

The key should no longer exist. A durable Redis service retains its keys instead.

## Change the port

Set `port:` to move the daemon's listener, healthcheck, endpoint, and Lando's `redis-cli` task together:

```yaml
services:
  cache:
    type: redis
    port: 6380
```

Lando passes `--port 6380` to `redis-server`, with or without persistence or password authentication. Other services connect to `cache:6380`. Redis has no daemon-native port environment variable.

If you author `command:`, include `--port 6380` yourself; Lando won't append it to a command you wrote. An authored `entrypoint:` still receives Lando's `redis-server` command, port included. The managed `password:` and `persist:` options can't be combined with an authored `command:` or `entrypoint:`.

If Redis never becomes ready, `lando start` reports which ports it's actually listening on, so a launcher that ignores `port:` is easy to spot. See [Inspect a failed start](./wait-for-your-app.mdx#inspect-a-failed-start).

Apply the change with `lando rebuild`, then probe the planned port:

```sh
lando redis-cli ping
```

## Pin a version

Set `image:` when `redis:7` isn't the version you want:

```yaml
services:
  cache:
    type: redis
    image: redis:6
```
