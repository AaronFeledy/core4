# Add Mailpit

Put `type: mailpit` in your services block. Lando routes the web UI so you can read captured SMTP:

```yaml
name: mailpit-demo
services:
  inbox:
    type: mailpit
```

Mailpit listens on SMTP port `1025` and serves its UI on `8025`. Open
`https://inbox.mailpit-demo.lndo.site` after start.

This is separate from the **global** Mailpit that lives in the host-level
Lando app (`https://mailpit.lndo.site`). Keep the global one when every
app on the machine should share one inbox. Use `type: mailpit` when this
app needs its own capture server.

## Choose PHP senders

Omit `mailFrom:` to connect every resolved PHP service to this inbox. Set it to `false` to wire none, or list only the PHP services that should send here:

```yaml
services:
  web:
    type: "php:8.3"
  worker:
    type: "php:8.3"
    via: cli
  inbox:
    type: mailpit
    mailFrom:
      - web
```

Run `lando rebuild`, then send a message from `web`:

```sh
lando exec web -- php -r 'mail("you@example.test", "Mailpit check", "Hello from PHP");'
lando info
```

Open the inbox URL printed by `lando info` and check for the message. Lando installs `msmtp` and sets PHP's `sendmail_path` only on selected services. Here, `worker` keeps its existing mail configuration. Duplicate names are removed in first-occurrence order. Unknown names and non-PHP targets fail planning before any provider action. An app with no PHP services needs no opt-out.

SMTP stays on `1025` unless you set `port:`. The UI stays on `8025`. Lando
adds a default hostname route to that UI port; override `routes:` when you
want a different URL.

## Replace MailHog

`type: mailhog` still plans as a working SMTP + UI service, but it is
deprecated since 4.2.0 and scheduled for removal in 5.0.0. Switch to
`type: mailpit`. `lando doctor --deprecations` reports the old type.
