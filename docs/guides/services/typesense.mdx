# Add Typesense with Compose

Put Typesense next to your app with `type: compose` on the official image, and pass the data dir plus API key the same way the upstream Compose file does:

```yaml
name: typesense-demo
services:
  search:
    type: compose
    image: typesense/typesense:30.2
    appMount: false
    home: false
    ports:
      - 8108:8108
    volumes:
      - ./typesense-data:/data
    command: '--data-dir /data --api-key=xyz --enable-cors'
```

`appMount: false` keeps Typesense off your app tree. Landofile-supplied images need `home: false` or `home.path`; omitting both refuses with `HomePathCapabilityError`. This example uses `home: false` because Lando does not know that image's user or home path. Set `home.path` when you know the path. See [Keep a service home across rebuilds and reach your host](../home-and-host/). Create the host data directory, then start:

```sh
mkdir -p typesense-data
lando start
lando info
```

`lando info` lists `tcp://localhost:8108` for `search`.

## Check health

Probe the HTTP surface from the host with the published port:

```sh
curl -sf http://localhost:8108/health
```

A healthy node returns `{"ok":true}`. Confirm the pinned version:

```sh
curl -sf -H 'X-TYPESENSE-API-KEY: xyz' http://localhost:8108/debug
```

That body includes `"version":"30.2"` for the image above. Swap `xyz` for your own key in both the Landofile and the header.

## Create a collection and search

Typesense's day-to-day API is plain HTTP. Create a collection, upsert a document, then search:

```sh
curl -sf -H 'X-TYPESENSE-API-KEY: xyz' -H 'Content-Type: application/json' \
  http://localhost:8108/collections \
  -d '{"name":"books","fields":[{"name":"title","type":"string"},{"name":"author","type":"string"}]}'

curl -sf -H 'X-TYPESENSE-API-KEY: xyz' -H 'Content-Type: application/json' \
  'http://localhost:8108/collections/books/documents?action=upsert' \
  -d '{"id":"1","title":"The Lando Files","author":"Cloud City"}'

curl -sf -H 'X-TYPESENSE-API-KEY: xyz' \
  'http://localhost:8108/collections/books/documents/search?q=Lando&query_by=title'
```

The search response reports `found` and the matching document. Same shape as the Typesense docs, just pointed at the Lando-published port.

## Reach Typesense from another service

Other services on the app join the same network. The hostname is the service key `search`, and the port is `8108`:

```
http://search:8108
```

From a Node or PHP service, call that URL with the `X-TYPESENSE-API-KEY` header. Do not use `localhost` inside another container. That is the container itself, not Typesense.

## Pass flags

A string `command:` or `entrypoint:` on a `type: compose` service splits into argv the way Compose splits it: on whitespace, with quotes grouping words. No shell runs. The example above becomes exactly:

```
["--data-dir", "/data", "--api-key=xyz", "--enable-cors"]
```

That is the upstream Typesense Compose one-liner, unchanged. A list works the same and skips the split:

```yaml
command:
  - --data-dir
  - /data
  - --api-key=xyz
  - --enable-cors
```

Typesense also reads `TYPESENSE_DATA_DIR`, `TYPESENSE_API_KEY`, and `TYPESENSE_ENABLE_CORS` from `environment:` if you would rather not put the key on the command line.

Splitting is not a shell. It does not expand `$VARS`, globs, or `~`, and an unquoted `;`, `&`, `|`, `<`, or `>` ends the argv there, so `a && b` only ever runs `a`. The Typesense image has a binary entrypoint, so every argv entry goes to that binary; a `sh -c` prefix would too. For the shell pattern on an image that has one, see [Add a Compose service](../compose-passthrough/).

Malformed quotes fail planning with `LandofileValidationError`. This split applies only to `type: compose`. Other service types keep their string `command` as a shell script.

## Pin a version

Change the image tag when you want a different Typesense release:

```yaml
services:
  search:
    type: compose
    image: typesense/typesense:29.1
```

Keep the data directory and API key the same across bumps unless that release's upgrade notes say otherwise.
