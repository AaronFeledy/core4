# Add Typesense with Compose

Need a Typesense server next to your app. Put `type: compose` on the official image and wire the data dir plus API key through environment variables:

```yaml
name: typesense-demo
services:
  search:
    type: compose
    image: typesense/typesense:30.2
    appMount: false
    home: false
    ports:
      - 8108:8108
    volumes:
      - ./typesense-data:/data
    environment:
      TYPESENSE_DATA_DIR: /data
      TYPESENSE_API_KEY: xyz
      TYPESENSE_ENABLE_CORS: "true"
```

`appMount: false` keeps Typesense off your app tree. `home: false` is required when the image comes from the Landofile, because Lando does not know that image's user or home path. Create the host data directory, then start:

```sh
mkdir -p typesense-data
lando start
lando info
```

`lando info` lists `tcp://localhost:8108` for `search`.

## Check health

Probe the HTTP surface from the host with the published port:

```sh
curl -sf http://localhost:8108/health
```

A healthy node returns `{"ok":true}`. Confirm the pinned version:

```sh
curl -sf -H 'X-TYPESENSE-API-KEY: xyz' http://localhost:8108/debug
```

That body includes `"version":"30.2"` for the image above. Swap `xyz` for your own key in both the Landofile and the header.

## Create a collection and search

Typesense's day-to-day API is plain HTTP. Create a collection, upsert a document, then search:

```sh
curl -sf -H 'X-TYPESENSE-API-KEY: xyz' -H 'Content-Type: application/json' \
  http://localhost:8108/collections \
  -d '{"name":"books","fields":[{"name":"title","type":"string"},{"name":"author","type":"string"}]}'

curl -sf -H 'X-TYPESENSE-API-KEY: xyz' -H 'Content-Type: application/json' \
  'http://localhost:8108/collections/books/documents?action=upsert' \
  -d '{"id":"1","title":"The Lando Files","author":"Cloud City"}'

curl -sf -H 'X-TYPESENSE-API-KEY: xyz' \
  'http://localhost:8108/collections/books/documents/search?q=Lando&query_by=title'
```

The search response reports `found` and the matching document. Same shape as the Typesense docs, just pointed at the Lando-published port.

## Reach Typesense from another service

Other services on the app join the same network. The hostname is the service key `search`, and the port is `8108`:

```
http://search:8108
```

From a Node or PHP service, call that URL with the `X-TYPESENSE-API-KEY` header. Do not use `localhost` inside another container. That is the container itself, not Typesense.

## Pass flags as a command list

Prefer the environment variables above. If you set `command:` instead, use a YAML list of argv entries:

```yaml
services:
  search:
    type: compose
    image: typesense/typesense:30.2
    appMount: false
    home: false
    ports:
      - 8108:8108
    volumes:
      - ./typesense-data:/data
    command:
      - --data-dir
      - /data
      - --api-key
      - xyz
      - --enable-cors
```

## Pin a version

Change the image tag when you want a different Typesense release:

```yaml
services:
  search:
    type: compose
    image: typesense/typesense:29.1
```

Keep the data directory and API key the same across bumps unless that release's upgrade notes say otherwise.
