# Add OpenSearch

Add `type: opensearch` under `services` in `.lando.yml`. That resolves to `opensearch:2`. Lando pulls `opensearchproject/opensearch:2` and listens on `9200`. OpenSearch uses the Apache 2.0 license. The default local-development configuration disables the demo security plugin; do not expose it as a production service:

```yaml
name: opensearch-demo
services:
  search:
    type: opensearch
```

## Check cluster health

After start, query the same cluster-health endpoint that Lando checks inside `search`:

```sh
lando exec search -- curl -sf http://localhost:9200/_cluster/health
```

A healthy single-node OpenSearch reports `green` or `yellow`.

## Use Elasticsearch 7 clients

OpenSearch 2 is API-compatible with Elasticsearch 7, so most Elasticsearch 7 clients and queries work against it unchanged. Local dev disables the demo security plugin. Production must configure TLS and auth.

## Change the HTTP port

Set `port:` to move the HTTP API, healthcheck, and endpoint together. Lando sets `http.port` from that value:

```yaml
services:
  search:
    type: opensearch
    port: 9201
```

The transport listener stays on `9300` by default. Move it with a scalar `transport.port` under `environment:` when HTTP needs that number:

```yaml
services:
  search:
    type: opensearch
    port: 9300
    environment:
      transport.port: "9301"
```

HTTP cannot equal the effective transport port. Planning fails when they collide.
Use one integer from `1` to `65535` for `transport.port`; ranges and malformed
values fail planning at `services.<name>.environment["transport.port"]`.
An authored `http.port` must match `port:`, or planning fails at that environment
key. Lando never appends flags to an authored `command:` or `entrypoint:`.

Validate with `lando app:cache:refresh --format=json` before start.

## Pin a version

Set `image:` when `opensearch:2` isn't the version you want:

```yaml
services:
  search:
    type: opensearch
    image: opensearchproject/opensearch:2.17.0
```
