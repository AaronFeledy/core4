# Add MySQL

Put `type: mysql` in your services block. Lando pulls `mysql:8.0` and listens on `3306`:

```yaml
name: mysql-demo
services:
  db:
    type: mysql
```

Set `creds:` when you want explicit values. Defaults stay `lando` / `lando` / the app name, plus a generated root password. `creds.user` is the database username. Container `user:` is not.

```yaml
services:
  db:
    type: mysql
    creds:
      user: lando
      password: lando
      database: mysql-demo
      rootPassword: secret
```

Start it. Lando puts the database on the app network:

## Connect from another service

Other services use the service name as the hostname. Here that's `db`. Defaults:

| Setting | Value |
| --- | --- |
| Host | `db` |
| Database | the app name (`mysql-demo`); override with `database:` under `services.db` |
| User | `lando` |
| Password | `lando` |
| Root password | derived per app; `LANDO_DB_ROOT_PASSWORD` inside the service |

From inside the app network the connection URL is:

```
mysql://lando:lando@db:3306/mysql-demo
```

## Open the client

The `mysql` type ships the client task. After start:

```sh
lando mysql --version
```

Import a dump with `lando db:import`. See [Import and export app databases](../tooling/db-import-export.mdx). You can still pipe into `mysql` with `lando exec`.

## Add server config

Set `config.server` to an app-relative file when you need to tune the server:

```yaml
services:
  db:
    type: mysql
    config:
      server: ./config/my.cnf
```

Lando mounts that file read-only at `/etc/mysql/my.cnf`. MySQL reads it directly on startup, after the image's `/etc/my.cnf`, without relying on that file's include directives. It has to be a regular file, not a directory.

The path has to stay inside the app root. Absolute paths, paths that climb out of the app root, and symlinks that point outside it are rejected when Lando plans the app, before anything starts.

## Pin a version

Choose a managed series in `type:`. Lando supports MySQL 8.0, 8.4 LTS, and 9.7 LTS. An unversioned `mysql` service stays on 8.0.

```yaml
services:
  db:
    type: "mysql:8.4"
```

Use unversioned `type: mysql` with `image:` only for a custom image whose compatibility you manage yourself. A versioned type plus `image:` is conflicting intent and fails during planning.

New stores use `<app>-<service>-mysql-data`, independent of the server version. If your app has exactly one MySQL service, its legacy `<app>-mysql-data` volume exists, and its scoped volume does not, Lando keeps using the legacy volume in place. If both volumes exist, the scoped volume wins. With multiple MySQL services, each uses its scoped identity and the legacy volume stays untouched. This selection never renames, copies, migrates, or deletes a volume.

Keeping a volume's identity is not an upgrade compatibility check. Existing databases still depend on the SQL recovery guard for changed or unknown initialized series; do not treat a type change as a safe datadir upgrade.

Oracle MySQL clients installed into PHP services use Oracle's signed Bookworm APT repository on amd64 and SHA256-pinned Oracle EL9 RPM payloads on Linux arm64 for all three series (8.0, 8.4, and 9.7). The arm64 support policy covers default `caching_sha2_password` authentication, not LDAP/SASL plugins. Live arm64 build, connection, and dump/restore verification is still pending. See [Customize PHP](./php-customization.mdx).
