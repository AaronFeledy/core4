Every `type: lando` service includes the `lando.boot` feature. During the artifact build it creates
the shared Lando directory scaffold with an idempotent `mkdir -p` step:

```text
/etc/lando
/etc/lando/env.d
/etc/lando/certs
```

The scaffold is baked into the service artifact. It is not a mount, so it does not hide files that
higher-priority features add beneath these directories. `lando.certs` uses the certificate directory
for service leaf material, while `lando.security` uses it for the injected CA bundle described in
[Corporate network trust](../config/corporate-network-trust.mdx).

`lando.boot` owns directories only. The higher-priority `lando.env` feature owns
`/etc/lando/environment`, `env.d/` content and per-exec sourcing, and the `LANDO_LINUX_*` distro
exports. See [Certificates with mkcert](../subsystems/certificates-mkcert.mdx) for the separate leaf
certificate paths and environment contract.
