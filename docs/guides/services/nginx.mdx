# Add nginx

Add `type: nginx` under `services` in `.lando.yml`. Lando pulls `nginx:1.26-alpine` and listens on `80`. Your repository is mounted at `/app` and served as the document root:

```yaml
name: nginx-demo
services:
  web:
    type: nginx
```

## Open the URL

Lando derives an HTTPS hostname from the nginx service's HTTP endpoint, such as `web.<app>.lndo.site`. Use the URL reported by `lando info`, including any fallback port. You only need a `proxy:` block to customize hostnames.

## Pair nginx with PHP

nginx is commonly paired with a `php-fpm` service: nginx serves static
files and proxies dynamic requests to the app service over the per-app
network.

```yaml
services:
  web:
    type: nginx
    backend: app
  app:
    type: "php:8.3"
    via: fpm
```

## Stop PHP in upload directories

Set `uploadDirs:` on the nginx service in front of PHP-FPM, not on the FPM service. Lando's generated PHP location blocks execution from these webroot-relative directories:

```yaml
services:
  web:
    type: nginx
    backend: app
    uploadDirs:
      - sites/*/files
      - uploads
  app:
    type: "php:8.3"
    via: fpm
```

The nginx service needs a non-empty `backend` and Lando's generated launcher, with no authored `command:` or `entrypoint:`. See [Keep PHP out of upload directories](./php.mdx#keep-php-out-of-upload-directories) for syntax, recipe defaults, Apache support, and how to check or clear the setting.

## Serve a subdirectory

Set `webroot:` to a path relative to the app mount at `/app`. For example, `public` serves `/app/public`. Omit it or use `.` to serve the app root. An absolute container path is allowed when you need a very specific location outside the usual app layout. Inside the container, `LANDO_WEBROOT` is always the resolved absolute path. Set `port:` to move nginx's listener, endpoint, and healthcheck together:

```yaml
services:
  web:
    type: nginx
    webroot: public
    port: 8080
```

## Run as a non-root user

Set `user: nginx` to run nginx as the image's own `nginx` account, with or without a PHP backend. Lando writes its whole nginx configuration to `/tmp/lando-nginx.conf`, points the PID file and temp directories at `/tmp` too, and starts the daemon with `nginx -c /tmp/lando-nginx.conf`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: nginx
    user: nginx
    port: 8080
```

Lando plans no home store for the `nginx` account, whose home on this image is its cache directory; set `home.path:` when you want a directory to survive a rebuild. A non-root process can't bind below 1024 on the default `lando` provider, so pick something at or above `1024`.

If you set your own `command:` or `entrypoint:`, your startup owns nginx's
configuration. Lando never appends listen directives or flags to an authored
launcher, and it does not generate a config or remove the image's default site.
Match the daemon to `port:` yourself.
If startup fails with this override, Lando includes a hint naming the required
`listen <port>;` directive with your planned port number.

## Pin a version

Set `image:` when `nginx:1.26-alpine` isn't the version you want:

```yaml
services:
  web:
    type: nginx
    image: nginx:1.27-alpine
```
