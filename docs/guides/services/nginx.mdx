# Add nginx

Put `type: nginx` in your services block. Lando pulls `nginx:1.26-alpine` and listens on `80`. Your repository is mounted at `/app` and served as the document root:

```yaml
name: nginx-demo
services:
  web:
    type: nginx
```

## Open the URL

The proxy auto-derives an HTTPS hostname from the nginx service's HTTP endpoint, something like `web.<app>.lndo.site`. You only need a `proxy:` block to customize hostnames.

## Pair nginx with PHP

nginx is commonly paired with a `php-fpm` service: nginx serves static
files and proxies dynamic requests to the app service over the per-app
network.

```yaml
services:
  web:
    type: nginx
    backend: app
  app:
    type: "php:8.3"
    via: fpm
```

## Run as a non-root user

Set `user: nginx` to run nginx as the image's own `nginx` account. Lando writes its whole nginx configuration to `/tmp/lando-nginx.conf`, points the PID file and temp directories at `/tmp` too, and starts the daemon with `nginx -c /tmp/lando-nginx.conf`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: nginx
    backend: app
    user: nginx
    home: false
    port: 8080
```

`home: false` is there because Lando persists the planned user's home directory and only knows where `root`'s home is on this image. Use `home.path:` instead when you want that directory to survive a rebuild. `port:` moves the listen port itself, not just Lando's endpoint, because Lando templates it into the generated config. A non-root process can't bind below 1024 on the default `lando` provider, so pick something at or above `1024`. This applies to the generated launcher, which nginx only uses with `backend:`; without it the image entrypoint starts the daemon and owns the port.

## Pin a version

Set `image:` when `nginx:1.26-alpine` isn't the version you want:

```yaml
services:
  web:
    type: nginx
    image: nginx:1.27-alpine
```
