# Add nginx

Put `type: nginx` in your services block. Lando pulls `nginx:1.26-alpine` and listens on `80`. Your repository is mounted at `/app` and served as the document root:

```yaml
name: nginx-demo
services:
  web:
    type: nginx
```

## Open the URL

The proxy auto-derives an HTTPS hostname from the nginx service's HTTP endpoint, something like `web.<app>.lndo.site`. You only need a `proxy:` block to customize hostnames.

## Pair nginx with PHP

nginx is commonly paired with a `php-fpm` service: nginx serves static
files and proxies dynamic requests to the app service over the per-app
network.

```yaml
services:
  web:
    type: nginx
    backend: app
  app:
    type: "php:8.3"
    via: fpm
```

## Stop PHP in upload directories

Add `noScripts:` to the nginx service from the PHP example above. List upload directories as URI paths relative to the webroot, not host filesystem paths:

```yaml
services:
  web:
    type: nginx
    backend: app
    noScripts:
      - sites/*/files
      - uploads
  app:
    type: "php:8.3"
    via: fpm
```

With Lando's generated FastCGI configuration, requests for PHP files beneath these paths return 403, including paths such as `/uploads/file.php/extra`. The match is case-insensitive. `*` matches within one path segment, so `sites/*/files` covers both `sites/default/files` and `sites/example.com/files`. Front controllers such as `/index.php` and Drupal image-style fallbacks remain reachable.

Use letters, digits, `.`, `_`, `/`, `-`, and `*` in these paths. An entry cannot be empty, consist only of `*`, start or end with `/`, or contain `..`, `**`, an empty segment such as `a//b`, or a `.` segment such as `a/./b`.

From the app directory, check the path syntax before rebuilding:

```sh
lando app:config:lint
```

An invalid entry produces a violation under `services.<name>.noScripts`. Fix it before running `lando rebuild` to apply the configuration.

Drupal and Drupal CMS set `sites/*/files` automatically when you choose nginx. Setting `noScripts: []` on that nginx service removes this protection, so do that only if you intend to allow PHP requests beneath the upload paths.

`noScripts` configures Lando's generated nginx FastCGI launcher. It has no effect on other service types, or when you replace nginx's `command:` or `entrypoint:` and supply your own configuration.

## Serve a subdirectory

Set `webroot:` to a path relative to the app mount at `/app`. For example, `public` serves `/app/public`. Omit it or use `.` to serve the app root. An absolute container path is allowed when you need a very specific location outside the usual app layout. Inside the container, `LANDO_WEBROOT` is always the resolved absolute path. Set `port:` to move nginx's listener, endpoint, and healthcheck together:

```yaml
services:
  web:
    type: nginx
    webroot: public
    port: 8080
```

## Run as a non-root user

Set `user: nginx` to run nginx as the image's own `nginx` account, with or without a PHP backend. Lando writes its whole nginx configuration to `/tmp/lando-nginx.conf`, points the PID file and temp directories at `/tmp` too, and starts the daemon with `nginx -c /tmp/lando-nginx.conf`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: nginx
    user: nginx
    home: false
    port: 8080
```

`home: false` is there because Lando persists the planned user's home directory and only knows where `root`'s home is on this image. Use `home.path:` instead when you want that directory to survive a rebuild. A non-root process can't bind below 1024 on the default `lando` provider, so pick something at or above `1024`.

If you set your own `command:` or `entrypoint:`, your startup owns nginx's configuration. Lando does not generate a launcher or remove the image's default site.

## Pin a version

Set `image:` when `nginx:1.26-alpine` isn't the version you want:

```yaml
services:
  web:
    type: nginx
    image: nginx:1.27-alpine
```
