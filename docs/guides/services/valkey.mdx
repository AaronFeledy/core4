# Add Valkey

Add `type: valkey` under `services` in `.lando.yml`. Lando pulls `valkey/valkey:8` and listens on `6379`:

```yaml
name: valkey-demo
services:
  cache:
    type: valkey
tooling:
  valkey-cli:
    service: cache
    cmd:
      - valkey-cli
```

## Connect from another service

From another app service, use hostname `cache` and port `6379`. `localhost` inside that service refers to its own container, not Valkey.

`lando info` advertises both a `valkey://` endpoint (primary) and a `redis://` alias, so new and existing client libraries connect without code changes:

```
valkey://localhost:6379
redis://localhost:6379
```

## Open the client

The Landofile above declares `valkey-cli` as an app tooling alias. Ping the cache to verify it's reachable:

```sh
lando valkey-cli ping
```

Store and read a key:

```sh
lando valkey-cli set hello world
lando valkey-cli get hello
```

## Pin a version

For a custom `image:`, also set `home: false` on that service, or supply `home.path` for a home directory you know exists in the image. Without either, planning fails because Lando cannot infer the custom image's home. See [service home configuration](./home-and-host.mdx).

Set `image:` when the default image isn't the version you want:

```yaml
services:
  cache:
    type: valkey
    image: valkey/valkey:7
```
