# Add Valkey

Add `type: valkey` under `services` in `.lando.yml`. Lando pulls `valkey/valkey:8` and listens on `6379`:

```yaml
name: valkey-demo
services:
  cache:
    type: valkey
tooling:
  valkey-cli:
    service: cache
    cmd:
      - valkey-cli
```

## Connect from another service

From another app service, use hostname `cache` and port `6379`. `localhost` inside that service refers to its own container, not Valkey.

`lando info` lists the App Network connection as a `valkey://` URL with a `redis://` alternate, so new and existing client libraries connect without code changes:

```
valkey://cache:6379
redis://cache:6379
```

Valkey publishes no host port by default, so there is no Host connection to open from this machine. Add a `ports:` entry when a desktop client needs one.

## Open the client

The Landofile above declares `valkey-cli` as an app tooling alias. Ping the cache to verify it's reachable:

```sh
lando valkey-cli ping
```

Store and read a key:

```sh
lando valkey-cli set hello world
lando valkey-cli get hello
```

## Configure the listener

Set `port:` to change Valkey's listener and healthcheck together. An authored `command:` owns the listener configuration; pass the planned port with `--port` or configure it in Valkey's config file. An authored `entrypoint:` still receives Lando's command with `--port` and must execute the supplied command and arguments. If Valkey never becomes ready, `lando start` reports which ports it's actually listening on, so a launcher that ignores `port:` is easy to spot. See [Inspect a failed start](./wait-for-your-app.mdx#inspect-a-failed-start).

## Pin a version

Set `image:` when the default image isn't the version you want:

```yaml
services:
  cache:
    type: valkey
    image: valkey/valkey:7
```
