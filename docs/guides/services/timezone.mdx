# Set the timezone

Set `TZ` under the service's `environment` map in `.lando.yml`. Landofiles have no dedicated `timezone:` key. This is a different mechanism from `LANDO_CONFIG__` env overrides (see [env-overrides](../landofile/env-overrides.mdx)), which overlay Lando's own config instead:

```yaml
name: timezone-demo
services:
  app:
    type: "node:22"
    primary: true
    environment:
      TZ: "Europe/Berlin"
```

## Don't interpolate host env

Do not use `${HOST_VAR}` to copy a host-shell variable into this setting. Lando rejects that form with `LandofileValidationError` at the value's path, here `services.app.environment.TZ`. Use `{{ env.HOST_VAR }}` to read your host, or `$${HOST_VAR}` when the container shell should expand it; see [Landofile expressions](../landofile/expressions.mdx#keep-var-and--as-text). The scenario below checks the rejection:

## Apply a changed timezone

After editing `environment:` in `.lando.yml`, restart the app. The
restarted containers pick up the new `TZ` value:

```sh
lando restart
```
