# Add Ruby

Put `type: ruby:3.3` on the primary service. Ruby has no bare `type: ruby` alias, so pin a version.
Lando currently supports `ruby:3.3`, and the default image is
`ruby:3.3-slim`. Your repository is bind-mounted read-write at `/app` by
default, which is also the working directory:

```yaml
name: ruby-demo
services:
  app:
    type: "ruby:3.3"
    primary: true
```

## Run the app

The default keep-alive command holds the container open so you can install
gems and run your app via tooling:

```sh
# Declare a bundle tooling alias to install gems inside the service
lando bundle install

# Run a Rails server with lando exec; bind to 0.0.0.0 so the proxy can reach it
lando exec app -- bundle exec rails server -b 0.0.0.0
```

Ruby publishes its port endpoint but has no default healthcheck, even with an authored `command:`. Add `healthcheck:` when you want start to wait for application readiness; otherwise Lando checks that the process stays running.

## Set the Rails webroot

Run `lando rebuild` after adding `framework: rails` and your `webroot:` to the service:

```yaml
services:
  app:
    type: "ruby:3.3"
    primary: true
    framework: rails
    webroot: frontend/public
```

Rails defaults to `webroot: public`; without a framework, Ruby defaults to `.`.
Your `webroot:` wins in either case. Relative paths resolve against
`appMount.target` (default `/app`), so this sets `LANDO_WEBROOT` to
`/app/frontend/public`. Set `appMount.target: /site` to get
`/site/frontend/public`, or use an absolute container path such as `/srv/www`.
Relative paths can't escape the app mount with `..`.

Verify the value inside the running service:

```sh
lando rebuild
lando exec app -- printenv LANDO_WEBROOT
```

The webroot doesn't move the working directory or start a Rails server.
Use `workingDirectory:` and `command:` for those. The Rails preset supplies
development environment defaults and a server command hint; an authored
environment value still wins. With `appMount: false`, Ruby omits the webroot
from `LANDO_WEBROOT` and its service metadata, even if you set `webroot:`.

## Pin a version

Set `image:` to use the full (non-slim) or an alternate Ruby base image when
`ruby:3.3-slim` isn't what you want. Slim lacks build tools that some gems need:

```yaml
services:
  app:
    type: "ruby:3.3"
    image: ruby:3.3
```
