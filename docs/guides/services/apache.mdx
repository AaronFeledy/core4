# Add Apache

Add `type: apache` under `services` in `.lando.yml`. Lando pulls `httpd:2.4-alpine` and listens on `80`:

```yaml
name: apache-demo
services:
  web:
    type: apache
```

Your repository is mounted at `/app`. The default `webroot` is `.`, resolving to `/app` for `APACHE_DOCUMENT_ROOT`. Start it. Lando wires the service into the proxy:

## Open the URL

The proxy derives an HTTPS hostname from the service's HTTP endpoint without a `proxy:` block. You'll get something like `web.<app>.lndo.site`.

Set `webroot:` to an app-relative path when Apache should serve a subdirectory. Lando resolves it against `/app`, writes the absolute path into Apache's generated config, and exposes that resolved absolute path as `LANDO_WEBROOT` and `APACHE_DOCUMENT_ROOT`. Omit it or use `.` for the app root. An absolute container path is allowed when you need a very specific location outside the usual app layout:

```yaml
services:
  web:
    type: apache
    webroot: public
```

An explicit `environment.APACHE_DOCUMENT_ROOT` still wins for custom setups. If you replace `command:` or `entrypoint:`, your launcher owns the Apache config too.

## Run as a non-root user

Set `user: www-data` to run Apache as the image's `www-data` account. Lando hands its directives to `httpd-foreground` as `-c` arguments and points the PID file at `/tmp/lando-httpd.pid`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: apache
    user: www-data
```

On the default `lando` provider, this non-root configuration also needs a port of 1024 or above: the process cannot bind the image's default port `80`. Set `port:` to 1024 or above and Apache listens there instead. Lando passes `Listen <port>` as a `-c` directive and drops the image's `Listen 80` from `httpd.conf` during the build, so the daemon binds only the port you picked:

```yaml
services:
  web:
    type: apache
    user: www-data
    port: 8080
```

Leave `port:` out and nothing changes: same launcher, same image, no extra build step. If you set your own `command:` or `entrypoint:`, Lando does not generate the launcher or touch the image config. Point `image:` at something other than `httpd:2.4-alpine` and Lando still generates the start command, but it does not emit `Listen` or edit `httpd.conf`. That image owns its own listener.

## Pin a version

For a custom `image:`, also set `home: false` on that service, or supply `home.path` for a home directory you know exists in the image. Without either, planning fails because Lando cannot infer the custom image's home. See [service home configuration](./home-and-host.mdx).

Set `image:` when `httpd:2.4-alpine` isn't the version you want. For example, a Debian-based image:

```yaml
services:
  web:
    type: apache
    image: httpd:2.4
```
