# Add RabbitMQ

Put `type: rabbitmq` in your services block. That shorthand is an alias for the RabbitMQ 4 image line:

```yaml
name: rabbitmq-demo
services:
  queue:
    type: rabbitmq
```

## Pick a version

Use `rabbitmq:4` when you want the default major version written out. Choose
`rabbitmq:3` for an app that still needs RabbitMQ 3:

```yaml
services:
  queue:
    type: rabbitmq:3
```

## Connect

Other services connect to `queue` on the standard AMQP port, `5672`. The
default username and password are both `lando`, so the local connection URL is:

```
amqp://lando:lando@queue:5672
```

That URL uses the default AMQP port. Use your authored `port:` in application connection URLs.

RabbitMQ also exposes its management UI on port `15672`. Lando gives that UI a
default route, so check `lando info` for the app URL instead of guessing a host
port. Sign in with `lando` and `lando`.

## Change the port

Set `port:` to move the AMQP listener and endpoint together:

```yaml
services:
  queue:
    type: rabbitmq
    port: 5673
```

Lando sets `RABBITMQ_NODE_PORT` from `port:`. An authored `RABBITMQ_NODE_PORT` must match the planned port, or planning fails; `lando app:config:lint` reports the mismatch at `services.<name>.environment.RABBITMQ_NODE_PORT`. An authored `command:` or `entrypoint:` owns the daemon's flags and must honor the planned port.

Ports `4369` (EPMD), `15672` (management UI), and `15692` (Prometheus) can't be the AMQP port. The AMQP port must leave room for distribution: at most `45535` unless you set `RABBITMQ_DIST_PORT` under `environment:`. That distribution port must be a TCP port number (1-65535), different from the AMQP port and all three reserved ports. Invalid or conflicting ports fail planning, and `lando app:config:lint` reports them at `services.<name>.port` or `services.<name>.environment.RABBITMQ_DIST_PORT`.

The healthcheck and `rabbitmqctl` use the local Erlang node, not an AMQP connection. The management UI and `rabbitmqadmin` stay on `15672`: `port:` only moves AMQP. Apply the change with `lando rebuild`, then check the broker's listeners:

```sh
lando rabbitmqctl eval 'rabbit_networking:active_listeners().'
```

## Keep queue data

RabbitMQ stores its data in `/var/lib/rabbitmq`. The service mounts persistent
storage there by default, which keeps queues and messages across ordinary
restarts. Destroying the app removes that app-owned data.

## Manage the broker

The service adds `rabbitmqctl` and `rabbitmqadmin` tooling aliases. Run them
from your host when you need to inspect queues, users, or broker state:

```sh
lando rabbitmqctl list_queues
lando rabbitmqadmin list exchanges
```
