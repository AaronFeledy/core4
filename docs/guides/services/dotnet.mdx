# Add .NET

Add `type: dotnet` under `services` in `.lando.yml` at the root of your .NET project. That shorthand is the .NET 9 SDK image, which includes the ASP.NET runtime. Lando mounts the app at `/app` and keeps the container idle until you set `command:` to your dev server:

```yaml
name: dotnet-demo
services:
  appserver:
    type: dotnet
    command:
      - dotnet
      - run
      - --no-launch-profile
```

## Pick a version

Use `dotnet:9.0` when you want the default major written out. Choose
`dotnet:8.0` for the previous LTS line:

```yaml
services:
  appserver:
    type: dotnet:8.0
```

## Run the app

Set `command:` to your project's development-server command. The example uses `dotnet run --no-launch-profile`, which lets ASP.NET Core use the port Lando supplies. Run `lando start` after saving the Landofile, then `lando info --format=json` to find the app route.

## Pass `port:` to ASP.NET Core

| Variable | Value | Who reads it |
| --- | --- | --- |
| `ASPNETCORE_HTTP_PORTS` | `port:`, default `5000` | ASP.NET Core 8+ binds HTTP on all interfaces at that port |

Lando uses the same port for this variable and the internal HTTP endpoint, replacing the official SDK image's `8080` environment default. To move the listener, set `port:` on `appserver`; you do not need `--urls` for the normal case.

An authored `environment.ASPNETCORE_HTTP_PORTS` must be one literal integer equal to the planned port. Malformed values, port lists, and unequal values fail planning at `services.appserver.environment.ASPNETCORE_HTTP_PORTS`, including inherited `appEnv` and env-file values. Set `port:` instead.

Use `--no-launch-profile`: `launchSettings.json` can set `applicationUrl`, which becomes `ASPNETCORE_URLS` and overrides `ASPNETCORE_HTTP_PORTS`. An authored `ASPNETCORE_URLS`, a `--urls` argument, or application code configuring Kestrel also takes precedence. Those settings remain yours to align with `port:`; Lando does not validate their URLs or rewrite them.

Projecting a port does not infer a healthcheck.

## Cache and the default route

NuGet packages land in a shared cache at `/root/.nuget/packages`. The
service declares an HTTP endpoint at `5000`, gets a default hostname route, and turns on
`lando.certs`. Set `certs: false` if you do not want a leaf certificate.

```sh
lando info --format=json
```
