# PHP

Add a PHP service to your app by declaring `type: php:8.3` for the primary
service — PHP has no bare `type: php` alias, so pin a version. Lando
currently supports four minor versions: `8.1`, `8.2`, `8.3`, and `8.4`. The
default (and only first-class) image is the `-apache` variant, tagged
`php:<version>-apache-bookworm` (e.g. `php:8.3-apache-bookworm`), which
serves your code over HTTP on port `80`. Your repository is bind-mounted
read-write at `/app`:

```yaml
name: php-demo
services:
  app:
    type: "php:8.3"
    primary: true
```

## No framework presets

There's no `framework:` key on the `php` service — it has no built-in preset that switches the
served webroot for Drupal, Laravel, Symfony, or WordPress. The apache docroot is fixed at `/app`.
To serve project code from a framework's public subdirectory (e.g. Laravel's or Symfony's
`public/`), you're responsible for pointing the web server at that path yourself — for example with
a custom vhost delivered through a bind mount or custom image. Compose's `configs:` block isn't
realized by `provider-lando`, so a custom `php.ini` or vhost file has to be mounted in, not declared
under `configs:`.

## Composer and the CLI

PHP projects typically expose Composer as a tooling alias targeting the
service:

```sh
lando composer install
```

Composer itself is installed from a checksum-pinned release (`2.10.2`), not resolved from whatever
happens to be latest at build time.

A `php` alias runs the CLI inside the service:

```sh
lando php -v
```

## Pin a version

Pin any of the four supported PHP minor versions under `type`:

```yaml
services:
  app:
    type: php:8.2
```

`image:` overrides the base image Lando builds from, but there's no first-class FPM pairing behind
it: Lando doesn't wire up a companion nginx service, proxy FPM's port `9000`, or adjust
prerequisites for a `-fpm`-style tag. Setting `image:` to something other than the built-in
`-apache-bookworm` tag is a raw substitution you're responsible for wiring end to end yourself.
