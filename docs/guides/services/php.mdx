# PHP

Add a PHP service by pinning a minor version — PHP has no bare `type: php`
alias. Lando supports `8.1`, `8.2`, `8.3`, `8.4`, and `8.5`. The default
serving mode is Apache with mod_php on port `80`, using
`php:<version>-apache-bookworm`. Your repository is bind-mounted read-write at
`/app`:

```yaml
name: php-demo
services:
  app:
    type: "php:8.3"
    primary: true
```

## Serving modes

`via:` picks the image variant and process shape:

| `via:` | Image | What you get |
| --- | --- | --- |
| `apache` (default) | `php:<version>-apache-bookworm` | Apache + mod_php on port `80`. `webroot:` and `allowOverride:` apply. |
| `fpm` | `php:<version>-fpm-bookworm` | PHP-FPM on port `9000`. Front it with `nginx` and `backend:`. `allowOverride:` is rejected. |
| `cli` | `php:<version>-cli-bookworm` | Idle worker for tooling and `command:`. No web server, no HTTP route. |

Pair FPM with nginx by naming the PHP service on `backend:`. Nginx writes a
FastCGI upstream to that service on port `9000`:

```yaml
name: php-fpm-nginx
services:
  appserver:
    type: "php:8.3"
    via: fpm
    primary: true
  edge:
    type: nginx
    backend: appserver
```

## No framework presets

There's no `framework:` key on the `php` service — it has no built-in preset that switches the
served webroot for Drupal, Laravel, Symfony, or WordPress. The apache docroot is `/app` unless you
set `webroot:`. To serve a framework public directory, point `webroot:` at that path (or put nginx
in front with `via: fpm`). Compose's `configs:` block isn't realized by `provider-lando`, so a
custom `php.ini` or vhost file has to be mounted in, not declared under `configs:`.

## Composer and the CLI

PHP projects typically expose Composer as a tooling alias targeting the
service:

```sh
lando composer install
```

Stock PHP services install a checksum-pinned Composer 2 release (`2.10.2`).
Set `composer:` on the service to pick a different pinned version or skip the
install entirely — see [PHP Composer workflows](../tooling/php-composer-workflows.mdx).

A `php` alias runs the CLI inside the service:

```sh
lando php -v
```

## Pin a version

Pin any of the five supported PHP minor versions under `type`:

```yaml
services:
  app:
    type: php:8.2
```

`image:` still overrides the base image Lando builds from. You're responsible
for wiring a custom tag end to end.
