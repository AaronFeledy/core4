# Add PHP

Put `type: php:8.3` in your services block. PHP has no bare `type: php` alias, so pin a minor. Lando supports `8.1`, `8.2`, `8.3`, `8.4`, `8.5`, and `8.6`. The default serving mode is Apache with mod_php on port `80`. 8.1 through 8.5 use `php:<version>-apache-bookworm`. 8.6 uses the official RC tag `php:8.6-rc-apache-bookworm` until GA. Your repository is bind-mounted read-write at `/app`:

```yaml
name: php-demo
services:
  app:
    type: "php:8.3"
    primary: true
```

## Pick a serving mode

`via:` picks the image variant and process shape:

| `via:` | Image | What you get |
| --- | --- | --- |
| `apache` (default) | `php:<version>-apache-bookworm` | Apache + mod_php on port `80`. `webroot:` and `allowOverride:` apply. |
| `fpm` | `php:<version>-fpm-bookworm` | PHP-FPM on port `9000`. Front it with `nginx` and `backend:`. `allowOverride:` is rejected. |
| `cli` | `php:<version>-cli-bookworm` | Idle worker for tooling and `command:`. No web server, no HTTP route. |

Pair FPM with nginx by naming the PHP service on `backend:`. The nginx service
generates a FastCGI upstream pointing at that service on port `9000`:

```yaml
name: php-fpm-nginx
services:
  appserver:
    type: "php:8.3"
    via: fpm
    primary: true
  edge:
    type: nginx
    backend: appserver
```

## Run as a non-root user

Set `user:` to run an Apache-served PHP service as an account the image already
ships. Lando hands its Apache directives to `apache2-foreground` as `-c`
arguments and bakes the branded error pages into the image, so nothing is
written into the image's root-owned configuration tree at start:

```yaml
services:
  appserver:
    type: php:8.3
    user: www-data
    home: false
```

`home: false` is there because Lando persists the planned user's home directory
and only knows where `root`'s home is on the PHP images. Drop it and set
`home.path:` instead when you want that directory to survive a rebuild.

Apache still listens on `80`, which a non-root process cannot bind on the
default `lando` provider. `port:` moves Lando's endpoint and healthcheck, not
Apache's `Listen`. If start fails on that bind, replace `command:` or
`entrypoint:` so your launcher owns `Listen`.

`via: fpm` works the same way with a different file. Lando writes its pool
override to `/tmp/lando-php-fpm.conf` and starts the daemon with
`php-fpm -y /tmp/lando-php-fpm.conf`, so the image's `php-fpm.d` tree is never
touched:

```yaml
services:
  appserver:
    type: php:8.3
    via: fpm
    user: www-data
    home: false
```

FPM listens on `9000`, so there's no privileged port to worry about. Under a
non-root user php-fpm logs that the pool's `user` and `group` directives are
ignored. That's a notice, not a failure; the pool already runs as the account
you set.

## Set the webroot yourself

There's no `framework:` key on the `php` service. It has no built-in preset that switches the served webroot for Drupal, Laravel, Symfony, or WordPress. The apache docroot is `/app` unless you set `webroot:`. To serve a framework public directory, point `webroot:` at that path, or put nginx in front with `via: fpm`. Compose's `configs:` block isn't realized by `provider-lando`, so a custom `php.ini` or vhost file has to be mounted in, not declared under `configs:`.

## Run Composer

PHP projects typically expose Composer as a tooling alias targeting the
service:

```sh
lando composer install
```

Stock PHP services install a checksum-pinned Composer 2 release (`2.10.2`).
Set `composer:` on the service to pick a different pinned version, skip the install entirely, or use the object form to also bake global Composer packages into the image. See [PHP Composer workflows](../tooling/php-composer-workflows.mdx).

A `php` alias runs the CLI inside the service:

```sh
lando php -v
```

## Pin a version

Pin any of the six supported PHP minor versions under `type`:

```yaml
services:
  app:
    type: php:8.2
```

`image:` still overrides the base image Lando builds from. You're responsible
for wiring a custom tag end to end.
