# Serve a static site

Add `type: static` under `services` in `.lando.yml`. That defaults to the nginx variant. Lando pulls `nginx:1.26-alpine` and listens on `80`. The webroot defaults to `.`, resolving to the app root at `/app`, and the app source is mounted read-only. The server can't mutate your repository:

```yaml
name: static-demo
services:
  web:
    type: static
    webroot: dist
tooling:
  curl:
    service: web
    cmd:
      - sh
      - -c
      - 'test -n "$1" || set -- ""; curl -sf -- "http://localhost:80/$1"'
      - curl
```


Before starting this example, build your site into `dist/` so that `dist/index.html` exists. The configuration serves generated files, not your source templates.

## Read missing paths and directories

On a matched host with default `static:nginx`:

- Missing file → **`404 · Lando web server`** / "Page not found"
- Directory without an index → **`403 · Lando web server`** / "Access denied"

Wrong hostname? You get the proxy page (`404 · Lando proxy`) instead. See [Use the Traefik proxy](../subsystems/proxy-traefik.mdx).

## Serve a subdirectory

Set `webroot` to a path relative to the app mount at `/app`, just as you do for nginx, Apache, and PHP services. The example uses `webroot: dist` to serve the build output directory. Inside the container, `LANDO_WEBROOT` is always the resolved absolute path, here `/app/dist`. Omit `webroot` or use `.` to serve the app root. Use an absolute value such as `webroot: /srv/site` only when you need a very specific container path outside the usual app layout; make sure that directory exists in the container. Relative paths that escape `/app`, such as `../srv`, are rejected.

## Serve with Caddy

Prefer Caddy? Set `type: static:caddy`. Its default image is `caddy:2-alpine`:

```yaml
services:
  web:
    type: static:caddy
```

## Run as a non-root user

Set `user: nginx` to run the default `static:nginx` server as the image's own `nginx` account. Lando writes its whole nginx configuration to `/tmp/lando-nginx.conf`, points the PID file and temp directories at `/tmp` too, and starts the daemon with `nginx -c /tmp/lando-nginx.conf`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: static
    user: nginx
    port: 8080
```

Lando plans no home store for the `nginx` account, whose home on this image is
its cache directory; set `home.path:` when you want a directory to survive a
rebuild. `port:` moves the listen port itself, not just Lando's endpoint,
because Lando templates it into the generated config. A non-root process can't
bind below 1024 on the default `lando` provider, so pick something at or above
`1024`.

If you set your own `command:`, Lando preserves it instead of generating the
launcher. Include the nginx `listen <port>;` directive or Caddy's
`--listen :<port>` flag with your planned port number. Lando never appends it
to your command. If startup fails, Lando includes a hint naming that setting.
An authored `entrypoint:` alone still receives Lando's generated command.

`static:caddy` writes nothing at start either, but it still listens on `80` by
default, so the same port rule applies there.

## Pin a version

Set `image:` to pin a specific nginx or Caddy version:

```yaml
services:
  web:
    type: static
    image: nginx:1.27-alpine
```

```yaml
services:
  web:
    type: static:caddy
    image: caddy:2.8-alpine
```
