# Serve a static site

Put `type: static` in your services block. That defaults to the nginx variant. Lando pulls `nginx:1.26-alpine` and listens on `80`. The document root defaults to `/app`, and the app source is mounted read-only. The server can't mutate your repository:

```yaml
name: static-demo
services:
  web:
    type: static
    root: dist
tooling:
  curl:
    service: web
    cmd:
      - sh
      - -c
      - 'path=${1:-/}; curl -sf -- "http://localhost:80/${path}"'
      - curl
```


## Read missing paths and directories

On a matched host with default `static:nginx`:

- Missing file → **`404 · Lando web server`** / "Page not found"
- Directory without an index → **`403 · Lando web server`** / "Access denied"

Wrong hostname? You get the proxy page (`404 · Lando proxy`) instead. See [Use the Traefik proxy](../subsystems/proxy-traefik.mdx).

## Serve a subdirectory

Setting `root: dist` (as the fixture above does) serves the build output
directory and sets `LANDO_WEBROOT=/app/dist` inside the container.

## Serve with Caddy

Prefer Caddy? Set `type: static:caddy`. Its default image is `caddy:2-alpine`:

```yaml
services:
  web:
    type: static:caddy
```

## Run as a non-root user

Set `user: nginx` to run the default `static:nginx` server as the image's own `nginx` account. Lando writes its whole nginx configuration to `/tmp/lando-nginx.conf`, points the PID file and temp directories at `/tmp` too, and starts the daemon with `nginx -c /tmp/lando-nginx.conf`, so nothing gets written into the image's root-owned config tree at start:

```yaml
services:
  web:
    type: static
    user: nginx
    home: false
    port: 8080
```

`home: false` is there because Lando persists the planned user's home directory and only knows where `root`'s home is on this image. Use `home.path:` instead when you want that directory to survive a rebuild. `port:` moves the listen port itself, not just Lando's endpoint, because Lando templates it into the generated config. A non-root process can't bind below 1024 on the default `lando` provider, so pick something at or above `1024`.

`static:caddy` writes nothing at start either, but it still listens on `80` by default, so the same port rule applies there.

## Pin a version

Set `image:` to pin a specific nginx or Caddy version:

```yaml
services:
  web:
    type: static
    image: nginx:1.27-alpine
```

```yaml
services:
  web:
    type: static:caddy
    image: caddy:2.8-alpine
```
