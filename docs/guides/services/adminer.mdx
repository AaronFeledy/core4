# Browse your database in Adminer

`lando psql` is fine until you want to click through tables or eyeball a schema. The phpMyAdmin service only talks to MySQL and MariaDB. Adminer is a one-file database UI that also speaks PostgreSQL and SQLite, and its official image runs as a Compose service in your app.

Run every command on this page from the app directory on your host.

## Add Adminer next to Postgres

Save this as `.lando.yml` in an empty directory:

```yaml
name: adminer-demo
services:
  db:
    type: postgres
  adminer:
    type: compose
    image: adminer:6
    appMount: false
    endpoints:
      - _tag: internal
        name: ui
        protocol: http
        port: 8080
```

- `adminer:6` is the official image on the Adminer 6 major. It serves the UI on port `8080`.
- `appMount: false` keeps your source out of the Adminer container. It only needs the network.
- The `ui` endpoint tells Lando that port `8080` speaks HTTP, so the proxy gives `adminer` its own `*.lndo.site` URL. Without an endpoint, the service has no route.

Start the app and give Postgres something to show:

```sh
lando start
lando psql -c "CREATE TABLE notes (id serial PRIMARY KEY, body text); INSERT INTO notes (body) VALUES ('hello from lando');"
```

`lando start` returns after Postgres accepts connections, so `lando psql` works right away.

## Log in

Run `lando info` and open the `adminer` URL, `https://adminer.adminer-demo.lndo.site`. If the browser warns about the certificate, see [Trust local HTTPS certificates](../subsystems/certificates-mkcert.mdx).

Fill in the login form:

| Field | Value |
| --- | --- |
| System | PostgreSQL |
| Server | `db` |
| Username | `lando` |
| Password | `lando` |
| Database | `adminer-demo` |

Without a `creds:` block, Postgres uses these defaults: `lando` for the user and password, and a database named after the app. `lando info` prints them. If your Landofile sets `creds:`, type those values instead.

The official image fills in `db` as the Server, which matches the service name here. To preset another service name, set `ADMINER_DEFAULT_SERVER` under the Adminer service's `environment:`. You can also type any service name in the Server field, such as a second database service.

After login, the `public` schema lists the `notes` table. Open it and select its data to see the row you inserted. That proves Adminer reached Postgres over the app network. It doesn't prove anything about your app's own connection settings.

If the URL doesn't load, check `lando logs -s adminer` for the PHP server's startup line, and see [Use the Traefik proxy](../subsystems/proxy-traefik.mdx) when the hostname doesn't resolve.

If the login fails with `password authentication failed for user "lando"`, the database holds a different password than your Landofile. The Postgres image applies `creds:` only when it creates the database, so a later change to `creds:` doesn't reach it. The `lando start` that applies such a change warns that `db` rejected the configured login. [Recover when credentials don't match](./postgres.mdx#recover-when-credentials-dont-match) fixes it without deleting data.

## Use MariaDB or MySQL instead

Point the same Adminer service at a `mariadb` or `mysql` service. Their default username and password are both `lando`, so no `creds:` block is needed:

```yaml
name: adminer-mariadb
services:
  db:
    type: mariadb
  adminer:
    type: compose
    image: adminer:6
    appMount: false
    endpoints:
      - _tag: internal
        name: ui
        protocol: http
        port: 8080
```

Start the app and give MariaDB something to show:

```sh
lando start
lando mariadb -e "CREATE TABLE notes (id INT AUTO_INCREMENT PRIMARY KEY, body TEXT); INSERT INTO notes (body) VALUES ('hello from lando');"
```

`lando start` returns after MariaDB accepts connections, so `lando mariadb` works right away.

Run `lando info` and open the `adminer` URL, `https://adminer.adminer-mariadb.lndo.site`.

Fill in the login form:

| Field | Value |
| --- | --- |
| System | MySQL / MariaDB |
| Server | `db` |
| Username | `lando` |
| Password | `lando` |
| Database | `adminer-mariadb` |

After login, the table list shows `notes`. Open it and select its data to see the row you inserted.

For MySQL and MariaDB alone, the typed [phpMyAdmin service](./phpmyadmin.mdx) finds your databases and gets its URL without an endpoint.

## Browse a SQLite file

Adminer can open a SQLite file you declare with `sqlite.path` on an app service. See [Use SQLite with db commands](../tooling/sqlite-database.mdx) for that key. Adminer won't log in to a database without a password, and SQLite has none, so you give Adminer a password of its own to check.

Save this as `.lando.yml` in an empty directory, and save the password file next to it as `adminer-password.php`:

```yaml
name: adminer-sqlite
services:
  appserver:
    type: "php:8.3"
    primary: true
    sqlite:
      path: data/site.sqlite
  adminer:
    type: compose
    image: adminer:6
    volumes:
      - ./adminer-password.php:/var/www/html/plugins-enabled/adminer-password.php
    endpoints:
      - _tag: internal
        name: ui
        protocol: http
        port: 8080
```

```php
<?php
return new Adminer\Password(password_hash("local-development-only", PASSWORD_DEFAULT));
```

The image loads every PHP file in `/var/www/html/plugins-enabled/`. `Adminer\Password` makes Adminer check the password you type against that hash itself, instead of asking SQLite. This Adminer service keeps the default app mount, so it sees the database at `/app/` plus your `sqlite.path`.

To give the database a table to show, save this as `notes.sql`:

```sql
CREATE TABLE notes (id INTEGER PRIMARY KEY, body TEXT);
INSERT INTO notes (body) VALUES ('hello from lando');
```

Start the app and import it:

```sh
lando start
lando db:import notes.sql --yes
```

`lando db:import` creates `data/site.sqlite` and its `data` directory when they don't exist yet. If your app already created the file, skip the import. In an empty directory, `lando start` also reports that `appserver` returned 403, because there is no app to serve yet. Adminer doesn't use that URL.

Run `lando info` and open the `adminer` URL, `https://adminer.adminer-sqlite.lndo.site`.

Fill in the login form:

| Field | Value |
| --- | --- |
| System | SQLite |
| Server | leave empty |
| Username | leave empty |
| Password | `local-development-only` |
| Database | `/app/data/site.sqlite` |

After login, the table list shows `notes`. Open it and select its data to see the row you imported.

On Linux, Adminer can read the file but can't save changes to it yet. The Adminer container runs as the image's own `adminer` user, which can't write a file your app owns, so an edit fails with `attempt to write a readonly database`. Change the data through your app or `lando db:import` instead.

## Remove it

Delete the `adminer` service from `.lando.yml`, or let Lando edit the file for you, then run `lando start`:

```sh
lando app:config:unset services.adminer
lando start
```

`lando start` removes the Adminer container, prints a notice that `adminer` is no longer defined in the Landofile, and stops routing its URL. Named volumes stay, so `db` keeps its data and the `notes` row is still there. See [Remove a service](../tutorial/app-lifecycle.mdx#remove-a-service) for what `lando restart` and `lando rebuild` do after a removal.
