# Terminal renderer visual QA

The visual QA gate is a deterministic unit suite that captures committed golden frames with no TTY,
provider, or network. It covers the default `lando` renderer's task-tree progress and grouped result
summaries, plus the frame snapshot harness used by the renderer-lando plugin.

The committed reference frames are read directly by reviewers, so output that is technically
structured but visually drab can still be rejected in review.

## Why the goldens are tokenized

ANSI SGR codes are rewritten to readable markers such as `bold`, `cyan`, `green`, `amber`, and
`dim`, so the committed golden stays human readable and a color-token regression shows up as a
marker change in the text diff. Cursor-control redraw bytes and carriage returns are stripped during
capture, so goldens never carry invisible control characters. Display-width invariants are checked on
the stripped raw frame, never on the tokenized string, because the readable markers change column
counts.

Regression classes are `spacing`, `color-token`, `truncation`, and `wide-character`.

## Provider-free capture

`TestRuntimeProvider` is the pure in-memory provider whose lifecycle methods resolve without a real
container runtime, network, signing credentials, or host mutation. Frames are produced from
fixed-timestamp task and message events fed through the event service and the bundled `lando`
renderer, so captures are deterministic and need no live command.

The frame snapshot harness in `plugins/renderer-lando/test/frame-snapshot-harness.ts` drives the
substrate's own test renderer from `@opentui/core/testing` (`createTestRenderer` with
memory-buffered `captureCharFrame`), and `plugins/renderer-lando/test/frame-snapshots.test.ts`
asserts stable captures across repeated runs for task-tree frames, prompt chrome, a 40-column
fixture, and a mid-tree resize. Committed character-frame fixtures carry no ANSI escape byte and no
machine-specific path, timestamp, or host data, so a frame regression shows up as a readable text
diff.

`LANDO_UPDATE_RENDERER_FRAMES=1 bun test plugins/renderer-lando/test/frame-snapshots.test.ts`
regenerates committed frame fixtures after an intentional renderer change; without the flag the gate
is read-only and a missing fixture is a hard failure.

## Renderer scope

The visual gate snapshots the decorated TTY renderer surfaces, not machine logs. Regression fixtures
prove the json renderer emits plain NDJSON, plain output carries no ANSI or panel framing, and the
non-TTY `lando` renderer degrades to undecorated text.

`LANDO_UPDATE_VISUAL_QA=1 bun test core/test/cli/renderer/visual-qa.test.ts` regenerates committed
goldens after an intentional renderer change. Without the update flag the gate is read-only and a
missing golden is a hard failure, never a silent create, so CI can't regenerate a golden it should be
checking.

Editing `core/src/cli/renderer` or `core/test/cli/renderer` requires touching this owned guide or
recording a Guide-Coverage-Skip reason, per the guide drift gate.
