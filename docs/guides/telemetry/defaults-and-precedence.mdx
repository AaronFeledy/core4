# Telemetry defaults and precedence

CLI telemetry is enabled by default (`telemetry.enabled=true`). A flag,
environment overlay, or global config value can override that default.

Library runtimes default the other way: telemetry stays off unless the embedding host explicitly
opts in with `telemetry: true` at runtime construction.

## Precedence chain

The highest-precedence telemetry source wins, in this order:

```text
runtime option > env > config > default
```

- An env overlay (`LANDO_CONFIG__TELEMETRY__ENABLED=0`) disables telemetry before runtime
  construction, even if `config.yml` enables it.
- A valid global config setting (`telemetry.enabled: false`) disables CLI telemetry when no env
  overlay is present.
- An explicit runtime telemetry option (`telemetry: false`) wins before env and config resolution.
