# Update and deprecation telemetry events

## Update outcome

The update command records its outcome through the Telemetry service as an `update-outcome` event.
Only the canonical inventory fields are emitted: `version`, `targetVersion`, `channel`, `platform`,
`outcome`. Every update result maps to one approved outcome category: `success`,
`signature_failure`, `launch_probe_failure`, `permission_failure`, `network_failure`.

## Deprecation usage

`DeprecationService` publishes a `deprecation-used` runtime event after recording usage; `Telemetry`
observes that shared event stream instead of running a parallel deprecation reporter. Deprecation
telemetry carries only `kind`, `id`, `since`, `severity` — it omits callsites, app ids, plugin ids,
and timestamps.

## When telemetry is disabled

Disabled telemetry (`telemetry.enabled=false`) suppresses both update outcome and deprecation
telemetry records. Deprecation recording, renderer behavior, and doctor summaries are unaffected —
they continue to use the normal deprecation path regardless of the telemetry setting.
