# Fork the current app into a scratch

From an app root, run `lando scratch --fork` to start a scratch using that app's
Landofile. The example below shares the source tree: code edits are visible to
both apps. It creates separate containers and does not stop or rename the
original app. Outside an app root, the command fails before creating a scratch.

```sh
lando scratch --fork --detach
```

After startup succeeds, run `lando scratch:list` to find the fork's id and use
`lando scratch:info <id>` to inspect it. `--fork` is a boolean flag, not
`--fork=<app>`.

## Start the fork

```sh
lando scratch:start --fork --detach
lando scratch --fork --name review --detach
```

`lando scratch` and `lando scratch:start` are aliases of `apps:scratch:start`. Pass exactly one of `--fork` or `--from`.

`--detach` returns only after the fork passes startup readiness, including enabled healthchecks. Without it the session stays attached until Ctrl+C, then the scratch is destroyed. Readiness failure or interruption during acquisition cleans up the scratch unless you passed `--keep-on-failure`; user-app start retention does not apply to scratch apps.

`--name` is only the base for the generated id (`scratch-<base>-<6hex>`). The source Landofile is not rewritten.

## What stays shared

The fork keeps the source app root. Code edits show up in both apps. No project files are copied into the scratch cache.

Isolation is containers, networks, DNS, and derived volume names. It is not a second copy of your tree.

## What stays separate

The fork gets its own scratch id, slug, containers, and per-app bridge (`lando-<scratch-id>`). Starting it does not stop or rename the current app.

Service DNS uses the scratch slug (`web.<scratch-id>.internal`).

## Inspect and destroy

Replace `<id>` with the fork's id from `lando scratch:list`. Inspect it before
running the final command: destroy removes the fork's containers, volumes, and
snapshots. Use `--keep-volumes` if you need its volumes and snapshots afterward.

```sh
lando scratch:list
lando scratch:info <id>
lando scratch:destroy <id>
```

`scratch:destroy` removes the fork's containers, volumes, and snapshots it took. Snapshots of the app you forked stay put, even with `--isolate=cwd`. Add `--keep-volumes` to keep the fork's volumes and snapshots for inspection.

To materialize a recipe instead of forking the app, use [Start a scratch app from a recipe](./scratch-from-recipe.mdx).
