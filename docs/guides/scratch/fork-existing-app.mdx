# Fork the current app into a scratch

From an app root, run `lando scratch --fork` to start a scratch using that app's
Landofile. By default the fork works on its own copy of your project, so its
edits never touch your files. It creates separate containers and does not stop
or rename the original app. Outside an app root, the command fails before
creating a scratch.

```sh
lando scratch --fork --detach
```

After startup succeeds, run `lando scratch:list` to find the fork's id and use
`lando scratch:info <id>` to inspect it. `--fork` is a boolean flag, not
`--fork=<app>`.

## Start the fork

```sh
lando scratch:start --fork --detach
lando scratch --fork --name review --detach
```

`lando scratch` and `lando scratch:start` are aliases of `apps:scratch:start`. Pass exactly one of `--fork` or `--from`. Bare `lando scratch --help` shows the scratch topic page, the same as `lando help scratch`; ask `lando scratch:start --help` for this command's flags.

`--detach` returns only after the fork passes startup readiness, including enabled healthchecks. Without it the session stays attached until Ctrl+C, then the scratch is destroyed. Readiness failure or interruption during acquisition cleans up the scratch unless you passed `--keep-on-failure`; user-app start retention does not apply to scratch apps.

`--name` is only the base for the generated id (`scratch-<base>-<6hex>`). The source Landofile is not rewritten.

## Choose a copy or a shared tree

By default a fork uses `--isolate=full`: Lando copies your project into the scratch's own directory under the user data root and mounts that copy. Edits inside the fork stay in the copy, and edits to your project after startup don't reach the fork. The copy skips `.git/`, `node_modules/`, `vendor/`, `.lando/cache/`, and `.DS_Store`; see [Control a full fork copy](./mount-and-share-flags.mdx#control-a-full-fork-copy) for more exclusions.

To work on the same files from both apps instead, share the directory you run the command from:

```sh
lando scratch --fork --detach --isolate=cwd
```

With `--isolate=cwd` (or `--mount-cwd`), Lando copies nothing and code edits show up in both apps.

## What stays separate

The fork gets its own scratch id, slug, containers, and per-app bridge (`lando-<scratch-id>`). Starting it does not stop or rename the current app.

Service DNS uses the scratch slug (`web.<scratch-id>.internal`).

## Inspect and destroy

Replace `<id>` with the fork's id from `lando scratch:list`. Inspect it before
running the final command: destroy removes the fork's containers, volumes, and
snapshots. Use `--keep-volumes` if you need its volumes and snapshots afterward.

```sh
lando scratch:list
lando scratch:info <id>
lando scratch:destroy <id>
```

`scratch:destroy` removes the fork's containers, volumes, and snapshots it took. Snapshots of the app you forked stay put, even with `--isolate=cwd`. Add `--keep-volumes` to keep the fork's named volumes and snapshots for inspection; an anonymous volume from an image `VOLUME` path still leaves with its container.

To materialize a recipe instead of forking the app, use [Start a scratch app from a recipe](./scratch-from-recipe.mdx).
