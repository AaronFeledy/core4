# List scratch apps

`lando scratch:list` prints every registered scratch: id, source, isolation mode, created time, and status.

```sh
lando scratch:list
```

To see route URLs, mounts, networks, and endpoints, run `lando scratch:info <id>`, replacing
`<id>` with an id from this list.

## List

```sh
lando scratch:list
lando scratch:list --format json
```

`lando scratch:list` is the alias of `apps:scratch:list`. The table columns are `ID`, `SOURCE`, `MODE`, `CREATED`, and `STATUS`. `--format json` emits the same fields as an array.

Include running scratch apps in the host-wide app inventory when you need one list:

```sh
lando list --include-scratch
lando list --all
```

Plain `lando list` still omits scratch apps. `--all` includes them too.

Source is `fork` or `recipe:<ref>`. Mode is `full`, `baked`, or `cwd`.

## Read status

Status comes from the local registry without calling the provider. It describes
the scratch's ownership and attachment state, not a live container health check.

| Status | Meaning |
| --- | --- |
| `attached` | Foreground scratch whose owning CLI process is still running. |
| `detached` | Started with `--detach` or kept with `--keep`. Lives until destroy or gc. |
| `orphan` | Foreground scratch whose owner exited without cleanup. `scratch:gc --prune` can reap it. |

## Inspect one scratch

```sh
lando scratch:info <id>
lando scratch:info <id> --format json
```

`lando scratch:info` is the alias of `apps:scratch:info`. The id is required.

If you started the scratch with `--name`, you can pass that name instead of the
id. `scratch:info`, `scratch:logs`, `scratch:stop`, and `scratch:destroy` look
for an exact id first, then for the one scratch whose id was built from that
name:

```sh
lando scratch --fork --name review --detach
lando scratch:info review
```

When two scratches were started with the same name, the command fails with
`ScratchAppNotFoundError` and lists their ids in `suggestions`. Pass one of
those ids instead.

Info repeats the list fields, then prints `root`, the per-app bridge (and the shared network when the scratch joined it), each mount (service, target, source, kind, read-only), and endpoints grouped by service.

Under `routes`, look for the URLs the router confirms for this scratch. The
JSON `routes` entries include `service`, `hostname`, `scheme`, `port`, and
`url`, which includes any nonstandard port and route path prefix. If the
router cannot confirm a route, info does not report it, and an empty `routes`
list means the scratch declares routes but none are confirmed yet. A scratch
with no routes, or with routing turned off, has no `routes` field. A reported
URL does not imply the service behind it is healthy.
