# Start a scratch app from a recipe

`lando scratch:start --from <recipe>` materializes a recipe into a throwaway app. It does not write a Landofile into the current directory.

```sh
lando scratch:start --from lamp --yes --detach
```

This accepts the recipe defaults and returns after the services pass startup
readiness. Use `lando scratch:list` to find the new id, then inspect it with
`lando scratch:info <id>`. Unlike `lando init`, this does not create a permanent
project in your current directory.

## Pick exactly one source

Pass exactly one of `--from` or `--fork`. Both or neither fails.

```sh
lando scratch:start --from wordpress --yes --detach
lando scratch:start --fork --detach
```

`--from` takes a recipe reference. Bundled recipes include `lamp`, `lemp`, `wordpress`, `drupal`, and `drupal-cms`. There is no `--recipe` flag on this command.

`--fork` uses the current app's Landofile as the scratch source. You must be in an app root.

`--yes` accepts recipe prompt defaults. `--answer key=value` (repeatable) fills prompts. `--option` is an alias for `--answer`.

## Inspect and destroy

Replace `<id>` with the scratch id from the list. The final command destroys that
scratch; run it when you have finished inspecting or using the app.

```sh
lando scratch:list
lando scratch:info <id>
lando scratch:destroy <id>
```

Destroy keeps the newest image Lando built for each of the scratch's services for up to seven days. Start another scratch app from the same recipe in that window and it reuses those images instead of building them again.

`--detach` returns after services pass startup readiness. Enabled healthchecks must pass; services without checks settle in a running state, and completion jobs must exit 0. Without `--detach` the session stays attached.

If acquisition fails or you interrupt it, Lando tries to remove anything it created for that scratch. If cleanup fails, Lando reports the scratch id alongside the original failure. Check `lando scratch:list` and, if it still lists the scratch, run `lando scratch:destroy <id>` after fixing the reported problem. Use `--keep-on-failure` to skip automatic cleanup and inspect what the failed start created. The start still reports a failure.

`lando run --from lamp -- composer --version` runs one command in a disposable scratch app. When `--from` is omitted, `lando run` uses the bundled toolbox recipe.

## Keep a real app instead

To scaffold into this directory, use init:

```sh
lando init --recipe lamp --yes
lando start
```
