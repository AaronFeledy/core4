# Scratch from recipe

## Scratch recipe command

Materializes the named recipe into an ephemeral scratch app instead of scaffolding into the current directory.

The scratch namespace alias reaches the same recipe mode behavior.

apps:scratch:start requires exactly one of --fork or --from `<recipe-ref>`; passing both or neither fails with ScratchSourceUnresolvedError.

```sh
--fork XOR --from
```

Returns after the provider apply starts the recipe resources instead of keeping an attached command session (`--detach`).

## Scratch recipe answers

Recipe prompts are auto-answered from flags so scratch mode can run non-interactively in CI.

Repeatable; supplies a recipe prompt answer so prompts that take defaults can be auto-answered.

```sh
--answer key=value
```

Synonym for --answer; on a key collision --option wins because answers are merged before options (last write wins)

```sh
--option key=value
```

Accepts every recipe prompt's default without asking; the -y shorthand is equivalent (`--yes`).

Never prompts; remaining prompts must be satisfied by defaults or --answer, otherwise the recipe fails; --non-interactive is accepted as a synonym (`--no-interactive`).

## Scratch recipe run

Runs the command tail in a disposable scratch app and exits with the tool command's exit code.

The top-level run alias reaches the same disposable scratch execution path.

```sh
lando run -- composer install
```

When --from is omitted, scratch run uses the bundled toolbox recipe instead of the current app.

Overrides the recipe used for the disposable scratch app before the command is executed.

```sh
--from lamp
```

Runs in the requested service; an unknown service fails with the available service names.

```sh
--service appserver
```

The current working directory is mounted into the scratch app unless --no-mount is passed.

Retains the scratch app after the command exits and prints the kept scratch id (`--keep`).

stdout and stderr are forwarded as renderer stream frames; non-json output renders both streams, while json keeps stderr out of the result body.

Allowed agent-context environment values are forwarded below service environment values and registered as redaction tokens.

## Scratch recipe render

The recipe is rendered into the scratch cache root and planned under a generated identity, mirroring fork mode's materialize then plan then apply shape.

The recipe renders into `<userCacheRoot>`/scratch/`<id>`/root/, never into the current working directory.

The scratch id is generated from --name, then the recipe reference as a fallback, and forced onto the rendered Landofile name (`scratch-<base>-<6hex>`).

The rendered Landofile is re-planned under the scratch id so plan id, name, and slug all match the scratch identity.

The recipe's postInit: actions are not run for scratch mode; --run-post-init opt-in is a later flag (`skipped`).

## Scratch recipe unresolved

A recipe reference that cannot be resolved fails before any scratch app is created so no partial state is left behind.

An unknown or unresolvable --from `<recipe-ref>` maps recipe-resolution failures to ScratchSourceUnresolvedError.

Render, IO, or parse failures of an otherwise resolvable recipe surface as ScratchAppError instead.
