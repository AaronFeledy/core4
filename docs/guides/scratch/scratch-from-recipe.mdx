# Start a scratch app from a recipe

`lando scratch:start --from <recipe>` materializes a recipe into a throwaway app. It does not write a Landofile into the current directory.

```sh
lando scratch:start --from lamp --yes --detach
```

Scratch is a hotel room. Init is a lease.

## Pick exactly one source

Pass exactly one of `--from` or `--fork`. Both or neither fails.

```sh
lando scratch:start --from wordpress --yes --detach
lando scratch:start --fork --detach
```

`--from` takes a recipe reference. Bundled recipes include `lamp`, `lemp`, `wordpress`, `drupal`, and `drupal-cms`. There is no `--recipe` flag on this command.

`--fork` uses the current app's Landofile as the scratch source. You must be in an app root.

`--yes` accepts recipe prompt defaults. `--answer key=value` (repeatable) fills prompts. `--option` is an alias for `--answer`.

## Inspect and destroy

```sh
lando scratch:list
lando scratch:info <id>
lando scratch:destroy <id>
```

`--detach` returns after the scratch starts. Without it the session stays attached.

`lando run --from lamp -- composer --version` runs one command in a disposable scratch app. When `--from` is omitted, `lando run` uses the bundled toolbox recipe.

## Keep a real app instead

To scaffold into this directory, use init:

```sh
lando init --recipe lamp --yes
lando start
```
