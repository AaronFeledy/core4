# Run a command in a disposable scratch

`lando run` boots a throwaway scratch app, waits for startup readiness, runs the argv after `--`, then destroys the scratch. An exhausted healthcheck or unsupervised startup exit fails acquisition before the tool runs; interrupted acquisition also cleans up. User-app readiness retention does not apply here.

```sh
lando run -- composer --version
```

No `--from` means the bundled `toolbox` recipe. Tokens after `--` are the tool, not Lando flags. Think hotel minibar: use it, then it is gone.

## Pick a recipe and service

```sh
lando run --from lamp --yes -- composer --version
lando run --from lamp --service appserver -- composer --version
```

`--from` is a recipe reference, the same kind `scratch:start --from` takes. See [Start a scratch app from a recipe](./scratch-from-recipe.mdx).

`--service` selects the service. The default is the recipe's primary (or only) service. An unknown name fails with `ScratchRunTargetError`.

`--answer key=value` (repeatable) fills recipe prompts so the one-shot path does not block.

## Mount the project

By default the current directory is bind-mounted so the tool sees your files.

```sh
lando run --no-mount -- composer --version
```

`--no-mount` keeps `$PWD` out of the disposable app.

## Pipe input or work interactively

Output streams as the tool writes it. Pipe or redirect into `lando run` and the tool reads that input to the end:

```sh
printf 'hello\n' | lando run --no-mount -- cat
lando run -- wc -l < composer.json
```

From a terminal with nothing piped in, the tool gets your keyboard and a real terminal, so prompts, editors, and shells work:

```sh
lando run --no-mount -- bash
```

Lando paints the scratch's build and start progress first, then hands the terminal over. From there Ctrl+C goes to the tool, the same as in any shell.

With `--format=json`, `--format=yaml`, or `--renderer=json`, piped input still arrives but the keyboard does not, so a tool that waits for typed input reads end of input instead of hanging an agent.

## Keep the scratch

```sh
lando run --keep -- composer --version
lando scratch:list
```

`--keep` detaches the scratch after the command exits and prints its id on stderr, away from the tool's own output. With `--format=json`, the id is `result.scratchId`. Reap leftovers with [Reap orphaned scratch apps](./scratch-gc.mdx).

Normal exit, a non-zero tool exit, and Ctrl+C all run the destroy finalizer unless you passed `--keep`.

## Exit codes

The tool's exit code becomes the CLI exit code. `exit 7` from the tool is `7`, not a tagged Lando error.

```sh
lando run -- sh -c 'exit 7'
```

`lando run` and `lando scratch:run` are aliases of `apps:scratch:run`.
