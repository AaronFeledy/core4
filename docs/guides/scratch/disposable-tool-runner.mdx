# Disposable tool runner

## Run default toolbox

Disposable tool runs boot a real container and exec a tool inside it, so this scenario documents the command surface without a live provider.

Runs the tool tail in a one-shot toolbox scratch that lives exactly as long as the command.

```sh
lando run -- composer install
```

The top-level run alias reaches the canonical apps:scratch:run command.

With no --from, the bundled toolbox recipe supplies one general-purpose CLI service on a version-pinned image.

Tokens after -- are passed to the tool unchanged and never parsed as Lando flags.

Normal exit, non-zero exit, and Ctrl+C all converge on the finalizer that destroys the scratch and its resources.

## Run source and service

Swaps the disposable recipe from the default toolbox to any recipe the standard source registry resolves.

```sh
--from lamp
```

Runs the command in the named service; the default is the recipe's primary or only service.

```sh
--service appserver
```

An unknown --service fails with ScratchRunTargetError listing the recipe's available services.

Repeatable; supplies recipe prompt answers so the one-shot path never blocks on a prompt.

```sh
--answer key=value
```

## Run mount

cwd mounting binds real host files into a running container, which requires a live provider.

By default the current working directory is bind-mounted into the scratch so tools operate on real project files.

Switches to baked isolation so the run cannot see the current working directory (`--no-mount`).

## Run keep and GC

Detaching a kept scratch and reaping it through gc touches the registry and provider resources, so this scenario documents the lifecycle without a live provider.

Converts the scratch to detached after exec completes instead of destroying it, and prints the kept scratch id (`--keep`).

A kept run appears here with its source, isolation mode, scratch id, and detached status.

```sh
lando apps:scratch:list
```

Reaps an orphaned kept scratch and its provider resources through the registry plus the provider-label scan.

## Run exit and streaming

Exit-code propagation and JSON stream frames come from a live tool process, so this scenario documents the machine surface without executing a tool.

The tool process exit code becomes the command exit code; a non-zero tool exit is not a Lando tagged error.

Exits 7 with no tagged error and no remediation, just the propagated code.

```sh
lando run -- sh -c 'exit 7'
```

Emits StreamFrame NDJSON for stdout and stderr plus a terminal result frame carrying the exit code and scratch id.

```sh
--format json
```

A second run against the same toolbox reuses the content-addressed recipe render and the standard buildKey up-to-date check, so it pays container start, not recipe resolution or image build.
