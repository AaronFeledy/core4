# Scratch GC

## Scratch GC command

Inspects registered scratch apps, scratch cache directories, and provider resources tagged with scratch labels.

```sh
lando apps:scratch:gc
```

The scratch namespace alias reaches the same garbage-collection helper.

```sh
lando scratch:gc
```

Without --prune, garbage collection reports inspected and orphan counts without deleting registry entries, directories, or provider resources.

## Scratch GC prune

Pruning removes local and provider-side scratch orphans, which requires a real provider and host cache state.

Reaps orphaned scratch ids by pruning provider resources, removing the cache directory, and deleting the registry entry.

A missing provider resource or scratch directory is treated as success, so a second --prune pass reports no remaining work.

The durable scratch registry is a versioned StateStore bucket (registry.bin); legacy registry.json envelopes are migrated on first read and list/info/gc all use the same store (`<userCacheRoot>/scratch/registry.bin`).

Provider containers for scratch apps carry the scratch id label so GC can find resources whose registry entry is gone (`dev.lando.scratch-id`).

## Scratch GC orphans

Orphan categories are classified by cross-referencing local registry state, cache dirs, and provider labels.

A scratch cache directory with no registry entry is removable with --prune.

A provider resource tagged with a scratch id but missing from the registry is pruned via the provider scanner seam.

A foreground registry entry whose owner process is gone is considered orphaned and eligible for prune.
