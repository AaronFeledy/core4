# Reap orphaned scratch apps

`lando scratch:gc` reports leftover scratch apps. It deletes nothing until you pass `--prune`.

```sh
lando scratch:gc
```

Dry run first. Then prune. Scratch gc is a janitor with a clipboard, not a flamethrower.

## Inspect

```sh
lando scratch:gc
lando scratch:list
```

`lando scratch:gc` is the alias of `apps:scratch:gc`. The report prints `inspected`, `reaped`, and `errors` counts.

Without `--prune`, Lando only inspects and reports scratch state. Provider resources, cache directories, and registry entries stay unchanged.

## Scan every running provider

GC checks every installed provider that is available and running, not just the default one. A scratch started under Docker still shows up when your default is `lando`, and you don't switch providers to clean it up.

GC never starts a runtime. A stopped or unreachable runtime is skipped, so its scratch resources stay out of the report. Start that runtime, then run `lando scratch:gc` again to pick them up.

## Prune

Warning: `--prune` deletes. Run the dry run above first and read the counts.

```sh
lando scratch:gc --prune
```

`--prune` removes orphaned scratch ids: provider resources, the scratch cache directory, and the registry entry. Each provider resource is deleted through the provider that owns it, matched by scratch identity; a volume goes only if the generation Lando observed still matches at delete time. Anything that doesn't match stays put.

Prune is safe to repeat. A second `--prune` should report no remaining work.

If a provider scan or removal fails, GC reports the failure instead of treating the scan as empty. Fix the cause, then run it again.

Orphans include:

- a cache directory with no registry entry
- a provider resource tagged with a scratch id that is gone from the registry
- a foreground registry entry whose owner process is gone

Destroy a known id instead of sweeping:

```sh
lando scratch:destroy <id>
```
