# Mount the working directory into a scratch

Use `--mount-cwd` when a scratch needs access to the files in your current host
directory. It bind-mounts `$PWD` into the scratch's primary service, so this is
shared access to your files, not an isolated copy. The separate
`--share-global-storage` flag joins the shared cross-app network.

```sh
lando scratch:start --from lamp --yes --detach --mount-cwd
```

`--mount-cwd` takes an optional container path. A bare flag is valid: the CLI rewrites it to `--mount-cwd=` and binds `$PWD` wherever the app root was bound. That means the app mount (usually `/app`) and every mount whose source is a relative path in the Landofile, in every service. To verify the mount, find the scratch with `lando scratch:list`, then run
`lando scratch:info <id>` and check its mount source and target.

## Mount `$PWD`

```sh
lando scratch:start --from lamp --yes --detach --mount-cwd
lando scratch:start --from lamp --yes --detach --mount-cwd=/srv/site
```

An explicit path binds `$PWD` at that container path in the primary service and replaces whatever was planned exactly there. Every other mount stays as planned. Pass the app mount's own path (`--mount-cwd=/app`) to replace only that mount, so other services keep their app-relative mounts.

The same mount controls apply to recipe scratches and forks. `lando run` defaults to mounting `$PWD`; pass `--no-mount` to skip it. See [Run a command in a disposable scratch](./disposable-tool-runner.mdx).

## Share global storage

```sh
lando scratch:start --from lamp --yes --detach --share-global-storage
```

`--share-global-storage` is never inferred. Without it the scratch stays off the shared network.

The provider must support shared cross-app networking. If it does not, start fails with `ScratchAppError`.

You can pass both flags:

```sh
lando scratch:start --from lamp --yes --detach --mount-cwd --share-global-storage
```

## Isolation

`--isolate` accepts `none`, `full`, `baked`, or `cwd`. `none` is a legacy alias for `cwd`.

```sh
lando scratch:start --fork --detach --isolate=full
```

Do not combine `--mount-cwd` with `--isolate=full`. That pair fails with `ScratchIsolationConflictError` and creates nothing.

On a fork, `--mount-cwd` defaults isolation to `cwd` unless you set `--isolate`.

Isolation decides where the app mount and every mount with a relative source, such as `source: ./assets`, point:

| Mode | App mount and relative mounts |
| --- | --- |
| `full` | The scratch's own copy of your app. |
| `baked` on a recipe | The recipe's scaffold, which Lando keeps in its own directory. |
| `baked` on a fork | Not mounted. |
| `cwd` | The directory you ran the command from, in every service. |

Mounts with absolute sources pass through in every mode. Under `full` and recipe `baked`, a relative mount that leads outside the scratch's directory, for example `../shared` or a symlink pointing elsewhere, is not mounted, and Lando warns with the service and path. Use an absolute source when a scratch really needs that directory.

## Control a full fork copy

```sh
lando scratch:start --fork --detach --isolate=full --exclude=coverage/ --no-local-overrides
```

Full isolation always skips `.git/`, `node_modules/`, `vendor/`, `.lando/cache/`, and `.DS_Store`. Repeat `--exclude` for project-specific paths. `--no-local-overrides` also drops `.lando.local.yml` and `.lando.user.yml` from the scratch copy. The source app stays untouched.

## Control scratch hostnames

Scratch routes get `--<scratch-id>` before the final two DNS labels. Keep every planned hostname with `--no-hostname-suffix`, or keep selected hostnames by repeating `--hostname`.

```sh
lando scratch:start --fork --detach --no-hostname-suffix
lando scratch:start --fork --detach --hostname=api.example.test
```

Recipe scratches skip post-init hooks by default. Add `--run-post-init` when the recipe needs them. Add `--keep-on-failure` to retain the scratch root and registry entry after a failed start so you can inspect logs or destroy it yourself.
