# Mount and share flags

## Scratch mount cwd

Mounts the current working directory ($PWD) into the scratch app's primary service so the scratch serves your live files.

Bare --mount-cwd rebinds the primary service's app mount to $PWD; the container path defaults to the service's app-mount destination (/app)

An explicit container path mounts $PWD at that path as an additional bind mount, leaving the primary app mount in place (`--mount-cwd=/srv/site`).

Works in recipe mode too: the rendered recipe runs against the scratch root while $PWD is bound into the primary service.

apps:scratch:run uses the same scratch mount controls for one-off commands; --no-mount leaves $PWD out of the disposable app.

## Scratch share global storage

Joins the scratch app to the shared cross-app network so it can reach the global app and its storage scope.

--share-global-storage is never inferred from another flag; without it a scratch app stays isolated from cross-app storage by default.

The active provider must support shared cross-app networking; otherwise the start fails with a ScratchAppError explaining the limitation (`sharedCrossAppNetwork`).

## Scratch mount and share together

The two flags are independent opt-ins that compose; this scenario documents their combined use.

The flags are mutually compatible and may be combined to serve $PWD while joining the shared cross-app network.

--mount-cwd cannot be combined with --isolate=full; passing both fails fast with ScratchIsolationConflictError.

```sh
--mount-cwd + --isolate=full
```
