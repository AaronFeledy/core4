# Testing runtime

`makeTestRuntime()` creates an isolated test runtime for library hosts. Every service double records what your code asked for and touches nothing on the host.

```ts
import { Effect } from "effect";
import { Logger, ProcessRunner } from "@lando/core";
import { makeTestRuntime } from "@lando/core/testing";

const runtime = makeTestRuntime();
await Effect.runPromise(
  Effect.gen(function* () {
    const log = yield* Logger;
    const processes = yield* ProcessRunner;
    yield* log.info("hello from a host test");
    yield* processes.run({ cmd: "podman", args: ["info"] });
  }).pipe(Effect.provide(runtime.layer)),
);
console.log(runtime.calls.logger, runtime.calls.processRunner);
```

## Deterministic runtime

The FileSystem double records calls and never writes to the real disk (`in-memory`).

The Logger double records messages for assertions without printing by default (`captured`).

The ProcessRunner double records commands and never reaches the host shell or network (`captured`).

The same runtime inputs produce identical recorded calls across runs (`repeatable`).

## Default service tags

`provideTestRuntime({ bootstrap: 'minimal' })` provides the minimal service set.

`provideTestRuntime({ bootstrap: 'provider' })` adds provider-level services.

`provideTestRuntime({ bootstrap: 'global' })` adds global app services.

`provideTestRuntime({ bootstrap: 'scratch' })` adds scratch app services.

Library runtimes can acquire a scratch app up front; legacy isolate 'none' inputs are normalized to the canonical cwd mode before persistence.

`provideTestRuntime({ bootstrap: 'app' })` adds the full app service set.

## Provider contract

The provider bootstrap layer resolves a RuntimeProvider by default.

The default fake provider is TestRuntimeProvider.

The fake provider reports the stable provider id test.

The fake provider satisfies the RuntimeProvider contract used by core tests (`valid`).

@lando/sdk/test exposes runProviderDataPlaneContract for provider volume, service file, and artifact byte round trips, including native-vs-copy path observations.

TestRuntimeProvider implements the data-plane methods in memory so contract tests can run without a live container runtime (`in-memory`).

## Composition contracts

runServiceCompositionContract replays service type resolution and requires stable base and normalizedConfig output.

runServiceFeatureContract validates service feature requires entries, deterministic drafts, and storage, endpoint, mount, and extension intents without realization decisions.

runAppFeatureContract validates app feature global service requirements and proves activatedBy misses are no-op paths when expectNoActivation is set.

runHttpClientContract accepts an optional timeout probe so HttpClient implementations prove timeoutMs aborts and reaps hung request or stream connections without leaking sockets.

makeTestHttpClient records fetchInitForNetwork output with injected host roots so HttpClient contract tests can assert network.ca.trustHost merges default roots with custom CAs or fails closed when disabled.

## Tool provisioning extraction limits

Tool provisioning extraction limits are locked by SDK unit tests with deterministic in-memory archives.

Tool provisioning caps gzip and zip member decompression before installing pinned helper binaries so malformed artifacts fail with ToolExtractError instead of unbounded memory growth.

Library hosts and tests can lower the cap for deterministic boundary coverage without changing production defaults (`ProvisionToolInput.maxDecompressedBytes`).

## Runtime overrides

withService(tag, impl) lets hosts replace one service tag.

with: { RuntimeProvider } swaps the provider implementation for a test host.

makeLandoRuntime({ config }) relocates userConfRoot, userCacheRoot, userDataRoot, and systemPluginRoot for an isolated PathsService.

@lando/core/testing is stable on the next channel for Beta 1.

## Interaction test double

@lando/core/testing exports makeTestInteractionService for driving prompt flows without a terminal.

Seeded answers are keyed by prompt name and reuse the real makeInteractionService engine so coercion, validation, and precedence match the Live service.

The test double fails on any stdin read, so a seeded flow can never block on the terminal.

The service captures a prompt transcript that hosts can assert against (`captured`).

@lando/sdk/test exposes runInteractionContract so the Live service, the test double, and plugin or host implementations all prove the same interaction guarantees.

## Event service test helpers

EventService.waitFor(name, { filter, timeout }) waits for the first typed event match and reports EventError reason timeout when the test clock reaches the deadline.

EventService.waitForAny([{ name, filter }], { timeout }) waits for the first matching event across several event names under one timeout.

EventService.query(name, filter?) snapshots matching events from the bounded redacted in-memory history without blocking.

GlobalConfig sets the positive per-subscriber delivery queue capacity; a full subscriber queue drops only that delivery so publish remains non-blocking.

@lando/core/testing exports expectEvent(name, options?) with a five second default timeout so missing test events fail fast.

@lando/core/testing exports waitForEvent(name, options?) for tests that need the EventService waitFor contract without the expectEvent default timeout.

@lando/core/testing exports recordedEvents() as a snapshot of EventService.query('*') for assertions against emitted runtime history.

## State store test double

@lando/core/testing exports makeTestStateStore for hosts and plugin tests that need StateStore without filesystem IO.

makeTestStateStore returns a Layer hosts can merge into provideTestRuntime or custom test stacks (`Layer.succeed(StateStore)`).

The double applies the same schema codecs, version framing, advisory lock modes, and path containment rules as StateStoreLive.

list(dir) reports stored file basenames under the resolved directory so Windows and POSIX paths stay portable in contract tests.

@lando/sdk/test exposes runStateStoreContract so live, in-memory, and host-provided StateStore implementations prove the same bucket guarantees.

## Live provider socket gate

Live integration gates resolve sockets through @lando/core/testing helpers without documenting a separate CLI walkthrough.

@lando/core/testing resolves an optional LANDO_TEST_PODMAN_SOCKET override when it is a real socket, otherwise the Lando-managed Paths default from lando setup (`resolveLiveProviderSocket`).

Integration suites skip unless resolveLiveProviderSocket finds a live socket on disk (`hasLiveProviderSocket`).

linux-x64 provider-integration CI prepares the managed socket through lando setup instead of exporting LANDO_TEST_PODMAN_SOCKET.

```sh
lando setup --yes --provider=lando
```

## Probe primitive

@lando/sdk/probe exports RetryPolicy, ProbeSpec, ProbeOutcome, ProbeResult, toSchedule, and runProbe as a contracts-only tier with no service Layer.

runProbe stops on the first green outcome and retries yellow or red per policy until maxAttempts or overall timeout.

Backoff, jitter, and timeout are driven through Effect Clock and Schedule so attempt counts and elapsed time are deterministic in tests (`TestClock`).

runProbe returns lastError verbatim on non-green terminal outcomes; callers redact through RedactionService before events or transcripts.

sdk/test/probe/run-probe.test.ts locks terminal ProbeResult semantics including zero-timeout and post-success lastError clearing.
