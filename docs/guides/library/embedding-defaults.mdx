# Embedding defaults

An embedded runtime is silent by default and loads only plugins supplied by the
host. These defaults let your application decide how Lando reports output,
collects telemetry, and loads code.

## Library defaults

| Setting | Default |
| --- | --- |
| Logger | Silent |
| Renderer service | JSON |
| Telemetry | Disabled (`off`) unless the host opts in |
| Plugin discovery | Host-provided only (`explicit`); the root entry installs no bundled plugin modules |

## Library overrides

Choose overrides when constructing the runtime. For example, set the renderer
to `plain` or opt into telemetry with `true`. To load bundled plugins, import
`@lando/core/bundled-plugins` before construction; this enables bundled-only loading.

Host plugin layers are built once and override matching generated runtime services.
You can also supply resolved plugin manifests to register contributions without
enabling external imports. See [Embedding the Lando runtime](./embedding-runtime.mdx)
for runtime construction and plugin options.

## Library import boundary

Import `makeLandoRuntime` from the default package entry, `@lando/core`.

OCLIF is development-only; the private CLI spec directories contain native metadata/adapters and manifest tooling, and no published package specifier exposes them (`not-published`).

The library default JSON renderer does not pull TUI paths into the default entry.
