# The global-app doctor check

`lando doctor` includes a `global-app` section in its combined report
without requiring app bootstrap. `meta:doctor` starts at bootstrap level
`none` and safely builds the provider runtime inside its own scoped program,
so a provider bootstrap failure leaves this disk-backed section available
while the provider section degrades. The check is backed by
`DefaultGlobalAppDoctorLayer`, which only requires `ConfigService` and reads
from `GlobalAppService`, `PluginRegistry`, and `FileSystem`.

## Not installed

If the global app has not been materialized yet, the check `warn`s:
`context.installed` is `false`. Starting an app that needs Traefik, Mailpit,
or ssh-agent provisions it automatically. The solution also surfaces
`lando global:install` if you want to materialize the stack now.

## Installed

Once the dist file exists, the check `pass`es and reports:

| Field | Meaning |
| --- | --- |
| `context.installed` | `true` |
| `context.distLandofilePath` | Absolute path to the generated dist Landofile, `<userDataRoot>/global/.lando.dist.yml` |
| `context.userLandofilePath` | Absolute path to the hand-editable overlay Landofile, `<userDataRoot>/global/.lando.yml` |
| `context.lastInstallTimestamp` | ISO 8601 mtime of `.lando.dist.yml`, updated on every `meta:global:install` run |
| `context.services` | Comma-separated list of service ids materialized in the dist Landofile, e.g. `mailpit, traefik` |
| `context.contributingPlugins` | Comma-separated plugin names whose manifests declare `globalServices:` contributions, e.g. `@lando/proxy-traefik` |

## In the ndjson stream

`lando doctor --renderer=json` emits `global-app` as a standard
`doctor.check` event, alongside every other check, in this order:
`selected-provider`, `runtime-service`, `proxy`, `certs`, `ssh`,
`healthcheck`, `scanner`, `host-proxy`, `network-trust`, `global-app`,
`mcp`. That's 11 checks total when no provider-conflict check fires — 2
provider checks plus 7 subsystem checks plus `global-app` and `mcp`.

Two related subsystem remediations worth knowing:

- **certs warning** (no certificate-authority plugin available): "The local
  certificate authority is not installed. Run `lando setup` to install and
  trust the dev CA."
- **network-trust warning** (unreadable configured CA path): "Point
  `network.ca.certs` or `LANDO_NETWORK_CA_CERTS` at readable host CA files,
  or fix the Landofile `security.ca` path. Then rerun `lando setup`." A
  malformed `LANDO_NETWORK_CA_CERTS` gets a more specific remediation: "Set
  `LANDO_NETWORK_CA_CERTS` to a JSON array such as
  `[\"/path/to/corp-root.pem\"]`, or configure `network.ca.certs` in the
  global config."
