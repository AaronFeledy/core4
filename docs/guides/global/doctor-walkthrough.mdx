# Read the global-app doctor check

```sh
lando doctor
```

Doctor includes a `global-app` section without bootstrapping a project app. If the provider section degrades, this disk-backed check can still run.

The default provider is `lando` (managed Podman). After a successful `lando setup --provider=docker`, later `lando doctor` stays on Docker because that explicit flag writes `defaultProviderId`. `LANDO_PROVIDER` does not persist.

## When it is not installed

The check warns and sets `installed` to `false`. Starting an app that needs Traefik, Mailpit, or the SSH sidecar provisions the global app. To materialize it now:

```sh
lando global:install
```

## When it is installed

The check passes and reports the generated dist Landofile (`<userDataRoot>/global/.lando.dist.yml`), the overlay (`<userDataRoot>/global/.lando.yml`), the dist file mtime as `lastInstallTimestamp`, materialized service ids, and plugin names that declare `globalServices:`.

If the dist file exists but cannot be read, the check fails and tells you to fix permissions or rerun `lando global:install`.

## Verify

```sh
lando doctor
lando global:status
```

For the rest of the report, see [Run lando doctor](../subsystems/doctor-walkthrough.mdx).
