# Uninstall and purge

## Global lifecycle namespace

Materializes the global Landofile and installs bundled global services.

```sh
lando meta:global:install
```

Applies the global-rooted plan and brings every global service up.

```sh
lando meta:global:start
```

Destroys the running provider resources without removing volumes or state.

```sh
lando meta:global:stop
```

Inspects each planned global service and reports its runtime status.

```sh
lando meta:global:status
```

Prints the generated global Landofile and the hand-editable overlay path.

```sh
lando meta:global:config
```

Clears global services from the materialized Landofile; --purge also removes data.

```sh
lando meta:global:uninstall
```

Tears down the global app provider resources behind a --yes confirmation.

```sh
lando meta:global:destroy
```

## Global lifecycle aliases

Each meta:global:* command publishes a top-level global:* alias (the global: prefix is reserved for meta:global:*; other plugin- or tooling-contributed aliases starting with global: are rejected) so operators can use the shorter form.

`lando global:install` is the alias for `lando meta:global:install`

```sh
lando global:install
```

`lando global:start` is the alias for `lando meta:global:start`

```sh
lando global:start
```

`lando global:status` is the alias for `lando meta:global:status`

```sh
lando global:status
```

`lando global:uninstall` is the alias for `lando meta:global:uninstall`

```sh
lando global:uninstall
```

`lando global:destroy` is the alias for `lando meta:global:destroy`

```sh
lando global:destroy
```

The compiled $bunfs binary routes every meta:global:* command and its alias through the same dispatcher as source mode.

## Global uninstall vs purge

meta:global:uninstall unregisters global services from the materialized Landofile while --purge additionally destroys the provider data; neither path requires a confirmation flag.

Without --purge, uninstall regenerates the global Landofile with its services cleared and leaves provider volumes untouched (`unregister`).

With --purge, uninstall first destroys the provider resources and volumes, then clears the services.

Passing a plugin argument that is not installed fails with a tagged error before any provider or dist mutation (`GlobalAppError`).

## Global destroy confirmation

meta:global:destroy is a destructive command gated behind the cross-cutting --yes confirmation rule; running it without --yes fails before any provider call.

meta:global:destroy requires --yes (or -y); without it the command fails with GlobalDestroyConfirmationError and touches nothing.

The tagged error surfaced when --yes is omitted (`GlobalDestroyConfirmationError`).

With --yes the provider state is removed but service data volumes are preserved unless --purge is also passed.

meta:global:destroy --yes --purge removes provider state and the data volumes together.
