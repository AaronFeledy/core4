# Uninstall the global app

This is the host-level global app. It is not `lando uninstall` for the CLI.

## Stop one global service

```sh
lando global:stop --service mailpit
lando global:status --service mailpit --format=json
```

That stops Mailpit and removes its container. Status reports it as `stopped` in `result.services[].status`. `--service` (or `-s`) is repeatable: `lando global:stop -s mailpit -s ssh-agent` stops both.

Dependencies aren't stopped for you. Lando leaves volumes, the shared network, and every service you didn't name alone, so Traefik keeps serving its routes. An unknown name fails before anything stops. A selected stop needs the global app's applied state; if containers outlived it, the command fails and changes nothing.

This isn't a permanent off switch. Starting an app that needs a global service can bring it back. To start it yourself:

```sh
lando global:start --service mailpit
```

Mailpit's route needs Traefik, so that also starts Traefik when it's stopped and lists it in `servicesStarted`. Routes follow what runs: services you didn't name keep theirs while they're up, and a stopped service's hostname gets the proxy's 404 page.

## Clear generated services

```sh
lando global:uninstall
```

That regenerates the global Landofile with services cleared and leaves provider volumes in place. Uninstall does not require `--yes`.

To destroy provider resources and volumes first, then clear services:

```sh
lando global:uninstall --purge
```

A plugin argument is not available yet. It fails with `GlobalAppError` before any provider or dist mutation.

## Destroy provider resources

`lando global:destroy` needs `--yes`. Without it the command fails with `GlobalDestroyConfirmationError` and touches nothing. `--yes` is consent.

```sh
lando global:destroy --yes
```

Volumes stay unless you also pass `--purge`:

```sh
lando global:destroy --yes --purge
```

Stop and destroy use the global app's applied state, so an invalid edit to a global Landofile doesn't block cleanup. Fix the config before starting the app again.

If nothing needs removing, both commands report `unchanged`. With `--format=json`, check `result.outcome` for `stopped`, `destroyed`, or `unchanged`; `materialized` only says whether the generated Landofile exists. An unchanged destroy reports `volumesRemoved: false`, even with `--purge`.

## Related commands

```sh
lando global:start
lando global:stop
lando global:status
lando global:config
```

With no `--service`, `global:stop` tears down the whole global app's running provider resources and keeps volumes. `global:restart` and `global:rebuild` always act on the whole global app. `lando poweroff` stops the global app after your apps unless you pass `--keep-global`. `global:config` prints the effective global Landofile, merged from the generated file and your canonical `.lando.yml` overrides, plus the paths behind it.

Each `meta:global:*` command publishes a `global:*` alias.
