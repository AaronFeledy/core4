# Uninstall the global app

This is the host-level global app. It is not `lando uninstall` for the CLI.

## Clear generated services

```sh
lando global:uninstall
```

That regenerates the global Landofile with services cleared and leaves provider volumes in place. Uninstall does not require `--yes`.

To destroy provider resources and volumes first, then clear services:

```sh
lando global:uninstall --purge
```

A plugin argument is not available yet. It fails with `GlobalAppError` before any provider or dist mutation.

## Destroy provider resources

`lando global:destroy` needs `--yes`. Without it the command fails with `GlobalDestroyConfirmationError` and touches nothing. `--yes` is consent.

```sh
lando global:destroy --yes
```

Volumes stay unless you also pass `--purge`:

```sh
lando global:destroy --yes --purge
```

Stop and destroy use the global app's applied state, so an invalid edit to a global Landofile doesn't block cleanup. Fix the config before starting the app again.

If nothing needs removing, both commands report `unchanged`. With `--format=json`, check `result.outcome` for `stopped`, `destroyed`, or `unchanged`; `materialized` only says whether the generated Landofile exists. An unchanged destroy reports `volumesRemoved: false`, even with `--purge`.

## Related commands

```sh
lando global:start
lando global:stop
lando global:status
lando global:config
```

`global:stop` tears down running provider resources and keeps volumes. `global:config` prints the effective global Landofile, merged from the generated file and your canonical `.lando.yml` overrides, plus the paths behind it.

Each `meta:global:*` command publishes a `global:*` alias.

## Verify

```sh
lando global:status
lando doctor
```
