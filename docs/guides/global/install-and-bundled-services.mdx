# Install and bundled services

## Global app reserved id

The reserved-id guard runs during user-app resolution; declaring name: global is rejected before any plan is built.

The app id `global` is owned by the global Lando app and cannot be used by a project.

A Landofile that resolves to name: global is rejected with this tagged error (`AppIdReservedError`).

The remediation surfaced to the user.

The rejection happens during user-app resolution, before any AppPlan is built (`plan`).

## Global app root

GlobalAppService resolves and materializes the global app directory under the per-user data root; production materialization lands with the bundled global services.

The global app is Lando-owned and lives under the per-user data root (`userDataRoot/global`).

The core service that resolves the root and ensures the directory exists (`GlobalAppService`).

The global app directory is excluded from cwd-based app discovery; only meta:global:* commands resolve it.

## Global app bundled services

Traefik and Mailpit ship as bundled global services in a later Beta story; this scenario documents the install surface they materialize into.

Traefik runs inside the global app and backs the default proxy referenced by per-app services (`traefik`).

Mailpit runs inside the global app and captures mail for every per-app service (`mailpit`).

Plugins contribute additional global services through this manifest surface (`globalServices:`).
