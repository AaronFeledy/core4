# Release compiled bytecode budget

Release binaries use Bun bytecode. The reference `linux-x64` build has a ten-minute
cold-build budget; exceeding it fails the release with `ReleaseCompileBudgetError`.

## Bytecode compile budget

Stage 7 compiles the canonical CLI entry, `./core/bin/lando.ts`, through
`scripts/build-compiled-binary.ts`. The wrapper enables the equivalent of
`--compile --bytecode` for every release target.

Use Bun 1.4.3 or newer; `.bun-version` pins the CI compiler. The release targets
are `darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64`, `windows-x64`,
and `windows-arm64`. Windows release binaries must be compiled on a Windows
host so Bun embeds the Lando icon and Windows version information. See
[Platform scope](../../contributing/release.md#platform-scope) before choosing
a target.

The orchestrator logs each target's compile duration and the `600000ms` budget.
Only the `linux-x64` reference target enforces that limit. The log confirms
compilation, not completion of later signing stages; local rehearsals can skip
those stages with warnings when credentials are missing.

Release-orchestrator tests inject the runner and clock to check this contract
without compiling every platform binary during docs tests.
