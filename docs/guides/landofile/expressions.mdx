# Landofile expressions

Load-time `{{ recipe.<option> }}` and `{{ env.* }}` sites resolve when Lando reads the Landofile. Route hostnames still use plan-time `app` and `proxy`. `${...}` shell params stay blocked.

What also works besides those scopes is a whole-file template, includes, and env overlays.

```yaml
template: handlebars
```

If you came here for `${VARS}` magic in volumes or tooling, that path is still not up.

## Load-time recipe and env

Recipe Landofiles keep values like `php:{{ recipe.php }}`. Lando fills those from that same file's merged `recipe.options`. It does not look up a recipe plugin or run recipe code.

`{{ default(env.LANDO_NODE_VERSION, 'lts') }}` reads the host environment. A missing variable fails closed unless the expression supplies a `default()`.

A missing recipe option, or an unset env var with no default, is a Landofile validation error that names the YAML path.

The `recipe:` block itself is provenance. Lando does not rewrite expressions inside it.

## Route hostnames

Recipes write a primary route like this:

```yaml
routes:
  - hostname: "{{ app.name }}.{{ proxy.defaultDomain }}"
    scheme: both
```

Lando evaluates that string at plan time, before it matches endpoints. `app.name` and `app.slug` come from the app. `proxy.defaultDomain` comes from global config and defaults to `lndo.site`. Change `proxy.defaultDomain` once and every recipe URL that uses the expression follows, without editing Landofiles.

A bad expression raises `ConfigExpressionError` with the YAML path and a fix.

Services with no authored `routes:` still get `<service>.<app>.lndo.site`.

These two scopes work only in route hostnames today. Do not drop `{{ app.name }}` into `environment:`, `volumes:`, or tooling. That still fails at load.

Keep `env` / `recipe` and `app` / `proxy` on separate value sites. A hostname that mixes them stays literal for the planner.

## What to do instead

Use `template: handlebars` or `template: mustache`, then write ordinary YAML. See [Template engines](./template-engines.mdx).

Share fragments with `includes:`. See [Includes and the lockfile](./includes-and-lockfile.mdx).

Override config from the environment with `LANDO_CONFIG__` or `env_file:`. See [Env overrides](./env-overrides.mdx).

`${VARS}` in volumes or tooling is still not up. `load()` and `import()` stay on their own file-IO path.
