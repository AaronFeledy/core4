# Override config with env

Prefix a host environment variable with `LANDO_CONFIG__` to override global config without editing `config.yml`. Export the variable in your shell before running Lando, or prefix a single command with its assignment in a POSIX shell. The examples below show variable names and values, not complete commands. Double underscores separate path segments:

```sh
LANDO_CONFIG__telemetry__enabled=true
```

A single underscore inside a segment maps to a camelCase key:

```sh
LANDO_CONFIG__default_provider_id
```

JSON-parseable values become objects and arrays. Values that are not valid JSON stay as strings:

```sh
LANDO_CONFIG__default_provider_id=podman
```

Some keys also have short aliases, such as `LANDO_ROUTER_HTTP_PORT` for `router.httpPort` and `LANDO_NOTIFY_ENABLED` for `notify.enabled`. Root vars (`LANDO_USER_CONF_ROOT`, `LANDO_USER_DATA_ROOT`, `LANDO_USER_CACHE_ROOT`) sit in the same layer.

An override that fails validation stops every command that needs config with a `ConfigError` that names the variable and what the schema expected, never the value you exported: `Invalid global configuration (environment override LANDO_ROUTER_HTTP_PORT): router.httpPort: Expected a value between 1 and 65535. Unset LANDO_ROUTER_HTTP_PORT or set it to a valid value.`. `lando config validate` reports the same error, so you can check without running anything else. An invalid `LANDO_CONFIG__RENDERER` or `LANDO_CONFIG__LOG_LEVEL` is reported the same way while the command falls back to the default renderer and log level; `LANDO_RENDERER` is not a config override and an invalid value there fails before dispatch.

## Read precedence

Highest-precedence source wins. Env overrides sit above `config.yml` and `config.d/*.yml` drop-ins; see [the layer table](../config/global-config.mdx#choose-the-effective-value). A command flag overrides an env-resolved value:

```sh
lando setup --provider=docker
```

That flag wins over `LANDO_PROVIDER=podman` for that command. The flag persists; the env var does not. See [What persists](../setup/provider-selection.mdx#what-persists).

A local Landofile overrides the main Landofile during merge.

## Share env files across services

Create `shared.env` in your app root with the `KEY=VALUE` entries you want to share, then add the following configuration to `.lando.yml`. Top-level `env_file` loads app-root-relative `KEY=VALUE` files into every service. Later files win, then a service's own `env_file` and `environment` values override the shared values.

```yaml
name: env-overrides-shared
env_file:
  - shared.env
services:
  web:
    type: node:lts
  worker:
    type: node:lts
    environment:
      APP_STAGE: worker
```

Lando fails with the resolved path and a fix when a declared file is missing, instead of starting services with a half-loaded environment.

## Quote env file values

Use single quotes in an env file when backslashes or `${NAME}` should stay literal. For example, add these lines to `shared.env` in your app directory:

```text
WINDOWS_PATH='C:\new'
LITERAL_REFERENCE='${NAME}'
```

The service receives `C:\new` and `${NAME}` as written, without the surrounding quotes. Within single quotes, only `\'` changes: it becomes a literal apostrophe.

Double quotes decode `\a`, `\b`, `\f`, `\n`, `\r`, `\t`, `\v`, `\$`, `\"`, `\\`, and `\0NNN` with exactly three octal digits for a byte value (000 through 377). Other escapes keep their backslash. For example, `"C:\new"` contains a newline after decoding because `\n` is an escape. Use single quotes or double each backslash to keep it. Single- and double-quoted values can span lines.

Env files never interpolate values, regardless of quoting. A bare `NAME` line is an error, not a request to copy that variable from the host. To use a host variable, add it under the service's `environment:` in your Landofile:

```yaml
services:
  web:
    type: node:lts
    environment:
      NAME: "{{ env.NAME }}"
```

Replace `NAME` in both places with your host variable's name, and set that variable in the shell where you run Lando.

Check the files from your app directory:

```sh
lando app:config:lint
```

Lint warns when decoding changes a double-quoted value or when an unquoted or double-quoted value contains `${`. Single-quoted `${` does not warn. Warnings do not make an otherwise valid configuration invalid; syntax errors, including a bare `NAME` line, still need a fix.

## Inspect the resolved config

```sh
lando config
lando config get defaultProviderId
lando config --format=json
```

`lando config` prints the resolved global config with the env overlay already applied. `lando config get` reads one key. `--format=json` is for scripts.
