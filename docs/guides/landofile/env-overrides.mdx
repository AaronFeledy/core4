# Env overrides

## Generic overlay

Prefix that marks an env var as a config overlay.

```sh
LANDO_CONFIG__
```

Double underscore separates path segments (a.b.c) (`__`).

Sets telemetry.enabled to true with no edits to config.yml.

```sh
LANDO_CONFIG__telemetry__enabled=true
```

A single underscore inside a segment maps to a camelCase key (defaultProviderId)

```sh
LANDO_CONFIG__default_provider_id
```

JSON-parseable values are parsed into objects and arrays.

Values that are not valid JSON are kept verbatim as strings.

```sh
LANDO_CONFIG__default_provider_id=podman
```

## Precedence

Highest-precedence source wins for any given value.

An env overlay overrides the on-disk config value.

A command flag overrides an env-resolved value.

```sh
lando <cmd> --provider=docker beats LANDO_PROVIDER=podman
```

A local Landofile overrides the main Landofile during merge.

## Share env files across services

Top-level `env_file` loads app-root-relative `KEY=VALUE` files into every service. Later files win,
then a service's own `env_file` and `environment` values override the shared values.

```yaml
name: env-overrides-shared
env_file:
  - shared.env
services:
  web:
    type: node:lts
  worker:
    type: node:lts
    environment:
      APP_STAGE: worker
```

Lando fails with the resolved path and a fix when a declared file is missing instead of quietly
starting services with incomplete environment values.

## Inspect

Print the resolved global config (env overlay already applied)

```sh
lando config
```

Read a single resolved value to confirm an override took effect.

```sh
lando config get defaultProviderId
```

Emit the resolved config as JSON for scripts.

```sh
lando config --format=json
```
