# Write a Landofile

A Landofile is `.lando.yml` in the app root. Services, tooling, and proxy routes live in one file.

```yaml
name: your-landofile-demo
services:
  app:
    type: "node:22"
    primary: true
  db:
    type: postgres
tooling:
  node:
    service: app
    cmd: node
  psql:
    service: db
    cmd: psql
```

Start it. Lando starts Traefik for you. You do not start Traefik by hand.

```sh
lando start
lando info
```

That's the whole product in one file. The rest of this site is footnotes.

## Add a hostname

Most apps skip `routes:`. Default hostnames look like `app.your-landofile-demo.lndo.site`. Authored routes replace the default hostname, so list every name you want:

```yaml
services:
  app:
    type: "node:22"
    primary: true
    routes:
      - hostname: app.your-landofile-demo.lndo.site
        scheme: both
```

Top-level `proxy:` is the other spelling: a map of service name to the same route list. Set `routes: []` to give a service no hostname at all.

## Override a list in a local layer

Put machine-local changes in `.lando.local.yml`. Layers load from low to high precedence: `.lando.base.yml`, `.lando.dist.yml`, `.lando.upstream.yml`, `.lando.yml`, `.lando.local.yml`, then `.lando.user.yml`.

Maps deep-merge and scalars use the later value. Collection rules come from each field's schema, not the properties of its entries. Included Landofiles follow the same rules.

- Routes match by scheme, case-insensitive hostname, and path prefix in either shorthand or object spelling. Omitted scheme means HTTPS and omitted path means `/`. A `both` route participates in both scheme identities; an HTTPS-only overlay leaves its HTTP route alone. Backends and filters are not route identity.
- `dependsOn` matches by service, in list, map, or object-entry form. Logs match by `id`, which defaults to the path basename.
- Route filters match by `name`, otherwise by `type`. Named filters never match unnamed ones. Changing a matched filter's type replaces that entry.
- Endpoints and ports match by exact, case-sensitive `name` only when every entry on both sides is named. Otherwise the list replaces.
- Every other list replaces, including scalar arrays, tooling `cmds`, event step lists, and opaque extension arrays. A step's `service` is where it runs, not a merge identity.

Route identities with template expressions match by their literal text, including case. Untouched `both` entries stay authored; matching one of their schemes splits only that entry.

An explicitly empty array (`[]`) clears any inherited list. Omit a key to leave its inherited value alone. Mapping keys themselves cannot be deleted by an overlay. See the generated [Landofile schema reference](../../reference/schemas/landofile-shape.mdx#layer-merge-rules) for per-field rules.

For example, start with this `.lando.yml`:

```yaml
name: empty-routes-overlay
services:
  web:
    type: "node:22"
    routes:
      - hostname: web.example.test
tooling:
  test:
    cmds:
      - service: web
        cmd: echo base-first
      - service: web
        cmd: echo base-second
```

Clear the inherited routes and replace the tooling steps in `.lando.local.yml`:

```yaml
services:
  web:
    routes: []
tooling:
  test:
    cmds:
      - service: web
        cmd: echo local-only
```

Inspect the merged config without starting containers:

```sh
lando app:config --format=json
```

`services.web.routes` is now `[]`, not the inherited object route. `tooling.test.cmds` contains only `echo local-only`; neither base step remains. Event step lists replace the same way. To add a route rather than clear the list, set a distinct path such as `{hostname: web.example.test, pathPrefix: /api}`; the inherited root route stays, even if it was a shorthand string.

## Reach for other keys

| Key | What it does |
| --- | --- |
| `events:` | Tasks at start, stop, rebuild, and destroy. |
| `includes:` | Pull in Landofile or tooling fragments. |
| `env_file:` | Shared `KEY=VALUE` files for every service. |
| `environment:` | Per-service env. There is no top-level `env:` key. |

## Verify

```sh
lando app:config --format=json
lando info
```

`app:config` prints the resolved Landofile. `info` prints URLs and connection details.
