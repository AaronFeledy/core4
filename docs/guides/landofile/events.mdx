# Run tasks at app lifecycle events

Use `events:` when work must run every time an app reaches a lifecycle point, whether the command came from the CLI or an embedding host.

```yaml
name: events-demo
services:
  web:
    type: "node:22"
    primary: true
events:
  pre-start:
    - cmd: echo "Preparing the app"
      service: ":host"
  post-start:
    - task: warm-cache
tooling:
  warm-cache:
    service: web
    cmd: echo "Cache ready"
```

`pre-*` failures stop the lifecycle operation. A `post-*` failure becomes a warning because the operation has already completed. Event output uses the normal task-detail renderer and secret redaction. A bare or plain-string step defaults to provider exec, which needs a running service. `pre-start` fires before any service exists, so a `pre-start` step must use the object form with `service: ":host"` to run on the host instead. Use `pre-stop` for work inside a running service; `post-stop` fires after that service is gone and needs `service: ":host"` for shell work.

## Available events

You can attach tasks to `pre-start`, `post-start`, `pre-stop`, `post-stop`, `pre-rebuild`, `post-rebuild`, `pre-destroy`, and `post-destroy`. Your steps run first in declaration order, followed by lower-precedence service-type contributions in deterministic service-name order.
