# Install a plugin from npm

`lando plugin:add` installs an npm registry package into your user plugin root
and validates its manifest. Trust allows plugin code to run on your host. Use
`--trust` in the example below only if you have decided to trust that package;
it skips the trust prompt and saves the package name.

```sh
lando plugin:add @lando/plugin-php --trust
```

Only npm registry specifications are supported in this Beta. Git URLs, tarball
URLs, and `file:` paths fail with `NotImplementedError`. To develop a checkout,
use [Link a local plugin](./link-local-plugin.mdx).

## Add the package

Pass a registry name. Pin a version with `@version` when you care which tarball lands.

```sh
lando plugin:add @lando/plugin-php
lando plugin:add @lando/plugin-php@1.2.3 --trust
```

`--trust` and `-y` skip the trust prompt and persist that name. Without prior
trust or `--trust`, behavior depends on the package: a package with a non-empty
`postinstall` script is unpacked as untrusted and its script is skipped. A package
without that script takes the trust-prompt path and fails with
`InteractionRequiredError` when no interaction is available. See
[Trust plugin postinstall](./trust-postinstall.mdx).

Packages land at `<userDataRoot>/plugins/<name>/<version>/`. A directory that already exists is left in place.

If a step fails, the command stops with `PluginPackageOperationError` and
exits `1`. The error names the operation that failed (`resolve`, `download`,
`verify`, `extract`, or `postinstall`), the package spec, and the child's exit
code when a Bun child ran and exited nonzero. Nothing after that step runs, so
a failed add never activates the plugin or refreshes the command cache. Lando
doesn't undo what the step already wrote on disk. Fix the cause the message
points at
(a bad spec, a registry problem, or the package's own script), then run
`lando plugin:add` again. `lando plugin:remove` reports its failures the same
way with operation `remove`. The full field list and the `--format=json` shape
are in [Script Lando with JSON](../scripting-with-json.mdx#capture-bun-backed-commands).

`lando plugin:add` is the top-level alias of `meta:plugin:add`.

## Install from a private registry

Add your team's scope and registry token reference to your npm user config,
`~/.npmrc`. If you set `NPM_CONFIG_USERCONFIG`, edit that file instead:

```ini
@acme:registry=https://npm.example.com/
//npm.example.com/:_authToken=${NPM_TOKEN}
```

Replace the example scope and host with your team's values. In your host shell,
export the token supplied by your registry, then install the plugin:

```sh
export NPM_TOKEN='<your-registry-token>'
lando plugin:add @acme/lando-plugin-x
```

When the install succeeds, the command reports the plugin name and version, and
the package lands at `<userDataRoot>/plugins/@acme/lando-plugin-x/<version>/`.
Trust prompts and postinstall rules are the same as for public packages.

Lando reads the scope's registry first, then `registry`, then the public npm
registry. `NPM_CONFIG_REGISTRY` overrides the file's default registry; a scoped
registry still takes precedence. Plugin updates and npm recipe sources use the
same configuration. Lando doesn't store registry credentials or read a project's
`.npmrc`. Only path-matched `_authToken` bearer tokens are supported, not npm
basic authentication or npm certificate settings.

If installation reports HTTP 401 or 403, read the error's remediation. It names
your npm user config and the `//host/path/:_authToken` key Lando matched:

- If it says a variable such as `NPM_TOKEN` is not set, export that variable in
  the shell that runs Lando and retry.
- If it says the registry rejected the token, replace it with a token that can
  read the package.
- If no token matched, add the line it shows for your registry.

A private registry can also answer 404 for an unauthenticated request; the
remediation then shows the token line to add.

## Trust the name

Trust applies to an exact package name, not an organization wildcard.

```sh
lando plugin:trust @lando/plugin-php
lando plugin:trust list
```

See [Trust plugins by name](./trust-and-wildcards.mdx).

## What you cannot pass

These specs are rejected today:

```sh
lando plugin:add git+https://github.com/acme/lando-plugin.git
lando plugin:add https://example.com/plugin.tgz
lando plugin:add file:./my-plugin
```

## Verify

```sh
lando plugin:trust list
lando plugin:add @lando/plugin-php --trust
```

The second add should report the same name and version instead of fetching a new tree.
