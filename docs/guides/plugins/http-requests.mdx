# Make HTTP requests from a plugin

Use `ctx.httpClient`. It is Effect's standard `HttpClient` from `effect/http`, and Lando has already wired your user's proxy and CA settings into it.

```ts
import { Effect } from "effect";
import { HttpClientResponse } from "effect/http";
import type { SubscriberFactory } from "@lando/sdk/plugins";

const notifyDeploy: SubscriberFactory = (ctx) => (event) =>
  ctx.httpClient.get("https://status.example.com/api/ping").pipe(
    Effect.flatMap(HttpClientResponse.filterStatusOk),
    Effect.flatMap((response) => response.json),
    Effect.tap((body) => Effect.log("status service answered", body)),
    Effect.asVoid,
    Effect.orDie,
  );

export default notifyDeploy;
```

Do not call `fetch` yourself. A bare `fetch` skips the user's proxy, ignores their private CA, and hides the request from Lando's `pre-http-call` and `post-http-call` events.

## What Lando adds to every request

- **Proxy and `NO_PROXY`.** Lando reads `network.proxy` from global config plus the usual `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` variables.
- **Private CAs.** Certificates from `network.ca.certs` or `LANDO_NETWORK_CA_CERTS` are trusted for that request. `network.ca.trustHost: false` drops the system roots and trusts only those certificates.
- **Trust resolution per request.** Lando resolves trust when the request runs,
  using the configuration service in that request's Effect context unless an
  explicit `NetworkTrust` is supplied. A standard runtime keeps a configuration
  snapshot: later config-file or environment changes require a new runtime.
  CA file contents are read again when trust is resolved without an explicit
  trust override.
- **Redacted telemetry.** Each request is a span named `HttpClient.request`, with the method and a URL that has credentials and query values stripped. Lifecycle events record the origin and method, not the raw URL.
- **Interrupts abort.** Interrupting the fiber aborts the connection. Stream the body with `response.stream` when the payload is large; nothing is buffered until you ask for it.

## Send JSON

`HttpClientRequest` builds anything beyond a plain `GET`:

```ts
import { Effect } from "effect";
import { HttpClientRequest, HttpClientResponse } from "effect/http";
import type { LandoPluginContext } from "@lando/sdk/plugins";

const report = (ctx: LandoPluginContext, payload: unknown) =>
  HttpClientRequest.post("https://hooks.example.com/lando").pipe(
    HttpClientRequest.bodyJsonUnsafe(payload),
    ctx.httpClient.execute,
    Effect.flatMap(HttpClientResponse.filterStatusOk),
  );
```

Failures arrive as `HttpClientError`. When trust is the problem, the error's `cause` is a Lando `HttpTrustError` with a `kind` and a `remediation` line you can show the user. `missing-custom-ca` means the server's issuer isn't trusted; `certificate-invalid` means the certificate is expired, not yet valid, issued for another host, or revoked; the proxy kinds mean the proxy refused the tunnel or wants credentials. A reset, refused, or timed-out connection is not a trust failure and arrives as a plain transport error. The client sends each request once and never retries it for you.

## Download files

Fetching a binary or archive you will keep on disk? Use the `Downloader` service instead. It streams through the same client and checks the SHA-256 before it hands you the file.

You don't choose whether a download retries; the command running your code does. During commands that download on purpose, such as `lando setup`, `lando update`, `lando init`, and `lando plugin:add`, the `Downloader` makes up to three attempts, waiting 1 second and then 2 seconds, and only for a dropped, refused, or timed-out connection or an HTTP 408, 429, 500, 502, 503, or 504 response. During everyday commands like `lando start` it makes one attempt, so a missing download fails fast. Every download fails after 120 seconds without response headers or 60 seconds without body data, instead of hanging.

When a download fails, the `DownloadFetchError` tells you what happened: `reason` is `connection-reset`, `connection-refused`, `timeout`, `dns-temporary`, `host-not-found`, `network-unreachable`, `tls-handshake`, `trust`, `http-status`, or `transport`, and `attempts` counts the tries. Its message and remediation are written for the user, so show them as they are, and keep the error as the `cause` of your own error instead of copying its text into yours.

A library host that runs its own download step can opt in the same way the CLI does, by providing `OnlineAcquisition` from `@lando/sdk/services`:

```ts
import { Effect } from "effect";
import { OnlineAcquisition } from "@lando/sdk/services";

// Downloads inside `step` retry transient failures, as they would during `lando setup`.
const asDownloadStep = <A, E, R>(step: Effect.Effect<A, E, R>) =>
  step.pipe(Effect.provideService(OnlineAcquisition, true));
```

## Try it from a library host

The same client ships in every Lando runtime. This scenario starts a tiny local server and calls it through the runtime's `HttpClient`:
