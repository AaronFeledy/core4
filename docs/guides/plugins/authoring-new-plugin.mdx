# Author a new plugin

Scaffold a new plugin from an embedded template instead of hand-building the
package layout. Every scaffold template is embedded in core, so compiled
binaries never read template files from the runtime filesystem:

```sh
lando meta:plugin:new @acme/lando-plugin-demo ./demo \
  --template bare --cspace acme \
  --description "Demo plugin" --no-interactive
```

Available templates: `service-type`, `provider`, `tooling-engine`,
`template-engine`, `route-filter`, `config-translator`, `recipe`, `bare`.

The generated project includes:

| File | Purpose |
| --- | --- |
| `package.json` | Plugin metadata, `landoPlugin.api: 4`, and scripts for `meta:plugin:test`/`build`/`link` |
| `src/config.ts` | An Effect Schema config entry point for plugin options |
| `test/plugin.test.ts` | A starter test that verifies the exported manifest and core compatibility declaration |
| `README.md`, `tsconfig.json` (strict) | Ready to author without hand-creating boilerplate |
