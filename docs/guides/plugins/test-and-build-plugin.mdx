# Test and build a plugin

Run these from the plugin root (or a nested cwd). Lando walks up to the nearest plugin `package.json`.

```sh
lando meta:plugin:test
lando meta:plugin:build
```

After both commands succeed, check `dist/` for the built entrypoints and
`dist/package.json` for the package metadata. To select test files or pass Bun
flags, use the form below.

## Test

```sh
lando meta:plugin:test test/plugin.test.ts -- --bail
```

Paths before `--` are test files. Flags after `--` go to Bun `test` unchanged. The command validates the plugin manifest first.

Both commands run Bun through the Lando executable you invoked, so no separate
Bun install is needed. Test and build output streams to your terminal as it
runs. A failing test or build exits with Bun's own code; under `--format=json`
you get one envelope with `ok: false`, `result.exitCode`, and the collected
output. Fix what Bun reported and rerun. The envelope shape and the other
failure tags are in
[Script Lando with JSON](../scripting-with-json.mdx#capture-bun-backed-commands).

## Build

```sh
lando meta:plugin:build
```

Build reads `package.json` `exports`, compiles those entrypoints to `./dist` as ESM for Bun, emits declaration files, then writes `dist/package.json`. Nested `dist/` under a source export tree, or `package.json` `exports` that mix source and dist entrypoints, are rejected rather than built.

## Verify

```sh
lando meta:plugin:test
lando meta:plugin:build
```

A passing pair leaves `dist/` with the built entrypoints.
